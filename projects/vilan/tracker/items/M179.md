# M179 — A request handler that PANICS ends the node server process (the `createServer` callback's promise rejects unhandled), while the native server reports it and never answers the client (the response is left open)

- status: OPEN - filed 2026-10-26 (http-55's find, Order 55)
- kind: robustness (std::http; S) - both backends wrong, differently
- area: Standard library

Repro: sweeps/order55/http-55/finds/handler_panic_ends_node_server.vl - `GET /boom` panics. Node: `curl` gets `Empty reply` (exit 52) and the process exits with the panic (`node:internal/process/promises ... triggerUncaughtException`) - every later request is refused. Native: `vilan_rt::http` spawns the handler and the executor prints `unhandled task error (spawned in an http request handler)`, but nothing ends the response, so the client waits until it gives up. M164's `__http_respond` already wraps the answer and lets a cancellation end quietly; it rethrows everything else unchanged (the lane kept today's behaviour). Rec: a panic in `answer` is reported once (the unhandled-task line, both backends) and, when the response has not started, answered `500` with `Connection: close`; natively the same at the spawned task's failure. The rpc server already does this for a throwing `[rpc]` (M165's rpc half).
