# N31 — an `#[ignore]` reason must name a tracker item, and a gate should say so

- status: OPEN — audit run 4's process recommendation; third consecutive run to find an untracked known-bug pin
- kind: process
- area: Testing & CI
- source: audit run 4, 2026-08-29

The house rule ("a known-but-unfixed bug is pinned `#[ignore]`d" + "an open
defect is not tracked unless it has an item") has no enforcement seam, and
runs 2, 3 and 4 each found an ignored pin whose defect lived nowhere but the
ignore-reason string (run 4's: the NativeMap use-after-free, now B154).
`crates/vilan-cli/tests/ci_ignored_pins.rs` already gates the weekly leg's
flags; extend it (or add a sibling) to require every `#[ignore = "…"]` reason
in the workspace to carry a tracker item id, with an allowlist for the
deliberate non-bug ignores (platform gates, quiet-machine perf).
