# N170 — vilan-rust's `type_of` looks a CALL up in `inferred_return_types` by the call's id, but that table is keyed by FUNCTION id — the lookup can never hit, and the arm silently falls through to `declared_return_type`

- status: OPEN — filed 2026-10-12 (fix-51's find, Order 51)
- kind: tidy (native; XS)
- area: Native targets & rendering

`Expr::Call(call_id) => self.program.inferred_return_types.get(call_id)..` (the table's doc: "keyed by function alone"). Harmless today because `declared_return_type` → `signature_return_type` → `return_type_of(function)` reads the inferred return for an unannotated callee, but the first hop reads as if call-keyed answers existed. Fix: drop the hop (or key it by the call's target). Found reading the native backend while B578 (fix-51) taught the JS emitter a call's result type. Sizing XS; native-51's.
