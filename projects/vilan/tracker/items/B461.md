The sketch writes this shape throughout: `Signal<List<TransientSource<str>>>`, `CollSignal<TransientSource<str>>`, `Signal<Option<Signal<i32>>>`.

**Reading.** Each nested bare-trait mention mints an implicit generic (B186's `mint_implicit_generic`, as B184 did for fields): `Signal<Option<Signal<i32>>>` at a `let` reads `exists I: Signal<i32>. Signal<Option<I>>`, grounded by the initializer; at a parameter, `fun f(x: Source<List<Source<i32>>>)` reads `<I: Source<i32>, S: Source<List<I>>>`.

**The limit to state.** One implicit generic = ONE concrete type, so every element of `List<Source<i32>>` is the SAME source type; a heterogeneous list is `List<dyn Source<i32>>`, and the diagnostic for a mixed literal must steer there.

Positions: `let` (the ask), parameter, struct field (B184's rule, nested), return (B460 — same ruling question).

Related: B161, B184, B186, B460, B298 (naming anonymous binders in diagnostics — nested mints make it more visible).
