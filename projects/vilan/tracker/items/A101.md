# A101 — the `css` block's declarations become CALLS: `property: value;` → `property(value);`, the strategy element syntax took for attributes (`type("checkbox")`, `stroke-width("2")`), so `css { outline("none"); width(pct(100)); .script_label(); }` — the property keeps its hyphenated CSS name, its ARGUMENTS are ordinary vilan expressions (`pct(100)`, `Color::current().alpha(0.5)`, `size.get(4)` — no `{expr}` holes, no CSS token soup), and a dotted item without a block `.method(args);` is the method call on the chain (today a nested-rule head REQUIRES `{ … }`). The lowering does not move: every declaration is still exactly one `.raw(property, value)` (css-block.md §5.2's one rule, name-blind, total), typed values through `raw`'s §6 groundwork. What it buys: one hole spelling fewer (the `{ }` hole exists only because a value was a token span), the §4.1 lexer cost gone (no CSS value tokens — `100%`, `1rem`, `#333` never reach the lexer; the css block's `#333` refusal row retires), value-position completion becomes ordinary expression completion (the paper's Q4 half-dissolves: `pct(`, `Color::` complete as expressions), the formatter's value pass (§8) becomes expression formatting.
