# B190 — a struct literal through a module-qualified path does not parse

- status: OPEN — b172 lane's find (2026-09-01)
- kind: bug
- area: Type system & the type solver
- source: lane b172 (it forced two pins to construct through a `make()` helper)

`shapes::Dot { x = 1 }` → `expected ';' to end this statement`.
Expression-position paths already resolve (`shapes::make()` works),
and B172 now admits `shapes::Dot` in every TYPE position — the struct
LITERAL is the one spelling left that cannot take a qualified head.
The parser's literal rule keys on a bare identifier followed by `{`;
extend it to the same `type-path` production B172 introduced, with
the usual `if x == y { … }` disambiguation preserved (a qualified
path before `{` in condition position must still read as a
comparison operand, exactly as the bare form does today). Pin: the
literal through one and two segments; the enum-variant-with-fields
twin (`shapes::Kind::Round { r = 1 }`); the condition-position
control.
