# A169 — a mirrored store's client cannot forget a released slot's READER: a `Patch` already in flight may still name the slot, and an op's value can only be read at its own type (the codec has no skip), so the client keeps every released slot's applier for the life of its channel view

- status: OPEN — filed 2026-10-09 (store-49's find, Order 49)
- kind: protocol design (S)
- area: Reactive core & UI

A153 S2's `MirrorView` moves a slot whose last hold went to `retired`, where its applier reads (and discards) whatever a late frame carries for it; a view closes when its channel's last grant goes, taking them all, but a long session that scrolls through many keyed boundaries grows the list. Doors: (a) the server acknowledges an `Unsubscribe` (a `Gone(slot)` in its next patch, after which the client forgets the reader); (b) a skippable op encoding (a length or a deserializer `skip`); (c) bound the list. Rec: (a) — one op, and it is also what a client needs to tell a revoked boundary from a slow one. Sizing S; std::rpc::mirror both halves.
