# F188 — Two rough edges in every native build, seen preparing the hardware run: the emitted Rust has unreachable code after `process::exit` (warnings in every generated project), and the printed binary path lacks `.exe` on Windows

- status: open
- kind: native backend polish (emitter; CLI output)
- area: crates/vilan-rust/src/lib.rs (what follows a diverging host call), crates/vilan-cli/src/native.rs (`cargo_build`'s returned path)

(1) After `vilan_rt::process::exit(2)` the emitter still writes the unit value (`vilan_rt::str_new("")` in the sample), so rustc warns `unreachable expression` on every build of a program that exits; the emitter knows the callee diverges (the analyzer types it `never`) and should end the block there. A generated project that builds without warnings is worth holding with a pin: `RUSTFLAGS=-D warnings` over the native differential's shared target would have caught this. (2) `cargo_build` returns `target/debug/<name>` on every system; on Windows the file is `<name>.exe`. Launching works (the process launcher appends the extension, and CI's Windows shards run native programs), but the path `vilan build --backend rust` PRINTS is not a file that exists. Use `std::env::consts::EXE_SUFFIX`. Related, not a defect but a decision for the desktop work (F166): no `windows_subsystem` attribute is emitted, so a GUI program is a console program on Windows: double-clicked, it opens a console window beside its own.
