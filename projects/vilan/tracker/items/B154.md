# B154 — the internal `NativeMap::insert` frees the caller's value while the table holds it

- status: OPEN — found by B153's same-shape sweep (Order 20), confirmed by audit run 4; the hazard is pinned `#[ignore]`d
- kind: bug
- area: Memory & resources
- source: lane b153's std sweep + audit run 4 finding 5, 2026-08-29

A measured host-side use-after-free: `NativeMap::insert(&mut self, key, value)`
declares `value` bare, so the widened temporary predicate frees a resource
argument at the insert statement while the table goes on holding it. Reachable
only by importing the non-public `std::native_map` directly — `Map<K, resource>`
and `Set<resource>` are R10-refused, and `Map`/`Set`'s own inserts are `own`.
Two candidate fixes, and the choice is a ruling: `own value: V` closes it but
buys a redundant deep copy on EVERY `Map`/`Set` insert in the language
(12 corpus goldens move) to fence a module nothing public reaches; adding the
internal head to R10's rejecting list is zero-cost but makes `Map<K, Res>`
report through two heads, which the `assert_fails_once_with` pins read. The
evidence and the full reasoning live in the `#[ignore]` pin
`r10_refuses_a_native_map_of_a_resource` (crates/vilan-core/tests/inference/resources.rs).
