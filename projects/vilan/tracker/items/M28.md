# M28 — `plan_resource_drops` costs 350–600 ms per analysis and switches on WHOLE-PROGRAM the moment any type is `resource`

- status: OPEN — paper lane m19-paper's find (2026-09-03); per-module-analysis-reuse.md Q4 (file separately)
- kind: performance
- area: Type system & the type solver

Inside `checks` on kolt: `plan_resource_drops` 387 ms +
`liveness::LastUse` 345 ms + `check_resource_moves` 264 ms of a
2,675 ms phase, gated by `declares_a_resource()` — a whole-program
predicate that turns the drop planning on for EVERY body once any
type in the program is a resource. M19 tranche 1 hides it for the
editor (a frozen module's drops are frozen); `vilan build` still
pays. Fix: plan drops per body only where the body's types reach a
resource (a per-function predicate from the type tables), and make
`LastUse` incremental per body. Pin: a program with one resource
type and a thousand resource-free functions plans drops for the
functions that mention it only; numbers on kolt.
