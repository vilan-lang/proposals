# B628 — A generic struct LITERAL whose one field fixes `T` and another holds a bare `None` types as `Page<T>` at its use — `let words = Page { items = ["a"], first = None }; shown(words)` is refused "'Page<T>' does not implement trait 'Debug'" (`first = Some("b")` runs; `[derive(Json)]`'s `to_json` meets the same as "generic parameter 'T' is missing the bound")

- status: OPEN — filed 2026-10-13 (std-52's find, Order 52)
- kind: false refusal (S)
- area: Type inference

Met writing B622's Wire pin (`encode_json(words)` on a `[derive(Wire)] struct Page<T> { items: List<T>, first: Option<T> }`). `items = ["a"]` alone binds `T = str`; the `None` beside it (an `Option<hole>`) seems to leave the literal's argument slot unresolved, so the binding's type is the declaration's own `Page<T>` at the next bound check. Reproduces on v0.49.0. Rec: the literal's arguments unify across every field before the binding settles (the hole from `None` is filled by `items`' `str`). Sizing S; the solver.
