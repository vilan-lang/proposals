# M22 — a watch round recompiles every leg of the workspace, not the reached one

- status: OPEN — editor-perf lane's HMR measurement (2026-09-01)
- kind: perf
- area: Performance & footprint
- source: lane editor-perf: a one-char views.vl edit emits 18 lines — client + probe + server all recompiled

`vilan build --watch` re-analyzes and re-emits the WHOLE workspace on
any edit; the edited module is reached by one leg (views.vl → client
only). E113's reachability answers "which legs reach this file" —
the watch loop should recompile only those (plus any leg whose stamp
inputs changed). Pin on the watch harness: an edit in a client-only
module re-emits the client leg only; a shared-module edit re-emits
every reaching leg. Caveat from the lane: build hooks run per round
too — kolt's lucide hook regenerated a stub mid-experiment; the hook
freshness stamp already handles that, keep it in the pin.

Measured 2026-09-01 on the owner's 0.40.0 at idle: a views.vl edit
recompiles client + probe + server, 4.0 s wall for the round; only
the client leg reaches views.vl.
