# F117 — natively, a member of a blanket whose subject is a PARAMETERIZED bare trait (`impl Iterator<type T> with Again<T>`) that returns `Self` is refused "the `rust` backend does not emit a value of type `a trait object` yet" at the member — the native instance types `Self` as the bare trait, not the receiver

- status: OPEN — filed 2026-10-08 (solver-48's find, Order 48)
- kind: bug (native refusal; S–M)
- area: Native targets & rendering

B567 made the call's return type read the bare-trait subject as the implicit binder the call bound to the receiver (`bare_trait_subject_as_binder`), so `[5, 6].iter().map(..).again().to_list()` types and runs on JS (and std's own `it.iter()` through `impl Iterator<type T> with Iterable<T>`). The native emitter builds the member's signature from the declared `Self`, a `Type::Trait` slot structurally equal to the subject, and refuses it as an object. The binder spelling (`impl type I: Iterator<type T> with Again<T>`) runs on both. Rec: the native instance substitutes a `Self`-typed position of a bare-trait impl member by the receiver it is instantiated for (the subject's own slot is already bound to it by `bind_subject_and_bounds`). Sizing S–M; native.
