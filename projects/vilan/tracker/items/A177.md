# A177 — A173 S3 (a line editor on `process::keys()`) needs four things S2 does not give, found building S2: the terminal's SIZE and a resize signal, a portable ESC in a string literal, a decoder answer for the cursor-position report, and grapheme display widths

- status: OPEN - filed 2026-10-26 (std-55b's find, Order 55); on a shown need
- kind: design note - A173 S3 (line editing on keys), what S2 taught
- area: Language

S2 leaves a line editor everything on the INPUT side (`Press` with the modifier set, `Paste` whole, the escape timeout, the shared pump so `read_line` and `keys` interleave) and `io::write` (E332) on the output side. What it would still need: (1) the terminal's width (and height) and a resize notification - wrapping a line longer than the screen, or redrawing after a resize, needs `process.stdout.columns`/`TIOCGWINSZ` and SIGWINCH (natively one more FFI call and one more signal in `vilan-rt-term`); (2) an ESC in a vilan string literal: every cursor move or erase (`ESC [K`, `ESC [nD`) is written from vilan source, and today `"\u001b[1m".len()` is 9 and `"\x1b[1m".len()` 7 on JS (the escape text, not the decoded string) - B652 (parser-55) settles the decode, and S3 should start after it; (3) the cursor-position report (`ESC [ row ; col R`, the reply to `ESC [6n`) is the same CSI as a modified F3 (`ESC [1;5R` is Ctrl+F3): the decoder reads `R` as F3 today, so an editor that queries the cursor needs the decoder to tell a report from a key (a mode set while a query is outstanding, as crossterm does); (4) display widths: a wide (CJK) or combining or ZWJ scalar does not advance the cursor by one column, and std has no width table. Rec: S3 stays on a shown need (the ruling); when one is shown, slice it as `process::terminal_size()` + a resize stream first (S, both backends), then the editor.
