# E100 — a module-load parse error carries no span

- status: OPEN — deliberate today (`report_module_parse_errors` pushes EMPTY_SPAN, "the rendered position rides in the message"); the machinery exists and generated code makes the cost acute
- kind: bug
- area: LSP & tooling
- source: the lucide-evidence lane, 2026-08-28

The same parse error in the ENTRY file renders at its true position; in
an imported module it anchors at 1:1 with the position only in prose.
The diagnostic is already attributed to the module's own SourceId, so
only the span is discarded — `render_at` has `error.span` in hand when
it throws it away. The measured cost: one bad generator character
produced 798 errors all pointing at line 1 of an 18k-line generated
file, out of source order. Three shipped tests assert the current
message shape (document.rs, module_resolution.rs, workspace.rs), so the
fix is a deliberate span-carrying change across core + LSP, not a
one-liner.
