# B164 — a supertrait's type argument is not substituted through a sub-trait bound

- status: OPEN — found by the a32-paper lane's probes (Order 22), FIX-NOW;
  in-order lane running
- kind: bug
- area: Type system & the type solver
- source: reactive-traits.md §8.2, probed on 0.39.0

With `trait Sig<T> with Src<T>` (a supertrait carrying the parameter),
`fun bad<S: Sig<u32>>(s: S): str { s.get() }` compiles — `get` comes from
`Src<T>` and its `T` is never substituted with the bound's `u32`, so a
`u32` flows out typed as whatever the annotation claims. Controls confirm
the boundary is exactly the supertrait path (direct bounds substitute
correctly). Low estate reach today (supertraits are rare) but
`trait Signal<T> with Source<T>` — the A32 arc's own spine — walks
straight into it, so it gates the arc. Fix the substitution through the
supertrait chain; pins per shape (method from the supertrait under a
concrete sub-bound, two levels deep, the direct-bound control staying
green).
