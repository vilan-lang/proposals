# B459 — `then`/`else` conditionals: the EXPRESSION form `EXP then EXP else EXP` (sugar over `if EXP { EXP } else { EXP }`) and three STATEMENT forms — `EXP then STMT;`, `EXP else STMT;`, `EXP then STMT else STMT;` (sugar over `if EXP { STMT; }`, `if EXP {} else { STMT; }`, `if EXP { STMT; } else { STMT; }`) — so `|x| x then count.derive(Some) else Source::constant(None)` and the guard `should_debug else ret;` need no blocks

- status: OPEN — filed 2026-09-29 (the owner's item, from kolt's `reactive2.vl` sketch)
- kind: design (grammar sugar; S–M)
- area: Type system & the type solver

**Forms (the owner, 2026-09-29).** In expression position the ONLY valid form is `EXP then EXP else EXP`, exactly as `if` in expression position needs its `else`. In statement position the three statement forms; `EXP else STMT;` is the guard. The branch of a statement form is a single statement (no block).

Pure desugaring: `c then a else b` lowers to `if c { a } else { b }` before analysis, so typing, `is`-binding scope (B171: bindings of `c` reach `a`, not `b`), emission and diagnostics are the `if`'s.

Questions for the paper/ruling:
1. **Precedence.** Lowest of the binary forms — `a || b then x else y` reads `(a || b) then x else y` — and below `=`? (rec: above assignment, below `||`).
2. **Associativity / chaining.** `a then x else b then y else z` as `a then x else (b then y else z)` (right-assoc, an else-if chain).
3. **`then` without `else` in expression position** — RULED refused (2026-09-29); a bare `c then x` is the statement form only.
4. **The keyword.** `then` is not a keyword today; make it CONTEXTUAL (B414's paper: only in infix position after a complete expression — no production starts with an expression followed by a name, so no lookahead cost).
5. **Formatter/editors.** The line-break rule for a long form (break before `then` and `else`), both editor grammars, hover on `then`.
6. **Statement vs expression at statement position.** `a then f() else g();` is read as the STATEMENT form, so the branches need not unify (rec) — the meaning is identical either way; only typing differs.
7. **The guard's `is` bindings — RULED 2026-09-29: yes, as recommended.** `opt is Some(let v) else ret;` desugars to `if opt is Some(let v) {} else { ret; }`, where B171 scopes `v` to the empty then-block — useless. Rec: when the `else` statement DIVERGES (`ret`, `break`, `continue`, `panic` — `never`, B204), the condition's `is` bindings extend to the rest of the enclosing block (Swift's `guard`, Rust's `let … else`). This is the one place the sugar is not a pure rewrite.
8. **`let` as the STMT.** `c then let x = 1;` binds into a synthetic block and is dead — refuse with a steer.

Related: B414 / `proposal/contextual-keywords.md` (contextual words), B171 (`is` scope).
