# B660 — A tuple literal's trailing comma, which the grammar deliberately has none of, is diagnosed as "unclosed `(`" when the tuple is a call argument (`combine((a, b,))`), and as a bare "expected an expression" otherwise; neither says that tuples take no trailing comma

- status: OPEN — filed 2026-10-20 (kolt's message editor: a four-signal `combine((..))` written one element per line, as call arguments and list literals are)
- kind: diagnostics (parser; S)
- area: Language

```vilan
fun main() {
	let pair = (
		1,
		2,
	);
}
```

vilan 0.52.0: `found ')' expected an expression` at the `)`. Inside a call, `let lit = combine((\n\ta,\n\tb,\n)).derive(..)` reports `unclosed '(' in expression: expected a matching ')'` and highlights the whole call, whose parentheses are balanced.

The missing trailing comma is by design: the formatter's notes (E314, E321) and `formatter.rs` say a tuple expression takes none. But a call's arguments, a list, a struct literal, an import set and a signature all take one, and the formatter writes it on every multi-line one, so writing it on a multi-line tuple is the natural mistake. Ask: when `)` follows a `,` inside a tuple, say so: "a tuple takes no trailing comma; remove the `,` before `)`". The call case should not fall back to "unclosed `(`".
