# A172 — `list.to_array(): Option<[T; N]>` (array-lengths.md §9, an intrinsic slated for S3) was never built — std has no way to make a `[T; N]` from a `List<T>`, so B623's `FromJson` for arrays seeds a repeat with the first element and overwrites, with length `0` as its own impl

- status: OPEN — filed 2026-10-13 (std-52's find, Order 52)
- kind: std surface + intrinsic (S)
- area: Language

The paper's row: `fun to_array<const N>(self)` on `List`, an intrinsic (JS `xs.length === N ? Some(xs.slice()) : None`; Rust `<[T; N]>::try_from(v).ok()`), fallible so `Option` (Q9). No compiler or std file defines it on next @697c9517. B623's decoder works without it (`[first; N]` then index writes, `impl [type T: FromJson; 0]` for the empty array — the specificity §5.4 gives) and would collapse to `elements.to_array()` with it. Rec: build it (both emitters, a native intrinsic in vilan-rust) in the next std/native order; then fold the length-0 impl away. Sizing S.
