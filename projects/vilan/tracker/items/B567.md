# B567 — a blanket written with a TRAIT as its subject — `impl Iterator<type T> with Pour<T>` — compiles, and calling its member on a concrete iterator is an INTERNAL error at emission ("a call resolved to `Iterator`'s requirement `next`, which has no body"); written `impl type I: Iterator<type T> with Pour<T>` it builds and runs on both backends

- status: OPEN — filed 2026-10-05 (store-47's find, Order 47)
- kind: emission: internal error (S–M)
- area: Type system & the type solver

std's own `impl Iterator<type T> with Iterable<T>` is this shape, and `it.iter()` on an adapter chain is refused "cannot call 'to_list' on a value of bare trait type 'Iterator'" — so `Iterable` is unusable today. Either the trait-subject spelling should mean what the type-binder one means, or it should be refused with a steer to it. A158's `Items<T>` uses the binder form.
