# B632 — M110 S6/S7's per-source path keys were off by one: std's `lib.vl` (and a dependency's surface) registered a source without pushing its key into `id_windows.source_keys`, so every later source was keyed by the NEXT source's path and the last by `0` - the demand table and the item-record keys of every package module named the wrong file

- status: FIXED - filed and fixed 2026-10-13 (incr-52b's find, Order 52)
- kind: bug (incremental; XS) - FIXED in incr-52b 0d612b20
- area: Type system & the type solver

Item records stayed sound only because the text hash and the signature validate a served record; two files with an identical item text could have collided under a shifted key. The entry-module arm of the drain also pushed a key for a source it did not register. Each source now registers its own key beside it, debug-asserted (`source_keys.len() == sources.len()`) at the build's source-path seam.
