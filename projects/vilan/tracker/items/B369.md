# B369 — an INTERNAL error when a generic CONSTRUCTOR FUNCTION with an UNDECLARED return type builds a user-written generic `Slot` impl: `fun hold<C: Slot>(body: || C) { Holder { body } }` then `<div>{hold(|| <span/>)}</div>` fails `vilan check` with `internal: a call resolved to Slot's requirement place, which has no body … The receiver's type could not be resolved` anchored in STD (`browser/ui.vl open_row_before<C: Slot>`); declaring the return type (`: Holder<C>`) fixes it — the inferred return type of a generic function loses `C`

- status: OPEN — filed 2026-09-21 (the kolt sweep before Order 39); MINIMIZED the same day
- kind: bug (internal error; clean-to-internal, never a wrong program)
- area: Type system & the type solver

## Measured (vilan 0.40.0, c3f7d1a38)

`scripts/integration/sweeps/order39/probes/b369_min.vl` — 20 lines, one file, `prelude = "std::web"`, a browser entry:

```
struct Holder<C: Slot> { body: || C }
impl Holder<type C: Slot> with Slot {
	fun place(self, parent: View) {
		let region = Region::open(parent);
		let _row = region.open_row((self.body)());
	}
}
fun hold<C: Slot>(body: || C) { Holder { body } }          // <- no return type
fun main() { let _root = ui::mount_root("app", || <div>{hold(|| <span>{"x"}</span>)}</div>); }
```

→ the internal error. With `fun hold<C: Slot>(body: || C): Holder<C>` it checks and builds. Building the struct DIRECTLY at the child position (`<div>{Holder { body = .. }}</div>`) is also clean, as is the same impl with an `effect` nesting or a `context owner_scope` clause on the field — the ONE ingredient is the generic function's inferred return type. E107's family (undeclared return types) reached through B55's guard.

Found as kolt's `lib/conditional_value.vl` `when_value<T, S: Source<Option<T>>, C: Slot>(..) { ConditionalValue { condition, body } }`; kolt now DECLARES the return type (its working tree, with a comment naming this item). Two red herrings on the way, recorded so nobody repeats them: it is NOT impl admission (every import-side variant failed identically) and NOT the call shape (a trivially-typed call failed too); and a first 'minimal' package passed VACUOUSLY because its manifest keys were wrong and the entry was never built — a probe that passes must be shown to BUILD something.

## Fix direction

The inferred return type of a generic function must carry the function's own parameters (`Holder<C>`), not the erased nominal; find where an inferred return type is recorded for a body whose tail is a struct literal of a generic type (the `inferred_return_types` writer) and why the literal's arguments are dropped or left as holes that a later instantiation never fills. Whatever the fix, B55's guard should anchor at the USER's call (E190's rule), not in std.
