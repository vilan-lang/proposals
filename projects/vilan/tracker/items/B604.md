# B604 — A closure parameter over the result of a `.map` is not checked against its uses — `let words = ["a", "bb"].map(|word| word.len()); words.filter(|length| { let probe: str = length; .. })` checks clean (JS runs it; rustc refuses E0308 natively), while an annotated `let words: List<usize>` refuses the `let` "Expected str, but got usize"

- status: OPEN — filed 2026-10-10 (native-50's find, Order 50)
- kind: bug (checker; S)
- area: Type inference

Found while pinning F128: the probe `let probe: str = length` inside `.map(..).filter(|length| ..)` was accepted, so the closure parameter's type is still open when the body is checked and nothing re-checks it once `map`'s `U` settles. The native backend renders the settled `usize` and rustc refuses the program ("a BACKEND defect" by the CLI's sentence) — the checker owes the error. Expected on both: `Expected str, but got usize instead.` at the `let`. Sizing S; the solver (re-check of a closure body after its parameter settles, or fill-from-use B599).
