# E315 — a TYPE in the middle of a module-qualified value path paints nothing — `Length` in `style::Length::px(4)`, `Overflow` in `style::Overflow::Hidden` (kolt views.vl:218, every `style::Length::rem(..)` in kolt) carry no semantic token, while `Theme` in `Theme::stroke1()` paints Struct

- status: OPEN — filed 2026-10-13 (editor-52's find, Order 52)
- kind: editor (semantic tokens; S)
- area: Editor

The analyzer records a type-reference row (`Program::type_references`) for a type that HEADS a value path (`Theme::stroke1()` -> `Theme`) but not for one reached through a module first (`style::Length::px`): the module segment paints Namespace (its `Expr::Module` entity), the leaf paints Function since E311's `path_leaf`, and the type between them is in no table, so neither hover-by-span nor tokens see it. Fix at the path resolution: record the middle segment's (source, span, definition) row as the head's is. Pins: `style::Length::px(4)`, `style::Overflow::Hidden`, a three-module path, the hover on the segment (the struct's declaration).
