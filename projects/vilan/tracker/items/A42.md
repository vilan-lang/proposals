# A42 — `bind_each` demands both `T: PartialEq` AND a key fn; split the value-keyed and key-fn forms (kolt writes the key twice and gets a stale row)

- status: OPEN — the owner's ask while migrating kolt (2026-09-04); triage lane's survey at 289e2a2b
- kind: design
- area: Reactive core & UI

`fun bind_each<T: PartialEq, K: PartialEq, S: Source<List<T>>>(source, key,
render)` (browser/ui.vl ~307). `T: PartialEq` is used in ONE place:
`reconcile` (reactive.vl ~765–803, line ~783 `old == item → Keep else
Refresh`) — K decides identity and node MOVES; T decides, for a
surviving key, reuse (~339) vs dispose-and-rebuild (~343). The SSR twin
(process/ui.vl ~237) declares the bound and never uses it.

Usage: kolt 3 sites (views.vl ~404/588/755), all identity key `|x| x`;
website 2 (`|row| row.id`); std 0. kolt hand-writes `impl Command with
PartialEq { self.id == peer.id }` (views.vl ~625) and the same for
`Theme` (theme.vl ~95) — the equality IS the key, written twice
(`Command` carries a closure so it cannot derive). Consequence, latent:
a `Theme` whose `variables` change compares equal → Kept → never
re-renders. The double bound caused a staleness bug.

Shape (additive): keep the 3-arg form (moves AND skips unchanged rows);
add `bind_each<T: PartialEq, S>(source, render)` (key = identity,
unchanged = `==`; kolt's three sites) and `bind_each_by<T, K:
PartialEq, S>(source, key, render: (sync |Source<T>| View) context
owner_scope)` with NO bound on T: a surviving key keeps its row and
owner and std writes the new item into the row's own `SignalCell<T>`
(`set` never compares, ~570) so the row updates through its bindings —
Solid's `<Index>` beside today's `<For>`. Engine: parameterize
`reconcile` on `same: sync |T, T| bool`; `bind_each_by` never emits
Refresh. Migration zero forced; kolt's two hand impls become optional.
Size M (~15 reconcile, ~70 browser/ui, ~25 process/ui, docs).
Related: analysis-reuse.md ~652 ("bind_each requires derive(PartialEq),
so most kolt-shaped entries bypass the cache"); A14.
