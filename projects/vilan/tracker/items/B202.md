# B202 — `[expose]` of a field implementing no `Source` leaves `cannot find type '_'` twice: the expansion's own placeholder

- status: OPEN — cascade-25 lane's find (2026-09-01); B189's residual
- kind: bug
- area: Type system & the type solver
- source: `vilan/std/src/rpc.vl` pushes the literal `"_"` into `exposed_elements` when it cannot read an element

After B189, an `[expose]` on a non-Source field is 6 → 4 errors; the
three follow-ons left are one `cannot infer 'T' … ': Wire'` and two
`cannot find type '_'` — the `service` macro's placeholder, which is
not a type. Fix: when the element cannot be read, generate NOTHING
for that field (the field's curated refusal already stands alone) —
the mirror and the `expose` call are skipped for a refused exposure.
Pin: one refused field → exactly one diagnostic.
