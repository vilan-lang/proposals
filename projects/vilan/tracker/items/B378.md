# B378 — SPECIFICITY — the impl-selection order does not rank a SUBTRAIT bound above its supertrait bound: `impl type S: Narrow<T>` vs `impl type S: Base<T>` where `trait Narrow<T> with Base<T>` → 'neither impl subject is more specific'. Repro (with a control): `trait Base<T> { fun f(self) }`, `trait Narrow<T> with Base<T> { fun g(self) }`, `impl type S: Base<T> { fun h(self) }`, `impl type S: Narrow<T> { fun h(self) }` — a call `x.h()` on a type implementing both → 'neither impl subject is more specific'. `Narrow<T>` implies `Base<T>` by declaration, so `S: Narrow<T>` is strictly the smaller set and must win. Fix: the specificity comparison consults the trait inheritance graph (a subject bound by a subtrait is more specific than one bound by any of its supertraits).
