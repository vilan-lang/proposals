# B658 — `let x = opt is Some(let t) else ret;` inside an `if` block is reported only at the `else` branch below it ("found ')' expected ','" in an unrelated call); the line with the mistake is never named

- status: OPEN — filed 2026-10-20 (kolt's message editor: the link modal's apply closure)
- kind: diagnostics (parser; S)
- area: Language

```vilan
fun consume(value: str, link: Option<str>) {}
fun pick(target: Option<str>, inserting: bool) {
	if inserting {
		let target = target is Some(let t) else ret;
		consume(target, Some(target));
	} else {
		consume("x", target);
	}
}
```

vilan 0.52.0 (`vilan test`): `found ')' expected ','` at `consume("x", target);` in the `else` branch (line 7), then `expected ';'` at an unrelated `test` item. Line 4, where the mistake is, is not mentioned. The parser seems to read `target is Some(let t) else ret; … } else {` as one expression running into the outer `if`'s `else`. In kolt's larger file, the same shape also produced three type errors on the following line ("Expected str, but got Option<str>"), which point at the symptom, not the cause.

The same line at the top of a closure body gets a usable diagnostic ("expected `;` to end this statement" at `else`). Ask: inside a block, report `let … = <is-pattern> else …` at its own line, ideally with a hint that the let-else form is `opt is Some(let x) else ret;` with no `let x =`. Repro: the snippet above.
