# F122 — natively, a large fixed array lives on the stack: `mut big = [0; 4000000]` emits `std::array::from_fn::<_, 4000000, _>(..)` and the program aborts "thread 'main' has overflowed its stack" where JS prints the element

- status: OPEN — filed 2026-10-09 (papers-49's find, Order 49)
- kind: bug (native backend; runtime abort) (S) — a rendering decision
- area: Native targets & rendering

Repro (`finds/native_big_array_stack.vl`, vilan 0.46.0): `mut big = [0; 4000000]; big[3999999] = 7; print(big[3999999]);` -> JS `7`; natively "thread 'main' has overflowed its stack / fatal runtime error: stack overflow, aborting". `[T; N]` renders as a Rust array (`rust_type`, vilan-rust lib.rs ~2378), which is right for a pixel and wrong for a 16 MB table; value semantics copy it on every binding, so a boxed rendering must keep the copy (`Box<[T; N]>` clones its contents). Rec (array-lengths.md Q12): keep the type, box the STORAGE above a byte threshold fixed in the emitter (element size x N; measure where the default 8 MB main stack and the copies stop being safe), and pin both sides of the threshold on the native differential. Sizing S; native.
