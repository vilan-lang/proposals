# B198 — Windows: `generated_root_covering` fails open for a product not yet on disk when canonicalization degrades to the lexical fallback

- status: OPEN — audit run 7's hazard (c) (2026-09-01); RULING wanted; the pin lands EXPECTED RED as #[ignore]
- kind: bug
- area: Macros & const
- source: audit run 7's Windows analysis; `manifest.rs` ~854 `resolved.starts_with(&root)`

On a case-insensitive filesystem, `canonical_path` folds a path to its
on-disk spelling — which makes G17's identity ladder STRONGER — but
when one side of a containment test is a product the generator has
not written yet, `canonicalize` fails, the lexical fallback keeps the
caller's spelling, and `starts_with` compares a folded root against an
unfolded child: the product falls outside its own generated root.
Same family as Order 22's `import std::Default;` catch. RULE: does
`covering_from` fold case itself (compare case-insensitively on
Windows) or require both sides canonical-or-fail? The pin
`a_product_the_generator_has_not_written_yet_is_still_covered`
(`#[cfg(windows)]`, lane audit7-windows) reds on CI's Windows leg
until this lands.
