# M110 — INCREMENTAL analysis: an edit should invalidate only what depends on what changed, instead of re-running the whole entry's analysis on every keystroke

- status: OPEN — filed 2026-10-03 (the owner: 'why does this happen per keystroke? Ideally a document change would recalculate against the known graph where only specific areas are invalidated'); paper in papers-b-46
- kind: design (paper; architecture) — HIGH for the editor
- area: Performance & footprint

Why it is per keystroke today: the analyzer is a whole-program pipeline (resolve the world, analyze every module over it, then whole-world post passes: checks, const-eval, platform colour, reachability). Its results are tables keyed by program-wide ids, not per-declaration answers with recorded dependencies, so nothing can say 'this edit touched only these'. M19's reuse skips re-ANALYZING an unchanged module's bodies but cannot reach the passes that dominate (M99), and the world is re-resolved each time (M73).

The paper: (1) measure what a typical edit actually invalidates on kolt - a body edit (nothing outside the function, unless its inferred return type moves), a signature edit (its users), an import edit (the module's scope), a type's shape (its users and impls); (2) candidate architectures - a query system with memoized, dependency-tracked queries (salsa-style: parse(file), item signatures, body typecheck(fn), impls-for(type), ..), against 'firewalls' in today's pipeline (signature/body split so a body edit re-checks ONE body; per-module post passes with a world-level merge), against finer reuse in the present tables; (3) what blocks each: inferred return types and opaque returns crossing function boundaries, monomorphization and blanket impl selection being global, macro expansion, the context pass, const-eval; stable ids across edits; (4) what the CLI shares (an on-disk cache is the same graph persisted - the ruled optimization order's 'on-disk world cache' and the parallel-analysis paper fold in here); (5) a staged path where each slice ships a measured win, starting with the body-edit firewall, and the targets: a body keystroke re-checks one function (E121's <500 ms to diagnostics with room to spare) and Find References stays whole-entry. Doors and recs; slices.
