# A171 — A fixed-array type cannot head a path, so an array's associated functions have no spelling at a call site — `[i32; 3]::default()` and `[i32; 2]::from_json(..)` are "this expression cannot be used as a type", and `Default::default()` is refused for having no default body

- status: OPEN — filed 2026-10-13 (std-52's find, Order 52)
- kind: language surface (design; S–M)
- area: Language

B623 gave arrays `Default` and `FromJson` and had to add `std::default::default_of<T>()` and `std::json::from_json_value_of<T>(value)` — `T::member()` spelled as a generic call — because neither a derive nor a user can name `[T; N]::default`. The same holds for any associated function of an array (and of a tuple once one has any). Two doors: (a) admit a bracketed or array type as a path head in expression position (`[i32; 3]::default()`), the parser's and the resolver's; (b) a qualified form (`<[i32; 3]>::default()`, Rust's). Rec: (a) — it is the spelling users try first and it reads like `List<i32>::new()`; the helpers stay as generic conveniences or are retired. Owner's call.
