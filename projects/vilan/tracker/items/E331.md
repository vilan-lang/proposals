# E331 — vilan-dap under `watch: true` DISCONNECTS the VS Code debugger at the first file change — `vilan run --watch` does restart the program, but the session ends instead of re-attaching to the new round; the plain launch and the panes' tooltips work (the owner's F5 check of v0.51.0 on kolt's server leg)

- status: OPEN — filed 2026-10-16 (the owner's F5 check of v0.51.0, after Order 53)
- kind: bug (vilan-dap; S7 watch mode; S-M)
- area: LSP & tooling

S7 (debug-53, 592ee67a) runs `vilan run --watch --inspect-brk` and its `attachRounds` loop is meant to re-attach to every round's inspector at the same port; the lane's scripted watch session re-attached across two rounds on a small fixture, and the Windows fix (3a093e5c) added three program-ended signals (`NodeRuntime.waitingForDisconnect`, the default context destroyed, the console line) that close the round's socket. On kolt (a workspace with a server leg and a browser client leg, HMR, a multi-second rebuild per round) the session ends at the round boundary. Suspects, to be settled by a reproduction on a kolt copy through the scripted DAP client: (1) `finish()` from the `vilanPid` liveness check — the pid captured as the round's `process.ppid` may be an intermediate process that dies with the round, not `vilan run`; (2) an unhandled rejection in the adapter after the socket closes (a pending `cdp.send` in the breakpoint re-bind or `programEnded`) crashing the inline adapter; (3) the next round's inspector opening on a different port or after a gap long enough that the terminal/console mode branch finishes; (4) the workspace watch writer's round shape (two legs) differing from the lone-package script's. Gate: a scripted session over a kolt copy's server leg under `--watch` with a file change, asserting re-attach and NO `terminated`; the fix lands with the pin. Workaround meanwhile: `"adapter": "js-debug"` in the launch configuration keeps S6's child-process attach for watch runs.
