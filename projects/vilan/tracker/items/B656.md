# B656 — A local named `css` inside a closure in an element hole loses the keyword diagnostic: `{items.map(|item| { let css = ..; <span style(css)>..</span> })}` reports only "a hole in element syntax takes a `View` … `List<void>`" and two "expected `;` to end this statement", never "`css` is a keyword"

- status: OPEN — filed 2026-10-19 (kolt's rich text editor: a per-leaf `let css = styles.css(leaf.style)` inside an `each_by` row)
- kind: diagnostics (parser; S)
- area: Language

```vilan
fun probe(items: List<str>): View {
	<div>
		{items.map(|item| {
			let css = "color:red";
			<span style(css)>{item}</span>
		})}
	</div>
}
```

vilan 0.52.0 (`vilan check`): three errors, none naming the cause — the hole's type error (`List<void>`), then "expected `;`" at `<span style(css)>`'s `>` and at the closing tag. The same two lines at the top of a `fun` body DO get the good diagnostic ("`css` is a keyword: it begins a `css { … }` block …"), but even there it is printed SECOND, after "Expected View, but got void instead: this body ends without producing a value", a cascade of the same root. Two asks: (1) the keyword diagnostic must fire wherever a `let`/parameter binds `css` (it is a parse-time fact; position should not matter); (2) once it fires, suppress (or at least order after it) the cascade errors that follow from the abandoned parse — the first error a user reads should be the cause. Repro: the snippet above in any browser-target package file.
