(1) The subject of a selector is a TYPE; resolve paths inside it with root paths allowed (`pkg::` / `std::` heads resolve as import paths do), in the type resolver rather than at the subject's head - so `(impl (pkg::d::T, std::e::U))`, `(impl List<pkg::d::T>)`, `(impl [std::e::U; _])` and a closure type all take absolute paths in every position; the bare-name rule (resolved in the importing file's scope) and the module-qualified rule stay. (2) The bare form `import m::(impl T);` and `import m::(impl T)::first;` as the one-selector spelling, exactly as `import a::b;` is the one-name spelling of `import a::{ b };`; the formatter canonicalizes a one-selector set to it (formatter.rs ~:5870's rule for a one-member set), so braces appear only with two or more members. (3) E359's quick-fix then emits `import {module}::(impl {absolute subject});`.
