# A181 — Impl selectors: an ABSOLUTE-PATH subject (`(impl pkg::lib::overlay::Overlay)`, `(impl std::web::style::Style)`) resolves from the root anywhere a path stands in the subject type - tuple elements, generic arguments, array elements, closure types - independent of the importing file's scope (today: '`pkg` is a namespace, not a value'); and the bare one-selector form `m::(impl T)` beside `m::{ (impl T) }`, canonicalized by fmt as a one-member set is

- status: OPEN - RULED 2026-11-03 by the owner (part A option 4 accepted; the bare form and non-identifier subjects asked - answered in the reply, built as the item says); Order 56's parser/solver lane
- kind: language (imports; S-M)
- area: Language

(1) The subject of a selector is a TYPE; resolve paths inside it with root paths allowed (`pkg::` / `std::` heads resolve as import paths do), in the type resolver rather than at the subject's head - so `(impl (pkg::d::T, std::e::U))`, `(impl List<pkg::d::T>)`, `(impl [std::e::U; _])` and a closure type all take absolute paths in every position; the bare-name rule (resolved in the importing file's scope) and the module-qualified rule stay. (2) The bare form `import m::(impl T);` and `import m::(impl T)::first;` as the one-selector spelling, exactly as `import a::b;` is the one-name spelling of `import a::{ b };`; the formatter canonicalizes a one-selector set to it (formatter.rs ~:5870's rule for a one-member set), so braces appear only with two or more members. (3) E359's quick-fix then emits `import {module}::(impl {absolute subject});`. Pins: each subject position with an absolute path, red before; the bare form parses, formats, round-trips; the module-qualified and bare-name rules unchanged; the estate's existing selectors unchanged (kolt writes `(impl Overlay)`, `(impl bool with Display)`). Spec names.md §4.3. Sizing S-M.

- 2026-11-03 (the owner): RULED - the whole-module selector is spelled `(impl *)`, not `(impl _)`: `*` already means 'everything' (`export *;`, `::*`) where `_` means 'nothing / a hole'. The parser accepts `*` at the whole-subject position and refuses `_` there with a steer to `*`; fmt rewrites; the estate's `(impl _)` sites move (std fixtures, docs, kolt). `_` INSIDE a type (`(impl List<_>)`, a type hole for 'any element') stays `_` - `List<*>` is not a type. Builds with this item.

- 2026-11-03 (the owner's formal reading, for the spec): the surface forms elaborate to `use <path-expression>` over namespace VALUES - `import pkg::app_overlay::(impl pkg::lib::overlay::Overlay);` ≡ `use (import pkg)::app_overlay::(impl (import pkg)::lib::overlay::Overlay)::*;` - where `(import X)` is a root as a value, `::name` / `::(impl T)` / `::*` are projections and `use` brings the result into the file's scope. Not adopted as syntax; adopted as the spec's semantic model (names.md gains the elaboration table), which is what makes A181's absolute subjects and A182's explicit admissions consequences rather than rules.
