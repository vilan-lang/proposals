# B731 — Owner question: should a backed enum implement `SqlValue` automatically, as it gets `Hashable`?

- status: open (owner ruling)
- kind: design question
- area: std::db / language

M175 made bind lists `List<dyn SqlValue>`. A string-backed enum (kolt's `Role`) no longer binds: four kolt sites need `.value()`. Node used to bind the enum as its string; natively it never built. Options: (a) backed enums get a `SqlValue` impl automatically, bound as their backing value; (b) leave it explicit (`role.value()`), the shipped state. Recommendation: (b) for now; a derive (`[derive(SqlValue)]`) is the lighter door if the sites multiply.
