# B383 — the rpc route's LONG argument list is unchecked — `open_request` never closes the list and `RpcRequest.arity` is ignored, so a call with MORE arguments than the method takes decodes cleanly and the extras are dropped silently (the SHORT list now poisons since 2321790e)

- status: OPEN — filed 2026-09-21 (Order 39 sweep; std-39's find 3)
- kind: bug (std::rpc)
- area: std::rpc / wire

Fix: the route decoder calls `end_list` after the last declared parameter (which 2321790e made hold the list to being read whole) and compares `RpcRequest.arity` to the method's declared count, answering the typed Decode failure on mismatch. Pin in `service_layer`: one extra argument → Decode, not Success; the arity field read at least once (a planted wrong arity reds). Sized S.
