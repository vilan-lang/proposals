# B196 — every native operator except `+` is unchecked for a `bool`/`str`/backed-enum LEFT operand

- status: OPEN — audit run 7's F1 (2026-09-01); RELEASED MISCOMPILE (present at v0.40.0's d9532a9e); FIX-NOW lane
- kind: bug
- area: Type system & the type solver
- source: audit run 7, `analyzer.rs:34333` — `if native_left && matches!(op, BinaryOp::Add)`

The gate's own comment scopes it to `+` because "the other operators
emit arithmetic on numbers, where `+` emits a rendering" — true only
for a NUMERIC left operand. A binary takes its static type from the
left, the host operator returns a number, so wherever the left is
`bool`, `str`, or a backed enum the result is a number wearing a
non-numeric type: `let c: bool = true - 3` → `-2`, takes the TRUE
branch, `c == true` is false; `"12" - "3"` typed str holds 9 and
`.len()` is undefined; `Level::Low - Level::High` is a Level matching
NO variant. 55 wrong-running squares in the audit's 216-program
matrix, all one root. Rule: the native-operand check covers every
operator whenever the left operand is non-numeric; `f64 * i32` stays
the legitimate numeric carve-out. Census the estate BEFORE the
refusal lands (run 8's charter item 1).
