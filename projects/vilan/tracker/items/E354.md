# E354 — A struct literal with a method call after it is never broken, at any width

- status: OPEN - filed 2026-10-31 (kolt, upgrading to 0.53.1)
- kind: fmt edge
- area: Formatter

`vilan fmt` (0.53.1) breaks an over-budget struct literal one field per line when it is a statement's value, but leaves it on one line however long when a method is called on it (`Body { .. }.size()`). In the repro below the literal alone would break; with `.size()` after it the line stays at 110 columns, and kolt's `src/file_page.vl` keeps a 161-column `body = MessageBody { version = body_version, blocks = [BodyBlock { .. }] }.to_json(),` after `vilan fmt .`. The same holds inside another literal's field and as a `then`/`else` arm. Nothing stops parsing; the line just isn't wrapped.

Repro (standalone, runs and prints `1`; `vilan fmt` leaves it unchanged): kolt session scratchpad `fmtrepro/receiver.vl`, copied below as the whole file.

```
struct Inner {
	kind: str,
	content: str,
}

struct Body {
	version: i32,
	blocks: List<Inner>,
}

impl Body {
	fun size(self): usize {
		self.blocks.len()
	}
}

fun main() {
	let shown = "a block of code, long enough to push the line past the budget";
	let blocks = Body { version = 1, blocks = [Inner { kind = "code", content = shown.to_uppercase() }] }.size();
	print(blocks);
}
```

Likely the chain printer treats a receiver that isn't a path or a call as atomic, so neither the chain (one link) nor the literal inside it gets the split the statement hook arms (the E347/E348/E352 family). Recommendation: when a chain's receiver is a struct or list literal and the line is over budget, break the literal as it breaks standing alone, with the `.method()` after its closing brace. Sizing XS-S.
