# F168 — Native backend mints the hidden `Owner` parameter per function, not per instance: a static `MaybeSignal` argument through a generic function is refused natively

- status: open
- kind: bug (native backend; context parameters)
- area: crates/vilan-rust/src/lib.rs (context parameter minting), crates/vilan-core/src/context.rs

The context pass mints a hidden `Owner` parameter on a FUNCTION when one candidate of a dispatch inside it reads the owner (`MaybeSignal`'s reactive arm does). The instance a STATIC argument selects then declares the parameter too, and a caller with no owner threads none. The checker resolves the site per call (B737) and accepts the program; JavaScript passes `undefined`; the native emitter refuses the call by name. With `std::ui` switched to `MaybeSignal` the lane saw the counter example, a one-line `row().gap(dp(8))` and `layout(..)` all refused natively: every tree, static ones included, would have to be built under `comp` or `mount_root`. Repro and pin: `native_differential`'s `#[ignore]`d `f168_a_static_maybe_signal_through_a_generic_needs_no_owner_on_both_backends` (fails natively, passes on JS); `inference::std_surface`'s `ui_r9_a_bound_tree_needs_no_owner_at_the_top_of_main`. Fix: instances carry their own context needs (mint per monomorphic instance, by the per-entry refinement B737 already computes). After it, `std::ui` can move to `MaybeSignal`, and the owner rules on the one remaining difference: a binding with no ambient owner refused (`MaybeSignal`) or kept by its source (`Bindable`).
