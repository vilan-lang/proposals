# B586 — `vilan check <file>` on a NESTED module of a `[library]` resolves `pkg::` from the file's own directory: `vilan check src/deep/pair.vl` in a library whose `pair.vl` imports `pkg::util::unit` reports "cannot find 'util' in the imported path" (and every use after it); the same on 0.45.0, and std's own `vilan check vilan/std/src/web/dom.vl` fails the same way (`pkg::reactive`)

- status: OPEN — filed 2026-10-09 (layout-48's find, Order 48)
- kind: CLI bug (file mode) (S)
- area: LSP & tooling

`file_project` treats a file under a `[library]` manifest as a bare file (`pkg_root_of(entry)` = its parent directory), where a `[package]` file takes the package's declared `root`. The language server already roots a library file at the deepest layer root containing it, else the base root (`vilan-lsp` document.rs, the `[library]` arm). Repro: finds/b_library_file_mode_pkg_root (`vilan check src/deep/pair.vl`). Rec: in `file_project`, a `[library]` owner gives `pkg_root` = the deepest of its layer roots containing the file, else its base root — the editor's rule — still with no platform and no entries.
