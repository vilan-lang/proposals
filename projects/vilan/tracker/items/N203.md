# N203 — The gfx and webview notices byte checks depended on clearlydefined.io: CI went red on the miniz_oxide block with no dependency changed

- status: open
- kind: harness (nondeterminism; network in a byte gate)
- area: scripts/ci-local.sh (legs gfx and webview), crates/vilan-rt-gfx/about.toml, crates/vilan-rt-webview/about.toml, .github/workflows/ci.yml

cargo-about asks clearlydefined.io for licence data unless `--offline`, and that service answers differently once it harvests a new crate version; the gate compared its output byte for byte. FIX: both legs run `cargo fetch --locked` (the notices cover every platform's crates) and then `cargo about generate --offline`; the texts come from the crates' own files; both committed notices files are byte-identical to the offline output on this box. STILL OPEN: (1) confirm on CI that the offline path is green on a cold cache (the run on 923b9615 says). (2) The compiler's own notices (`cargo test -p vilan-cli --test third_party_notices`) check coverage of the lockfile, not bytes, so they are not exposed; the documented regeneration recipe in the root `about.toml`, `CLAUDE.md` and that test's message still says the online form: decide whether the root recipe should say `--offline` too (it changes what text a regeneration produces for crates clearlydefined knows better). (3) The release workflow: check whether it regenerates any notices online.

CORRECTION 2026-11-14: the first reading above was WRONG. The check went red again WITH `--offline` (CI run 43554792373, next 38b52525, the same byte 174807). REAL CAUSE, proven: `miniz_oxide` (0.8.9 and 0.9.1, both locked) ships two texts of its MIT licence, `LICENSE` and `LICENSE-MIT.md`, that differ by one blank line, and cargo-about takes whichever it meets first (directory order on the runner). Pointing a `clarify` entry at `LICENSE-MIT.md` reproduces CI's failure at that exact byte on this box. FIXED at next ceb5b6ff: `[miniz_oxide.clarify]` in `crates/vilan-rt-gfx/about.toml` names `LICENSE` with its checksum (one checksum for both versions). A scan of the gfx lockfile's 368 crates found no other crate with two differing MIT-looking licence files; the webview lockfile does not hold `miniz_oxide`. `--offline` and `cargo fetch --locked` stay (a byte gate should not ask a network service), but they were not the fix. STILL OPEN: (1) the same exposure returns with any new dependency that ships two differing texts of one licence: a small script (or a test in the gfx leg) that scans the lockfile's crate sources for that shape would name it before CI does; (2) the root recipe's wording, as above; (3) lesson for the integrator's notes: a failure that cannot be LOOKED at (the runner's output was never uploaded) was diagnosed by inference and the inference was wrong; upload the generated notices as an artifact on failure (with N201's golden images).
