# B653 — A struct literal may name the same field twice: `Pair { left = 1, left = 2 }` checks clean and the last value wins (prints 2), so a copy-paste slip that meant another field leaves that field's intended value silently dropped

- status: OPEN — filed 2026-10-19 (kolt's rich text editor; first met as a `// FIXME: No error reported when this field was ...` in kolt's old `lib/rich_editor.vl`)
- kind: diagnostics (checker; S) — a missing error
- area: Language

```vilan
struct Pair {
	left: i32,
	right: i32,
}

fun main() {
	let pair = Pair { left = 1, left = 2 };
	print(pair.left); // 2 — and `right` is reported missing only when it is
}
```

vilan 0.52.0 compiles and runs this. The kolt find was a two-field struct whose second initializer repeated the first field's name: the struct still built because the literal happened to supply every field, and the value meant for the second field went nowhere. Rec: refuse a repeated field in a struct literal, spanned on the second occurrence with the first as a secondary label ("`left` is already set here"); the same check belongs on the shorthand form (`Pair { left, left }`) and on struct-update/spread forms if any reach a field twice. No estate site should depend on it (count first).
