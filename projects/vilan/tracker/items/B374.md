# B374 — `HttpTransport` CRASHES THE PROCESS on an unreachable host — an unhandled `fetch failed` rejection — against `Transport`'s own contract, which is `Err(reason)` for a transport failure

- status: OPEN — filed 2026-09-21 (Order 39 sweep; papers-39's HIGH find)
- kind: bug (std, HIGH)
- area: std::rpc / transport

Repro: `AuthClient<HttpTransport>` against a port nothing listens on → node exits with an unhandled rejection; the caller's `match` never runs. Fix: the `fetch` call wrapped, the rejection mapped to `Err(Transport(reason))` (or whatever the `Transport` error variant is named); a `rpc_http` pin against a closed port, asserting the typed `Err` and the process alive. Sized S.
