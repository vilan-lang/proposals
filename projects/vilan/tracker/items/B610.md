# B610 — A directed array literal at an OPEN element left the element unbound natively — `first(["a", "b", "c"])` against `fun first<T>(values: [T; 3])`, and `Trio { slots = [7, 8, 9] }` for `struct Trio<T> { slots: [T; 3] }`, were refused natively "does not emit a value of an unbound generic type parameter" while JS printed the answer

- status: FIXED — filed and closed 2026-10-10 by lang-50 (Order 50), commit aa573089 on branch lang-50
- kind: bug (checker/native; S)
- area: Type inference

Pre-existing on v0.47.0. infer_type_inner's directed array-literal arm answered with the constraint's element id, so the call reconciled the callee's `T` with itself. Now the literal types its element by its items wherever the expected element is open (a grounded one keeps the constraint's id, so nothing that compiled natively moves).
