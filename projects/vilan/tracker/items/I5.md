# I5 — ONE spelling for an index: `usize`. std spells positions, lengths and counts as `i32` almost everywhere (~100 signature sites — `List::len(): i32`, `insert(index: i32, ..)`, `remove(index: i32)`, `get(index: i32)`, `str::len`/`repeat(count: i32)`, `Bytes::slice(from: i32, to: i32)`, `Iterator::take(count: i32)`, `index_of(): Option<i32>`, `Map::len`, `Set::len`) and as `i53` in a dozen more, so a position can be NEGATIVE by type, two halves of std disagree, and ids (`u53`) and indexes meet with casts. The owner's ruling-in-waiting (2026-09-21): switch std to `usize` for every index — one spelling everywhere — with `usize` = `u53` on JS targets unless revisited

- status: OPEN — filed 2026-09-21 (the owner's ask, mid-Order 39); PAPER first — this is the widest breaking surface since A101
- kind: design (breaking)
- area: Collections

Two decisions, then a migration.

**1. What `usize` IS.** (a) a DISTINCT numeric type whose representation is per target — `u53` on the JS backends (the owner's default), the platform word (`u64`/`usize`) on the Rust backend, where `Vec::len` already is one (the native emitter casts every `len()` today: `((xs).len() as i32)`) — with the documented rule R6 of Order 37 gave `i53`/`u53`: the RANGE guarantee is the JS one, so a program round-tripping both backends behaves the same; or (b) a plain ALIAS of `u53` (cheaper; loses the ability to revisit without a second break; type aliases — does the language have them?). Rec (a). It joins the numeric family in number.vl (`Add`/`Sub`/`Ord`/`Display`/`Default`/`Hashable`/`Wire`/`Json`, the `as_*` conversions, literal typing: does an unsuffixed `0` infer to `usize` in an index position? it must, or every `list[0]` needs a suffix).

**2. What is an INDEX.** Positions, lengths, counts, capacities, arities, `take`/`skip`/`repeat` counts, `slice` bounds, `enumerate`'s counter, `index_of`'s answer, `Region`/row positions in std::ui, `KeyedCell.positions`, A112's `Splice(at, ..)` (NOT yet built — it should be BORN `usize`; tell collections-39's S2), the indexing operator `list[i]`. NOT an index: ids (`u53` stays), byte VALUES (`Bytes::get` answers an `i32`-typed byte — its INDEX changes, its answer does not), durations, numeric payloads, scale steps, wire integers.

**The hard parts, which are why this is a paper.** (i) SUBTRACTION: `i - 1` at `i == 0` and the downward loop `for i > 0 { .. i -= 1 }` (kolt lib/storage.vl had one until A73) — unsigned arithmetic needs a ruling: panic on underflow in debug, wrap, or saturate; and `checked_sub`/`saturating_sub` in std. JS's `u53` has no native wrap, so whatever is chosen is EMITTED. (ii) SENTINELS: any `-1` 'not found' (census them — `index_of` already answers `Option`, good) dies. (iii) INFERENCE at the boundary: `let n: i32 = list.len()` and `list[i]` with `i: i32` become type errors in every program ever written — the migration needs a CODEMOD (A101's precedent: the `css` call codemod touched 227 blocks with no golden moved) and a diagnostic that names the conversion (`as_usize()` / `as_i32()`), plus a quick fix. (iv) the WIRE: a length or index that crosses rpc (`KeyedCell`'s positions in a `Patch` frame, `Delta`) has a wire width — `usize` needs a Wire lane or rides `u53`'s; the frames must stay byte-identical or the contract hash moves (say which). (v) the NATIVE backend gets SIMPLER (no casts at `len`), the JS backend's emitted code should not change at all for the common paths (a number is a number) — the corpus goldens are the measure. (vi) the DOCS: every tour/guide fence indexing a list.

**Census owed by the paper** (exact, by parse not grep): every std signature position of index kind, by module; every estate program that names an index type explicitly (std, vilan/test, examples, docs fences, benchmarks, templates, the `.vl` consts in Rust tests, vilan-website, vilan-playground, kolt — a first grep finds kolt naming none explicitly, which suggests inference carries most user code across untouched); every `-1` sentinel; every downward index loop.

**Slices (proposed).** S1 the type + number.vl's family + literal inference + the underflow rule, no std signature moved (S–M). S2 the std signatures + the codemod + the estate, ONE breaking commit merged last in its order (L). S3 the native backend drops its casts; S4 A112's ops and std::ui's positions if not already born so. The v0.41.0 cut is HELD and already carries A101 and A108 — this belongs in the same breaking train, BEFORE the cut, or it waits a whole release.

**Rulings the paper asks.** distinct type or alias; the underflow rule; whether `isize` exists at all (rec: no — a signed offset is `i53`); whether `len()` on the WIRE-visible types changes width; whether an unsuffixed literal in index position infers `usize`.

- 2026-09-21 (the owner's rulings, the same day — sent under the heading "A101", read as this item since they answer its questions one for one):
  1. **DISTINCT TYPE** — `usize` is its own numeric type (`u53` on JS targets unless revisited; the platform word natively), not an alias.
  2. **SUBTRACTION MAY BE UNDEFINED BEHAVIOUR** — no check is emitted for an underflowing `usize` subtraction. Recorded with the integrator's reading, for the paper to state precisely: "undefined" means the RESULT is unspecified (on JS the number simply goes negative and leaves the type's range; natively Rust's own rule applies — a panic in a debug build, a wrap in release), NEVER memory-unsafe (`vilan-rt` forbids `unsafe`; an out-of-range index still meets the bounds check every backend already has). Consequences to write down: the native differential cannot cover a program that underflows (outputs may differ by backend, legitimately); `checked_sub`/`saturating_sub` are still worth having for code that wants a defined answer; a downward loop is written `for i > 0 { i -= 1; .. }`-style and never reaches the edge.
  3. **LITERAL INFERENCE IS A GENERAL LAW, NOT AN EXCEPTION FOR `usize`** — an unsuffixed literal takes its type from context everywhere. Probed the same day: it already does in 14 of 16 positions; the two gaps (a literal on the LEFT of a binary operator; the elements of an annotated list literal) and the census of the rest are filed as **B370**, which this item's S1 depends on.
  4. Everything else in the item as proposed: what counts as an index (and what does not — ids, byte values, wire integers), the codemod + naming diagnostic + quick fix for the migration, A112's `Splice(at, ..)` born `usize`, no `isize` (a signed offset is `i53`), and the timing — in the breaking train BEFORE the held v0.41.0 cut.
  Still the paper's to settle: whether a length or position that crosses rpc keeps its wire width (frames byte-identical) or moves the contract hash. READY for a paper lane in Order 40; S1 (the type + number.vl's family) can start once B370's two gaps are closed.

- 2026-09-22 (the owner's rulings before Order 40): RULED (the last open question) — a length or position that crosses rpc KEEPS its wire width: frames byte-identical, the contract hash does not move; the paper proves it (a `Patch`/`Delta` frame before and after, byte-compared).
