# B463 — AFFINE HOLE: a trait DEFAULT method whose receiver is the loan `self` can MOVE `self` into an aggregate when `Self` is instantiated as a `[resource]` — `fun wrap(self): Holder<Self> { Holder<Self> { inner = self } }` in a trait, `impl R with Wrap {}`, then `r.wrap(); r.wrap();` compiles and runs (`1 1`): the resource is COPIED; the same body in a concrete `impl R` is refused ("cannot move the resource `self` out of this function: it is declared `self`, a loan")

- status: OPEN — filed 2026-09-29 (found prototyping the pipe model for A142; probed on 0.41.1)
- kind: bug (soundness — affine discipline, spec §6.8 R1)
- area: Type system & the type solver

Repro (22 lines): `[resource] struct R { n: i32 }`, `struct Holder<X> { inner: X }`, `trait Wrap { fun wrap(self): Holder<Self> { Holder<Self> { inner = self } } }`, `impl R with Wrap {}`, `main` wraps the same `r` twice and prints both. Expected: the concrete-impl refusal, reported at the default body under the resource instantiation (resource-ness is per instantiation, §6.8 "Per-instantiation for generics"), or at the impl that admits the default.

Why it matters now: A142's pipe variant makes every combinator a trait default over a `[resource]` node; a default written with `self` instead of `own self` would silently duplicate a pipe — the exact double instantiation the affine rule exists to refuse.
