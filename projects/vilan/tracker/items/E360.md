# E360 — A path through an imported *function* (`editor::reader(...)`, where `editor` is a function) reports only "could not be resolved" errors, never the cause

- status: OPEN - filed 2026-11-02 (kolt, as E357; renumbered E360 at the sync - E357 on main was taken the same day by lane parser-56's find, the lone-file fmt reflow)
- kind: diagnostic
- area: Checker / diagnostics

When a module and a function share a name, importing the function and then writing a path as if the name were the module (`editor::reader(...)`) gets no error that says so. All that's printed is the "could not be resolved" cascade (B680's family), with no root error above it. In kolt, inside a large view expression, the only error was about a different part of the call:

```
Error: `event` is never given a type: this closure is never called and its parameter is unannotated; annotate it (e.g. `|event: List<i32>|`)
```

It pointed at a closure argument several lines below. Kolt imports the function `message_editor` from module `message_editor`. Adding `message_editor::message_reader(...)` there cost a round of guessing, until importing `message_reader` directly made it build.

Repro (0.53.1 and `next` 2f89bee9): kolt session scratchpad `pathfn/`, a package of two files.

`src/editor.vl`:
```
export *;

fun editor(text: str): str {
	i"editing {text}"
}

fun reader(text: str): str {
	i"reading {text}"
}
```

`src/main.vl`:
```
import pkg::editor::editor;

fun row(body: str, on_menu: |str| void): str {
	on_menu(body);
	body
}

fun main() {
	let shown = row(editor::reader("hello"), |event| {
		print(event);
	});
	print(shown);
}
```

`vilan build` prints four errors, and none of them is about `editor::reader`:
```
Error: type of variable 'shown' could not be resolved
Error: type of function call arguments could not be resolved   (the whole `row(...)` call)
Error: type of function call arguments could not be resolved   (`editor::reader("hello")`)
Error: type of function call arguments could not be resolved   (`print(shown)`)
```

Recommendation: resolving `a::b` where `a` names a function (or any value) in scope, and not a module or type, should be an error at that path. Something like "`editor` here is the function imported from `pkg::editor`, not the module; import `reader` too (`import pkg::editor::{ editor, reader }`), or import the module (`import pkg::editor::{ self, editor }`)". With that root error, B680's demotion would hide the cascade.
