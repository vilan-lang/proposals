# B150 — `drop(x)` is not exception-safe: the explicit drop removes the scope `finally`

- status: OPEN — reproduced on 0.38.0 (lifetimes session probe E2, 2026-08-28); lifetimes.md §6 fixes it structurally (a last-use drop always rides `finally`), S3
- kind: bug
- area: Type system & the type solver
- source: the lifetimes session's error-path probes, 2026-08-28

`drop(x)` moves the binding into the drop sink, so `plan_resource_drops`
removes it from `dropped_bindings` and the scope-end `finally`
disappears — the emission shows a bare `$a(r);`. A panic between the
acquisition and the `drop(x)` therefore leaks the resource permanently,
where an implicit scope-end drop would have released it. The narrow fix
is to keep the `finally` and make the explicit drop idempotent against
it; the structural fix is lifetimes.md §6's last-use lowering, under
which every drop rides `finally`. Red-first pin: probe E2's shape
(acquire, panic before the explicit drop, catch — assert the drop ran).
