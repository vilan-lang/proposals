# L22 — NEW — `publish-brew` mints its tap token through `app-id`, an input `actions/create-github-app-token` deprecated at v3.1.0 in favour of `client-id`: the v2 → v3 bump must switch inputs in the same change, and the App's client ID is a different value from the one `TAP_APP_ID` holds

- status: OPEN — the review of vilan-lang/vilan#3 (2026-09-18; the PR closed unmerged)
- kind: process
- area: Release engineering & beta
- size: S
- blocked on: the owner, for one secret (the App's client ID)

`release.yml`'s "Mint the tap token" step passes
`app-id: ${{ secrets.TAP_APP_ID }}` to `actions/create-github-app-token`,
pinned at v2.2.2. Upstream v3.1.0 (2026-04-11) added `client-id` and
DEPRECATED `app-id`; v3.2.0 is the current release. Under v3 the step still
works and warns on every release. A later major that removes the input fails
`publish-brew` at release time — after the GitHub Release and npm are already
out, the half-finished release this job's ordering exists to avoid.

The work, when the v3 bump arrives as its own PR against `next` (vilan
9e4ab461 narrows Dependabot's group to minor/patch and targets `next`):

1. The owner stores the App's CLIENT ID (the `Iv…` string on the App's
   settings page — not the numeric app id `TAP_APP_ID` holds) as a new secret,
   `TAP_APP_CLIENT_ID`.
2. The step passes `client-id:` from it, and the gate step above it ("Is there
   an app to push with?") tests the new secret's presence, its notice text
   renamed to match.
3. `TAP_APP_ID` is deleted once a release has gone out on the new input.

v3.0.0's other breaking change — custom proxy handling removed, so
`NODE_USE_ENV_PROXY=1` is required beside `HTTP(S)_PROXY` — does not apply:
the job runs on a GitHub-hosted runner with no proxy.

Verification is the release itself; `release.yml` runs on tags only. L23's
dry-run lane can carry the mint step as well, since minting a token scoped to
`homebrew-vilan` is harmless without the push.
