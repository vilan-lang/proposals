# M17 — cross-subject body sharing: identical bodies from DIFFERENT functions still emit one copy each

- status: OPEN — perf lane's residual (Order 23)
- kind: perf
- area: Performance & footprint
- source: lane perf, 2026-08-31

M16 deliberately narrowed its sharing key to one subject (a generic
function's own instantiations, or one trait default's). Two DIFFERENT
functions that emit identical bodies still get one copy each — the
corpus carries several (`slot`/`peek`, `text`/`integer`/`big_integer`,
`hold_in_list`/`hold_in_struct`, the `hash`/`hash2`/`hash3` derive
families). Merging across subjects is a further win of roughly M16's
order and a SEPARATE decision: the shared name then belongs to no
source function, which touches stack traces, sourcemap attribution,
and the instance-log instrument. Decide, then build on M16's
emitted-body comparison machinery.
