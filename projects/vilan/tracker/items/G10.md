# G10 — `[[build.hook]] inputs` are declared to the stamp but not to the watcher

- status: OPEN — the lucide evidence run's biggest defect find (Order 19); the manifest already carries the answer
- kind: bug
- area: Macros & const
- source: the lucide-evidence lane, measured under `vilan build . --watch`, 2026-08-28

Three edits to files the manifest names in `inputs` produced ZERO watch
rounds — the banner says "watching . for .vl changes", so the freshness
predicate is right and the wake-up set is wrong. One later .vl edit woke
the loop and the hook then correctly re-ran. Fix: the watcher's set
extends to every declared hook input (recorded-inputs doctrine — the
same shape markdown.md §11 ruled for asset::read). `build.vl` would not
have fixed this, which is half of why Q1 closed against it.
