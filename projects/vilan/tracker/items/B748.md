# B748 — MISCOMPILE (JavaScript): a copy of a plain unit-only enum changes when the original is written through `&mut` - `let copy = a; set(&mut a)` moves `copy` too

- status: open
- kind: miscompile (JS backend; rule 1, a view write in place)
- area: crates/vilan-core/src/analyzer.rs (`is_cloneable_aggregate`, the B691 comment), the transformer's `__replace` for a view write

Repro: `scripts/integration/sweeps/order58/repros/b748-plain-enum-copy-aliases-through-mut.vl`. A plain (unbacked) unit-only enum lowers to a mutable `[index]` array. `let copy = a;` shares it, on the reasoning (the B691 comment in `is_cloneable_aggregate`) that a payload-less enum is only ever REPLACED whole. A `&mut` write is not a replacement of the binding: it goes through `__replace`, which assigns into the shared array, so every copy moves. Two doors: copy a plain enum on assignment like any other aggregate, or make a unit-only enum a scalar to a view, a `(base, key)` place, by the rule B746 set (`enum_lowers_to_js_primitive` would then need the lowering itself to be a primitive, which is the larger and cleaner change). Pin the repro on both backends, and the same through a field and a generic `&mut self`.
