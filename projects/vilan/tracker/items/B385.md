# B385 — CRASH — any GENERIC recursive type in a world that holds a resource type overflows the analyzer's stack: `import std::reactive::SignalCell; enum M<type T> { Base(T), Map(List<M<T>>) }` (nine lines) aborts `vilan check` AND the language server (`thread has overflowed its stack` → SIGABRT, the server restarts and dies again on the same buffer). The recursion is `container_resource_in` ↔ `container_resource_in_anonymous` (R10's resource-in-container walk, analyzer.rs ~10820/~10957) with `substitute_type` above each frame — its `visiting: HashSet<TypeId>` guard never repeats because each member substitution mints a fresh `TypeId` for `M<T>`. The non-generic `enum M { Map(List<M>) }` is fine; a bare file with no resource type in the world is fine (the container list is empty)

- status: OPEN — filed 2026-09-22 (the owner's report: the LSP aborts with `has overflowed its stack` on a recursive `SignalMapper` enum); reproduced and minimized by the integrator on 4f990aa2c and 051e2254; HIGH — Order 40's solver lane, FIRST
- kind: bug (CRASH — stack overflow in the analyzer; the language server dies with it)
- area: Type system & the type solver

**Repro** (`sweeps/order39/probes/b385_generic_recursive_type_overflow.vl`):

```vl
import std::reactive::SignalCell;
enum M<type T> {
	Base(T),
	Map(List<M<T>>),
}
fun main() {}
```

`vilan check` → `thread '<unknown>' has overflowed its stack / fatal runtime error: stack overflow, aborting`. Sixteen variants bisected: the wrapper does not matter (`List`, `Option`, `Shared`), struct or enum does not matter, the parameter count and permutation do not matter (`M<U, T, O>` and `M<T, U, O>` both overflow), `any` does not matter; what matters is (a) the type is GENERIC and recursive and (b) a resource type is loaded (`std::reactive` or `std::ui` imported — kolt's every file). `enum M { Base(i32), Map(List<M>) }` with the import passes; the generic one with no import passes.

**Where** (gdb on the debug binary): the stack is `container_resource_in` → `container_resource_in_anonymous` → `container_resource_in` … with `substitute_type`/`substitute_argument_types`/`TypeCycleGuard::enter` between each pair. `container_resource_in` guards re-entry with `visiting.insert(type_id)` and descends into each member's type SUBSTITUTED in the head's own context (`substitute_type(&member_type, &context)`), skipping a member whose substituted id equals its declared one. For `Map(List<M<T>>)` the substitution `{T → T}` hands back a `List<M<T>>` whose `M<T>` is a NEW `TypeId` every time (interning does not fold a re-substituted generic application onto the declaration's own id), so `visiting` never sees a repeat and the walk descends forever — the substituted type is not `==` the member's declared id either, so the skip does not fire.

**Fix direction** (the lane verifies): key the guard on the HEAD id when the arguments are the head's own parameters (a recursive application at the declaration site is the declaration), or on `(head_id, arguments)` structurally rather than on `TypeId`; and give the walk a depth bound as a backstop that reports an `internal:` instead of aborting (an abort takes the language server with it). Check the sibling walks the doc names — `compute_resource` (B103 says this one mirrors it) — for the same guard shape.

**Pins**: the nine-line repro checks clean; the owner's `SignalMapper` shape; the same with a struct and with `Option`; a MUTUALLY recursive generic pair (`A<T>` holding `List<B<T>>`, `B<T>` holding `Option<A<T>>`); and a resource actually inside a recursive generic (`enum M<T> { Base(T), Map(List<M<Database>>) }` or through a member) is still REPORTED by R10 — the guard must not hide the diagnostic the walk exists for. Plus an LSP pin: the document analyzes without the server process dying (vilan-lsp's harness over the repro).
