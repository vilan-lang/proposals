# B235 — a `= Self`-defaulted trait parameter is read as a BOUND when the member is reached through a sub-trait's parameterized clause: `trait Mixer<A = Self, B = Self>` under `trait Mixed with Mixer<i32, str>` refuses `i32`

- status: OPEN — lane cascade-27's find (2026-09-04, Order 27)
- kind: bug
- area: Type system & the type solver

`'i32' does not implement trait 'Mixer', required by a generic bound of this call` — and the same for `str`. `Add<i32>` escapes only because `i32` genuinely implements `Add`; a direct call on an impl does not hit it. A default is not a bound: the clause argument substitutes the parameter and the parameter's own bound (if any) applies to the argument — the trait itself is never required of the argument. Localize where the defaulted parameter's declaring trait is pushed as a bound on the substituted argument. Pins: the Mixer shape with two defaulted parameters, the `Add<i32>` control, a genuinely bounded parameter still refusing.
