# B665 — a `css { … } + style()` sum outside `const` is reported at a caller's closure, not at the sum, with no word about the sum

- status: OPEN — filed 2026-10-21 (kolt's channel.vl: a message row's `.styled(css { … } + style::style().hover(…))`)
- kind: diagnostic (checker / const-eval; S)
- area: language / css, const

A one-module browser package (`vilan check .`):

```vilan
fun row(content: View): View {
	<div .styled(css { padding(rem(4 / 16)); } + style::style().hover(style::style().opacity(0.5)))>
		{content}
	</div>
}

fun main() {
	let names = Signal::new(["a", "b"]);
	let _root = ui::mount_root("app", || <div>
		{ui::each_values(names, |name| {
			row(<span>{name}</span>)
		})}
	</div>);
}
```

→ `Error: this closure (it reaches `asset::emit`) is compile-time-only; call it directly inside a `const` expression` at the `|name| { … }` closure in `main` (lines 10-12).

`row` itself is not mentioned. Neither is the `+`, which is what leaves the compile-time block. A css block is `const` by construction (A68), so it is easy to miss that adding a runtime `style()` to it makes the whole sum runtime. In kolt, the closures named were two callers 150 lines from the cause, inside `each_by` and `when_remote_live`. Writing `const css { … } + style::style()…` fixes it.

Recommendation: report at the expression that first reaches `asset::emit` outside a `const` (here the `css { … } + style()` sum in `row`), with a hint to write `const` in front of it. Any caller that transitively reaches it can be a secondary note.
