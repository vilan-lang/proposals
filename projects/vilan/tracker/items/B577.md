# B577 — JS backend: an `Option<&str>` whose payload views a LIST ELEMENT, handed to `unwrap_or`, answers the view's (base, key) PAIR instead of the element — `shelf.at(1).unwrap_or("none")` prints `[ [ 'first', 'second' ], 1 ]` on JS and `second` natively

- status: OPEN — filed 2026-10-08 (native-48's find, Order 48)
- kind: JS backend miscompile (S–M)
- area: JavaScript backend

A shared view of an element (`Some(&self.items[index])`) is a (base, key) pointer pair on JS. A `match` subject reads through it, but a generic consumer monomorphised at the pointee (`unwrap_or(own self, lazy fallback: T): T`) hands the pair back as the `T`. Native-48's F99 half reads the payload out at that position (`.cloned()`); the JS backend needs the same read where an `Option` of a view meets code written against its pointee. Repro: finds/js_option_view_of_element_unwrap_or.vl. Sizing S–M; JS emitter.
