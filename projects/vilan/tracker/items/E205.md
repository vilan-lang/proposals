# E205 — `vilan fmt` never REFLOWS a comment: a `//` or `///` line longer than the line width stays as written, and a paragraph edited in the middle keeps its ragged lines — the owner's ask (2026-09-21): wrap comments across multiple lines automatically, as the formatter already does for code

- status: OPEN — filed 2026-09-21 (the owner's ask, mid-Order 38)
- kind: editor
- area: LSP & tooling

Scope: consecutive `//` lines (and `///`, `//!` if it exists) at one indentation are ONE paragraph; the formatter re-fills it to the line width at that indentation (the width `vilan fmt` already uses for code; tabs counted at the configured tab width), preserving the marker and a single space after it. Idempotent, and a no-op on a paragraph already filled.

What must NOT be reflowed — the whole difficulty: fenced code inside a doc comment (``` … ```), indented code, markdown LISTS (`- `, `* `, `1. ` — re-fill each item with a hanging indent, never join two items), tables (`|`), headings, block quotes, a line ending in two spaces or a `\`, URLs and `inline code` spans longer than the width (never broken — the line overflows), ASCII drawings and aligned columns (a line with a run of 2+ interior spaces is left alone — N98's bimodal-gap measurement is the precedent), directive comments the toolchain reads (`// witness:`, `// expect:`, `// FIXME:`/`// TODO:` prefixes keep their first line's marker and hang the rest), commented-OUT CODE (heuristic: the line parses as a statement, or ends in `;`/`{`/`}` — leave it), a trailing comment after code on the same line (move nothing; at most leave it), license headers, and blank `//` lines (paragraph breaks).

Doors: (1) always on; (2) opt-in — `[fmt] wrap_comments = true` in vilan.toml, default off for one release because the first run rewrites every long comment in an estate (std's doc comments are hand-filled at ~90–100 columns; measure how many lines a run over std/kolt would touch and put the number here); (3) a code action 'Reflow this comment' only. Rec: (2) then (1), with (3) free from the same function. The token-stream safety net (`reprint` compares tokens) does not cover comments — a reflow needs its OWN net: the comment's words, in order, are identical before and after (whitespace-only difference), else decline by N90's exit 2 naming the comment.

Pins owed: a long `//` paragraph fills; a doc comment with a fence, a list, a table and a URL each survive byte-identical; idempotency over std; the words-in-order net planted red; kolt's hyphen convention untouched (no character substitution, ever).
