# A95 — `Style`'s CONDITION MODEL is the source of the styling pain: a condition is a COMBINATOR WRAPPING an inner style (`hover(inner)`, `attribute(name, value, inner)`), one condition per axis slot, nested outside-in in a fixed order — so two pseudo-classes on one rule are unspellable (`hover:not(:active)` becomes a raw token that miscompiles when wrapped, B311), `not` had to be a MARKER read by the enclosing combinator (A89), the author memorises `md(within(attribute(hover(..))))` or meets a refusal, and every wrap mints an intermediate style whose rules land dead on the sheet (B308). REDESIGN: a condition is a VALUE — `hover()`, `active().not()`, `pseudo("focus-visible")`, `attribute("disabled")` (presence), `attribute("data-selected").eq("true")`, `within(..)`, `children()`, `md()` — a rule is `style()…on(conditions..)`, rules compose by `.add(rule)` (an inner rule inherits the outer's conditions), and the compiler CANONICALISES the set into the slot order (media, relation, attributes, pseudos): duplicates merge, only a contradiction (`hover()` with `hover().not()`) refuses; `.hover(inner)` and friends stay as one-condition sugar; the css block's name-blind head takes the arguments it already parses as expressions (`.on(hover(), active().not()) { … }`; `.hover { }` = `.on(hover()) { }`), no bare selectors. B308 dies structurally (a rule set is a value, emitted once at application), B311 and the two-pseudo gap die (no condition is ever a string), A89's marker and A93's fence go, `Style::when`'s runtime merge becomes const `.add` composition. BREAKING for every `hover(inner)` in std, kolt, the website and the docs — a mechanical migration. L; a PAPER before any lane: canonicalisation and the specificity band (ui-styling §0bis) are where a hasty version goes wrong

**The model.** A `Style` = base declarations + a set of RULES; a rule = a CONDITION SET + declarations. `style().color(c).on(hover(), active().not(), attribute("disabled").not())` is one rule; `outer.add(inner)` nests: `inner`'s rules carry `outer`'s conditions too, `inner`'s base declarations become a rule under `outer`'s conditions, and an `.add` with no conditions on either side is today's merge (`+`). Condition values are typed (`Pseudo`, `Attribute`, `Relation`, `Media`), `.not()` is a method on each, `attribute(name)` is presence and `.eq(value)` the valued form (A89's `Option<str>` argument folds into it); `pseudo(name)` keeps its leading-`!` fence and REFUSES a `:` in the name (the token is one pseudo-class; two are two values — B311's whole class becomes unspellable).

**Canonicalisation.** The set sorts into the shipped slot order (media, relation, attributes, pseudos — the sheet's band is still the OUTERMOST kind, so ui-styling §0bis's specificity story survives unchanged); equal conditions merge; a value and its negation refuse at const time (curated, one row). The nesting-order refusals (`.dark { .md { } }` out of order, one-pseudo-per-slot) go away because there is no nesting order to get wrong.

**What stays.** `hover(inner)`/`md(inner)`/`attribute(name, value, inner)` as sugar for `.add(inner.on(..))` so the estate migrates mechanically (or is rewritten by the E167 converter); `when(condition, delta)` (A36) for RUNTIME conditions; `Declarations`/`rule`/`declare` ride the same values; `raw`; the class-list emission and the split gate.

**What it closes.** B308 (no intermediate styles exist to emit dead rules — a rule set is a value until `class_list`/application); B311 (`pseudo_not` is never needed); A89's marker mechanism (replaced, its pins rewritten); A93 (`children()`/`divide()` are relation values, `child_relation`'s raw hatch is deleted). Order 30's compact-styling measurement (css-block §15.3) is re-run after: the const class list should not move.

**The block spelling.** `.on(hover(), active().not()) { color: {c}; }` — the head is already an expression list the lowering passes through name-blind (`css.rs`), so no grammar change; `.hover { }` stays as `.on(hover()) { }`. The owner's `.add {}` with no head is a plain nested merge = flatten into the parent, which the formatter can offer as a fix. No bare selectors (css-block.md §10's refusal stands).

**Owner's sketch, and the two places I diverge.** (1) `.pseudo(pseudo("hover"))` doubles the word — `.on(hover())` names the axis once; (2) `.set(property, Length)` — a typed `raw`, which is css-block §6's S1 groundwork (typed values in `raw`) and is taken as-is.

**Cost.** style.vl's condition machinery (~1400 lines around the combinators) rewritten on condition sets; the formatter's `STYLE_CONDITION_METHODS`/`ConditionAxis` sort becomes a canonicaliser; completion tables (css-block §7.1) and `style_table_sync` follow; guide + reference pages rewritten; kolt/website/docs migrate (mechanical). Paper questions: the canonical order of pseudos within the slot (written order vs. a fixed table), whether `.on` on a style that already has rules applies to the rules too (yes: conditions are intersected), and whether `hover(inner)` sugar is kept or deleted at the migration.
