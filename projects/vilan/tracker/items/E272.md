# E272 — a fragment where ONE view is wanted — `fun pair(): View { <><p>"a"</p><p>"b"</p></> }` — is refused with the plain mismatch "Expected View, but got List<View> instead"; the book promises "a type error that says so", and nothing in it says fragment or how to fix it

- status: OPEN — filed 2026-10-05 (docs-47's find, Order 47)
- kind: diagnostic (XS–S)
- area: Diagnostics & error messages

A fragment lowers to a list literal, so the mismatch is accurate but reads as if the author wrote a list. When the found expression is a fragment literal and the expected type is `View`, a steer would close the gap: "a fragment `<>…</>` is a `List<View>`, not one view — wrap its children in an element (`<div>…</div>`), or return `List<View>`".
