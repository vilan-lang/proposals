# M23 — the M9 overlay rule refuses the base cache exactly where a session lives: an entry importing an OPEN buffer never hits

- status: OPEN — perf-25 lane's find (2026-09-01); the largest single item on E121's diagnostics path after M21
- kind: performance
- area: Language server & tooling
- source: lane perf-25, measured on the final binary, 3-file scripted session (views.vl → theme.vl → client.vl)

M21 made `pkg::`-importing entries cache-eligible: views.vl analyses
2–5 and theme.vl 7–10 read `base 0.0ms`. But client.vl (analyses
11–19) read `base 1357–2713 ms`, NEVER a hit: client.vl imports
`pkg::views`, views.vl is an open buffer, so its load is OVERLAY-
served and `owned_modules::analysis_owns_overlay_loads()` refuses the
store — M9's rule (§7.9.4a), which §7.9.2 proved necessary in its
naive form (a stored world borrowing analysis-owned text was
unsound). Every keystroke in a file that imports any open sibling
pays the whole base again. Fix shape: intern overlay-served text for
stored worlds (the world owns a copy keyed by content), or a world
that can borrow analysis-owned text SAFELY — the paper (editor-
latency.md) must sequence it against the keystroke path and M19's
remaining tranche. Pin: the scripted session's third file hits from
its second analysis.
