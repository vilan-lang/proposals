# B433 — ASSIGNMENT THROUGH A `&mut T` PLACE does not check the value against `T`: `let cell: Shared<Option<i32>> = Shared::new(None); cell.write() = 5;` passes `vilan check` (0 diagnostics) and emits `cell.v = 5` — a bare `i32` in an `Option<i32>` slot, which every later read misreads (`is_some()` false, `match` takes `None`); the same with a struct into `Shared<Option<Plain>>`. The PLAIN places are refused correctly (`let x: Option<i32> = 7` and `mut x: Option<i32> = None; x = 5` both say `Expected Option<i32>, but got i32`), so the gap is the assignment whose target is a call returning `&mut T` (`Shared::write(self): &mut T borrows self`). Kolt's own `channel_globals.write() = channels` (a `SignalCell` into `Shared<Option<SignalCell<..>>>`) compiled and silently never cached — the cache read `None` on every call
