# M173 — A keyed replica's per-key `gone` (and every write at a keyed collection) diffs EVERY watched key: `keyed_hashes(node)` snapshots the collection's key list and `store_diff` walks it, so releasing K keys one turn each costs K^2 key copies (1.05M `__map_keys` copies at 1024 keys; 65k at 256)

- status: OPEN - filed 2026-10-26 (rpc-55's find under M172, Order 55)
- kind: performance (std reactive store core; M)
- area: Standard library

Measured under M172's program after the mirror's own lists were keyed: the table's unmount (K holds released, each in its own turn since nothing batches a dispose) grew 15x -> 4.9x for 4x the keys, and the residual is `Array.map <- __map_keys <- keyed_hashes` - `store.vl`'s keyed `store_diff` (`:182` `let watched = keyed_hashes(node); for hash in watched { .. store_diff .. }`, `:239` the set form) and `store_core.vl`'s `node_empty` (`:364` `keyed_hashes(Some(node)).is_empty()` - a full key snapshot for an emptiness check). Each key's `gone` is a write at the collection (`MirrorAt`'s boundary `gone` removes the key from the replica), and a write at a keyed collection diffs every watched key. Not the 550 ms (that was the mirror's lists, M172) but the next quadratic under a large keyed replica. Doors: (a) a write that names its key (a `Key` touch) diffs that key alone - the store already records `StoreTouch::Key(hash)`; (b) `node_empty` asks the table's `len()`; (c) `keyed_hashes` iterates without the snapshot. Rec: (a)+(b), a std lane in Order 56; a counting pin like M172's over the `done` phase (bound 6x for 4x the keys).
