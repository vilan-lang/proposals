# B740 — MISCOMPILE (JavaScript): a context parameter's flavour (strict `Owner` or optional) is fixed per function, so `owner_scope.get_safe()` in an instance called with no owner answers `Some(undefined)`

- status: open
- kind: bug (context pass; miscompile on JS, refusal natively)
- area: crates/vilan-core/src/context.rs (parameter flavour), crates/vilan-core/src/transformer.rs (the safe read's lowering), crates/vilan-rust/src/lib.rs

`fun noted<V: Note>(own value: V) { value.note() }` with `impl str with Note` reading `owner_scope.get_safe()` and `impl SignalCell<str> with Note` reading `owner_scope.get()` strictly. One strict candidate makes `noted`'s hidden owner parameter STRICT for every instance. Called from `main` with no owner and a `str`, JavaScript passes `undefined` to the strict-flavour parameter and the safe read lowers to `Some(undefined)`: the program prints `top: owned`. Natively the same shape is refused (`call to ... threads fewer context arguments`) although the checker accepts it: `examples/ui-list` and `ui-virtual-list` are refused that way with `std::ui` on `MaybeSignal`. This is the per-function decision F168 removed, in a second dimension: the flavour must follow the instance (or the per-entry refinement B737 computes), not the function. Fix in the context pass; pin on both backends (the repro, a forwarding generic, a trait default, a bounded receiver, a closure); the JS corpus goldens are a byte gate, so expect and verify changes only where a safe read sat behind a strict parameter. After it, rerun the `MaybeSignal` trial (`repros/f168-trial-ui-on-maybesignal.patch`) and report.
