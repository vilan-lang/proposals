# A110 — NESTED FORMS ON ONE SOURCE settle child-before-parent: `drain` runs a wave in SUBSCRIPTION order, so an inner `swap`/`when`/`each` fires with a value its enclosing form is about to exclude (a wasted build, a panic if that arm is `unreachable`); and OUTSIDE a turn the inline notify walks a SNAPSHOT, so an observer whose owner was disposed earlier in the same notify STILL FIRES — a `swap` then builds a subtree under a fresh owner nothing will ever dispose, into a closed region

- status: OPEN — filed 2026-09-19 (the nested-`swap` conversation; kolt views.vl:72)
- kind: bug + design (the second face is a bug on its own; the first is a scheduler ordering rule)
- area: Reactive core & UI

## The shape that asks for it

```
{swap(get_route().map(shell_of), |shell| match shell {   // OUTER: coarse key
  Shell::Login => ..,
  Shell::App => <div>{swap(get_route(), |route| ..)}</div>,  // INNER: fine key
})}
```

Projecting the outer key is the right way to stop the outer form rebuilding on every navigation (`place_swap` already dedups on `==`, browser/ui.vl `place_swap`), and it is what the guide should teach. But both forms now stand on one source, and the outer reaches it THROUGH a derivation, so it is always one wave behind the inner.

## Measured (vilan 0.40.0, 0fa109eb7)

Probe: `route` cell; `shell = route.map(..)`; an outer `shell.on_change` that disposes a boundary; an inner `route.effect_on_change` owned by that boundary; one `route.set`.

```
inline: outer disposes the inner boundary
inline: INNER fired with 10 (boundary disposed: true)     <- face 2
turn:   INNER fired with 10 (boundary disposed: false)    <- face 1
turn:   outer disposes the inner boundary
```

**Face 1 — in a turn, child before parent.** `route`'s subscribers are `[map's, inner's]`. Wave 1 runs both: `map`'s sets the derived cell, which ENQUEUES the outer effect for wave 2; the inner effect runs now. The inner form builds for a value the outer is about to tear down. `Subscription::dispose`'s pending-queue scrub (reactive.vl, `dispose`) cannot help — by the time the outer disposes the inner, the inner has already run.

**Face 2 — outside a turn, a disposed observer fires.** `SignalCell::notify`'s inline arm iterates `self.subscribers.read()` — a snapshot. `map`'s subscriber runs first and cascades depth-first: derived → outer effect → the inner boundary is disposed and its subscription removed from the LIST, but the snapshot still holds it, so it is called next. For a `swap` that means: `live_owner` (already disposed) no-ops, then `render` runs under a FRESH `Owner` that the boundary's `defer` — which has already run — will never dispose, and `open_row` inserts before an anchor `region.close()` already removed. The scrub's own comment promises "a disposed observer never fires"; that holds only under an ambient turn.

## Doors

1. **Face 2, minimal (bug fix, S):** a subscriber carries a liveness flag its `Subscription::dispose` lowers; the inline loop and `drain`'s wave loop skip a lowered one. One `Shared<bool>` per subscriber, or reuse the `release` cell's one-shot. No ordering change. Fixes the leak in every form at once.
2. **Face 1, ordering (design, M):** two-phase settle — drain DERIVATIONS (`map`/`combine`/`flatten`/`selector` subscribers) to a fixpoint, THEN run effects in ascending subscriber `id`. `fresh_id` is monotonic and a parent form's effect is always created before anything its render creates, so id order IS parent-before-child with no owner-depth bookkeeping; the existing scrub then removes the disposed children before they run. Cost: a sort (or a bucketed insert) per wave, and derivations must be tagged at `on_change` time — a `Subscriber.kind` or a second `on_change_derived`. Solid's computations-before-effects, parent-first render effects, is the same rule.
3. **Nothing in the scheduler; document the latch.** The app feeds the inner form a cell that only follows values the outer admits (kolt `page_content`, views.vl): correct under both faces today, but it is the app routing around std.

Rec: (1) now — it is a leak; (2) as a paper section in `reactive-turns.md` before building, since it changes observable effect order for every app (ruling needed: is effect order across ONE wave part of the contract?); (3) is what kolt does meanwhile and should be retired when (2) lands.
