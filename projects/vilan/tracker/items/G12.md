# G12 — `read_dir_all`'s fuel is charged on the result, not on the walk

- status: OPEN — audit run 4 finding 4; the false rationale is already fixed (Order 20's audit-response commit cites this item)
- kind: design
- area: Macros & const
- source: audit run 4, 2026-08-29

One `DIR_ENTRY_FUEL × (files returned + 1)` per call, while the walk that
produced it does one `readdir` per directory and a classifying stat per entry
— directories walked are never counted, so an arbitrarily deep tree of empty
directories costs 2,048 fuel total however many syscalls it drives. If the
budget is meant to bound build WORK (its stated purpose), the basis should
charge what the walk does: per directory listed and per entry seen, files and
directories alike. The price itself may stand; the basis is the question.
The interpreter comment now records the gap and names this item.
