# F184 — Icon packages after S4: users outside a clone cannot get `vilan/packages/lucide`, a declared dependency is analysed whole (+21% check instructions), and two tool gaps the package met

- status: open
- kind: follow-ups (packages; tooling)
- area: vilan/packages/lucide, scripts/lucide-native.mjs, release packaging (scripts/, .github/workflows/release.yml), crates/vilan-cli (check of a library, dependency diagnostics)

(1) DISTRIBUTION: nothing in the release ships `vilan/packages`; the std blob is `vilan/std` and `vilan/macro_std`, and the npm and tarball packages carry binaries. A program takes the package by a PATH dependency (`lucide = { path = "../../packages/lucide" }`), which works inside a clone only. How packages outside std reach users (a registry, git dependencies, vendoring into the release) is gfx-path.md's open section 8 question and the owner's design call. (2) COST: declaring the dependency raises `vilan check` from 0.29 s to 0.35 s, peak memory 110 MB to 134 MB and instructions by 21% (1.97 G to 2.37 G) even when nothing imports it, because a declared dependency is parsed and analysed whole (428 KB, 1,999 functions); the native binary pays only for icons used (five icons: 512 bytes). If it matters: one module per icon or per letter, or lazy analysis of unreferenced items in dependencies. (3) TOOL GAPS, not fixed: `vilan check <library dir>` checks only the platform contract, not types (a planted type error in the package passed; the package's test checks `src/lib.vl` on both backends instead); a missing name in a dependency is reported as `cannot find 'trash_2' in module 'src'` instead of naming `lucide`. (4) DECIDED IN LANE, owner may overrule: the pin is lucide-static 1.64.0 (the newest release at least two weeks old; tarball integrity in the generated header); the 276 deprecated alias names are left out; a keyword name gets a trailing `_`, a name starting with a digit the prefix `icon_`; the generated `lib.vl` is not formatter-stable and lives under the library's `generated` root; `examples.rs` staging keeps the repository layout and copies `vilan/packages` for a manifest that names it.
