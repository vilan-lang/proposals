# A60 — style smalls from kolt's styles.vl: `flex_grow` missing beside `flex_shrink`, no `Color::current()` for `currentColor` — and the `[hidden]` HACK, which is not a small: the preflight rule loses to ANY app `display` because it sits a CASCADE LAYER below, so `View::show()` silently does nothing on every flex container

- status: OPEN — the owner's kolt TODO/FIXME sweep (2026-09-07)
- kind: design
- area: Reactive core & UI

Three FIXMEs in kolt/src/styles.vl and one HACK in views.vl. The first two are missing siblings, the
third is not a gap at all, and the fourth is a defect wearing a HACK comment.

1. `flex_grow` — styles.vl:11-15
       // FIXME: Implement with std.
       fun flex_grow(self, value: f64) { self.raw("flex-grow", i"{value}") }
   std has `flex_shrink(self, value: f64)` (vilan/std/src/style.vl:869) and the `flex` shorthand (:865), and
   the shorthand-expansion table already names the property (`"flex" => ";flex-grow;flex-shrink;flex-basis;"`,
   style.vl:644). `flex_grow` is simply absent. Nine call sites in kolt (views.vl:104, :112, :151, :343 and
   the rest).

2. `Color::current()` — styles.vl:32-37
       // FIXME: Implement with std.
       fun current() { style::Color { text = "currentColor", root = "" } }
   std's Color constructors (style.vl:165-215) are `white`, `black`, `transparent`, `hex`, `var`, `gray`,
   `blue` — no `currentColor`. Note kolt composes it: `style::Color::current().alpha(0.1)` (channel.vl:153),
   so whatever `alpha` emits has to remain valid over a keyword color, which is worth checking as part of the
   build rather than after it.

3. `Length::full()` — styles.vl:26-30 — NOT A GAP, and the hand-written form can be deleted today.
   kolt writes `style::Length::raw("100%")`; `style::Length::pct(100f)` (style.vl:74-76) renders exactly
   `100%`. Eleven call sites (views.vl:116, :157, :252, :302, :337, :496, :513, :694, :711;
   channel.vl:136, :145) can move to `pct(100f)` with no std change. Whether std wants a `full()` alias for
   the most common percentage is taste, not a hole — decide it, but do not let it hide the two above.

4. THE `[hidden]` HACK — views.vl:132-139
       // HACK: Setting display overrides the preflight's `[hidden]` rule so the hack below toggles display.
       .child_relation("not([hidden])", "display", style::style().flex_col());
   std's preflight carries `preflight_rule("[hidden]", declarations().raw("display", "none"))`
   (style.vl:1747) with the comment "`[hidden]` last in reading order and strongest in the cascade — (0,1,0)
   against the element selectors above, so hiding still wins". Specificity is not what decides the outcome
   here: the preflight is `@layer vilan.preflight`, described in the same file as "std's floor", with the
   app's `declare` landing "one layer ABOVE this one" (style.vl:1750-1756). A cascade layer beats specificity
   outright, so ANY app style that sets `display` defeats `[hidden]`, whatever its specificity.
   The consequence reaches std's own surface, not just kolt's: `View::show(condition)`
   (vilan/std/src/browser/ui.vl:632-639) hides by `element.set_hidden(!visible)`, i.e. by the `hidden`
   property and therefore by that same preflight rule — so `show` is a no-op on every element whose style
   sets a display, which is every flex container in a real app. kolt's `child_relation("not([hidden])", ...)`
   is the workaround: put the `display` behind `:not([hidden])` so the app layer stops fighting the reset.
   OPTIONS TO RULE BETWEEN: emit the preflight `[hidden]` with `!important`; have `styled` emit a companion
   `[hidden]` rule in the APP layer alongside any `display` it writes; or make `show` toggle `display`
   directly and document that it does. Whichever wins, the pin is `show(cond)` on a flex row actually
   disappearing.
