# E280 — a file OPENED into a world another document already holds is served at once (M104's `serve_from_held_world`) but its FURTHER worlds are never analyzed — a module both a browser and a node entry reach shows only the browser leg's verdict until the next edit, where opened the other way round the open's sweep analyzes the node world

- status: OPEN — filed 2026-10-08 (editor-48's find, Order 48)
- kind: LSP correctness (S)
- area: LSP & tooling

`did_open`: when `serve_from_held_world` serves the opened file it refreshes and RETURNS, skipping the branch below it that runs `reanalyze_dependents` when a landed document has `further_worlds` — the branch that analyzes a further world that should exist and does not (M104's own comment). So with `client.vl` open and settled, opening `shared.vl` (reached by the client and the server entries) leaves the server world unanalyzed: no node-leg diagnostics on the file (E113) and, with E254's held patch, no twin legs. Opening `shared.vl` first, then `client.vl`, analyzes it. Fix: after a held-world serve, schedule the sweep for the served document's further worlds that no kept world or open entry holds. Observed in an LSP test (`server.worlds` empty, the document's `further_worlds()` = the server entry); not built — LSP scheduling is incr-48's this order.
