# A58 — `std::dom::Event` has `key` and `target_value` but no `code`, no `target` and no `current_target`: three apps-facing getters hand-written in three different kolt files, two of them under an explicit "FIXME: Implement with std"

- status: OPEN — the owner's kolt TODO/FIXME sweep (2026-09-07)
- kind: feature
- area: Reactive core & UI

Three hand-written `Event` getters, in three files:

- kolt/src/input_system.vl:5-9
      impl Event {
          // FIXME: Implement with std.
          [extern(get, "code")]  external fun code(self): str;
      }
  The keyboard-shortcut matcher wants the PHYSICAL key — app_input_system.vl spells its bindings
  "KeyE", "KeyB", "KeyD" — which is `event.code`, not `event.key`. A layout-independent shortcut cannot be
  written with `key` alone.

- kolt/src/views.vl:31-34
      impl Event {
          // FIXME: Implement with std.
          [extern(get, "currentTarget")]  external fun current_target(self): Element;
      }

- kolt/src/overlay.vl:91-94, under the banner the owner wrote himself
  ("// DOM bindings `std::dom` lacks yet"):
      impl Event {
          [extern(get, "target")]  external fun target(self): Element;
      }

WHAT STD HAS TODAY: vilan/std/src/browser/dom.vl:193-245 — `prevent_default` (:197), `button` (:201),
`meta_key`/`ctrl_key`/`shift_key`/`alt_key` (:205-215), `key` (:218), `pointer_x`/`pointer_y` (:229-232),
and `target_value` (:244). That last one reaches THROUGH the target to read its `.value`, so the host
property is already on the binding's path — what is missing is the accessor that hands the element back.

PROPOSED: `code(self): str`, `target(self): Element` and `current_target(self): Element` on
`std::dom::Event`, sited beside `key`. Keeping `target` and `current_target` distinct is the point, and
kolt's two uses are the exhibit: overlay.vl asks "did this click land inside me" (`target`, paired with
`Element::contains` — A59), views.vl asks "which element carries the handler that fired" (`current_target`).
Document `key` vs `code` in the same pass — a shortcut table wants `code`, a text-entry handler wants `key`,
and today's surface silently offers only the second.
