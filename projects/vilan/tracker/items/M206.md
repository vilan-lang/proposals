# M206 — `std::image::Format` and `Fit` do not implement `PartialEq`: `format == Format::Webp` is refused, so a caller checking what `sniff` answered writes a `match`

- status: OPEN - filed 2026-11-10 (kolt)
- kind: feature gap (std::image; S)
- area: Standard library / image
- renumbered: filed as M204 on the local branch `kolt-image-gaps` (kolt-side session); synced to main as M206 on 2026-11-16, because main's M204 is another item. Kolt's sources cited the old number until its v0.56.0 patch.

Both enums in `std/src/image.vl` are bare `export enum`s with no `[derive(..)]`, so neither can be compared with `==`. Kolt met it testing account avatars: the test asserting that an encoded copy sniffs as WebP had to write `match Image::sniff(bytes) { Some(Format::Webp) => true, _ => false }` instead of `Image::sniff(bytes) == Some(Format::Webp)` (`Option<T>` is `PartialEq` only when `T` is). Repro on 0.55.1:

```vilan
import std::image::Format;

fun main() {
	let a = Format::Png;
	let b = Format::Png;
	let same = a == b;
	print(i"{same}");
}
```

`vilan check` refuses it: `type 'Format' does not implement the `PartialEq` operator; add `impl Format with PartialEq` providing `eq``. The same program over `Fit::Cover` gives the same refusal for `Fit`. A caller cannot add the impl, since both types are std's.

Rec: `[derive(PartialEq, Debug)]` on `Format` and `Fit` (the shape `std::time`'s `Instant` and `Duration` already use), and `Eq`/`Hashable` too if a caller keys a map by format. Neither crosses the extern seam as itself (they cross as `format_code` / `fit_code` integers), so nothing changes there. Pin: `Image::sniff(png) == Some(Format::Png)` checks and runs on both backends. Docs: std/image.md's signature block shows the derive.
