# E69 — NEW — attribute-NAME completion in an element head is a semantics decision

- status: OPEN — RE-OPENED and RULED 2026-09-14 (owner): the vocabulary is GENERATED from the HTML attribute spec by code-gen; was DEFERRED since the 2026-08-22 ruling ('if offered at all, GENERATED — the generation source is the open question')
- 2026-09-14 (owner): 'File an item to provide auto-complete for element attributes derived from the html attribute spec (code-gen)' — this item already carried the deferred question, so it is re-opened with the ruling rather than duplicated. DESIGN: a generator script beside `scripts/lucide.mjs`'s pattern (`scripts/html-attributes.mjs`, pinned to a source tag) consumes the spec's attribute index — the WHATWG HTML attribute index (html.spec.whatwg.org/multipage/indices.html#attributes-3, per-element + global) and the SVG attribute index (lucide's `stroke-width`, `viewBox`) — and emits a checked-in Rust table `HTML_ATTRIBUTES: &[(element-or-*, &[name])]` with a sync test that regenerates and diffs (the gate E67 asked for: generated AND gated = one source of truth, no hand list); completion at `<tag |>` offers the tag's attributes plus the globals (E67's head-position machinery), `on:` events from GlobalEventHandlers as a second table; the desugar stays NAME-BLIND (completion only — a lint on unknown names is a later question); the playground reaches it through vilan-ide. Pins: `<input |>` offers `type`, `disabled`, `value` and the globals; `<svg |>` offers `viewBox`; the sync test fails on a stale table; a custom `data-*` name is never refused. Size M.
