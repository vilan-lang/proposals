# E304 — the function tooltip writes `: void` where the function declares NO return type - `fun f(): void` - instead of ending at the parameter list; today the signature label omits the return type exactly when the source omitted it, so a reader cannot tell a void function from one whose return type the label dropped

- status: OPEN — filed 2026-10-12 (the owner's ask, mid-Order 51)
- kind: editor (hover; XS)
- area: Editor

`function_signature_label` (and the trait-member form) appends `: void` when the declaration writes no return type and the body's return type is void; a function whose return type is INFERRED non-void (a lambda-bodied `fun f() = 3`, a `fun` the analyzer typed from its tail) writes the inferred type the same way (`: i32`), so the label always carries a return type. The source is untouched (the formatter keeps `fun f() {` as written). Everywhere the label is read follows: hover, the completion detail, signature help, E206's second line, the `dbg`/explain surfaces that print a signature. Pins: a void `fun` with no annotation (`: void` shown), a `fun` with a written `: void` (unchanged), an inferred non-void, a method, a trait requirement, a closure-typed parameter's label unchanged. Sizing XS (analyzer.rs label writers + the hover/completion goldens that move).
