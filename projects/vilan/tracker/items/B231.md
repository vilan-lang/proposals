# B231 — a `match` expression as a binary operand (`flag && match probe() { .. }`) is a parse error: `found 'else' expected an expression`

- status: OPEN — found by lane b224 (2026-09-04); the triage lane's `s_and_match.vl` produced no `.mjs` for the same reason
- kind: bug
- area: Type system & the type solver

`if flag && match probe() { Some(let n) => n > 0, None => false } { .. }`
fails to parse (`found 'else' expected an expression`); a `match` (and
presumably an `if`-expression in the same position — check) is not
accepted as the operand of a binary operator, while it is accepted as
an initializer and a return tail. Decide the grammar: block-like
expressions (`match`, `if`, a block) as operands of binary operators,
or a documented refusal with a steer to bind it first. Recommend
accepting — the emitter now has a statement slot for a conditional
operand (B224) so the lowering is uniform. Pins: the `&&` form, an
`if`-expression operand, a parenthesized control, and the emitted JS
running under node.
