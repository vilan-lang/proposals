# E164 — the TextMate `generics` rule swallows a CLOSING TAG straight after text: `<span>hello</span>` paints `</span>` as `meta.generic.vilan` with generic delimiters (its begin is `(?<=[A-Za-z0-9_])<` and `hello` ends in an identifier character) — the commonest markup shape in the language, mis-coloured, invisible to E161's regex pins; and the `>` closing an OPENING tag WITH attributes (`<div class="row">`) is painted `keyword.operator.vilan` because the terminator rule is line-start only

- status: OPEN — Order 33's finds (2026-09-11)
- kind: editor
- area: LSP & tooling

(1) The generics begin must not fire when the `<` is followed by `/` (a closing tag) — `(?<=[A-Za-z0-9_])<(?!/)`; the element rule's `</tag>` arm then wins. (2) An element-head begin/end (from `<tag` to `>`/`/>`, spanning lines) replaces E115's line-start terminator, so the `>` of any opening tag is a tag delimiter wherever it sits. Pins: scope pins once E163 lands (regex pins else): `</span>` after text is a tag; `<div class="row">`'s `>` is a tag delimiter; `a < b` stays an operator; `List<i32>` stays generic.
