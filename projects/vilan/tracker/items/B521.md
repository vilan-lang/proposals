# B521 — a body closure with ONE PARAMETER PER TUPLE ELEMENT for tuple-taking combinators (`when_all_some((a, b), |a, b| ..)` instead of `|(a, b)| ..`)

- status: OPEN — filed 2026-10-03 (owner's ruling: tuple parameter first, this later)
- kind: language/std sugar (S–M); LOW, after A152
- area: Type system & the type solver

A152 ships `when_all_some` with a single tuple parameter, destructured at the call site. This item is the spread form: either per-arity overloads whose closure takes N parameters, or a general rule that a closure of N parameters is accepted where a closure of one N-tuple is expected. Decide which (the general rule also touches `combine(..).derive(\|(a, b)\| ..)`), and whether the two-character saving is worth a solver rule at all - measure against A152's call sites in kolt first.
