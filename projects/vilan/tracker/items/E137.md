# E137 — the formatter never breaks a ONE-link chain: a single `.map(closure)` stays inline at any width (220 columns)

- status: OPEN — the owner's find while migrating kolt (2026-09-04); reproduced at 289e2a2b by the triage lane
- kind: bug
- area: Language server & tooling

`let selected_theme = combine((filtered_themes, selected_index)).map(
|(themes, i)| themes.find(|t| t == initial_theme).or_else(|| themes.get
(i.clamp(0, themes.len()))));` comes back from `vilan fmt` unchanged at
220 columns while the signature above it broke correctly. The
formatter HAS a width rule — `LINE_BUDGET = 100` (formatter.rs ~1667),
`over_line_budget` (~3149), recursive chain/list splitting with a
`Split::Tail` descent. Bisect: `alpha(a).beta(x).gamma(y)` over budget
breaks one link per line; `alpha(a).children([..])` breaks the list;
`alpha(a).map(|t| <150 cols>)` NEVER breaks.

Cause: `is_breakable_chain` (~3282) requires ≥ 2 postfix call links;
`combine(x).map(f)` has one, and `print_expr`'s split door (~4241) is
gated on it, so neither the width split nor the tail descent is armed.
Documented as deliberate ("one link is not a chain — breaking it would
buy a line and no clarity"), which exempts the whole statement when the
single link carries a large closure.

Fix (M): arm the split for a one-link chain when over budget — lower the
threshold to ≥ 1 under `over_line_budget`, or (narrower) let
`Split::Tail` descend into a closure's expression body so the inner
`themes.find(..).or_else(..)` (2 links) breaks and the closure body
indents. Byte-gated corpus: expect golden churn; review each reflow.
Related: B213 (same command, unrelated cause).
