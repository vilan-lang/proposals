# B762 — A type reached through a module path is accepted as a value: `let q = model::Task;` checks clean, where `let q = Task;` is refused

- status: open - filed 2026-11-26 (lane `keys-s1a`'s find; reproduced on `next` @7887a037)
- kind: checker hole (a type used as a value is not refused when its name is qualified)
- area: crates/vilan-core/src/analyzer.rs (path expressions)

Repro (two files):

```
// src/model.vl
export struct Task { title: str }

// src/main.vl
import pkg::model;
fun main() {
	let q = model::Task;
	print(1);
}
```

`vilan check`: no errors, and the program runs. The unqualified form is refused: "`Task` is a type, not a value; construct it (`Task { .. }`) or call a static like `Task::new(..)`". Before struct keys, `model::Task.title` took the same hole and threw a `ReferenceError` at run time; S1a makes that form a key literal, which leaves the bare `model::Task` case.

Rec: the qualified path takes the unqualified one's refusal. Size S.
