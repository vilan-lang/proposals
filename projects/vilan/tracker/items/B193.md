# B193 — a trait default's `self <op> self` miscompiles: host `+` over two lowered structs

- status: OPEN — operators-tail lane's find (2026-09-01); pinned #[ignore]d `platform::a_trait_defaults_self_operand_dispatches_to_the_specialized_type`
- kind: bug
- area: Type system & the type solver
- source: lane operators-tail (B175's one deliberately-left `Type::Trait` shape)

`trait Doubler with Add { fun twice(self): Self { self + self } }`;
`Money { cents = 21 }.twice()` prints **2** — the host `+` over two
lowered structs (`"2121"`, slot 0). Both halves are one defect: the
analyzer's operator check skips this `Type::Trait` shape because
refusing it would be advice nobody can take (the explicit
`self.add(self)` does not resolve there either — `Expected Doubler,
but got Add instead`), and `transformer.rs`'s binary dispatch has no
`GenericDispatch::OnType(None, …)` case to dispatch a default body's
operand on the type being specialized. Fix at the dispatch: a default
body's `self` operand dispatches on the SPECIALIZED type (the same
substitution B175 gave `T::default()`), and the analyzer stops
skipping. Miscompile family; the pin runs it.
