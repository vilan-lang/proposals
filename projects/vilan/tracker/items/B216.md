# B216 — a PARAMETERIZED supertrait clause loses `Self` in a default body: `trait Bumper with Add<i32> { fun bumped(self): Self { self.add(1) } }` → `Expected Bumper, but got Add instead.`

- status: OPEN — lane cascade-26's find (2026-09-03); B205's deliberate gate
- kind: bug
- area: Type system & the type solver

B205 rebinds a supertrait member's `Self` to the sub-trait inside a
default body — gated to an ARGUMENT-LESS `with` clause on purpose:
with `Add<i32>` written, `b: B` (`i32`) and the `Self` return (the
sub-trait) part company, and nothing in the RESOLVED types separates
them — only the WRITTEN name does. Fix: carry the written-name rule
B206 built for labels (`function_signature_label_for` renders by the
written name) into method resolution's substitution for supertrait
members, so `B = i32` binds from the clause and `Self` from the
receiver. Pin the repro (scratchpad cascade-26/b205/param.vl), a
two-parameter clause, and B205's argument-less control.
