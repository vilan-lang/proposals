# N211 — Nothing in CI compiles the GPU or webview crates for macOS, and the nightly macOS perf job is dead (N209): macOS is the one release target with no check at all before a user's machine

- status: open
- kind: CI coverage (macOS)
- area: .github/workflows/ci.yml (job `gfx`), scripts/ci-local.sh (`leg_windows`, which already cross-lints the workspace, gfx and webview for msvc), crates/vilan-rt-webview

Two additions, both small: (1) cross-lint the GPU crate for `aarch64-apple-darwin` on the Linux runner beside the Windows cross-lint (it needs only `rustup target add`; seconds once cached); a local leg `macos` in ci-local.sh the way `windows` is one, with the same honesty: it proves the tree BUILDS for that target and nothing about what it does. (2) the webview crate needs a real `macos-latest` runner for even a `cargo check`; one job, check only, on pushes that touch `crates/vilan-rt-webview` or its lockfile. The release workflow builds the compiler for both Apple targets, so the compiler itself is covered; the runtime crates a user's native build links are not.
