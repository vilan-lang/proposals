# B631 — A closure was a receiver of a `Callable` struct's impl: `twice.call(5f)` on a closure `|n: f64| n * 2f` beside `impl Scale with Callable { fun call(self, n: f64): f64 }` compiled to `Scale`'s `call` with the closure as `self` and printed `NaN`

- status: FIXED - filed and fixed 2026-10-13 (incr-52b's find, Order 52)
- kind: miscompile (JS; S) - FIXED in incr-52b e3ca0a48
- area: Type system & the type solver

`impl_subject_admits` asked `compare_type`, whose B340 arm admits a closure against a `Callable` value of the same shape (the coercion into a closure slot). Asked of an impl SUBJECT that is the wrong question - the same one the trait-object rule in `impl_subject_admits` already answers for `dyn`. Every shape-matching closure was in reach of the struct's members, and std's own `type_is_callable(\|T\| R)` answered yes through any package's callable struct (kolt's `Scale`), which is what refused kolt's client the std prefix (M145's second refusal). Fixed: an impl on a struct or enum head admits no closure or function receiver; pinned by `callable::a_closure_is_no_receiver_of_a_callable_structs_impl` and `a_callable_struct_still_coerces_into_a_closure_slot`. Estate 0. NOTE for solver-52: the change is in `impl_subject_admits` (inference).
