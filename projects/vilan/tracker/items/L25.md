# L25 — Homebrew has not been updated since v0.41.1 (2026-09-27): the release job reads the secret `TAP_APP_CLIENT_ID`, the repository holds `TAP_APP_ID`, and the job skips its steps while reporting green

- status: open
- kind: release engineering (a broken publish channel; the owner's step)
- area: .github/workflows/release.yml (`publish-brew`, the `Is there an app to push with?` step), scripts/brew-formula.sh, the website's install page

Commit 1946f746 (2026-09-28) moved the token step from the App's numeric id to its CLIENT id (the action deprecated `app-id`), and the secret it reads became `TAP_APP_CLIENT_ID`. That secret was never created, so `publish=false`, every later step is skipped, the job is green, and only a `::notice` says the tap was not updated. The website and the hello-vilan tour advertise `brew install vilan-lang/vilan/vilan`, which installs 0.41.1. THE OWNER'S STEP: add the App's client id (the `Iv...` string on its settings page) as the repository secret `TAP_APP_CLIENT_ID`, then re-run `publish-brew` for the latest tag (or wait for the next release). TWO CODE FOLLOW-UPS: (1) a publish channel that is configured-then-broken should fail, not skip: make the skip an error once the tap has ever been published (or when `TAP_APP_PRIVATE_KEY` is set and the client id is not); (2) the fold's manifest check has a cousin to add: after a release, read the tap's formula version and refuse a fold that leaves it behind.
