# B195 — a NEGATED `is` capture is readable in its then-branch and reads `undefined`

- status: OPEN — rulings-smalls lane's find (2026-09-01); LIVE unsound read; FIX-NOW lane after that lane merges
- kind: bug
- area: Type system & the type solver
- source: lane rulings-smalls (B171's fourth boundary neighbour)

`if !(maybe is Some(let n)) { print(n); }` compiles and prints
`undefined` — emitted `if (!($a[0] === 0)) { console.log($a[1]); }`,
the payload slot read when the pattern did NOT match. The same
unsound read the `||` arm had, which B171's lane closed with a
visibility RANGE on positional declarations (`LocalDeclaration {
visible_from, visible_until }`); a capture under a negation gets the
same treatment: not visible in the then-branch (it is visible in the
ELSE branch, and — B187's design — in the continuation after a
diverging then-branch). Fix on top of the range machinery; pins for
the then-branch refusal, the else-branch acceptance, and `!(a is X
&& b)`. Miscompile family; run the emitted JS in the pin.
