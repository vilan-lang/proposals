# A135 — an `[rpc]` body that returns `field.map(..).cell()` (kolt store.vl:197/206/258 after the flip's `.cell()` edits) mints a FRESH derived cell per CALL: A92's `expose_dynamic` dedup keys on `cell_identity`, so it never hits — one capability, one forward and one copy of every update per `Subscribe` for a value the connection already carries; and the dispatcher runs handlers under NO ambient owner, so the cell's `register_with_owner` keeps its upstream subscription on the module-level store cell for the PROCESS — a leaked subscription per call, growing with every re-lease and reconnect (`reattach_mirrors` re-issues the call). Not new to the flip (the pre-flip `map` was per-call too) but now written out in every migrated service

- status: OPEN — filed 2026-09-28 (the integrator's find while diagnosing A134)
- kind: bug (leak) + design
- area: Reactive core & UI

Doors: (a) the SERVICE memoizes the derived cell per (method, args) — a `Memo` field on the store, which kolt's `users: Memo<UserId, SignalCell<Option<User>>>` already does for `get_user` and which A134's door (a) mirrors client-side; document it as the rule for a handle-returning `[rpc]` ("return a cell that OUTLIVES the call"). (b) the dispatcher runs each handler under the CONNECTION's owner (`Service::factory` has the seam: the instance is dropped with the connection), so a per-call cell dies with the connection instead of the process — bounds the leak, does not restore the dedup. (c) a check: a handle-returning `[rpc]` whose tail is a `.cell()` (or any derivation constructor) gets a warning with the memo steer — static, cheap, catches every migrated site. Rec: (b) + (c) now, (a) as the documented idiom. Sizing S (b, c) / doc (a); std/rpc + the analyzer's service expansion, Order 43.
