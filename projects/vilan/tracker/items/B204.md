# B204 — should `panic(…)` count as divergence for the CHECKER (return-position checking, R4/R7), as it now does for paint?

- status: OPEN — lane e114-rest's find (2026-09-01); a language question, needs a paper note
- kind: bug
- area: Type system & the type solver

E114's paint treats a `panic(…)` call (lowers to `throw`) and an
endless `for { … }` as diverging leaves; the checker's
`Divergence` deliberately does not, so `fun f() -> i32 { panic("x") }`
still wants a value after the panic (rpc.vl:308's `0 - 1` exists
for this). Counting `panic` in the checker is a language change:
R4/R7's exemption list and return-position checking. Decide: (a)
panic diverges everywhere (drop the `0 - 1` idiom, pin the
return-position case), or (b) it stays paint-only, documented.
