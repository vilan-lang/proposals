# B180 — a nominal left operand's declared `B` is never checked: `Counter + Point` compiles and reads slot 0

- status: OPEN — b179 lane's find (2026-09-01); LIVE MISCOMPILE, wider than B179 and not generic-specific
- kind: bug
- area: Type system & the type solver
- source: lane b179; the dispatch path, not the native path

With `impl Counter with Add { fun add(self, other: Counter): Counter }`,
the GROUNDED `Counter { n = 1 } + Point { x = 1, y = 2 }` compiles and
prints `2`: dispatch resolves the impl and passes a `Point` where the
declared `B` says `Counter`, reading the struct's slot 0. Same with a
`T: Add` right operand. B179's refusal fires only on the NATIVE-left
path; the impl-dispatch path never checks the right operand against
the impl's declared `B` at all.

Needs care, not a guard: an impl may legitimately declare `B` as its
own type parameter. NOTE: until this closes, B179's second steer
("put a left operand there whose `Add` declares a `B` that admits
`T`") steers into a broken route — the fix makes that sentence
truthful. Top-slot candidate for Order 24.
