# C13 — a closure over a view parameter escapes through a storing callee

- status: OPEN — pinned `#[ignore]`d (borrows.rs, the Holder shape), found by Order 19's capture-spec lane while closing C12; P4c's residue, not C12's
- kind: bug
- area: Memory model
- source: the capture-spec lane's probes, 2026-08-28

`fun keep(g: || i32): Holder { Holder { f = g } }` /
`fun make(v: &mut i32): Holder { keep(|| *v) }` /
`fun outer(): Holder { mut n = 3; make(&mut n) }` compiles and prints 3 —
a closure over a `&mut` PARAMETER, handed to an ordinary callee that
stores it, escapes the frame whose local the view names. P4c refuses the
directly-returned form; `check_view_escape` skips argument positions on
purpose, so the stored form slips through. Memory-safe on JS only
because the host boxes and traces. Closing it needs the closure-escape
analysis (does this callee store its closure argument?) — the same
machinery lifetimes.md's opaque set could feed. Recorded as spec §6.9's
honesty limit; un-ignore is the acceptance.
