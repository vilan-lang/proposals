# A186 — A callback made outside a turn and called from an event handler runs in NO turn: its writes notify on the spot, so a handler can dispose its own owner halfway through and everything it builds after is released as it is placed, silently

- status: OPEN - filed 2026-11-10 (kolt, from task 127; vilan 0.55.1)
- kind: design (std::reactive turns) + diagnostic
- area: Standard library / reactive, web ui

`View::on` says each dispatch runs the handler "inside a fresh turn — an event's signal writes settle as one wave". That holds for writes written in the handler literal. A write made through a callback that the handler CALLS, where the callback is a plain `|| void` made while rendering (a menu row's action, handed to the row as libraries do), resolves `turn_scope` at the callback's creation (spec §8.4), finds none, and takes `notify`'s inline path: every observer runs at once, depth-first, before the next line of the handler.

When the write closes the boundary the callback sits in (a menu row's action closing its menu, the most ordinary thing a row does), the boundary's owner, which is also the callback's ambient owner, is disposed mid-handler. Whatever the rest of the callback builds is registered with a disposed owner, which B291 releases on the spot: a `when` placed into a host that outlives the menu (a portal, an overlay's container) subscribes and is released in the same call, so nothing is ever placed. There is no error, and the state that was meant to show it reads `true`.

Kolt met it as a dialog built in a menu row's action: `open()` ran, the overlay's open flag was true, nothing appeared. Kolt's overlay library now refuses to open an overlay with no live attachment, and the app builds the dialog from an effect the area owns; the std half is this item.

Minimal repro (a browser package, `vilan init --template browser`, this as `app.vl`):

```vilan
import std::reactive::{ get_owner, turn_scope };

fun main() {
	let _root = ui::mount_root("app", || page());
}

/// A menu row whose action is handed in, as a menu library's rows are.
fun row(label: str, act: || void): View {
	<button on:click(|_| act())>{label}</button>
}

fun page(): View {
	let menu_open = Signal::new(true);
	let host = view("div");
	let log = Signal::new("");
	<div>
		<button on:click(|| menu_open.set(true))>"reopen menu"</button>
		{ui::when(menu_open, || {
			let inline_button = <button
				on:click(|| {
					let in_turn = turn_scope.get_safe().is_some();
					menu_open.set(false);
					let shown = Signal::new(false);
					host.child(ui::when(shown, || <p>"dialog from inline"</p>));
					shown.set(true);
					log.set(i"inline: in a turn {in_turn}; owner disposed after the close {get_owner().is_disposed()}; dialog flag {shown.get()}");
				})
			>
				"inline"
			</button>;
			<div>
				{inline_button}
				{row("handed in", || {
					let in_turn = turn_scope.get_safe().is_some();
					menu_open.set(false);
					let shown = Signal::new(false);
					host.child(ui::when(shown, || <p>"dialog from handed in"</p>));
					shown.set(true);
					log.set(i"handed in: in a turn {in_turn}; owner disposed after the close {get_owner().is_disposed()}; dialog flag {shown.get()}");
				})}
			</div>
		})}
		<p>{log}</p>
		{host}
	</div>
}
```

Clicking "inline" logs `in a turn true; owner disposed after the close false` (the close waits for the turn; the dialog is placed, then goes with the menu when the turn settles, which is ordinary ownership). Clicking "handed in", on a fresh page or after "reopen menu", logs `in a turn false; owner disposed after the close true; dialog flag true`, and the dialog is never in the DOM. The same two blocks of code, differing only in where the closure was made, see different worlds after the same write.

Recommendation, two parts:

1. **Make `on`'s promise hold for what the handler calls.** A write that finds no captured turn joins the innermost turn being RUN, not only one being drained: `turn` pushes its turn on a dynamic stack for its extent (as `draining_turns` already does for drains), and `notify`'s no-ambient-turn path consults it before going inline. Capture-at-creation stays the rule for a closure that HAS a turn (a stored callback keeps the turn it was made in); only the "none at all" case changes, from eager to the caller's wave. Alternative, smaller: document that a callback must be typed `(|| void) context turn_scope` to join its caller's turn, and warn (B677's shape) when a plain `|| void` parameter that writes signals is called from a handler.
2. **Diagnose placing under a disposed owner.** B291 is right that a LATE registration (an async continuation after its scope went) is not an error. A `when`/`swap`/`each` PLACED under a disposed owner in the same synchronous extent that disposed it is almost always this bug: in a dev build, a one-time warning naming the placing call site (`follow` already carries `track_caller`) would have pointed at the line at once.

Either part alone would have turned this from a silent nothing into a visible cause; part 1 also removes the surprise for code that reads state after a write.
