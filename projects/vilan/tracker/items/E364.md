# E364 — The "block's methods resolve only in a file that imports from its module" error names an EMPTY module when the `impl` block is in a dependency

- status: OPEN - filed 2026-11-09 (kolt, moving `impl Style { fun flex_col .. }` into a library)
- kind: bug (diagnostic text)
- area: Diagnostics / packages

With `impl std::web::style::Style { fun select_off(self) .. }` declared in the library `lib` (module `lib::style_ext`) and called from an app file that doesn't import that module:

```
Error: `select_off` comes from the `impl Style` block in ``, which extends a type declared elsewhere, and this file does not import `` or a name from it: such a block's methods resolve only in a file that imports from its module. Import it (`import ::(impl std::web::style::Style);`)
```

The module is printed as nothing three times, and the suggested import (`import ::(impl ..)`) does not parse. For a block in the same package the message names the module. Expected here: `lib::style_ext`, and `import lib::style_ext::(impl std::web::style::Style);`.

Rec: render a dependency's module path under its dependency key in this diagnostic (and check the other diagnostics that print a module path for the same hole). Pin: the two-package case above.
