# G19 — the const channel's containment fence is lexical: a symlink reads and SHIPS outside files

- status: OPEN — audit run 6's F7; carries a PRODUCT QUESTION for the owner
- kind: design
- area: Macros & const
- source: audit run 6, repro verified

`contained_input`/`bundled_name` reject `..` and absolute paths LEXICALLY,
then use the path unresolved — so `asset::read("escape.txt")` where the
file is a link to `../../outside/secret.txt` compiles the outside content
into the bundle, and `bundle` ships it (the refusal message meanwhile
CLAIMS resolution: "paths resolve inside the package root"). This may be a
deliberate allowance — G15 ruled a link is an ordinary way a static tree
gets its name — but then the message is wrong and the doctrine unwritten.
THE QUESTION: is following a link out of the package a supported spelling
(fix the message, write the doctrine) or an escape (resolve-then-refuse,
matching the message)? Related recordable: `same_file`'s
canonicalize-both-sides lets a planted dist-side symlink count as
"already copied" (F24) — the ruling covers both.
