# M32 — allocation is ~19% of a cold check: 5.7M mallocs per kolt client compile, the parser moving `Node` by value and 1.1M `Type` clones

- status: OPEN — kolt-benchmark's find (2026-09-04; callgrind at 289e2a2b); census recorded, two slices to cut
- kind: performance
- area: Type system & the type solver (+ the parser)

Self cost of `malloc`/`free`/`realloc`/`memcpy` is **~19% of a full
client check's 7.19e9 Ir** (5,699,022 `__rdl_alloc` calls; on the
lucide-stubbed copy the same family is 24% of 3.21e9, so it is the
compiler's own constant, not the module's). Two named sources:

- **The parser moves `Spanned<Node>` by value through every
  precedence level.** `parse_member_accessor` (400k + 258k + 238k
  memcpy calls across its frames) and `parse_binary_level` (279k +
  277k) are the top `memcpy` callers — each `Option<Spanned<Node>>`
  return copies the whole `Node` enum up the recursion. Slice:
  measure `size_of::<Node>()`, box the fat variants (or return
  through the arena the tree already leaks into) so a level returns
  a pointer-sized value.
- **`Type` is cloned 1.1M times** (`TypeId::get_type` 197k,
  `classify_resource` 169k, `infer_type_path` 204k + 198k,
  `analyze_over_world` 97k) through `get_type_by_type_id`, whose
  borrowing twin `borrow_type_by_type_id` already exists for callers
  that only read. Slice: migrate the five hot callers to the borrow
  (each is a read), leaving the clone for callers that mutate.

Pin for each slice: Ir per entity on the E121 generated exhibit
(1,791 functions) and on kolt's client, before/after, in
`perf-baseline.jsonl`'s shape.
