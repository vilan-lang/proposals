# B634 — B457's write summaries are COARSE: any call through a closure VALUE counts as 'may write any cell that is written somewhere', so F135's read() copy (and B457's own) fires for every read() argument beside a closure call - std's hot paths stayed clean only after the derive-span fix; a closure LITERAL's write summary (what its body writes) should stand in for 'any write' where the callee is a known literal

- status: OPEN — filed 2026-10-13 (native-52's Q3, Order 52; integrator)
- kind: analyzer precision (B457's write summaries; S–M)
- area: Language

Where the callee of a later argument is a closure LITERAL (or a let-bound closure whose body is in reach), its write summary is the body's own in-place writes (B457's per-function summary applied to the closure body), not 'any write'; a closure VALUE of unknown origin keeps the conservative answer. Measure: the number of F135/B457 copies on kolt, the website and the corpus before/after (the count is a census line), the emitted JS byte-identical except the copies removed, both differentials green; `ci-local.sh perf` within 0.1%. Pins: a literal that writes the cell (copy kept), a literal that does not (copy dropped), an unknown closure value (copy kept), a let-bound literal. Sizing S–M (analyzer.rs's clone-site summaries).
