# B761 — `Self.field` inside a static function checks clean and throws at run time (`ReferenceError`)

- status: open - filed 2026-11-26 (lane `keys-s1a`'s find; reproduced on `next` @7887a037, before struct keys)
- kind: checker hole + miscompile (JS: a checked program throws)
- area: crates/vilan-core/src/analyzer.rs (member access whose subject is `Self` where there is no `self`)

Repro:

```
struct Meta { owner: str }
impl Meta {
	fun k(): str { Self.owner }
}
fun main() { print(Meta::k()); }
```

`vilan check`: no errors. Run: `ReferenceError: $a is not defined`. `Self` names the type here, and a type is not a value (`let q = Meta;` is refused with "`Meta` is a type, not a value"), so `Self.owner` should be refused the same way.

With struct keys (B711 S1a) `Meta.owner` in that position is a key literal. S1a does not read `Self.x` as a key; whether it should is a small question for the keys work (it would make this program a type error for a different reason: a `Key<Meta, str>` where a `str` is expected). Until then: refuse it. Size S.
