# E116 — a file's platform color does not update when the file becomes reachable

- status: OPEN — owner report 2026-09-01; E113's follow-up
- kind: bug
- area: LSP & tooling
- source: the owner: an unreferenced file defaults to the process layer (E113's fallback — fine), then keeps that color after the import that reaches it is written; a server restart is required

E113 computes reachability per analysis, but the answer for an OPEN
document is evidently cached (or the file's own analysis is not
re-run) when ANOTHER file's import graph changes. The fix: a
`pkg::` reference edit anywhere in the package invalidates the
coloring of every open document in that package (re-publish), the
way a manifest edit already re-colors. Pin: open A (unreached,
process color, a process-View error published), add `import pkg::a`
to the entry, the error clears without a restart.
