# G13 — `dist/` never sweeps a bundled asset the build no longer names

- status: OPEN — audit run 4 finding 2; order-material
- kind: bug
- area: Build & assets
- source: audit run 4 (delta over Orders 19–20), 2026-08-29

`write_bundled` copies and returns names, and no counterpart exists to the
three sweeps beside it (`sweep_stale_chunks`, `sweep_stale_sidecar`,
`prune_and_record_asset_kinds`) — whose own doc comment states the doctrine:
a stale flush in `dist/` SHIPS, which is worse than a missing file. The gap
pre-dates Order 20; Order 20 made it reachable with no source edit and
UNBOUNDED: `read_dir_all` makes a deletion invisible (drop a file from a
listed tree — the copy stays), and the `digest`-minted fingerprint recipe
orphans one copy per save under `--watch` for the life of the session.
`serve_build` routes from the manifest so strays are not routed, but `dist/`
is the deploy artifact — a static host in front of it serves a deleted
`robots.txt` indefinitely. The fix mechanism already exists:
`read_asset_kind_record`/`write_asset_kind_record` extended to bundled names.
The disappearance pin (asset_bundle.rs "disappearance is the same event")
asserts only on the emitted JS today — its `dist/` half is part of the fix.
