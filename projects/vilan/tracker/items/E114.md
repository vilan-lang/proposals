# E114 — gray out unused imports, unused declarations, and unreachable code in the editor

- status: OPEN — owner-proposed 2026-09-01
- kind: feature
- area: LSP & tooling
- source: the owner: "graying out dead code generally looks better to me" (the VS Code treatment other languages get)

The LSP protocol's door is `DiagnosticTag::Unnecessary` on a
hint/information-severity diagnostic — VS Code renders the range
faded instead of squiggled. Three classes, each needing its own
detection honesty:
1. UNUSED IMPORTS — the compiler knows binding uses; an import whose
   every bound name has zero references grays (mind re-exports,
   prelude shadowing, and imports used only in other cfg/platform
   colors — a browser-only use must not gray the name under the
   process analysis, which is E113's coloring done right).
2. UNUSED DECLARATIONS — a private fn/let/struct with no references
   (pub/exported items exempt; entry points exempt; note the
   reachability pruner already computes much of this at emission —
   reuse its answer rather than a second walk).
3. UNREACHABLE CODE — statements after a diverging expression
   (return/panic/never-typed call), the classic post-`return` tail.
Severity posture per the owner: gray, not warn — these should not
enter the diagnostics count or gate anything; they are paint.

## 2026-09-01 — one third shipped (editor-fixes)

Unused IMPORTS gray via `DiagnosticTag::Unnecessary` at hint
severity, appended where the wire payload is assembled so nothing
that counts diagnostics can count it; detection reuses Organize
Imports' answer (same leaf walk), inheriting its honesty and its
conservatism (nothing fades in a stale or broken file). Five pins.
REMAINING: unused private declarations (reuse the emission-time
reachability pruner) and unreachable statements after a diverging
expression.
