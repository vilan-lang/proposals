# M30 — `callee_bindable_generics` scans every impl and every trait's declaration list per call: 857k calls, ~9% of a kolt client check's instructions

- status: OPEN — kolt-benchmark's find (2026-09-04; callgrind of `vilan check src/client.vl` at 289e2a2b, full vs lucide-stubbed)
- kind: performance
- area: Type system & the type solver

`Analyzer::callee_bindable_generics` (analyzer.rs, the B102 bindable
set) is the single hottest named function in a cold client check:
its inlined frames sum to **9.4% of 7.19e9 Ir** with lucide and
**15% of the lucide delta**, at **856,908 calls** from
`analyze_over_world` (the fixpoint re-resolves every call site per
round, so calls ≫ call sites). The cost is not the function's own
work but its two helpers: `impl_binder_generics` does
`self.implementations.iter().find(|i| i.declarations.values().any(|d| *d == member_id))`
— a linear scan over all 417 impls and each one's declaration map —
and `declaring_trait_generics` does the same over `self.traits`.
Both answer a question whose inverse is a map: "which impl/trait
declares this member id" is fixed at registration. On top,
`method_signature` clones `function.parameters` on every call and
`callee_bindable_generics` discards the clone (`(_, own_generics)`).
Orthogonal to M19 (which cuts the ENTITY count; this cuts the
per-call constant), so it pays on `vilan build` and every keystroke
alike. Fix: a `member_id → implementation index` and
`member_id → trait id` reverse index filled where `declarations` are
inserted (or memoized on first miss), and a signature accessor that
borrows. Pin: `impl_binder_generics` is O(1) in the impl count — a
generated program with N impls and one call resolves in the same Ir
for N = 10 and N = 1000; numbers on kolt beside the M19 paper's.
