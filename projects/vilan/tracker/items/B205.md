# B205 — `self.add(self)` written explicitly in a trait default over a supertrait does not resolve: a supertrait member's `Self` is not specialized to the subtrait

- status: OPEN — operators-25 lane's find (2026-09-01)
- kind: bug
- area: Type system & the type solver

`trait Doubler with Add { fun twice(self): Self { self.add(self) } }`
→ two errors: `Expected Doubler, but got Add instead.` at the call
and `Expected Add, but got Doubler instead.` at the argument (text
from `argument_mismatch`, analyzer.rs ~27684). The OPERATOR spelling
`self + self` now dispatches (B193), but the explicit method spelling
remains unwritable: inside a default body, a supertrait member's
`Self` should substitute to the subtrait's `Self`. A refusal, not a
miscompile. Fix in method resolution's `Self` substitution for
supertrait members reached through a subtrait's default body; pin
both spellings side by side.
