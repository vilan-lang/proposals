# C12 — the ban on closures capturing views is documented but not enforced

- status: OPEN — reproduced 2026-08-28 (lifetimes session, semantics leg); lifetimes.md §2.2/S5 owns the decision
- kind: bug
- area: Memory model
- source: probe q05 against 0.38.0, 2026-08-28

`memory.md` says a view "may not be captured by a closure that outlives
the place"; the checker does not enforce it — a closure capturing a view
of a local compiles, can be returned or stored, and reads through the
escaped view (memory-safe today only because JS boxes the place and the
host GC traces it; a use-after-free on any non-GC backend).
`memory-management-impl-plan.md` records the deferral ("capturing an
outer view binding"). Either enforce the sentence (refuse the capture)
or admit and specify it under lifetimes.md §6's liveness extension —
the spec and the checker must stop disagreeing either way.
