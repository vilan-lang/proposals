# M211 — `std::key` in the prelude costs every program about 4.7 M instructions of `vilan check` (+1.86 % on a tiny program, +0.46 % on the website): load it only when a program writes a key or names `Key`

- status: open, an owner question - filed 2026-11-26 (measured by lane `keys-s1a`, B711 S1a)
- kind: performance (compile cost of an ambient std module)
- area: std loading (the prelude), crates/vilan-core/src/analyzer.rs

`Key` is ambient (the struct-keys paper: "nothing to import"), so `std::key` loads for every program. Measured with `perf_count.py`, medians of 5 warm `vilan check` runs:

| Subject | Before | After | Change |
|---|---|---|---|
| A tiny program | 253.01 M | 257.71 M | +1.86 % |
| The website | 8,043.5 M | 8,080.5 M | +0.46 % (inside run-to-run noise) |

Where it goes, each std variant swapped in under one binary:

| Variant | Cost over a std without the module |
|---|---|
| The analyzer change itself (no module) | +0.43 M (+0.17 %) |
| The file on disk, not in the prelude | 0: a module nothing imports is never loaded |
| The three structs only, in the prelude | +0.28 M |
| The full module (7 impl blocks, 15 functions) | +4.0 M |
| The full module with its three loop bodies stubbed | +2.4 M |

So the cost is the impls and functions, not reading or registering the module, and it does not depend on which module they live in. The floor with free bodies is about +1.3 %.

It does not turn a gate red today: the CI budget rows sit 4 to 5 % under their ceilings (`example:math` x0.959 against a limit of x1.005), and the absolute cost is about 1 ms.

Options:

1. Accept it. About 1 ms per check; it is the price of an ambient name with methods.
2. Load `std::key` on demand: when a program writes a key literal or names `Key`. Programs without keys then pay only the 0.17 % analyzer change. Needs on-demand std loading and finding `Key` before name resolution has seen the module. The same mechanism would serve any later ambient std type (`MaybeKey` in S3 will add to this cost).
3. Make the `KeyPath` / `KeyStep` methods compiler intrinsics: saves at most about 1.6 M plus part of the per-function cost, and both backends carry more emitter code.

Rec (the integrator): 1 now, and 2 before S3 adds `MaybeKey` to the same module, since S3 will raise the figure and every program pays it.
