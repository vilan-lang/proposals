# B447 — integer literals inside TUPLES inside a LIST literal are not typed from the expected element type: `total([(0, 3), (7, 11)])` against `total(ranges: List<(usize, usize)>)` → 'Expected List<(usize, usize)>, but got List<(i32, i32)>'; the annotated binding `let one: (usize, usize) = (0, 3);` types fine, so the expected type stops at the list literal's element position

- status: OPEN — filed 2026-09-28 (kolt's search system)
- kind: bug (inference)
- area: Type system & the type solver

Repro (0.41.1):

```vilan
fun total(ranges: List<(usize, usize)>): usize {
	mut sum = 0usize;
	for range in ranges {
		sum += range.1 - range.0;
	}
	sum
}

fun main() {
	let one: (usize, usize) = (0, 3);
	print(i"{total([one])}");              // ok
	print(i"{total([(0, 3), (7, 11)])}");  // Expected List<(usize, usize)>, but got List<(i32, i32)>
}
```

The family of B406/B442/B423 (a literal not typed from its position): here the position is argument → list element → tuple element. Workaround: suffix every literal (`(0usize, 3usize)`). Found writing kolt's search test (`pieces(text, [(0, 3), (7, 11)])`).
