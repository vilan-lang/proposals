# B754 — A closure in a generic struct's literal is checked against the struct's UNSUBSTITUTED parameter: `let r: Reach<Task, Meta> = Reach { borrow = |task| task.meta, .. }` reports "cannot access field 'meta' on type S"

- status: open - filed 2026-11-25 (the struct-keys paper's probes; vilan 0.56.1)
- kind: bug (inference: a closure parameter typed from a generic struct field before the expected type's arguments are applied)
- area: struct-literal checking under an expected generic instantiation; closure parameter seeding

Repro: `proposal/struct-keys-lab/b3.vl`.

```
struct Reach<S, F> {
	borrow: |&mut S| &mut F,
	lend: |&S| &F,
}

let reach: Reach<Task, Meta> = Reach { borrow = |task| task.meta, lend = |task| task.meta };
```

The binding's annotation gives `S = Task`, yet the closure's `task` is typed `S`, and `task.meta` is refused: "cannot access field 'meta' on type S". Annotating the closure parameter (`|task: &mut Task|`) is the workaround.

(The same file's other refusals are correct: a closure's result is a temporary, so `pick(&mut t).owner = "y"` is a lost write.)

Rec: seed a closure field's parameter types from the literal's expected instantiation, as an argument position already does. Pin with one and two type arguments. Size S.
