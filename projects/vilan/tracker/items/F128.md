# F128 — Natively, `.filter(|length| *length > 1)` over a `List<usize>` dereferences the by-value closure parameter (`(*length) > 1usize`): rustc refuses E0614, JS prints the count

- status: OPEN — filed 2026-10-10 (lang-b-49's find, Order 49; placeholder id)
- kind: native backend bug (S)
- area: Native

`["a", "bb", "ccc"].map(|word| word.len()).filter(|length| *length > 1).len()` builds on JS (prints 2) and is refused by rustc natively: the closure parameter is emitted `move |mut length: usize|` while the body keeps the source's `*length`. `filter`'s predicate takes `&T` (a view of a scalar element), the native emitter passes the element by value, and the explicit dereference survives. Either the parameter is emitted as `&usize` or the `*` on a scalar view read is dropped (transparent references R4). Found while pinning B571's native rows (the probe uses `length > 1` instead). Sizing S.
