# F177 — `std::ui` scroll: the doc says a scroll's child never shrinks to the viewport, but nothing enforces it (a text input wrapped, the virtual list works around it)

- status: open
- kind: design question (native UI; layout contract) — OWNER RULING
- area: vilan/std/src/ui.vl (`scroll_style`), crates/vilan-rt-gfx/src/ui (taffy style of a scroll's child)

Flexbox shrinks a child to its container along the main axis by default, and R4 put flex semantics under our own vocabulary. For a scroll that default is never wanted along its scroll axis. QUESTION for the owner: should a scroll force `shrink(0)` on its one child along the axis it scrolls (and remove the two kit workarounds)? Integrator's recommendation: yes; it is the contract the doc already states, and both components built so far needed it. Related open default from P2: `Align` stretch plus shrink 1.
