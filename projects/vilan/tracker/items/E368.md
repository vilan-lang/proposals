# E368 — `vilan test` looks in ONE folder: with no path it scans the manifest's folder (not `src/`), and a folder's subfolders are never searched

- status: OPEN - filed 2026-11-09 (kolt, grouping `src/` into folders)
- kind: gap (CLI: test discovery); the docs say "every test in the project"
- area: Tooling / CLI
- renumbered: filed as E363 on the local branch `kolt-mirror` (kolt-side session); synced to main as E368 on 2026-11-16, because main's E363 is another item. Kolt's sources cited the old number until its v0.56.0 patch.

At kolt's root `vilan test` prints "no `*_test.vl` tests found", since the tests are under `src/`. `vilan test src` ran them while `src/` was flat; once the sources were grouped (`src/client/tasks/`, `src/shared/`, ...) it finds none, and each folder has to be named: `vilan test src/shared`, `vilan test src/client/tasks`, and so on, nine in all with the libraries.

Kolt's workaround is a script that walks the tree and spawns `vilan test <folder>` per folder holding a test (`scripts/src/test.vl`), which itself needs a host binding for `spawnSync` (E365).

Rec: with no path, discover recursively from the package's source root (and, in a `[project]`, in every member); with a folder, search it recursively. Skip `generated` roots and symlinked folders. Report per file as now. Pin: a package with tests two folders deep, run with no argument.
