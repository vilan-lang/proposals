# B372 — INFERENCE — `Signal::new(expr)` as a CLOSURE's result does not fix `T` from its argument: `let inner = n.map(|m| Signal::new(m * 2));` → `the type of 'inner' is never fully determined: SignalCell<SignalCell<T>> keeps its callee's type parameters` — while `n.map(|m| SignalCell::new(m * 2))` and `n.map(|m| Some(m * 2))` both infer, and `let x = Signal::new(0)` at statement level infers. The B162 receiverless trait-default path (`Signal::new` resolves statically to the default body) loses the argument→`T` binding when the call is a closure's return expression

- status: OPEN — filed 2026-09-21 (found probing A123 on 4f990aa2c)
- kind: bug (inference)
- area: Solver

Repro (three files, `scratchpad/andthen/inf{1,2,3}.vl`, on 4f990aa2c):

```vl
let n = Signal::new(1);
let inner = n.map(|m| SignalCell::new(m * 2));   // inf1: compiles, prints 2
let inner = n.map(|m| Some(m * 2));              // inf2: compiles, prints 2
let inner = n.map(|m| Signal::new(m * 2));       // inf3: 'never fully determined: SignalCell<SignalCell<T>>'
```

So the closure-return path is fine (inf1, inf2) and `Signal::new`'s argument binds `T` at statement level (`let n = Signal::new(1)` in the same file); the intersection — the B162 receiverless default in return position — is what fails. Annotating the binding (`let inner: SignalCell<SignalCell<i32>> = …`) makes it compile and run, which is the workaround and the diagnostic's own advice, but `Signal::new` is the documented everyday spelling (the `Signal` trait doc: 'the everyday spelling … resolves statically to this default body') and it must infer wherever `SignalCell::new` does.

Hypothesis (verify): the B162 static resolution substitutes the default body's signature `fun new(value: T): SignalCell<T>` with a FRESH `T` when the call has no expected type (a closure body's return has none until the closure's `U` is solved from it), and that fresh `T` is never unified with the argument's `i32` — `SignalCell::new` goes through the ordinary inherent-call path which does unify. Pins: inf3 compiles and prints `2`; the same inside a `combine(...).map(|(a, b)| Signal::new(a + b))`; the existing B162 pins unchanged.
