# E103 — the `Some`-import steer is lost when the `Option` arrives through a `List` method

- status: OPEN — found by the prelude census (Order 21, lane prelude-paper), reproduced
- kind: bug
- area: Diagnostics
- source: prelude.md's census probes, 2026-08-29

`cannot find 'Some' in this scope` carries its import steer for a bare
`Some(1)` and for values reached through `std::iterator`/`map`/`result`
imports — and arrives with NO steer when the `Option` was minted by a `List`
method: `list.get(1)` hands back an `Option`, the `match` arm writes `Some`,
and the diagnostic names the missing name without the one-line fix every
sibling path offers. Reproducible; mechanism unconfirmed (the lane did not
dig). The standing rule applies: fix the CLASS (whatever distinguishes the
steer-carrying paths from this one), not the symptom. Note the prelude
angle: under B156's recommended default set, `Some` is ambient and this
steer retires — but the class may cover other names the prelude never
carries, so the fix stands on its own.
