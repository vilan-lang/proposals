# M138 — `async_infer::compute_adaptation` runs twice per analysis over every function as an (f, ∅) instance key (4,585 keys, 2 × 11 ms on kolt's client leg) and is the async pass's remaining whole-program cost after M110 S3b seeded the base fixpoint — a seeded form must carry the cold instances, their origins and diagnostics in the record

- status: OPEN — filed 2026-10-10 (incr-50's find, Order 50)
- kind: performance (M)
- area: Performance & footprint

The outer loop of `infer` re-runs the base fixpoint and the adaptation until the async set stops growing; on kolt the first adaptation always grows it (an adapted instance is async), so both run twice. S3b seeds the base fixpoint from the record's cold result (hot callees unknown) and derives the initializer refusals before `reachable_bindings` (30 ms) so the walk runs only when a refusal exists; the adaptation stayed whole-program: its result is per instance `(callee, bits)` with origins and diagnostics, and a cold instance reached only through a hot caller's closure bits is minted by that caller. Design: record the cold instances computed over the cold nodes alone, seed `instance_async` from them, and iterate from the hot keys and the dependents of any key whose verdict moved. Sizing M.
