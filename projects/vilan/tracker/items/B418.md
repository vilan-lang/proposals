# B418 — MISCOMPILE — copy elision on JS is wrong when a `read()` reaches a binding through a BRANCH or an ARGUMENT (B400's sibling): `let b = if flag { s.read() } else { [] }` and its `match` twin alias the LIVE list, so a later `s.write().push` shows through `b` (JS 4, native 3); a `.read()` passed BY VALUE to a `fun` or a closure that writes the cell sees the write (JS 6/5, native 5/4). It bit collections-42's first A129 draft silently (the `if` form dropped M86's copy pin from 11 to 6); std was re-spelled to not depend on it

Fix: a consumed read reaching a binding through a branch arm or an argument position is copied like the direct case (B267's walk covers the arms and the call arguments); differential pins on both shapes. Sizing S–M; solver.
