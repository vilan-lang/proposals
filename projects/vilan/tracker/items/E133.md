# E133 — the reference index is end-exclusive: rename and find-references miss with the caret at `name|`

- status: OPEN — the owner's find while migrating kolt (2026-09-04); reproduced at 289e2a2b by the triage lane with a fix verified green
- kind: bug
- area: Language server & tooling

`let value = 1;` name span 23..28: at offset 27 `index.at` = Some, rename
edits 2; at offset 28 `index.at` = None → `rename_edits` =
`Err(NotAnIdentifier)`, which `prepare_rename` (main.rs ~2878–2905)
turns into `Ok(None)` — VS Code's "can't be renamed" notice instead of
the rename box. Hover at the end is None too (a separate end-exclusive
check, `offset_touches_a_token` document.rs ~2220).

Cause: `ReferenceIndex::at` (references.rs ~565–573) is `start <= offset
&& offset < end`. The same `at` backs find-references, so `name|`
misses there too; only rename makes it visible because renaming is
caret-driven. The editor convention (hover/definition/rename) treats a
caret at the end of a word as on the word.

Fix (S, verified 564/564): after the strict-containment miss, fall back
to the row immediately before the partition point when `row.source ==
source && row.span.end == offset && row.span.start < offset` — rows are
identifier-exact and non-nesting, so at most one row ends there.
Extend the same convention to `offset_touches_a_token` for hover.
Pin: the lane's `issue2_rename_refuses_with_the_cursor_at_the_end_of_
the_name` in scratch `triage27/lsp-sync/repro.rs`. Related: the
kolt.local 002/003/034 lineage in references.rs's module doc.
