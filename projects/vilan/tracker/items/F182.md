# F182 — `std::ui` after the kit wiring: what F176, F177 and the clipboard keys leave open or decided in lane

- status: open
- kind: follow-ups (native UI; kit)
- area: vilan/std/src/ui/kit/{editing,inputs,text_areas}.vl, vilan/std/src/ui.vl, vilan/std/src/gfx.vl, crates/vilan-rt-gfx/src/host/{input,clipboard}.rs

DECIDED IN LANE, owner may overrule: the blink is 530 ms on and 530 ms off, only while the input, enabled, has the focus in a focused window (an unfocused window shows the caret steadily); auto-scroll steps every 100 ms within 25 dp of the edge, 50 ms from 25 dp, 33 ms from 50 dp, 25 ms from 75 dp; pasted line breaks become spaces in the single-line input and `\n` in the text area; Ctrl+Insert, Shift+Insert and Shift+Delete also copy, paste and cut; copy and cut with an empty selection do nothing and bubble; a `Both`-axis scroll is a grid with one max-content cell; the new PUBLIC names `std::ui::advance_clock(by)` (stops and steps the timers' clock, for recorded listings), `std::ui::timer_count()`, `TextInput::caret_shown()`, `TextArea::caret_shown()`, `std::gfx::use_memory_clipboard()` (an in-memory clipboard behind the same host worker, for `--check` modes). QUESTION worth the owner's eye: three of those are test seams in the public surface (`advance_clock`, `timer_count`, `use_memory_clipboard`); they could move under a `std::ui::testing` module before a release documents them. HOST FIX that rode along, affecting real use: a key pressed with Ctrl or Super also typed its letter (winit's `KeyEvent::text` leaves Ctrl in), so Ctrl+A selected all and then replaced it with `a`; such a key now types nothing unless Alt is also held (Windows reports AltGr as Ctrl+Alt): reasoned from winit's documentation, NOT run on Windows. NOT VERIFIED: Windows and macOS at run time; under xvfb a focused input now draws a frame every 530 ms, by design.
