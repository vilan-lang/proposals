# B758 — A GENERIC view return used at a scalar is wrong on JS: with `fun same<T>(x: &mut T): &mut T borrows x { x }`, `same(&mut n) = 2` is lost and `*same(&mut n)` prints the pair (`1,0`); native is correct, and a struct instantiation works on both

- status: FIXED 2026-11-26 on lane `b758-generic-view-return` @a40ae486, merged to `next` @1c253119, PUSHED 2026-11-26 @7887a037 (not released) - filed 2026-11-25 (lane `b753-view-return`'s find; pre-existing, the written `&mut x` tail behaves the same)
- kind: miscompile (JS: a write through a returned view is lost; a read prints the view's representation)
- area: the JS view protocol for a generic pointee (B506's rule: a caller reads a returned view by the DECLARED pointee, and `T` is never a scalar); crates/vilan-core/src/transformer.rs

Repro: `proposal/struct-keys-lab/generic_scalar_view_return.vl`. Expected (and native): `2 / 2 / b / 4`. JS: `1 / 1,0 / a / 3`.

The callee hands back what the instance makes: at `T = i32` that is the `(base, key)` pair the caller passed in. The caller decides how to read the result from the declared return type `&mut T`, and a type parameter is never read as a scalar, so it treats the pair as the aggregate itself. B753 fixed the non-generic case (a named place under a view return) and pinned the generic one at a struct.

Why it matters: it is exactly the accessor struct keys rest on. `fun at<F>(s: &mut S, k: Key<S, F>): &mut F borrows s { s[k] }` is generic in the field type, and a field is a scalar as often as not (B711 S1, paper §3.2). S1 either needs this fixed first or must make `s[k]` under a generic `F` not go through this protocol.

Rec: decide the scalar-ness of a returned view at the INSTANCE (the caller knows `T = i32` at the call site, as emission is per instantiation), so both sides agree; pin `i32`, `str`, `bool`, a backed enum and a struct, read and write, tail and written `&mut x`. A protocol change on both sides of a call: size M. Goes before B711 S1, or with it.

2026-11-26 (the integrator): FIXED locally. JS does emit a generic per instantiation (`emit_instance_with_bits`; byte-identical bodies are then shared), and a generic function has no value of its own, so every caller knows the instance. Both sides now decide there: the caller reads a bare-view call's result as the pair exactly when the callee's return pointee is a scalar under the call's binding (`view_call_is_scalar`, which absorbs the old `get_or_insert` special case), and the analyzer no longer fixes the return leaves of a bare-view function at the generic body's verdict (`compute_fixed_view_refs`). By-value and wrapped-view returns, non-generic view returns and the native backend are unchanged; no golden moved. A second face of the same defect is fixed with it: `fun inner<T>(b: &mut Box<T>): &mut T borrows b { b.value }` handed back the field's VALUE at a scalar `T` (the shape B711 S1's accessor has).
