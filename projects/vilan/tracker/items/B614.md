# B614 — A non-Wire `[derive(Wire)]` field (tuple, array, closure, or a plain non-Wire struct) and a NOMINAL non-Wire `[rpc]` parameter are refused by the boundary check and then restated by the generated code at the attribute — "Password has no method 'describe'", "cannot find 'rebuild' in Password", "(i32, i32) has no method 'describe'", "this expression cannot be used as a type" (a closure field emitted bare)

- status: OPEN — filed 2026-10-12 (tools-51's find, Order 51)
- kind: diagnostics (derive/macro; S)
- area: Services & rpc

E296 stood the `[service]` attribute's generated-code diagnostics down for a tuple/array/closure/view `[rpc]` type (reusing B490's `rpc_opaque_return_origins` filter at the end of `analyze`), and B597 fixed the `_` quote. What is left is the same restatement for (a) every `[derive(Wire)]` field the boundary check refuses — the derive's generated `describe`/`rebuild` bodies fail at the derive attribute for each refused field, 3-4 extra errors at a span the author did not write, for nominal types as much as for tuples — and (b) a nominal non-Wire `[rpc]` parameter (`fun a(self, p: Password)` draws "Password has no method 'describe'" at the attribute beside the signature refusal; B303's stand-down covers only the bound-failure path). Fix: record the derive's origin (the `derived_origins` row of the Wire impl) in the same stand-down set when `check_wire_boundary` refuses a field, and widen E296's origin insert from non-nominal forms to every refused `[rpc]` type; the closure-field case also needs the Wire derive to stop emitting a closure type bare in expression position (std/json.vl's derive). Pins: one error per refused field/parameter. Sizing S; analyzer core (check_wire_boundary, the rpc signature check, the final filter).
