# B670 — a method call on an arithmetic result of a closure parameter is refused: "cannot call method 'round' on unknown"

- status: OPEN — filed 2026-10-22 (kolt's image zoom: the footer's "250%")
- kind: checker / inference (S)
- area: language / types

```vilan
import std::reactive::MemoCell;

fun a(scale: SignalCell<f64>): MemoCell<f64> {
	scale.derive(|value| value.round()).memo()            // fine
}

fun b(scale: SignalCell<f64>): MemoCell<f64> {
	scale.derive(|value| (value * 100.0).round()).memo()  // refused
}

fun c(scale: SignalCell<f64>): MemoCell<str> {
	scale.derive(|value| i"{value.round()}").memo()       // fine
}
```

→ `Error: cannot call method 'round' on unknown` at `.round()` in `b` (web prelude, v0.52.0).

The parameter's type is known in the closure body (`a` and `c` call methods on it directly), but the type of `value * 100.0` is not, so a method call on the product finds nothing. Writing the parameter's type (`|value: f64|`) fixes it.

Recommendation: resolve a binary operator's result type once its operands are known from the receiver, before the method lookup on it; if that has to wait, defer the lookup rather than settle on `unknown`.
