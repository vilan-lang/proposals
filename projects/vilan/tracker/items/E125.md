# E125 — `semanticTokens/range` answers in ANALYZED coordinates while `full` answers the live buffer through the keystroke path's anchor

- status: OPEN — e122-fold lane's find (2026-09-01); a keystroke-path design call
- kind: editor
- area: Language server & tooling

After E121 §2.1 and E122's fold, `semanticTokens/full` (and its
delta) re-serve the landed capture through the two-sided edit
anchor — positioned against the LIVE buffer; `semanticTokens/range`
serves the same capture by line index but in the ANALYZED snapshot's
coordinates. A client that uses range requests (VS Code does, for
viewports) sees tokens drift on the lines below an edit until the
next analysis lands — the drift the keystroke path exists to remove.
Decide and build: route range through the same anchor (an Exact
verdict re-maps the window's landed spans; Stale/Unusable degrade as
full does) so both requests answer one picture. Pin: a range
request after an unlanded edit above the window agrees byte for
byte with full's window. Predates the fold; left because it changes
what a range response is positioned against.
