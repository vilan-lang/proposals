# B760 — Native: a view return that borrows one of TWO view parameters emits no lifetime (`fun pick(x: &mut i32, n: &mut i32): &mut i32 borrows n`), so rustc refuses it (E0106); JS is correct

- status: FIXED on `next` locally 2026-11-26 (lane `keys-s1b` @29dc7b69, merged @e43933b0; not pushed) - filed 2026-11-26 (lane `b758-generic-view-return`'s find; pre-existing on `next` @a510e123, concrete, not B758)
- kind: backend defect (native: a checked program is refused by rustc)
- area: crates/vilan-rust (signatures of `borrows` functions)

Repro:

```
fun pick(x: &mut i32, n: &mut i32): &mut i32 borrows n { n }
fun main() {
	mut z = 0;
	mut n = 1;
	pick(&mut z, &mut n) = 3;
	print(n);
}
```

JS prints `3`. Native emits `fn pick(x: &mut i32, n: &mut i32) -> &mut i32`, and with two reference parameters Rust's elision has no answer: `error[E0106]: missing lifetime specifier`. With one view parameter elision happens to give the right signature, which is why this went unseen.

The `borrows` clause already names the source. Rec: when a function has more than one reference-typed parameter and a view return, emit a named lifetime on the `borrows` source and the return (`fn pick<'a>(x: &mut i32, n: &'a mut i32) -> &'a mut i32`). Size S.

Why it matters beyond the repro: struct keys' accessors (B711) take the state by view and may take a second view argument.

2026-11-26 (the integrator): FIXED by the struct-keys native lane, whose two-view accessor (`fun from_left<F>(left: &mut Task, right: &Task, k: Key<Task, F>): &mut F borrows left`) met it. `name_the_borrowed_lifetime` in `crates/vilan-rust/src/lib.rs`: when a bare view return has two or more reference parameters, the borrowed ones and the return share the named lifetime `'v`. The repro above prints `3` natively; pinned by `keys_borrowed_lifetime.vl`. Not covered: a view inside a returned payload (`Option<&mut T>`). Not verified: an `async fun`.
