# B553 — an `impl` written in the ENTRY file is invisible to every MODULE's method resolution — `Foo has no method 'greet'` from `user.vl` when `impl Foo with Greet` sits in `main.vl` — while the same impl in ANY module serves every module, imported or not (i3); and a module's `Context::new()` whose only `run` is in the entry reports `T` unbounded

- status: OPEN — filed 2026-10-05 (incr-47's find, Order 47; met building M110 S1)
- kind: semantics (M) — analyzer, a canonical-order asymmetry
- area: Language & type system

Repro (vilan 0.44.0 + incr-47, `vilan check src/main.vl` in a package): `shapes.vl`: `export struct Foo { n: i32 }` / `export trait Greet { fun greet(self): str; }`; `user.vl`: `import pkg::shapes::{ Foo, Greet }; export fun use_it(): str { let foo = Foo { n = 1 }; foo.greet() }`; `main.vl`: `import pkg::shapes::{ Foo, Greet }; import pkg::user::use_it; impl Foo with Greet { fun greet(self): str { "hi" } } fun main() { print(use_it()); }` -> `Foo has no method 'greet'` at user.vl:5. Move the impl into any module (`impls.vl`, imported by main only) and it checks clean. Second shape: `c.vl`: `import std::context::Context; export let flavor = Context::new(); export fun read_it(): i32 { flavor.get() + 1 }`; `main.vl`: `flavor.run(5, || { print(read_it()); })` -> "`+` on `T` needs `T: Add` … `T` is unbounded" at c.vl:6; with the `run` in a sibling module it is clean. Cause: modules RESOLVE before the entry walks (the base cache's pre-entry world), so anything only the entry contributes to a module's resolution — an impl, a context's first `run` — arrives after the module committed. The language says impls are program-wide (no orphan rule) and a context takes its type from its first run; the entry is the one file for which neither holds. Doors: (a) defer a module's failed member lookups and ungrounded element slots to the post-entry `build()` instead of committing them pre-entry; (b) state the asymmetry in the spec and refuse an entry impl on a foreign type. This is also what bounds M110 S1 (the hot set behaves like the entry): S1's impl and use-inferred-binding guards exist because of it. Sizing M.
