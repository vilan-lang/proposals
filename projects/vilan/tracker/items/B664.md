# B664 — "cannot find trait 'PartialEq'" for an `impl X with PartialEq` that never imported the trait has no source location, or borrows an unrelated span in another file

- status: OPEN — filed 2026-10-20 (kolt's toast.vl: `impl ToastAction with PartialEq` without `import std::compare::PartialEq`)
- kind: diagnostic (checker; S)
- area: language / checker

A three-module package (`vilan check .`):

```vilan
// src/notes.vl
export *;
struct Action { label: str }
impl Action with PartialEq {
	fun eq(self, other: Action): bool { self.label == other.label }
}
fun note(): Action { Action { label = "x" } }

// src/other.vl
export *;
fun speed(): i32 { 90 }

// src/main.vl
import pkg::other::speed;
import pkg::notes::note;
fun main() { print(i"{speed()} {note().label}"); }
```

→ `Error: cannot find trait 'PartialEq'; import it first (import std::compare::PartialEq;)`, with no file, line or span at all.

In kolt, the same mistake in `src/toast.vl` was reported in `src/views.vl` at `import pkg::prefs::motion_ms;` (line 25), a span in a different file with nothing to do with the trait. That cost a detour: the reported location looked like the cause.

The derive path in the same file reported its own error with the right span (`in code generated by this attribute: 'ToastAction' does not implement trait 'PartialEq'` at `toast.vl:20`). The `impl … with Trait` header lookup is what loses its span. It seems to fall back to "no span", or to whatever span the resolver held last.

Recommendation: report the unresolved trait at the trait name in the `impl … with` header of the file that wrote it.
