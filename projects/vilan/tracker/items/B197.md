# B197 — an operator impl with no method compiles clean and panics naming nothing

- status: OPEN — audit run 7's F12 (2026-09-01)
- kind: bug
- area: Type system & the type solver
- source: audit run 7; `vilan/std/src/operators.vl:31-35`

`impl P with Add { }` satisfies the refusal "add `impl P with Add`
providing `add`" without the providing half: `check` clean, `run` →
uncaught `not implemented yet` — no type, no method, no span. The
panicking defaults are deliberate (`ret-checking.md:150`), so the
missing-method check can never fire for the operator family. Least:
the panic names the type and the method. Better: an operator trait's
required method is required at impl time (the defaults exist for
`+=`-family derivation, not to let `add` go unwritten) — rule which.

## 2026-09-01 — the owner accepted the ruling queue; recommendation adopted

An operator trait's required method is REQUIRED at impl time (the
panicking defaults exist for the compound-assignment derivation, not
to let `add` go unwritten); until that lands, the panic names the
type and the method. Order 25's operators tail.
