# B466 — `*view` of an AGGREGATE does not COPY on JS: `mut c: P = *v; c.x = 99;` writes 99 into the CALLER's value, and a snapshot `Some(*v)` changes with the next in-place write — rule 1 (a binding copies) is broken at a dereference; native refuses the emitted Rust

- status: OPEN — filed 2026-09-29 (Order 44, papers-44's find 3); HIGH
- kind: bug (UNSOUND on JS — value semantics; native refuses the emitted Rust)
- area: Type system & the type solver

A dereference of a view is a place the binding does not own, so binding it (or wrapping it) copies — the elision pass must not treat `*v` as the binding's own storage. Pin: mutate the copy, read the original; snapshot, write in place, read the snapshot; both backends. Sizing S; solver, FIRST in its batch (unsound).
