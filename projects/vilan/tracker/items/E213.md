# E213 — an attribute that marks an item INTERNAL-BY-MEANING — hidden from completion and GRAYED where it does appear — distinct from declaration visibility: it says 'be careful and know what you are doing with this' even to a first-party consumer in the same package. The owner's ask (2026-09-21); spelling proposed `[doc(internal)]` 'or something similar'

- status: OPEN — filed 2026-09-21 (the owner's ask, mid-Order 39)
- kind: design + editor
- area: LSP & tooling

What it means: visibility answers 'may this module NAME it'; this answers 'should a reader reach for it'. The motivating exhibit is std's own: `std::ui`'s `Region` exports `anchor`, `cut_row`, `insert_row`, `open_row`, `drop_row`, `hold_rows` because `each` and user-written `Slot` impls legitimately need them (kolt's `lib/conditional_value.vl` uses `region.anchor` and `cut_row`) — they are public on purpose and dangerous on purpose (a row moved without `hold_rows` corrupts the reconciler's view). Other candidates: `reactive::register_with_owner`, `defer_to_turn`, `Shared::read`'s place semantics, `style::raw`, `rpc::call`/`call_ack`, the `__`-free plumbing names A117 found in `std::style::prelude`.

Behaviour: (1) COMPLETION omits it unless the prefix already matches it exactly or the user invoked completion twice / a setting asks (rec: shown only on an exact-prefix match of 3+ characters, sorted last, with the label's reason in `detail`); (2) SEMANTIC TOKENS gray it at every use (a `deprecated`-like modifier — but NOT strikethrough; a new `internal` token modifier the themes map to a dimmed colour); (3) HOVER leads with the attribute's reason line; (4) the docs generator lists it under a collapsed 'Internal' heading; (5) NO diagnostic by default — it is a label, not a lint; an opt-in `[lints] internal_use = "warn"` for packages that want one. It applies to functions, methods, fields, structs, enums, variants, traits, module bindings; a FIELD is the case visibility cannot serve at all today (vilan has no per-field visibility).

Spelling to rule: `[doc(internal)]` (the owner's); `[internal("reason")]` with a REQUIRED reason string (rec — `[deprecated("use …")]`'s shape; the reason is what hover shows, and a label with no reason is how these rot); or `[advanced]`. It must not collide with the retired `[doc(hidden)]` steer, whose refusal text should then mention this attribute as the OTHER thing someone might have wanted.

Pins: completion omits/sorts it; the token modifier at a use and at the declaration; hover's first line; a field; the docs page; `[doc(hidden)]`'s refusal names the new attribute; formatter + grammar_sync + the EBNF.
