# A34 — a typed style token has no MID-VALUE spelling in a css block

- status: OPEN — surfaced by b148's census (Order 22); a real gap the new
  refusal reveals rather than creates
- kind: design
- area: Reactive core & UI
- source: lane b148's census hit 3, 2026-08-29

`border: 1px solid {Color::gray(500)}` — the idiomatic mixed value — was
silently emitting `1px solid var(--gray-500),:root{--gray-500:#6b7280}`
INTO THE DECLARATION: invalid CSS a browser drops, invisible to the one
test that met it (it compares two builds of itself). With B148's refusal
the spelling errors instead — but no correct spelling EXISTS: `.text`
reaches the var reference and drops the `:root` token line the one-hole
path carries (the exact hazard css-block S1 closed for whole values). The
design ask: a mid-value hole that carries its token's root line — the
value-assembly path learning what the single-hole path knows. Pinned as a
gap in styling.rs by the lane.
