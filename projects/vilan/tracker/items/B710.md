# B710 — A closure inside `Some(...)` doesn't take its parameter types from the expected `Option<|..|>` type

- status: OPEN - filed 2026-11-04 (kolt)
- kind: bug
- area: Type solver / closures

A closure literal whose parameters its body doesn't settle gets them from the expected type when it stands alone, but not when it's wrapped in `Some(...)`. Writing it in a typed field or binding doesn't change that. The error says the closure is "never called", which isn't the cause:

```
Error: `a` is never given a type: this closure is never called and its parameter is unannotated; annotate it (e.g. `|a: List<i32>|`)
```

Kolt met it while building a debug check stored as `check: Option<|List<T>, List<T>, Event| Option<str>>` and assigned as `root.check = Some(|before, after, event| explain(before, after, event))`. The fix there was annotating all three parameters.

Repro (0.54.0): kolt session scratchpad `someclosure/main.vl`.

```
struct Holder {
	check: Option<|List<i32>, List<i32>| bool>,
}

fun same_len<T>(a: List<T>, b: List<T>): bool {
	a.len() == b.len()
}

fun main() {
	mut held = Holder { check = None };
	held.check = Some(|a, b| same_len(a, b));                               // error
	let direct: Option<|List<i32>, List<i32>| bool> = Some(|a, b| same_len(a, b)); // error
	let bare: |List<i32>, List<i32>| bool = |a, b| same_len(a, b);          // fine
	if held.check is Some(let check) {
		print(i"{check([1], [2])} {bare([1], [2])} {direct.is_some()}");
	}
}
```

The first two lines report both parameters; the third compiles. A body that settles the types itself (`|a, b| a.len() == b.len()`) hides the bug, which is why it shows up only when the body passes the parameters to a generic function.

**Expected:** a variant constructor's payload gets the expected type's payload type (`Option<F>` → `F`), the same way a bare closure gets `F`.
