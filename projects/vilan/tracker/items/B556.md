# B556 — a file addressed by a bare relative path from inside its package — `cd src && vilan check main.vl` (or `../main.vl` from deeper) — is compiled as if it belonged to NO package: `owning_package` asks `Path::new("main.vl").parent()` = "" and finds no manifest, so the package's prelude, std and source root are ignored

- status: OPEN — filed 2026-10-05 (papers-47's find, Order 47)
- kind: CLI bug (S)
- area: LSP & tooling

Repro: a package with `prelude = "std::web::prelude"` and `src/main.vl` using `Signal`. From the package root `vilan check src/main.vl` -> no errors; from `src/`, `vilan check main.vl` -> "cannot find type 'Signal'; ... set `prelude = \"std::web::prelude\"` in vilan.toml" (the edit already made); `vilan check $PWD/main.vl` -> no errors; from `src/deeper/`, `vilan check ../main.vl` fails the same way (find_project_root walks ".." then "" and stops). kolt's server fails from `src/` with a `[service]` expansion error ("cannot infer 'T' ... ': Wire'"); every example package's server/main does too. Same in the installed 0.44.0. vilan-cli main.rs:3826-3832 (`owning_package`); `std_dir` (:5969) already canonicalizes. Fix: absolutize the entry (or map an empty parent to ".") before the manifest walk; a pin that runs check from inside src/. Sizing S.
