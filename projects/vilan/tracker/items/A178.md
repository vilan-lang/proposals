# A178 — `Length` is its CSS text, so lengths can't be computed with, converted, or chosen per property

- status: RULED 2026-10-31 - `proposal/length.md` APPROVED as written (lane-ready; Order 56 std lane: S1 + S2; S3 = kolt's codemod, the owner's)
- kind: design (std::web::style; M)
- area: Reactive core & UI — styling

`std::web::style::Length` is `{ text: str, root: str }`: `Length::px(8)` stores `"8px"`, and nothing can read the number or the unit back. So an app can't add two lengths, scale one, convert px to rem, compare them, or let a property decide how to write one. Everything that needs a value has to stay a bare `f64` until the last moment and be turned into text at the call site.

What that does to an app, measured in kolt (2026-10-31, `src/` excluding generated code):

- `rem(n / 16)` — design pixels hand-converted to rem at each call: **590** uses in 36 files (279 of them are literally `4 / 16` or `8 / 16`).
- `rem(name / 16)` — named spacing constants (`styles::row_gap`, `group_inset`, `bar_inset`) kept as `f64` **because** a `Length` can't be operated on: 23 uses. The constants exist but are used only 22 times; literals win because the constant buys nothing at the call site.
- `px(n)` 85, `Length::rem`/`Length::px` 54, a `Scale` call (`size(n)`, kolt's B340 customer: `Length::rem(self.unit * n)`) 60, and about 70 lengths written straight into CSS strings.

Five spellings of one idea, and the `/ 16` is a hack: it encodes "16px = 1rem" at hundreds of sites.

## Proposal

1. **A length is data:** `struct Length { value: f64, unit: Unit }` (`Px`, `Rem`, `Em`, `Pct`, `Vh`, `Vw`, plus `Token(name)` / `Raw(text)` / `Calc` for what isn't a number), rendered at the edge as today. `css_text` keeps its contract.
2. **Arithmetic and conversion:** `Add`/`Sub` between same-unit lengths, `Mul`/`Div` by `f64`, `Length::px(8).as_rem()` and `.as_px()` against a root size (16 by default, settable once per app), comparison. Mixed units fall back to `calc()`.
3. **Unit by property, unless stated:** a *design length* (`Length::design(8)`, or `px(8)` if the owner prefers that to mean it) carries no unit preference; each property renders it in the unit that suits it — `rem` for spacing and sizing (`padding`, `margin`, `gap`, `inset`, `width`, `height`, `font-size`) so it follows the user's text size, `px` for hairlines (`border-width`, `outline-width`, `box-shadow` offsets, `outline-offset`). An explicit `Length::rem(..)` / `Length::px(..)` is never re-unitized. The table lives in std beside the property builders, so `padding(space(2))` and `border(px(1), ..)` both do the right thing with no `/ 16` anywhere.
4. **Tokens stay first-class:** `space(2)` (`var(--space-2)`) and a Scale like kolt's keep working; a scale can now return data the caller can still adjust (`size(2) + px(1)`).

Customer: kolt's spacing cleanup (Kolt task "Spacing: one spelling for lengths") is waiting on this rather than building a parallel length type it would throw away. Related: A8 (styling tail), A106 (the style vocabulary outside a css hole), B340 (the Scale call operator).
