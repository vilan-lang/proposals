# E355 — A repeated `[derive]` is a parse error that doesn't say so ("expected `;`", or "cannot find 'derive'")

- status: OPEN - filed 2026-10-31 (kolt)
- kind: diagnostic
- area: Parser / diagnostics

Writing the same attribute twice over one item (easy to do when an edit adds a `[derive(PartialEq)]` that was already there) isn't reported as a repeated attribute. Standalone, the second line is "expected `;` to end this statement", pointing at the end of the attribute. Inside kolt's `src/lib/rich_text/controller.vl` (a struct between other items) the same mistake came out as four errors, none naming the cause:

```
Error: cannot find 'derive' in this scope; import it first (`import std::reactive::derive;`)
Error: cannot find 'PartialEq' in this scope; import it first (`import std::compare::PartialEq;`)
Error: cannot find 'derive' in this scope; ...
Error: cannot find 'PartialEq' in this scope; ...
Error: expected `;` to end this statement
```

The import suggestions send the author the wrong way: `derive` is an attribute, not something to import. A valid stack (`[derive(PartialEq)]` then `[deprecated("…")]`) parses and runs, so the parser does know attribute stacks; it seems to read the repeated one as an expression statement.

Repro (standalone): kolt session scratchpad `derive/twice.vl`, the whole file:

```
[derive(PartialEq)]
[derive(PartialEq)]
struct Pair {
	left: i32,
	right: i32,
}

fun main() {
	print(Pair { left = 1, right = 2 } == Pair { left = 1, right = 2 });
}
```

Recommendation: read a stack of attributes whatever it holds, then refuse a repeated one by name ("`[derive]` is written twice over `Pair`: merge them, `[derive(PartialEq, Json)]`"), the way B536 refuses attributes out of order. Sizing XS.
