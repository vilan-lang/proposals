# A36 — `Style::when(condition, delta)` — the conditional-merge combinator

- status: OPEN — RULED ACCEPTED 2026-08-31 ("change the ruling on
  `Style::when` to accepted and let it be lined up for a future work
  order"); ready to queue
- kind: feature
- area: Reactive core & UI (`std::reactive`, `std::ui`)
- source: style-variants.md §8 Q3, ruled after the owner's own 015
  exploration, 2026-08-31
- see-also: proposal/style-variants.md §6, kolt.local 015

The accepted surface, exactly the note's P15 shape — five lines, no
emission; `when` never constructs a style, it selects between two
already-built ones, so the construct-in-const rule is untouched:

```vilan
impl Style {
	fun when(self, condition: bool, delta: Style): Style {
		if condition { self + delta } else { self }
	}
}
```

Provenance: the owner arrived at the combinator independently (spelled
`toggle`) while trying their own variants system against the 015
exhibit, and prefers the chain spelling for readability; the accepting
message names it `Style::when`, so `when` is the recorded name.
Probe-verified 2026-08-31 against 0.39.0 (2ad39dd09): the user-code
impl compiles as written (inferred return type included), and the chain
spelling of the exhibit produces class lists byte-identical to the
shipped `button_style` at all four state cells.

Two lines of guidance from the ruling discussion for the building
lane's doc comment / guide sentence:

- The chain reads best when each condition mentions its own flag
  (independent state axes). When one `when`'s condition must mention
  another's flag (`!selected && !disabled`), the states interact and
  `match`/`if` states the exclusivity structurally — the compound
  condition is the tell, documented as guidance, not a prohibition.
- When two `when`s both fire, the later delta wins overlapping
  properties — chain order is precedence, exactly as with `+`. The doc
  comment should say so.
