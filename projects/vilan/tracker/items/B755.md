# B755 — `*` on a value that is not a view type-checks: `Some(*cell.read())` (where `Shared::read()` returns a `T`) ALIASES the cell on JS, so a later in-place write shows in the "copy", and rustc refuses it natively (E0614)

- status: open - filed 2026-11-25 (the struct-keys stand-in lab; vilan 0.56.1)
- kind: miscompile (JS: an aggregate is shared where the program reads as a copy) + checker gap (`*` accepted on a non-view) + backend defect (native)
- area: the checker's `*` rule (B749's "a view's value is explicit: `*v`"); JS copy insertion at an `own`/aggregate position under a `*`

Repro: `proposal/struct-keys-lab/standin/trials/src/t2a_deref_alias.vl`.

```
let state = Shared::new(U { tags = ["a", "b"] });
mut old: Option<U> = None;
old = Some(*state.read());
state.write().tags.insert(0, "z");
// old's tags: 3 on JS (want 2); rustc: E0614 type `U` cannot be dereferenced
```

Without the `*` both backends copy (`t2_copy_shared.vl` beside it). So the `*` does two wrong things on JS: it is accepted on a value, and it suppresses the copy that the bare read gets.

Rec: refuse `*` on an expression that is not a view ("`*` copies a view's value out, and this is already a value"), with the fix-it of removing it; and independently make sure a `*`'d aggregate is copied where the un-starred one is. Pin both backends. Size S. Related: B749/B685/B750 (scalar views consumed as values), B751.
