# B654 — A triple-quoted string as an ATTRIBUTE argument does not parse, and the diagnostics do not say so: `[extern("""…""")]` reports "cannot find 'extern' in this scope" at the attribute name and "expected `;` to end this statement" at the closing `)]`

- status: OPEN — filed 2026-10-19 (kolt's rich text editor, binding a ~40-line JS helper through `[extern(..)]`)
- kind: diagnostics / grammar (parser; S)
- area: Language

```vilan
[extern(
	"""
	(() => 1)
	"""
)]
external fun one(): i32;
```

vilan 0.52.0 refuses this with "expected `;` to end this statement" at `)]`; written with the delimiter on the attribute's own line (`[extern("""(() => …`) it adds "cannot find 'extern' in this scope" and "nothing may follow the opening \"\"\" on its line", and then `external fun one` "names no body". The grammar's attribute arguments evidently take the one-line string forms only; nothing in the error says that, and the follow-on errors read as if `extern` itself were unknown. The cost in practice: a host binding longer than one line has no spelling, so kolt either writes a 1,500-character one-line JS arrow in the attribute or (what it did) rebuilds the helper in vilan over many small externs. Doors: (1) accept every string-literal form in attribute arguments (a multiline string is raw, which also suits embedded JS regexes); (2) keep the restriction and refuse at the literal with a steer ("an attribute argument is a one-line string"). Rec: (1) — `extern` is the place long host code lives, and the raw multiline form is exactly what it wants.
