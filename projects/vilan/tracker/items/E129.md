# E129 — a code `::`-path completes only its LAST segment: `style::FlexDirection::` and `style::Color::` offer nothing

- status: OPEN — the owner's find while migrating kolt (2026-09-04); reproduced at 289e2a2b by the triage lane over stdio
- kind: editor
- area: Language server & tooling

`style::|` → 175 labels; `style::FlexDirection::|` → 0; `style::Color::|`
→ 0. Not a std/module issue: `mod geo { enum Shape }` … `geo::|` → Shape,
`geo::Shape::|` → 0. `MyEnum::|` and `FlexDirection::|` after an explicit
import both work — the name is IN SCOPE. Sharpest contrast: the IMPORT
path `import std::style::FlexDirection::|` → 4 variants: that arm descends.

Cause: `code_path_completions` (vilan-ide/src/completion.rs ~1660)
calls `identifier_ending_at(text, colon_offset)`, which walks back over
identifier bytes only, so `::` stops the scan and it sees just
`FlexDirection`; ~1665 `namespace_in_scope` is a SCOPE lookup
(`binding_in_scope(name).filter(is_namespace)`), and `FlexDirection` is
a member of `style`, not a binding → None → empty. The keystroke fast
path fails the same way (keystroke.rs ~917–926 captures one identifier;
`SymbolIndex::module` ~570 has no module named FlexDirection).

Fix (S–M, low risk — strictly more resolving paths): scan the whole
`::`-separated path back from the colon, resolve the head via
`namespace_in_scope`, walk the rest through `namespace_completions`'
own single-step descent (module → member, enum → variant) and offer the
last namespace's items; `import_completions` (~1610) is the precedent
for the descent and for stopping at an enum. Keep E53/E57's in-scope
rooting. Driver: scratch `triage27/lsp-completion/drive.py casesA.json`.
Related: M29, E53, E57; compounds with E131 on kolt's style-chain idiom.
