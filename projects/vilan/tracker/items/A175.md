# A175 — A174 door 1: revoke by value - `connection.revoke(store)` / `Service::revoke(connection_id, source)` ends ONE connection's subscriptions to a source the service handed out, sending the client the mirror's `Absent`, without closing the wire

- status: OPEN - filed 2026-10-26 (rpc-55's follow-up to A174 door 2, Order 55)
- kind: feature (std::rpc server; S-M)
- area: Standard library

Door 2 (`Connection::close(reason)`, Order 55) covers sign-out and member removal by dropping the whole session; a client with other, still-valid mirrors pays a reconnect, a re-attach and a re-seed of everything for one revoked store. Door 1 is finer. What door 2 taught about reaching a returned store's channel: a `Store<T>` reply opens one `MirrorChannel` per store ROOT per connection (`mirror_channel`, `session.controlled_channel_for(identity)` keyed by `store_identity_at(root, [])`) and a GRANT per handle path (`MirrorChannel::grant`, keyed by `bases: HashMap<identity, base>` since M172), so revoking `store` on `connection` is: find the session (`session_of(connection)`), the channel by the root's identity (`controlled_channel_for`), then either `session.revoke(channel)` (the whole root - every grant on it - the client's view hears `Gone` for every slot and the mint reads `Absent`... today a revoked channel's view closes and the mint re-asks on the next hold, which the service's `[rpc]` then refuses: the right end state) or a per-grant release (`release_grant(base)` for the handle's path identity, then the channel if no grant remains). The client side already handles both: a `Gone` on the base boundary lands `replica.set(None)` and `states()` reads `Absent`; the mint's next hold re-asks. Surface: `Connection::revoke<T>(self, store: Store<T>)` (the `Connection` value kolt's factory keeps) and `revoke_connection_store(connection_id, store)` for the id form. Pin: a client holding two stores on one connection, one revoked - that one reads `Absent` and the other keeps patching; a re-hold after the revoke re-asks and is refused by the `[rpc]`'s own check. kolt's `remove_member` is the exhibit (the removed user's connections, found by the app's own user -> connection map).
