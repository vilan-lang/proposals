# N29 — `[extern(…, retains)]` is documented only where nobody writing an extern looks

- status: OPEN — audit run 4 finding 6
- kind: docs
- area: Docs & book
- source: audit run 4, 2026-08-29

The flag appears in `vilan/docs/` at exactly two lines, both in
`spec/memory.md`'s retention section. The `[extern(…)]` form reference —
`appendix/cli.md` (which even states the flag-ordering rule against
`[platform(…)]` without naming this flag), `spec/types.md`, and
`tour/platforms.md` — never mentions it. A user binding a host API that
stashes a vilan value (an event listener, a queued callback) has no path from
the extern documentation to the flag that keeps their value alive, and the
failure mode is a use-after-free the compiler cannot warn about. Fix: the
form reference names the flag with one sentence and points at
`spec/memory.md` for the semantics.
