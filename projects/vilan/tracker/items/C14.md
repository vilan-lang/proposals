# C14 — `SignalCell` (and `Owner`) off `Shared` boxes and onto `Rc` or OWNER-ATTACHED arena `Handle`s — the necessary step for native apps with native code and NO garbage collector (F1). Today `SignalCell<T> { value: Shared<T>, subscribers: Shared<List<Subscriber>>, identity }` and `Owner { cleanups: Shared<..>, disposed: Shared<bool> }`; `Shared` is a compiler primitive (`external struct`, `primitive_struct_ids` 'Shared', 8 analyzer sites) whose doc says 'reference-counted' but whose JS backing is a plain object box the HOST GC reclaims — nothing counts, cycles (cell ↔ subscriber closures capturing cells) are the GC's problem, and a disposed owner's cells stay readable forever. Neither property survives a native backend. Two candidate representations, to be DECIDED in a paper: (a) a real `Rc<T>` — counted box with deterministic drop (`destruction.md`, `drop.vl`), cycles broken by the owner's disposal or by `Weak` (C1, OPEN); (b) owner-attached `Arena` + `Handle` (std::arena already exists; the owner holds the arena, a cell is `Handle<Slot<T>>` + its owner, disposal frees the arena wholesale — no counting, no cycles, and a stale handle reads `None` instead of a ghost value, which is a BEHAVIOUR change from today for a cell that escapes its owner: module-level cells, `std::memo` caches, rpc mirrors, `Task` results). Blast radius: reactive.vl 47 `Shared` mentions, 13 std files use `Shared`, kolt 4 (store, lib/input_system, lib/overlay, lib/rotary)
