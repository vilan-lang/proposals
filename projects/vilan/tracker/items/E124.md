# E124 — gray TOP-LEVEL dead items in a single-entry `[package]`? (owner's decision)

- status: RULED 2026-09-03 ("sounds good") — no visibility markers. PAPER first, then build, in an upcoming order.
- kind: editor
- area: Language server & tooling

E114 asked for unused declarations grayed. The lane found the
language has NO visibility marker (`pub` is a parse error: "a
module's items are importable as they stand"), so every top-level
`fun`/`let`/`struct`/`enum` is module surface an unanalyzed importer
may use — a single-entry LSP analysis cannot call it dead. Shipped:
function-local bindings (the one scope the language closes).
The exception: a single-entry `[package]` whose entry's analysis IS
the whole program — its top-level dead items genuinely are dead and
could fade behind an entry-count gate plus `main`/`[rpc]`/
`[expose]`/derive exemptions. Not built: a false gray is the worst
outcome paint has, and it is undecidable for a `[library]`.
QUESTION for the owner: build it for single-entry packages (kolt is
multi-entry — client/server/probe — so kolt would NOT get it), or
leave top-level items ungrayed until the language has a visibility
story?

## The owner's framing 2026-09-03 — reservations about visibility markers

1. Opt-in visibility requires switching between files to add missing
   publicity modifiers — developer overhead (DX loss).
2. A package that forgot to export all of its surfaces forces a FORK
   of the whole package (solid-js: signals over a wire needed
   internal signal/ownership functions Solid does not expose).
Questions: what options address these? Is E124 an XY problem? Are
markers on everything the right shape? What about markers only on
items NOT detected as used (a dead-code suppressor)? Are the
`[hidden]` / `[gone]` attributes for fields/methods of use here?
(Tree facts at the time: no `pub`; `export` re-exports an import;
`[doc(hidden)]` omits from completion; `[deprecated("…")]` steers a
use; no `[gone]` exists under that spelling.) Needs a paper before
any build — see the orchestrator's option sketch in the transcript.

## Ruling 2026-09-03 — the direction accepted

- A `[package]`'s entries are known from the manifest, and the
  reachability pruner already computes what each entry emits: a
  top-level item NO entry reaches is dead, by the bundle's own
  definition. The LSP unions reachability across the package's
  entries (kolt: client, server, probe). No markers, no file switching.
- A `[library]` gets NO top-level gray: every top-level item is
  surface a consumer may import — the property that saves consumers
  from forking an under-exported package. Locals and unreachable code
  stay painted.
- `[doc(hidden)]` (exists: omits from completion) is the soft surface
  tool: curate what consumers DISCOVER without forbidding access.
- A dead-code suppressor marker (`[keep]` or similar) is reserved as
  the escape hatch for false grays (reflection-reached items); macro
  and derive expansion is visible to the pruner, so add it only when
  the first false gray appears.
- `[gone]` (A37) is a METHOD-surface tool for blanket impls, not a
  module-surface one; it does not bear on this item.
Paper: `dead-code-paint.md` (or a section of editing-dx.md) — the
union-reachability definition, its cost on the diagnostics path (one
reachability walk per entry per landed analysis, or the pruner's
result cached per entry on M21's key), the library rule, the marker
reserved, pins.

## Paper landed 2026-09-03 (lane e124-paper, `dead-code-paint.md`) — FIVE QUESTIONS for the owner

Finding: the ruled definition taken literally over-grays — the union
of the pruner's walk across kolt's three entries grays 1,859 of 1,943
top-level items (95.7%): every `struct`/`enum`/`trait` (types are
type-level only — a USED `Point { x = 1, y = 2 }` emits `[ 1, 2 ]`
with no declaration), 1,815 lucide icons declared and 4 named, 27
const-module-binding holes (theme.vl, load-bearing), 1 context hole,
and 16 TRUE finds (twelve of them one unused overlay API). A
suppressor marker cannot be the answer at 1,859 markers — that is
reservation 1's DX loss. Recommendation: BUILD, narrowed to `fun` +
module-level `let`; land three exemptions FIRST (the `generated`
manifest root kolt already declares; the const-module-binding edges
the call graph drops; the bindings `context::thread_contexts`
rewrites away); compute per-entry sets OUT OF BAND on a package clock
keyed by (path, name span) — the LSP analyzes the OPEN FILE as the
entry, so 9 of kolt's 12 files have no `main` and no root; M21's
cache cannot amortize the per-entry analyses (the evicting edit is an
edit to a module the entry loads). Cost: union walk 8.2 ms (client
3.87 + server 2.23 + probe 2.12), ~1.2 µs/node; inputs one full
analysis per entry, 0.4–1.2 s load+walk cold. `file_platform_choices`
already runs a per-entry MODULE-level walk per keystroke — a free
coarser first slice. Derive/service-generated members live in
`DERIVED_SOURCE` (no path) so a file-scoped paint never grays a
`[derive]` line; trait impl members are per-instantiation — the
jumpiest true grays.
Q1 accept the narrowed definition (`fun` + module `let`; types are a
different analysis)? rec yes. Q2 paint OFF during an editing burst
(withdraw-on-edit over serve-stale — a gray is a claim acted on by
deleting)? rec withdraw. Q3 a workspace `[library]` opt-in via a
manifest key, not per-item markers? rec not in v1. Q4 the marker's
spelling: `[keep]` vs `[used]`/`[reachable]` (states the assertion)?
Q5 ship the free module-level slice first, alone — and where does it
render (editor vs explorer)?
