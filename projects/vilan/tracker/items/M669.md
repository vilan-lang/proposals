# M669 — `std::http::Server` can't be bound to one address, and `require_build` finds the build only in the working folder: an embedded server has no clean shape

- status: OPEN — filed 2026-10-21 (kolt's desktop app runs the Kolt server inside Electron)
- kind: API gap (std::http, std::build; S)
- area: std

Two gaps found while embedding a Vilan server in a desktop app.

1. **No bind address.** `ServerBuilder` has `.port(n)` and nothing else. `http.vl` calls `node_server.listen(port, cb)`, so Node listens on every interface (`::`). A server meant for this machine only (a desktop app's own, a dev tool, a test) is then reachable from the whole network, and on Windows the firewall asks the user about it. Recommendation: `.host("127.0.0.1")` (or `.bind(addr, port)`), passed through to `listen(port, host, cb)`.

2. **The build is found relative to the working folder.** `require_build("client")` panics with `no build manifest at dist/client.chunks.json … run the server from the project root`. A server started from anywhere else (the app's data folder, a service manager's working folder) can't find its own build, though it sits beside the server module. Kolt works around it by running the server from the repo root and pointing its data elsewhere with its own `KOLT_DATA` setting. Recommendation: resolve `dist/` beside the running module (`import.meta.url`), with the working folder as the fallback.
