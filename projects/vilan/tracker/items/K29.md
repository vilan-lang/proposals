# K29 — the playground's "Prelude: web" position spells a std PATH (`"std::web"`, in the website's worker.js) that A154 renames to `std::web::prelude`; and the page can pin an older compiler (`?v=`), so after v0.44.0 no single string is right for every wasm the page loads

- status: OPEN — filed 2026-10-03 (site-46's find, Order 46)
- kind: feature (S)
- area: Web presence (site, playground, docs delivery)

site-46 added the third prelude position K14's 2026-09-01 gap note asked for. vilan-wasm's `compile_with` takes `undefined` (the mode's set), `"off"`, or a module path, so the page's worker maps the word `web` to the path `"std::web"`. When A154 lands that path stops resolving on the new compiler, while the version selector still loads older compilers, where only the old path resolves. Rec: vilan-wasm accepts a second reserved word, `"web"`, beside `"off"` (`PlaygroundPrelude::from_option` maps it to `manifest::WEB_PRELUDE`, whatever that constant names in a given release), so the page never spells a std path. The worker feature-detects it the way it detects `compile_with` (a new export, or a `version()` comparison) and falls back to the old path on older wasm. The website's own copies of the string to update at that point: `src/playground/worker.js` (`preludeArgument`), `scripts/smoke-playground.mjs` (claim 6's web half), `tests/examples.test.mjs` (`playgroundDir`), and `vilan.toml`'s `prelude = "std::web"`. Sizing S (wasm plus the site).
