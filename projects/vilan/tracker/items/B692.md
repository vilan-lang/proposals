# B692 — An un-annotated closure parameter against a declared `|&mut Option<List<i32>>| void` loses its type inside `match &mut slot`: `Some(let l) => l.push(3)` is refused with `cannot call method 'push' on T`; the annotated parameter works

- status: OPEN - filed 2026-10-31 (lane b689's find; `HashMap::update`'s closure annotates its parameter to dodge it)
- kind: bug (checker; closure parameter type flows into a `match &mut` capture)
- area: Type system & the type solver

The expected closure type gives the parameter `&mut Option<List<i32>>`, but a `match &mut slot` over that parameter binds the `Some` capture as the still-unresolved `T` rather than `&mut List<i32>`, so a method call on it fails. Rec: the parameter's type from the expected closure type must be settled before the match's capture types are read (an ordering in the solver, or the expected type applied at the parameter's binding rather than at the call); pin: the un-annotated and annotated forms in inference/closures.rs both accept.
