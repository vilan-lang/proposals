# E217 — `vilan fmt` DECLINES a hand-wrapped generic `impl` header — `impl type S: DeltaSource<\n\tList<T>,\n\tSeqOp<T>,\n> { … }` is refused (a decline, not a reprint), so a header longer than the width has no formatted spelling at all

- status: OPEN — filed 2026-09-21 (Order 39 sweep; collections-39's FIND 5)
- kind: bug (formatter)
- area: LSP & tooling

The printer has no wrapping rule for an `impl` subject's generic argument list (declarations and calls have one), so a wrapped input reprints differently and the token/parse net declines. Fix: the impl-header printer shares the declaration's argument-list breaking (one per line, trailing comma) when the header exceeds the width. Pins: the reprint of the wrapped header is idempotent; an over-width single-line header is BROKEN by the formatter; the decline count over std is 0 (it is today — the lane kept the line long).
