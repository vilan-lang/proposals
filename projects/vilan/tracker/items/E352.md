# E352 — A method chain in the `else` arm of a `then … else` is joined onto one line, at any width

- status: OPEN - filed 2026-10-31 (kolt, upgrading to 0.53.0)
- kind: fmt edge
- area: Formatter

`vilan fmt` (0.53.0, and 0.52.0 before it) joins a chain that is the `else` arm of a multi-line `then … else` into a single line, however long that makes it. Written as

```
	let readers = private
		then [Row { name = "only the members" }]
		else rows_of("SELECT account_id FROM membership WHERE organization_id = ?")
			.filter(|row| row.name.len() > 0)
			.map(|row| Row { name = row.name.to_uppercase() });
```

it comes out with the whole `else` arm on one 161-column line:

```
		else rows_of("SELECT account_id FROM membership WHERE organization_id = ?").filter(|row| row.name.len() > 0).map(|row| Row { name = row.name.to_uppercase() });
```

The same chain as a statement's value (`let v = rows_of(..).filter(..).map(..);`) breaks one link per line, as kolt's other queries do. Kolt meets it in `src/store.vl`'s `mark_unseen` (`facts.private then channel_members(channel) else db.prepare(..).all([..]).map(..)`), which every `vilan fmt .` reflows to 170 columns and the owner reverts by hand.

Repro (standalone, runs and prints `1`): kolt session scratchpad `fmtrepro/then_else_chain.vl`, copied below as the whole file.

```
struct Row {
	name: str,
}

fun rows_of(query: str): List<Row> {
	[Row { name = query }]
}

fun main() {
	let private = true;
	let readers = private
		then [Row { name = "only the members" }]
		else rows_of("SELECT account_id FROM membership WHERE organization_id = ?")
			.filter(|row| row.name.len() > 0)
			.map(|row| Row { name = row.name.to_uppercase() });
	print(readers.len());
}
```

Likely the arm is printed without the width permission the statement hook arms (the E347/E348 family: a value reached through another construct is measured as if it had no room limit). Recommendation: measure a `then`/`else` arm against the column it starts at and break its chain as a statement's value breaks. Sizing XS-S.
