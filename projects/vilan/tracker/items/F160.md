# F160 — Native executor polls sockets on a 1 ms sleep - one client tops out near 1,000 requests a second

- status: open
- kind: performance (native runtime)
- area: native backend

Found by lane http-58 while measuring keep-alive. `IO_POLL_INTERVAL` in `crates/vilan-rt/src/executor.rs` is a 1 ms sleep between polls of every waiting socket. One kept-alive client therefore gets at most about 1,000 round trips a second: measured 690-870 req/s native against 880-1,190 on node, on a loaded machine. The fix is to wake on readiness (`poll(2)` on unix, `WSAPoll` on Windows) with the nearest timer as the timeout, instead of sleeping. It also removes the idle wake-ups. Size M. Related deviations recorded by the lane: a deadline is checked every loop turn, and the native server sends no `Date` header.
