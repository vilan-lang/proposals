# M21 — an entry with any `pkg::` import bypasses the BASE_CACHE entirely

- status: OPEN — editor-perf lane's find (2026-09-01); the next-largest per-keystroke cost after M19
- kind: perf
- area: Performance & footprint
- source: lane editor-perf's phase split (`VILAN_PHASE_TIMING`)

The BASE_CACHE keys std worlds on the entry's std reference set —
but an entry carrying ANY `pkg::` import misses it outright, so
kolt's views.vl/client.vl rebuild std's whole world on every
keystroke (`base` 248–288 ms) while theme.vl (no `pkg::` imports)
hits it at 0.0 ms. The key should be the std reference set
regardless of package imports (the world is std's; the package is
analyzed on top of it). Pin: an entry with one `pkg::` import hits
the cache on its second analysis; the base-cache pins (M11's
`base_cache_retained`) hold the world count.
