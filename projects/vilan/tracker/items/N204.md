# N204 — Twelve test helpers still read a served page with a fixed 5 s timeout and swallow the timeout into an empty response (a loaded Windows runner failed one of the family)

- status: open
- kind: harness (timeouts; a family)
- area: crates/vilan-cli/tests/{asset_bundle,hmr,init,serve_build,ssr_fullstack,service_layer,split}.rs

The same shape remains at twelve sites: `set_read_timeout(Some(Duration::from_secs(5)))` (one at 10 s) followed by a read whose error is ignored: `asset_bundle.rs:159`, `hmr.rs:278` and `:312`, `init.rs:630`, `serve_build.rs:199` and `:239`, `ssr_fullstack.rs:100`, `service_layer.rs:1700`, `:1733` and `:3611`, `split.rs:928`. On a loaded runner each can fail an assertion about content on an empty string, which reads as a product bug. Move ONE helper into `tests/support/` (a GET bounded by `run_liveness()` that fails by name on a timeout or a reset) and use it everywhere; check each site's intent first (a few may read a stream that is MEANT to stay open, where the timeout ends the read by design: those need a different helper, not a longer clock).
