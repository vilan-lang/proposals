# B678 — `[derive(Json)]` over a field whose type is MODULE-QUALIFIED and applied (`flag: option::Option<bool>` under `import std::option;`) generates code that does not parse - "macro `Json` generated invalid Vilan (unclosed `{` in struct initializer)" - on 0.52.0 and after M166

- status: OPEN - filed 2026-10-26 (std-55's find, Order 55)
- kind: bug - a derive's generated code does not parse
- area: Standard library

Met probing M166's syntactic `Option` test. The derive's `decoded` helper spells the field's decoder `{type_.render()}::from_json_value(..)`, and a qualified applied type renders as a path head with generic arguments in the middle of a path (`option::Option<bool>::from_json_value`), which the parser reads as a struct initializer. Doors: route a qualified type through `from_json_value_of<T>(..)` (as a tuple already is, B623), or render the path head without its module prefix when the type resolves. Rec: the first - `is_path_head` answers false for a `::`-qualified applied name. M166's absent-`Option` rule tests the bare written name `Option` and so does not reach such a field either (documented). `fix`.
