# B545 — under `match &mut place`, a capture inside a TUPLE sub-pattern (`Some((let a, let b))`) is still a copy: a write to it is refused with the old `declare it mut` steer, and `mut a` is accepted and its write does not land — the payload-view rule binds captures through variant payloads only

- status: OPEN — filed 2026-10-03 (solver-c-46's find, Order 46)
- kind: language gap (design; S–M) — B509's edge
- area: Type system & the type solver

Tuples store flat, so a tuple-typed leaf inside a tuple pattern is a reslice (`subject.slice(..)`), which cannot be a view; a one-slot leaf could be the `(tuple, offset)` pair. B509 S1 excluded tuple sub-patterns entirely, and the Q4 refusal (`mut` capture under a view subject) covers only the payload-view positions, so the trap B528 closed survives one pattern level down. Rec: one-slot tuple leaves become views (JS pair / native binding modes already give `&mut`), a multi-slot tuple leaf is refused under a view subject with a steer to bind the tuple whole; extend Q4 to every capture under a view subject. Sizing S–M.
