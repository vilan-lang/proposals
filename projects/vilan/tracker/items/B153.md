# B153 — `Option::replace` declares a loan and keeps the value

- status: OPEN — found by Order 19's lastuse-s3 lane; FIX-NOW shaped (a declaration correction), and C11's temporary predicate is deliberately narrowed until it lands
- kind: bug
- area: Type system & the type solver
- source: the lastuse-s3 lane's extern/ownership audit, 2026-08-29

`external fun replace(&mut self, value: T)` declares `value` as a BARE
parameter — a loan under mR3 — and then keeps it (the host stores the
value into the option). A loan that retains is exactly the contract
violation the `[extern(retains)]` work fenced; the honest declaration is
`own value: T`. Until it reads so, the last-use machinery treats the
argument conservatively and C11's statement-temporary predicate is
narrowed to `&`/`&mut` views and bare `self` receivers; widening it back
is the follow-up the fix unlocks. Sweep siblings while there: any std
extern taking a bare parameter it stores.
