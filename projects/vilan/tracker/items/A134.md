# A134 — a HANDLE STUB inside a COLD select re-mints per PULL: `get_client().and_then(|client| client.get_channels()).map(..).cell()` — the shape the Order 40 census prescribed as `map_safe`'s replacement, at all seven kolt model.vl sites — reads `[]` forever. `AndThen::get` re-runs `select` on every pull and a generated stub (`unleased_source`, rpc.vl:5941) mints a FRESH unleased mirror per call, so `.cell()`'s refresh (`cached.set(self.get())`) reads a mirror nothing ever leased (`None`) while the leased one — the one `on_settle`'s `follow` picked — lives on in the registration. The wire, the server and the wake are all correct; the value is read off the wrong object

- status: OPEN — filed 2026-09-28 (the owner's report: kolt stopped mirroring channels after the v0.41.0 migration; diagnosed by the integrator on 1a33340f)
- kind: bug (std design trap)
- area: Reactive core & UI

Mechanism, in order: `.cell()` reads `self.get()` once (select → mirror #1, unleased, `None`), then `on_settle` → `AndThen::on_settle`'s `follow` (select → mirror #2, leased: `Subscribe`, seed, forward), then each settle wakes the cell and its refresh calls `self.get()` again (select → mirror #3, unleased, `None`). Every pull is a fresh mint; the push path and the pull path never meet the same mirror. Pure selects are unaffected — the trap is a select with an EFFECT, and a sync stub is exactly that, by design (A92: "an app that mints a hundred handles and renders ten makes TEN calls").

Kolt's fix (applied 2026-09-28 at the seven model.vl sites, checks/builds/fmt clean): pin the mirror under a cell of its own between the `map` and the `and_then` — `get_client().map(|c| c.map(|c| c.get_channels())).cell().and_then(|mirror| mirror).map(..).cell()` — so the select is the identity and the one mirror the client made is what every pull reads.

Doors for std: (a) the generated client DEDUPS mirrors per ORIGIN (method + described args) — the client twin of A92's server-side identity dedup; a second stub call for the same origin hands back the same mirror, so a select that mints is idempotent and the census's shape simply works. Cost: a per-client table keyed by the origin's serialized args, released with the mirror's last lease (or with the connection). (b) `AndThen`/`Switch`/`FlattenOption::get` read the FOLLOWED inner while a subscriber is attached (the node keeps `inner` in its registration already) — but a cold node that answers differently attached vs unattached is a new kind of node, against A124's letter. (c) document the idiom above at the stub's doc (rpc.vl:5900) and remote-sources.md, and rewrite the census's two sites. Rec: (a) + (c); (a) also makes kolt's hand `Memo` tables optional. Sizing S–M; std/rpc, Order 43.
