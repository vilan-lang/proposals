# A41 — the dynamic-expose path leaks and goes dead: `ReactiveServer::stop` never removes the `sources` entry; `reattach_mirrors` rebinds only `__attach`'s positional list

- status: OPEN — found by the rpc triage lane (2026-09-04) at 289e2a2b, reading only
- kind: bug
- area: Reactive core & UI

Two holes on the path A39's recipe relies on (an rpc method minting a
channel at runtime via the public `session_of` + `ReactiveServer::expose`):

1. `ReactiveServer::stop` (std/src/rpc.vl ~1201) disposes the live
   forward but never removes the entry from `sources` (~1145), so every
   dynamic subscribe retains a closure (and its source) until the
   connection dies. Fix S: remove on stop; pin by counting `sources`
   across subscribe/unsubscribe.
2. `reattach_mirrors` (~1607) rebinds only the positional list that
   `__attach` produced, so every dynamically-minted mirror is silently
   dead after a reconnect — no error, no updates. Fix S–M: register
   dynamic mirrors in the same table (or refuse dynamic expose until
   A39 gives it a protocol form) and pin a reconnect with one dynamic
   mirror.

Neither is reached by the generated `[expose]` path (static, positional),
which is why nothing pins them. Read-only finding; needs a runtime repro
before the fix (the lsp/std harness that drives a socket pair —
`crates/vilan-cli/tests/` has the transport exhibits).
