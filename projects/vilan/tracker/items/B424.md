# B424 — RULING — an UNCONSTRAINED generic at a call: `err.or_else(|e| Ok(7))` leaves `or_else<F>`'s `F` with nothing to bind it (the closure only ever builds `Ok`), the analyzer records `any`, JS runs, and the native backend must pick a Rust type — it refuses by name today (`result-combinators.vl` stops there). Rule: (a) the analyzer refuses an unbound generic at the call with a steer to a turbofish/annotation (both backends agree; breaks JS programs that ran); (b) default `F` to the `Err` side's declared type when the closure never produces one (a defaulting rule); (c) native keeps refusing by name
