# B702 — `ReactiveServer::revoke` (rpc.vl:3165-3190) sends the client NO frame: a revoke from app code leaves the view reading a stale `Ready`, and its later `Subscribe`s are dropped silently

- status: OPEN - filed 2026-11-03 (lane papers-56's find; A175 depends on it)
- kind: bug (std::rpc server; mirrored stores)
- area: Standard library

A revoked channel must tell its client: one `Gone` per slot it held (the client's existing `Gone` handling lands `replica.set(None)` and `states()` reads `Absent`), then the channel is dropped; a later `Subscribe` on it is answered with a refusal frame, not dropped. Pin: a server-side revoke makes the client read `Absent` on the next tick and a re-hold re-asks. Sizing S; built as part of A175 or alone.
