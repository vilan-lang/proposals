# B476 — a bounded BLANKET impl over `Flow<X>` does not CHECK `X`: a bare `outer.flatten()` on `SignalCell<SignalCell<i32>>` compiles silently as the `Option` join, and sealed it types as the undetermined `MemoCell<Option<U>>` — which is why `std::ui` keeps a `Source` arm beside each `Flow` arm

- status: OPEN — filed 2026-09-29 (Order 44, reactive-44's find 5)
- kind: bug (UNCHECKED BOUND — a silent wrong overload)
- area: Type system & the type solver

The blanket's element bound (`Flow<Option<S: Source<U>>>`) must be checked at candidate selection, so a subject whose element is not an `Option` is not a candidate. Pins: the bare total join refused (steer to `switch(|i| i)`), the Option join accepted, the sealed type determined. Then std::ui drops its duplicate `Source` arms. Sizing S–M; solver, Order 45.
