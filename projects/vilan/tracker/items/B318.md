# B318 — VISIBILITY AND THE IMPORT SURFACE (the owner's design, 2026-09-12; paper on the next order): (1) items are PRIVATE by default; `export` marks an item and keeps it local; `export *;` opts a module into today's everything-public; `export(PATH)` narrows (`export(in mod)` keeps one item hidden under an `export *;`, `export(in pkg)` is package-wide); (2) visibility NEVER blocks access — an explicit reach spelling (`import a::{ #hidden }`, `#` recommended) imports a private item, and reaching a DEPENDENCY's private item is no diagnostic at all (RULED: whether an item should be exported is subjective; the consumer may need it); visibility gates COMPLETION and the "import it first" steers; (3) a WARNING when an exported item exposes an unexported type in a signature position (RULED wording: "`S` is returned here. `my_fun` is exported, but `S` is not. A consumer can call `my_fun`, but are unable to name the return type.") with the quick fix "Export `S`"; (4) `export mod name { … }` + `import path::name::*` — the named prelude set (inline `mod` already parses and works; `::*` is the one new row, legal once exports are explicit); (5) IMPL IMPORTS get a spelling: `import a::b;` keeps today's meaning (names + every impl along the path — probed: an intermediate module's impls arrive too), `import a::b only;` brings names and no impls (RULED `only`), `import a::b::{ impl List<i32> }` brings the impls COMPATIBLE with that TYPE (a module's `impl List<type T>` arrives for `List<i32>` only — RULED type-level, blanket impls covered), `impl PATH` resolves in the IMPORTER's scope (`impl S` after `import item::Struct as S`; `impl item::Struct` qualified — RULED), and a specific method is `{ impl List<i32>::first }` / `{ impl List<i32>::{ first, last } }` (proposed: the path grammar the import already has, nested under the selector). Consequence for the paper: the per-type method namespace (names.md §4.6, one namespace, collisions refused at DECLARATION) becomes per-IMPORTER — the change that lets independent extension modules coexist, and the one with solver reach

**RULED (owner, 2026-09-12).** Default private. `export` marks and keeps local. `export *;` per module. `export(PATH)` narrowing. Access never blocked: a reach spelling exists; a dependency's private item reached that way gets NO diagnostic. Warning wording as titled, with the quick fix. `export mod` as the prelude-set spelling. `only`. Type-level impl selection. Importer-scope resolution of `impl PATH`.

**RECOMMENDED (not ruled).** `#` as the reach marker (lexically free: the css lexer refuses `#333` only inside a block; attributes are bracketed). A plain `import a::hidden` of a private item is a WARNING with two fixes ("Export `hidden`", "Import as `#hidden`") so the default flip breaks nothing; `export *;` at the top of every existing multi-file module is the codemod for kolt, the website, the examples and the templates, while std curates real exports. The exposure warning's reach is signature positions: a value's type, parameter and return types, exported struct fields, enum payloads, trait bounds and generic arguments (`List<S>`); never bodies. The fix edits `S`'s declaration wherever it lives (workspace edit); when `S` is a dependency's, no fix, and the message says so. Grammar note: "are unable" → "is unable"/"cannot" for agreement with "a consumer" — the owner's sentence otherwise verbatim. `::*` is legal over any module once exports are explicit (prelude.md §8's 'no globs' was written under everything-public); `export mod` is the idiom. A brace set naming an `impl` selector implies 'these impls only' (so `only` is for statements without a selector); a selector may carry binders (`{ impl List<type T> }`) since it is the type grammar. A method selector refuses `as` (methods are called by name on a receiver). `import a::Length::rem` (B317) binds a static as a free name; `{ impl Length::rem }` brings the static into `Length`'s namespace for this file — two different things, both spellable. Impls follow the module's export posture (`export impl …` for an extension impl in a default-private module; `export *;` covers them).
