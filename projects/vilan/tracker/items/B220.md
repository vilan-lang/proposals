# B220 — an ARRAY receiver has B210's emission-side hole: `impl [i32; 2] with PartialOrd { partial_compare }` then `a < b` fails with the never-silent `internal:` error

- status: OPEN — lane b209-b210's find (2026-09-03); pre-existing
- RULED 2026-09-05 (owner deferred to the recommendation): arrays JOIN the nominal receiver set for user impls — B210's tuple precedent; the three sites B210 named gain `Type::Array`. Order 28.
- kind: bug
- area: Code generation

`transformer.rs`'s `resolve_member_on_type` — the re-dispatch a
specialized trait default uses to find its requirements — excludes
`Type::Array`, so the inherited `lt` default cannot find the impl's
`partial_compare` and the emitter's never-silent check fires. B210
fixed the same shape for tuples and deliberately did not widen to
arrays: arrays are STRUCTURAL in `resolve_method_call` (`len` only),
so whether an array gets method resolution at all is a decision, not
a fix (B177/B170 are the neighbours). Decide: arrays join the
nominal receiver set for user impls (then the three sites B210 named
gain `Type::Array`), or operator impls on arrays are refused at the
impl with a steer to a wrapper struct. Pin whichever: the `<` program
above, a user trait default on an array, the `len` control.
