# B688 — A trait's methods resolve in a file that doesn't import the trait, when another file in the build does

- status: OPEN - filed 2026-10-31 (kolt)
- kind: bug (checker; trait method visibility)
- area: Type system & the type solver

The rule (and the diagnostic that states it): "a trait's methods resolve only in a file that imports the trait". It holds for a file built alone, but not when another file in the same build imports the trait: then the method resolves in every file.

Repro (`vilan 0.53.0`, a package with `prelude = "std::web::prelude"`, browser entry):

```
// src/words.vl - no Display import
export *;
fun joined(list: List<str>): str {
	list.map(|each| each).join(", ")
}

// src/other.vl
import std::display::Display;
export *;
fun listed(list: List<str>): str {
	list.join("; ")
}

// src/main.vl
import pkg::other::listed;
import pkg::words::joined;
fun main() {
	print(listed(["x"]));
	print(joined(["a", "b"]));
}
```

`vilan build .` compiles. Remove `other.vl` (or its use) and the same `words.vl` is refused: "List<str> has no method 'join'; import std::display::Display to use it". `vilan test src/words_test.vl` on a test that imports only `words` refuses it too.

How kolt met it: `src/store.vl` used `.join(", ")` without importing `Display`; `vilan build .` (which compiles every module) accepted it, and `vilan test src/task_query_test.vl` (whose test reaches `store.vl` but not the files that import `Display`) refused it. So a file's correctness depends on which other files happen to be compiled with it, and a passing build hides an error a narrower entry later finds.

Recommendation: resolve trait methods against the calling file's own imports (and prelude) only, as the diagnostic says, whatever else the build contains.
