# E119 — a field miss on an overlaid std type should name the overlay and why it was chosen

- status: OPEN — owner ruling 2026-09-01 (A35's companion question)
- kind: bug
- area: LSP & tooling
- source: the owner: "does [naming the shadow] help with the View.element diagnostic when the process layer is used? If not, file it"

E113 colors REACHED files correctly; an unreached file still takes
the fallback color, and its `struct 'View' has no field 'element'`
says nothing about WHICH `View` (std's process twin) or WHY (this
file is analyzed under node because nothing reaches it yet, or
because default-entry is server). The diagnostic should name both:
"`View` here is std's process twin — this file is analyzed under
node: no entry reaches it (default-entry is `server`)" — and steer:
reference it from the client entry, or add `[platform(browser)]`
(B147's module-level default, if it lands). Pin under E113's
fixtures.
