# E167 — the shipped "Convert to a `css` block" refactor (css-block S5, `Document::css_spelling_conversion`) never fires on real code: the seed must be a BARE `style()` (`style_chain_links` matches `Node::Accessor("style")` only, so `style::style()` — the web prelude's own spelling, the one the templates and kolt write — is refused), and any TYPED link (`.color(c)`, `.flex_row()`, `.padding_x(..)`: every shorthand, i.e. every link an app writes) returns `None` for the WHOLE chain, because `render_css_items` knows only `raw` and the condition table. Make it fire: accept a path seed ending in `style()`; render a typed link as the declarations its std body writes — `STYLE_PROPERTY_METHODS.properties` names them and style.vl's bodies are `with_length`/`with_color`/`raw` chains, so inlining the body with the argument as a hole is exact (`padding_x(v)` → `padding-left: {v}; padding-right: {v};`, `flex_row()` → its two literals); a link with no block spelling (`when`, `add`, `rule`, `class_list`, a user extension such as kolt's `select_off`) becomes a TRAILING CHAIN on the block — `css { … }.select_off()` parses and types today (probed 2026-09-12) — instead of refusing the conversion

**Seed.** `style_chain_links` accepts a `Node::Path`/member path whose last segment is `style` called with no arguments (`style::style()`, `s::style()`); the program is available to the code-action path when one is wanted for resolving the alias, but the raw-parse rule (last segment `style`, zero arguments) matches every spelling in the estate.

**Typed links.** Two sources, and the choice is the design point: (a) a hand table beside `STYLE_PROPERTY_METHODS` giving each method's declarations with `$1`/`$2` holes for its arguments, gated by `style_table_sync.rs` against style.vl's bodies exactly as the `family` column is; (b) an INLINER over std's parsed `style.vl`: a shorthand body is a chain of `with_length(prop, value)`/`with_color`/`raw(prop, literal)` links over `self`, so substituting the call's argument text into the parameter's holes yields the declarations with no second table. Recommendation: (b) — it cannot drift, and a body that is not such a chain (a barrier) simply has no block spelling. Values render through `render_block_value`'s existing rule: a string literal token run as itself, anything else as a hole `{expr}`; a `Length`/`Color` argument is a hole (`gap: {Length::rem(0.5)};`), a numeric literal too.

**Unconvertible links.** Today one such link refuses the whole chain. New rule: split the chain at the first link with no block spelling; everything before it becomes the block, the rest is written as a postfix chain on the block (`css { … }.when(selected, delta).class_list()`); condition combinators keep converting recursively as they do. A link BEFORE a convertible one that has no spelling (e.g. `.raw("outline", i"..")` is fine, but `.add(other)` in the middle) — the split is at the FIRST such link, so `style().color(c).add(x).gap(g)` becomes `css { color: {c}; }.add(x).gap(g)`, which is equal (chain order is merge order and the tail keeps it).

**Round trip.** A typed chain → block → chain lands on `raw` links, not the shorthands; that is the block's meaning (§5.2) and is documented rather than fought. Comments still refuse (unchanged).

**Pins.** the `style::style()` seed; kolt's `new_button_style` shape (typed links + raw + attribute/pseudo combinators) converts and the converted block's `class_list()` equals the chain's (the corpus twin proves the block == chain equivalence already); a chain with a user extension splits at the extension; a chain of only unconvertible links offers nothing; `book_sync`'s title gate unchanged (no new titles).
