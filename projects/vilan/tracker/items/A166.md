# A166 — `==` over two fixed arrays is refused on both backends ("type '[i32; 3]' does not implement the `PartialEq` operator; add `impl [i32; 3] with PartialEq`") — std has `List`'s blanket and none for `[T; n]`, and the steer names an impl no program can write for every length

- status: OPEN — filed 2026-10-09 (native-49's find, Order 49)
- kind: std gap / design (S)
- area: Standard library

`let fixed: [i32; 3] = [1, 2, 3]; print(fixed == [1, 2, 3]);` is refused. A `[T; n]` is a value aggregate (destruction.md); a blanket `impl [type T: PartialEq; type N] with PartialEq` (or whatever the array-lengths paper's generic-length spelling rules) would match `List`'s, and the steer should not ask for a per-length impl. Natively Rust's `[T; N]: PartialEq` is structural, so the native half needs the same element dispatch F118's generic operators now take (a written element `eq`). Repro: finds/fixed_array_equality.vl. Sizing S once the array-lengths paper (papers-49) says how a length is generic; std + the steer's wording.
