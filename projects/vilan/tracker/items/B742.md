# B742 — False refusal: a trait default calling `self.note()` through `T: Note`, two levels deep, is refused although only covered code selects the strict impl

- status: open
- kind: bug (context pass; false refusal)
- area: crates/vilan-core/src/dispatch_refine.rs, crates/vilan-core/src/context.rs

B737 resolves a default's bound dispatch per call site, with a fallback to every candidate where the answer is not on record (a receiver-less `self.gap(..)` that may select an override). Two levels of such forwarding fall back although the instantiations on record say only covered code selects the strict candidate: only `announced(Deep {})` reaches `Deep::note`'s strict `depth.get()`, and that call sits under `depth.run(5, ..)`; the one call without the context, `announced(Plain {})`, selects `Plain::note`, which reads nothing; the refinement does not resolve the default's `self.note()` per entry when it is reached through the bounded `announced<T: Note>`, so it blames that call. Decide whether the refinement can carry the binding through the second level; pin the repro and the one-level form that already works.
