# B768 — The view-escape check accepts a view-capturing closure assigned through a `&mut` view to a closure-typed place

- status: open - filed 2026-11-27 (the integrator, reviewing lane `keys-s3a`; pre-existing on `next` @6744ee9d, no key involved)
- kind: bug (checker; a rule that is enforced on the direct store and not on this route)
- area: crates/vilan-core/src/analyzer.rs (C16, the view-escape check)

Repro:

```
fun direct(place: &mut (|| i32), n: &i32) {
	place = || *n;
}
fun make(): || i32 {
	mut f = || 0;
	let n = 4;
	direct(&mut f, &n);
	f
}
fun main() {
	let f = make();
	print(f());
}
```

`vilan check` is clean. The closure captures the view `n`, is stored in the caller's `f` through `place`, and is returned past `n`'s scope. The same store written as a field assignment (`h.f = Some(|| *n)`) is refused with "a view cannot escape its scope". The native build prints `4`; JS prints `0`, which is B767 (the write is lost there).

The same route exists inside any closure that is lent a `&mut` place, including B711 S3a's `change`: `Holder.f::Some.change(h, |place| { place = || *n; })` is accepted. S3a's `put` does refuse a view-capturing value (fixed in review, pinned).

Not established: whether the native program is memory-safe by construction here or reads a dead place; it was not examined past its output.
