WHAT STD HAS TODAY: vilan/std/src/browser/storage.vl:1-24 is six FREE functions over the two host
objects — `get`/`set`/`remove` (:6-14) and `session_get`/`session_set`/`session_remove` (:16-24) — and
the module header states the shape: "A missing key reads as "" (the host returns null; the helper
flattens it)". There is no handle type, no length, no key enumeration, no presence test, and no way to
tell a stored `""` from an absent key.

Those last three are not hypothetical. kolt's `StorageKeyAllocator::seal` (storage.vl:79-102) sweeps the
store: `delete_unknown_keys` walks `len()` down to 0 calling `key_at(i - 1)` to delete every key the app
no longer declares, and `initialize_unset_keys` needs `has(key)` — which it cannot write correctly today,
because `!get(key).is_empty()` is false for a key whose stored value is legitimately `""`.

PROPOSED: a `Storage` handle reached as `window().local_storage()` and `window().session_storage()`, with
`len()`, `key_at(index): Option<str>`, `get(key): Option<str>`, `has(key): bool`, `set`, `remove`,
`clear()`, and an iterator over the keys. Keep the six free functions as the one-liner form; the flattening
`""` belongs only there, and the handle's `get` is the one that tells absent from empty.
