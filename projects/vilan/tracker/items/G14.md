# G14 — a watch round lost to a transient action failure is lost for good

- status: OPEN — RULED 2026-08-29: restore the consumed difference on a
  failed action, retried ONCE (spin-guarded); a second consecutive failure
  waits for the next change as today. Build-ready.
- kind: design
- area: Dev loop
- source: Order 20's close, the one CI red and its diagnosis

`watch_loop` consumes a snapshot difference BEFORE it runs the action
(`snapshot = next; action()`), so a round whose action fails transiently — a
`cmd` hiccup on a loaded runner, any non-compile flake — can never re-fire:
the difference is spent, and the session sits healthy and silent until some
OTHER change arrives. For a compile error this is the right design (the fix
IS the next edit, and retrying a broken tree would spin); for a transient
failure it silently loses the round. The question is whether a FAILED action
should restore the consumed difference (retry on the next poll, with a
once-only guard against spin) or whether the current posture — wait for the
next change — is the ruling, recorded. The watch pins re-touch their
triggers and capture the loop's narration since 2ad39dd0, so the next
occurrence will name itself either way.
