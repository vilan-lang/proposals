# B697 — An open impl generic leaks into a user expression's type: `Ok(5).map_err(|code: str| code)` analyzes to `Result<T(impl generic), str>` - the call's result keeps the receiver's `T` open instead of binding it from the payload (`i32`)

- status: OPEN - filed 2026-11-03 (lane tooling-56's find)
- kind: bug (inference; E333/E342 residue)
- area: Checker / inference

The substitution for a variant receiver's method (`Result<T, E>::map_err` on an `Ok(5)` receiver) does not bind `T` from the constructor's payload when the method's own signature does not mention `T` in a position the call constrains. Rec: bind the receiver's enum parameters from the receiver EXPRESSION's recorded type before the method's substitution is built (the receiver type is `Result<i32, _>` already), so the result type closes; then E342's hover workaround and its nested residual fall away. Pin: the inference test answers `Result<i32, str>` for the repro and `Result<Option<i32>, str>` for `Ok(Some(2)).map_err(..)`. Sizing S-M.
