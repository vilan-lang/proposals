# B380 — indexing a `Shared<List<K>>::read()` TEMPORARY at a generic element type is refused ('element type is never determined') while `.get(at)` on the same temporary infers — `cells.read()[i]` vs `cells.read().get(i)` inside a generic body

- status: OPEN — filed 2026-09-21 (Order 39 sweep; collections-39's FIND 3)
- kind: bug (inference)
- area: Type system & the type solver

The index operator's receiver typing loses `K` when the receiver is a `read()` temporary (a `Shared<T>::read` answers `T` through the blanket; the subscript then asks the element type of an unresolved `T`), where the method call path resolves the same `T` first. Fix: the subscript path types its receiver through the same resolution the method-call path uses. Pins: the repro and its `.get` control agree; a concrete `Shared<List<i32>>` unchanged.
