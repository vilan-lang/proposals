# N177 — The const-site cache's keys depend on the world's SHAPE: kolt built over the forced std prefix writes `dist/.cache/const-sites` with 109 of its 113 keys different from a canonical build's, though the emitted bundle is byte-identical and each build is deterministic run to run

- status: OPEN - filed 2026-10-13 (incr-52b's find, Order 52)
- kind: tooling (S) - std-prefix P3's key
- area: Performance & footprint

`const_cache::site_key` hashes the `Debug` rendering of the lowered declarations, which carries ids; a prefix world numbers its entities differently (std's walk before the package's module nodes). Harmless today (layering is the server's, whose const cache is per process; the CLI builds canonically), but a cache shared across shapes misses wholesale, and std-prefix P3's persisted world will need a const key that is a function of content, not of ids.
