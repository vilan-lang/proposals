# A46 — fragment syntax `<>..</>` lowering to a `List<View>` literal (reverses element-syntax.md §7's refusal); NOT a multi-root View

- status: OPEN — the owner's ask while migrating kolt (2026-09-04); triage lane's survey at 289e2a2b
- kind: feature
- area: Reactive core & UI

Today `<tag ..>children</tag>` parses to `Node::Element` (parsing.rs
~3279–3338) and desugars BEFORE analysis into a chain (elements.rs
~88–186): `view("tag")`, `.attr`/`.on`/the dotted links, `.child(x)` per
child. The entry gate `peek_is_ctrl('<') && peek_at_is_name(1)` (~2706)
excludes `<>`, which falls through to a comparison parse. There is no
fragment VALUE: `View` is exactly one `Element` (ui.vl ~64); multi-root
is `impl List<View> with Slot` (~704, SSR ~324) and `View::children`.
element-syntax.md ~197 refused fragments: "List<View> and children(..)
already cover multiple roots". Usage of `List<View>`: kolt 0, website 6,
std 8.

Recommendation: lower `<>..</>` to a `List<View>` LITERAL, no new runtime
type. Grammar: a second gate `'<' then adjacent '>'` (helpers exist,
~790/~3227; `<>` is not an operator); `parse_element_inner` gains a
nameless arm; `parse_element_children` accepts `</>`. Lowering:
`build_chain` emits `Node::List(children)`; `desugar_interior` already
handles the children. Runtime: nothing. Honest limit, to document: the
fragment's TYPE is `List<View>` — legal in child position and wherever
a list is; NOT as `mount_root`'s body, a `fun ..: View` return, a
`bind_each` render, a `when` body or a `swap` render. That serves
grouping, not "a component returns multiple roots", which needs marker
text nodes so a fragment moves and dies as a unit — a redesign of
View, bind_each's order pass, when and swap (L), and why v1 refused.
Owner to name which. Size S–M (~80–120 lines parser + elements.rs +
tests + docs + the E115 punctuation vector for the LSP token pass).
Related: element-syntax.md §7; E69; E115.
