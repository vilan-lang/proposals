# B677 — `run_with_owner(owner, f)` with a closure parameter `f` is refused, and the obvious fix (`|| f()`) compiles but runs `f` under the owner it was made in

- status: OPEN — filed 2026-10-24 (kolt: page actions offered while a page has focus)
- kind: diagnostic (checker; S)
- area: Language & checker

```vilan
import std::io::print;
import std::reactive::{ Owner, get_owner, run_with_owner };

fun register(name: str) {
	print(i"+{name}");
	get_owner().defer(|| print(i"-{name}"));
}

fun while_on(provide: || void) {
	let owner = Owner::new();
	run_with_owner(owner, || provide());
	owner.dispose();
	print("disposed");
}

fun main() {
	let root = Owner::new();
	run_with_owner(root, || {
		while_on(|| register("a"));
	});
}
```

→ (v0.52.0) prints `+a`, `disposed`, and never `-a`.

Written as `run_with_owner(owner, provide)`, it's refused: "a `context`-typed parameter takes a closure literal, a named function or variant, a value with the same `context` clause, or a local closure binding (which adopts the clause)". The first choice the message lists, a closure literal, is what anyone reaches for, and `|| provide()` is accepted. But `provide` captured the owner where it was created (`root`), so what it registers belongs to `root`, and disposing `owner` takes nothing back. Nothing warns. The right fix is to type the parameter `provide: (sync || void) context owner_scope`. Then the closure takes the owner at call time, and `run_with_owner(owner, provide)` is accepted as written.

In kolt this was a leak that looked like a logic bug. Actions provided "while a page has focus" were never withdrawn, so a page that lost focus kept its commands in the palette. It took provider-level logging to find.

Recommendation: when the refused argument is a parameter of the enclosing function, say that the fix is to give the parameter the clause, e.g. "`provide` is a closure parameter; to run it under this context, type it `(sync || void) context owner_scope`". List the closure literal wrap last, noting that a closure called inside it keeps the context it was made in. Separately, a lint for `|| f()` passed to a `context`-typed parameter, where `f` is a plain closure parameter, would catch the accepted-but-wrong form.
