# B694 — SERVER: the one-shot owners the server `ui` twin makes for `when`, `when_live`, `swap`, `each` rows and `when_some` are never disposed, so whatever a body registers with its owner - a subscription, an `on_cleanup`, B693's keeper - stays on the store for the process's life, one per render

- status: OPEN - filed 2026-11-02 (lane b693's find)
- kind: bug (std process/web/ui; owner lifetime; leak per server render)
- area: Standard library (web, server)

The browser twin disposes a body's owner when the boundary goes; the server twin, which renders once, has no boundary end and so never disposes. Rec: dispose each one-shot owner right after its body has placed its view - the render is the body's whole life on the server (`let row = run_with_owner(owner, ..); owner.dispose();`), which runs `on_cleanup`s at the right moment too; pin with `store_feed_census` (a server `render` of `when_live` over a store leaves 0 feeds) and the existing server-twin pins unchanged. Alternatively a request-scoped root owner the five sites parent under, disposed at the end of `render`. Sizing S.
