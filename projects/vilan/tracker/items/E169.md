# E169 — Organize Imports OVER-KEEPS a whole-module import: `import pkg::a;` beside `import pkg::a::b;` with only `b` used is kept (no fade, no action; reproduced 2026-09-12: s2), because `import_leaf_is_used` rule (2) keeps a MODULE leaf when the file resolves ANYTHING declared in the module's file — and `b`'s uses are declared there, though the named leaf, not the module import, provides them. Count for the module leaf only what the module import ALONE provides: occurrences whose definition is NOT bound by another import leaf of this file (methods of the module's impls, and `a::x` qualified paths — which reference the module leaf itself and are already rule (1)'s)

- status: OPEN — filed 2026-09-12
- kind: editor
- area: LSP & tooling

**Mechanism.** Rule (2) in `Document::import_leaf_is_used` (document.rs, the `DefinitionKind::Module` arm) tests `declaration_source(occurrence.definition) == home`. Refine: build the set of definitions bound by this file's OTHER import leaves (`type_references` entries at each leaf span, aliases included — the map `unused_import_spans` already walks), and skip an occurrence whose definition is in that set. What remains is what only the module import brings: method occurrences resolved to impls declared in `home`, and anything the file reaches by `a::` qualification (those occurrences reference the module leaf and rule (1) keeps it). A module import whose remaining set is empty is unused: fades and prunes.

**Edge.** A definition reached BOTH through a named leaf and through the module (`a::b()` and `b()` in one file): the qualified use references the module leaf directly (rule (1)), so the module import survives — correct.

**Pins.** (1) `import pkg::a;` + `import pkg::a::b;`, `b()` used → the module import fades and prunes, `b`'s stays; (2) `import pkg::a;` + `const { style().select_off() }` (impl use) → kept (kolt.local 004's pin, unchanged); (3) `import pkg::a;` + `a::b()` → kept; (4) `import pkg::a;` alone, nothing used → pruned (today's behaviour, s3). E168 and E169 are one lane — they edit the same predicate and the same pin file.
