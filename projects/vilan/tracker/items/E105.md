# E105 — an unterminated `css` block completes with ordinary scope where CSS is promised

- status: OPEN — audit run 5's F10; recordable
- kind: bug
- area: LSP & tooling
- source: audit run 5, confirmed over JSON-RPC against the built server

With no closing `}` downstream, `css_position` finds no `Node::Css` and
completion falls to `CursorContext::Expression` — offering `fun`/`for`/
scope names inside what the author is writing as CSS. The code comment
says completion "simply does not fire there"; it fires with the wrong
vocabulary, and none of the 23 S5 pins covers the unterminated shape. The
fix likely rides the parser's recovery (an unterminated block still parses
AS a css node to its recovery point) or a lexical guard in `css_position`.
