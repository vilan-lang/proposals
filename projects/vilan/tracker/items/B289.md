# B289 — the Wire predicate is a SYNTACTIC ALLOWLIST, not trait resolution: `is_wire_type`/`resolved_type_is_wire` accept the six scalars, `List`/`Option`/`Map` of Wire, and `[derive(Wire)]` NAMES — so a hand-written `impl Result<type T: Wire, type E: Wire> with Wire` is invisible to the `[rpc]` signature check ("return type … is `Result<i53, str>`, which is not Wire"), to the `[expose]` element check and to the derive-field check; kolt's `store.vl:184` returns `Option<i53>` where it wants `Result<i53, str>`, with the forty-line impl sitting right above it (and the refusal's own list omits `Map`, which A39 admitted)

- status: OPEN — kolt marker sweep (2026-09-10)
- kind: bug
- area: Reactive core & UI

Make the predicate consult the trait table — a resolved type is Wire when an `impl … with Wire` applies to it (the allowlist stays as the fast path and as the rule for the primitives), recursing into arguments only where the impl's own bounds demand it (`impl Result<type T: Wire, type E: Wire>` binds both; `impl Handle<type T>` binds none, which is C7's phantom rule expressed by the impl rather than by a special case). The three call sites share one predicate. Pins: a user `impl Result<T, E> with Wire` admits `[rpc] fun f(self): Result<i53, str>` and refuses `Result<Opaque, str>` naming the argument; the refusal text names `Map`. A82 lands the std `Result` impl this makes usable without the workaround.
