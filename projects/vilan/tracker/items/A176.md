# A176 — What `any` holds: the native backend's `vilan_rt::Any` is a number, a `str`, a `bool`, NULL and an `Option` of those, the JS backend takes anything, and the checker admits anything - so the same program prints `[ 0, 1 ]` (JS, before M165) or `1` (native) at a user's `any` parameter, and a struct at one builds on JS and fails rustc natively

- status: OPEN - filed 2026-10-26 (std-55's find, Order 55)
- kind: design question
- area: Language

M165 made the JS backend convert an `Option` where it lands at `any` (the native semantics), excepting `print`'s and an external's direct `any` parameters, which take the value as it is. Open: (1) whether `any` is a language type at all for user code (std uses it for `print`, `canonical_hash` and the db bind list only); (2) if it is, refuse a value `any` cannot hold at the checker (F150 (2)); (3) if it is not, refuse `any` outside std. Rec: (2) now, (1)/(3) with `SqlValue` (M175), which removes std's last value-level `any` user.
