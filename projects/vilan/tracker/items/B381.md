# B381 — `==` on a `T: PartialEq` LOSES its bound inside a nested `match` arm within a closure — the same comparison one level up type-checks

- status: OPEN — filed 2026-09-21 (Order 39 sweep; collections-39's FIND 4)
- kind: bug (inference)
- area: Type system & the type solver

Shape: `fun f<K: PartialEq>(..) { xs.each(|x| match x { Some(let k) => if k == key { .. }, None => .. }) }` → 'no operator `==` for `K`' (or the bound-missing form) inside the arm; `if k == key` written outside the `match`, or the `match` outside the closure, both check. Fix: the closure body's generic environment must carry the enclosing function's bounds into nested pattern-arm scopes (the arm scope appears to be built from the closure's OWN parameters only). Pins: the nested shape; two levels of nesting; a control outside the closure.
