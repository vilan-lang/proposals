# B667 — a function with no written return type that calls itself in a `match` arm is refused: "type of match expression could not be resolved"

- status: OPEN — filed 2026-10-21 (kolt's `Panels::open`: the "right" arm fell back to `self.open(path, "split")`)
- kind: checker / inference (S)
- area: language / types

```vilan
fun open(how: str) {
	match how {
		"right" => open("split"),
		_ => print("here"),
	}
}

fun main() {
	open("right");
}
```

→ `Error: type of match expression could not be resolved (subject: str)` at the `match`. In a method with a nested `match` (`"right" => match self.beside() { Some(let at) => …, None => self.open("split") }`), both matches get the error.

Writing `fun open(how: str): void` fixes it. The function's return type is inferred from its body, and the body's `match` has an arm whose type is that same return type. The cycle never resolves, though every other arm says `void` and a function with no written return type is `void` everywhere else.

The error also doesn't say what's unresolved or why: the subject is a plain `str`, and the arm that causes it isn't named.

Recommendation: either treat a self-call's type as the function's declared-or-default return type (`void` when nothing is written and no `ret` gives a value), or resolve the match from the arms that do resolve. Failing that, name the arm and suggest writing the return type.
