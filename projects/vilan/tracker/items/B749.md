# B749 — MISCOMPILE (JavaScript): `if x` and `!x` over a `&bool` view read the `(base, key)` pair, so `if x` is always true and `!x` always false

- status: open
- kind: miscompile (JS backend; scalar views read as values)
- area: crates/vilan-core/src/analyzer.rs (`check_view_value_reads`), crates/vilan-core/src/transformer.rs (`walk_tested_subject`, `read_through_a_scalar_view`)

Repro: `scripts/integration/sweeps/order58/repros/b749-if-and-not-over-a-bool-view.vl`. A scalar view is a pair on JS, and reading it as a value is refused with the "write `*`" diagnostic at the positions `check_view_value_reads` covers. An `if` condition and a unary operand are not among them, and the emitter does not read through there either, so the pair itself is tested: an array is truthy. Decide ONE rule for both positions and every other condition position (`while`, `then`/`else` forms, `&&`/`||` operands, a guard): either the check refuses them as it refuses other value reads, or the emitter reads through as B746 made `match` and `is` do. The second matches what B746 chose for tests. Since B746 a backed enum's view is in the same class. Native is B750.
