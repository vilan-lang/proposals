# E353 — `vilan fmt` has no way to leave one statement as written

- status: OPEN - filed 2026-10-31 (kolt)
- kind: feature (formatter; S)
- area: Formatter

There is no directive that tells `vilan fmt` to keep a statement (or item) exactly as written. Searched `crates/vilan-core/src/formatter.rs` for the usual spellings (`fmt: skip`, `fmt: off`, `fmt-ignore`) and the tracker for an item asking for one: neither exists.

Why it matters: when the formatter gets a construct wrong (E352: a method chain in a `then … else` arm joined onto a 170-column line), the only workarounds are to revert its output by hand after every `vilan fmt .` (kolt has done this five times for `store.vl`'s `mark_unseen`), to stop formatting the whole file, or to rewrite correct code into a shape the formatter handles. Format-on-save makes the first one a recurring chore, and `vilan fmt --check` in CI can never pass on such a file.

Every mainstream formatter has an escape hatch for this reason: rustfmt's `#[rustfmt::skip]`, Prettier's `// prettier-ignore`, Black's `# fmt: skip` / `# fmt: off … # fmt: on`, gofmt has none (and Go is the usual counterexample, which works because gofmt reflows almost nothing).

Recommendation: a comment directive on the line before a statement or item, `// vilan-fmt: skip`, that keeps that node's source verbatim (the formatter already has verbatim slices for macro arguments and interpolated strings, see `formatter.rs` near "keeps the verbatim slices"). Optionally an attribute form for items (`[fmt(skip)]`), which survives comment stripping and reads like `[derive(..)]`. Keep it narrow (one node, not a region) so it is used for formatter bugs, not taste; `vilan fmt --check` could list skipped nodes so they don't outlive the bug they work around.

Kolt's first use: `src/store.vl` `mark_unseen`'s `let readers = facts.private then … else db.prepare(..).all(..).map(..)`, until E352 is fixed.
