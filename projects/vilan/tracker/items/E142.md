# E142 — should a `::` path be allowed to cross a line break? E135's unfixed face: `style::` ⏎ `print(..)` is the legal path `style::print` and swallows the next statement

- status: OPEN — lane parse-fmt-27's find (2026-09-04, Order 27)
- kind: design
- area: Language server & tooling

The parser has no line sensitivity anywhere (`tokens_adjacent` is byte-adjacency), so only a rule that `::` does not cross a newline catches an incomplete path before the next line's identifier. Free in this tree (census: zero occurrences). If accepted: the segment after `::` must start on the same line, else "a name after `::`" (E135's message) — pins for the swallowed-statement shape and a multi-line path written deliberately (refused with the steer to join the line).
