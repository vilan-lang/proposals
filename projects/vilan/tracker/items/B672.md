# B672 — an unsupported string escape (`"\u{10FFFF}"`) is kept as its literal characters, with no error

- status: OPEN — filed 2026-10-24 (kolt spelling: an upper bound for a SQL prefix range)
- kind: diagnostic (lexer; S)
- area: Language & checker

```vilan
import std::io::assert;

fun main() {
	let s = "a\u{10FFFF}";
	assert(s.len() == 3, "a, then U+10FFFF (two UTF-16 units)");
}
```

→ the assertion fails: `s` is 11 units long, `a` followed by a backslash (92), `u` (117) and the rest of `\u{10FFFF}` as written (v0.52.0). Nothing reports it: `vilan build`, `vilan check` and `vilan test` all accept the file.

The text that relies on it then fails quietly elsewhere. In kolt it was the upper bound of a SQL range (`word > ? AND word < prefix || "\u{10FFFF}"`): a literal backslash sorts before every letter, so the range matched nothing and word completion never answered, with no error anywhere.

Recommendation: either support `\u{…}` (Rust and JavaScript's form for a code point), or reject an escape the lexer doesn't know (`unknown escape \u in a string`), as it would any other malformed literal. Keeping it verbatim is the one choice nobody writing it can mean.
