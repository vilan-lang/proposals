# E366 — A `[library]`'s root file is analyzed for EVERY entry of the dependent, reachable or not; and a trait `impl` in a file declared `[platform("browser")]` colors every call of that trait's method

- status: OPEN - filed 2026-11-09 (kolt, splitting its UI toolkit into one library per module)
- kind: bug or design gap (platform coloring; packages)
- area: Platforms / packages

Two finds from the same change.

**1. Unreachable library roots are type-checked under the server's platform.** Kolt's toolkit was one library with a stub `lib.vl` and a module per file; the server reached only `rich_text::document`. Split into one library per module (each module now its package's `lib.vl`), the node entry started failing inside libraries it never calls:

```
Error: struct 'View' has no field 'element'
    ╭─[ ./lib/interact/src/lib.vl:70:4 ]
    ├─[ ~/.vilan/std-cache/../std/src/process/web/ui.vl:74:8 ]
```

The browser entry compiled. So a dependency's root module is loaded and analyzed for each entry of the package that declares the dependency, under that entry's `std::web::ui` twin, where a non-root module is only analyzed when something imports it. The fix on kolt's side was right anyway (`[platform("browser")] mod self;` at the top of each browser-only library), but nothing pointed there: the error reads as if std's `View` had lost a field.

Rec: analyze a dependency's root on the same terms as any other module (when imported or reached); or, when a file fails only under a platform no entry reaches it from, say so and suggest the file-platform declaration.

**2. A browser-declared file's trait impl makes the trait's method browser-only everywhere.** With `[platform("browser")] mod self;` on a library whose file holds `impl StorageKey<type T> with Hashable { fun hash(self): Hash .. }`, the SERVER build fails at unrelated sites:

```
Error: `hash` requires the `browser` platform its file declares and cannot run on `node:24`
  reachable from the entry: main → factory (std::rpc::server) → .. → reply_store (std::rpc::mirror) → walkers ..
    ╭─[ ./src/shared/dates.vl:59:2 ]
 59 │     civil_from_days(days) == (y, m, d) then Some(days) else None
```

No `StorageKey` exists on the server. Dynamic dispatch seems to count every impl of `Hashable` as a possible callee, so one platform-declared impl colors every `hash` call. Kolt left the declaration off that one library.

Rec: color a trait call by the impls whose subject type can reach the call site (or at least skip impls for types the entry never constructs). Pin: a node entry comparing tuples beside a dependency with a browser-declared `impl X with Hashable`.
