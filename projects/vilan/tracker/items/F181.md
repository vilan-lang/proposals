# F181 — Revisit the BSL-1.0 dependencies in the gfx crate (`clipboard-win`, `error-code`, the Windows half of `arboard`): accepted for now by the owner

- status: open
- kind: dependency review (licence) — OWNER asked to revisit
- area: crates/vilan-rt-gfx/{Cargo.toml,about.toml,THIRD-PARTY-NOTICES.txt}, crates/vilan-rt-gfx/src/host/clipboard.rs

The clipboard's Windows backend comes through `clipboard-win` 5.4.3 and `error-code` 3.4.0, both BSL-1.0 ONLY (the Boost Software Licence: permissive, the licence text must accompany source distributions, no attribution duty for binaries). Until now the gfx crate's accepted list was MIT, Apache-2.0, BSD, ISC, Zlib and Unicode; `about.toml` gains BSL-1.0 with this ruling. WHAT TO DECIDE WHEN REVISITING: (a) keep BSL-1.0 on the accepted list for good (and say so in the crate's licence comment and the release notes' notices); (b) replace the Windows half with our own code over the Win32 clipboard calls (needs `unsafe` or a safe wrapper crate with an accepted licence: `windows`/`windows-sys` are MIT OR Apache-2.0, but the calls are unsafe, and the crate forbids `unsafe`, see F171's ruling); (c) drop `arboard` for per-platform crates. Also check at that time whether `arboard` or `clipboard-win` have changed licence or whether the compiler's own workspace would ever take a BSL-1.0 dependency (it has none today). Trigger to revisit: before the first release that ships native UI as supported on Windows, or at the next dependency review, whichever comes first.
