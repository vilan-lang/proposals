# A163 — A161's premise does not hold: std cannot write `[T; n]`'s `Items<T>` impl — an impl subject's array LENGTH is an integer literal (`parse_array_length`), so there is no head that covers every length; the door is a length-erased head (`impl [type T; _] with Items<T>`) or I2's const-generic lengths

- status: OPEN — filed 2026-10-08 (std-48's find, Order 48)
- kind: language design (M–L): impl heads over every array length
- area: Collections

`xs.push_many(a)` over `a: [i32; 3]` is refused "'[i32; 3]' does not implement trait 'Items<i32>'", and no std impl can fix it: `Type::Array(element, usize)` carries a literal length, every comparator (`compare_type`, `compare_type_rigid`, impl_select's `elements_agree`) compares lengths by value, and the native backend monomorphizes on types (`write_type_key` writes `Arr[T;3]`, `rust_type` writes `[T; 3]`), so an any-length head would need (1) a length binder or wildcard in impl-subject position, (2) the comparators to admit it, (3) mono to key the instance by the receiver's concrete length and substitute it into `self`'s type, and (4) a rule for what `self.len()` means inside (today `.len()` folds to the literal, fixed-arrays.md §10). That is the narrow half of I2 (blocked on what `const N` means); the narrow door asks only 'every length', never names `N`. Natively F109 (an annotated array literal emits `vec![..]`) blocks any differential first. Also met: B582 (an array impl head's element binder). Rec: rule whether the length-erased head is worth its own slice ahead of I2; until then A161 stays open and `push_many(a.iter())` is not available either (arrays have no `iter()`). Sizing M–L; parser + solver + mono + both emitters.

- 2026-10-09 (the owner: every open Order 48 ruling accepted as recommended): RULED: not its own slice; goes with I2 (const-generic lengths) when that is designed. A161 waits on it.
