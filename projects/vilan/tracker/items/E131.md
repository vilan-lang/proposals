# E131 — member completion resolves a CALL receiver in ANALYZED coordinates: a receiver typed since the landing answers the OLD expression's type (`<div .styled(const style::style().` offers View's members)

- status: OPEN — the owner's find while migrating kolt (2026-09-04); reproduced at 289e2a2b by the triage lane (stale request inside the 150 ms debounce)
- kind: editor
- area: Language server & tooling

Base text landed: `<div .styled(base_style)>`. One un-landed change to
`<div .styled(const style::style().|)>` and a request inside the debounce
→ 22 labels: `element, text, class, styled, style_var, attr, on, child,
bind_text, ..` — View's method set, exactly the owner's report; settled
→ 89 Style members. Isolation: a BARE-NAME receiver (`base_style.|`)
answers Style even stale, because that arm reads the name off the LIVE
text; only the call-receiver arm is wrong.

Cause: `receiver_nominal_id`'s complex-receiver arm (vilan-ide/src/
completion.rs ~1450) and `lifted_member_completions` (~1408) do
`to_analyzed_offset(receiver_end - 1)` then `entity_at`; `to_analyzed_
offset` (analysis.rs ~207) is a line/character round-trip that CLAMPS —
it repairs other lines (E52) but the cursor's own line is always an
edited line; live col ~34 clamps to the end of the 25-char analyzed
line, `entity_at` yields the enclosing `.styled(..)`/element, typed
View. The keystroke layer does not catch it: `keystroke_verdict`
(document.rs ~2820) is `Exact` because `shape_stamp` (keystroke.rs
~271) skips `fun` bodies, and `keystroke_completion_over` (~3033) reads
Exact as "the landed analysis owns the member list" — but Exact is the
anchor's claim about TOKEN positions, and the anchor is line-aligned, so
the cursor's line is by construction inside the edit window.

Fix: (S, low risk) gate — if `receiver_end` falls inside the anchor's
edit window (or analyzed != live on the receiver's line), decline rather
than answer; a wrong list becomes no list, the next settled request is
right (Q4's "a lie is worse than silence"). (M) resolve live — walk back
from the `.` over balanced brackets on the live text and type the
receiver structurally against the landed Program (path::f() → callee
return; x.m() → x's nominal's m; x.f → field); `cursor_context` (~1215)
already parses the whole live buffer per request, so a live tree is free
today. M29 (drop the per-request parse; per-type member tables) must not
assume the receiver's type is findable in analyzed coordinates — the
receiver's IDENTITY has to come from live text; pair this with M29.
Related: E125 (closed; the identical coordinate bug fixed for
semanticTokens/range via `Anchor::map_span`), M25, E121, E52.
Compounds with E129 on kolt's style chains: user-visible cost on kolt
is E131 > E129 > E130.
