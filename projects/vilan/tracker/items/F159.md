# F159 — Native JSON objects keep insertion order only - JS puts integer-like keys first, ascending

- status: open
- kind: bug (native runtime)
- area: native backend

Found by lane std-58 while adding `JsonValue::keys` (F158). `{"b","2","a","1"}` gives `1,2,b,a` on node; native keeps `b,2,a,1`. So native `keys()`, `tag()` and `stringify` disagree with node for integer-like keys. The fix belongs in the parser's object insert (and any builder path). The lane could not add an ignored pin without a tracker id: add one under this id, then fix. Size S.
