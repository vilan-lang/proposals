# A153 — a MIRRORED `Store`: the server holds a `Store<Record>`, the client mirrors it, frames are PER-FIELD patches - so a snapshot is sent once, a rename sends one string, and a field handle reached through its parent is not a maybe type

- status: OPEN — filed 2026-10-03 (from the owner's design conversation); paper in Order 46 if asked
- kind: design (paper)
- area: Reactive core & UI

The owner's rule: an rpc for a granular field that can be called where the parent does not exist must answer a maybe type; a field reached THROUGH the parent struct need not, since the struct must exist to be passed and the field source is disposed when the parent's derivation turns `None`. Amendment: holding the struct proves the parent existed when the client last heard - a delete can cross a field call on the wire - so the WIRE answer stays a maybe; the client model hides it (inside the parent's scope an `Absent` field means the scope is about to be disposed: hold the last value).

The first value is the catch: a field mirror has nothing until its first frame, so a non-optional `Source<T>` needs a WAIT (A152) or a SEED (the snapshot carries the field's current value; the handle starts from it and follows its own channel). Seeding costs transfer only while the snapshot is the unit of update. The paper: `Store` over `std::rpc` - what a `[rpc]` returning `Store<T>`/`StoreSome<P>` puts on the wire (the seed frame, then slot-addressed patches), how leases map to slots (per-subscription slots are already the store's unit), keyed and sequence nodes (after A149 S3), identity and the contract hash, reconnect (re-seed), and what kolt's `GlobalStore` and `model.vl` become. Doors and recs; probes on v0.43.0.
