# M15 — the const-pass scaling gate is wall-clock and reds the suite under lane load

- status: OPEN — flagged by lane a30 (Order 21), bit lane fs-s5's verdict
  (Order 22: 8.83x vs the 6x bound at loadavg 82; 2.84 s solo)
- kind: perf
- area: Performance & footprint
- source: two lane reports, 2026-08-29

`perf_baseline::the_const_pass_scales_with_its_const_sites_and_not_with_
their_square` asserts a WALL-CLOCK ratio inside the default suite, so a
loaded machine (parallel lane suites, CI contention) reds it with no
regression anywhere — the second incident in two orders. Options, one to
pick: (a) move it to the deliberate-run tier (`#[ignore]` + the weekly
ignored-pins leg, the perf baseline's own posture — and N31's gate now
requires the reason to name this item); (b) measure CPU time rather than
wall clock (the ratio's intent, immune to load); (c) widen the bound
(refused: a bound wide enough for loadavg 82 catches nothing). (b) if the
harness can read thread CPU time honestly; else (a).
