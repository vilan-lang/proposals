# B152 — `ret <expr>` without a trailing semicolon emits `return return <expr>;`

- status: OPEN — reproduced on 0.38.0 (lifetimes session, 2026-08-28)
- kind: bug
- area: Type system & the type solver
- source: the lifetimes session's probes (side finding), 2026-08-28

`fun a(): i32 { ret 1 }` emits `function a() { return return 1; }` — a
bundle that does not parse. `ret 1;` is fine, so the tail-position
statement/expression seam double-wraps the return. Minimal repro is the
one-liner; the pin asserts the emitted bundle parses (node --check) and
runs.
