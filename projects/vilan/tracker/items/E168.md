# E168 — Organize Imports OVER-PRUNES a named leaf whose module the file still needs for its `impl`s: `import pkg::a::b;` with `b` unused fades as "unused import" and the action DELETES the statement, but `a.vl`'s `impl Style { fun select_off(self) .. }` arrived through that import (impls travel with ANY import reaching the module, not only a whole-module one), so the next analysis is "Style has no method 'select_off'" — the organizer broke a green build (reproduced 2026-09-12: s1c → s5). `import_leaf_is_used` rule (2) — "a whole-module import brings every impl in that module's file" — keeps a MODULE leaf on the file's provenance test, and a NAMED leaf never reaches that test. Fix: when every named leaf of a statement is unused but the file resolves something DECLARED in the module's file (rule (2)'s own test, applied to the statement's module), REWRITE the statement to `import pkg::a;` instead of deleting it; the fade stays on `b` (it is unused) and the action's edit is the rewrite

**Mechanism.** In `Document::organize_imports` (the `keep` predicate threaded into `formatter::organize_run`/`prune_import_branch`, formatter.rs ~1454), a statement whose every leaf is unused is today dropped by `prune_import_branch` returning `None`. New step before the drop: resolve the statement's module (the path minus its leaves; for a brace set, the common prefix), and ask rule (2)'s question of it — does `reference_index.occurrences_in(entry)` (excluding occurrences written inside import statements) contain a definition whose `declaration_source` is that module's file? If yes, the statement becomes `import <module>;` (rendered through the same canonical printer, sorted into place). If no, drop as today.

**Fade.** `unused_import_spans` keeps fading `b` — it IS unused — and the hover/fade text for that leaf can say "unused; the module's impls are in use, Organize Imports rewrites this to `import pkg::a;`" so the mark and the fix agree (E114's contract).

**Pins.** (1) `import pkg::a::b;` + `const { style().select_off() }` → rewrite to `import pkg::a;` and the rewritten file analyses clean; (2) `import pkg::a::{ b, c };` with `c` used → `{ c }` as today (the rewrite only fires when nothing survives); (3) `import pkg::a::b;` with neither `b` nor any impl used → deleted as today; (4) a module import + impl use → kept (the existing kolt.local 004 pin); (5) the fmt/organize agreement pin (`organize_imports_renders_a_split_run_the_way_fmt_does`) extended with a rewrite case.
