# M210 — A base-cache HIT still copies the stored world (0.30 G per keystroke), and the const pass costs 0.78 G when every one of its 1,227 sites is a cache hit

- status: open
- kind: performance (LSP latency; found by the 2026-11-17 profile)
- area: crates/vilan-core/src/analyzer.rs (the base cache's clone-on-serve), const_eval.rs + const_cache.rs (the hit path)

Two fixed costs paid on every served keystroke. (1) The stored prefix world is cloned for the hot set to be walked over; 3.3% of a leaf keystroke. Share what the hot set cannot write (persistent or copy-on-write tables), clone only what it can. (2) With every const site a hit, the pass still spends 8.6% of the keystroke finding that out: 1,227 lookups should not cost 0.78 G, so the cost is in building keys or in the walk to the sites, not in evaluation. Profile the hit path alone; M163 is the larger question of whether the pass can be skipped for items whose records say nothing moved.
