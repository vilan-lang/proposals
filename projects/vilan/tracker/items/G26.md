# G26 — the CONST interpreter has no `indexOf`/`lastIndexOf`: `str::index_of` / `last_index_of` (option.vl, over `raw_index_of`/`raw_last_index_of`) fail in any `const` evaluation with 'the string method `indexOf` is not available at expansion time' — the natural way to search a file `asset::read` returned; `includes`/`split`/`substring` are there, so the workaround is `split` on the needle

- status: OPEN — filed 2026-09-28 (kolt's search system)
- kind: bug (const)
- area: Macros & const

Repro (0.41.1, not fixed on next @26b0bba8):

```vilan
fun find(text: str): usize {
	match text.index_of("b") {
		Some(let at) => at,
		None => 99,
	}
}

fun main() {
	let at = const find("abc");
	print(i"{at}");
}
```

→ `const evaluation failed in index_of: the string method indexOf is not available at expansion time`.

The interpreter's string-method table (interpreter.rs, the `"trim"` … `"substring"` arms) has `trim charCodeAt toLowerCase toUpperCase includes startsWith endsWith repeat replaceAll split substring` — no `indexOf`/`lastIndexOf`. Worth a census of every `[extern(method, …)]` / external `str` method in std against that table, so the gap closes as a class rather than by the next one found.

Found by kolt's build-time search dictionary (`src/lib/search_dict.vl`: `const lookup(word)` reads a shard with `asset::read` and looks the headword up; it uses `split("\n" + word + "\t")` instead).
