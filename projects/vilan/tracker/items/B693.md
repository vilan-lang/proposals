# B693 — A read through `StoreSome::assume` copies the whole payload, every time (what `when_remote_live` hands its body)

- status: OPEN - filed 2026-11-02 (kolt, measuring B689's fix on next f9fcc6ce)
- kind: perf bug (std reactive store)
- area: Standard library (reactive store)

B689's fix makes the keyed step lend in place, and its repro is now flat on next (2,000 reads in 2-3 ms whatever the record's size). Kolt's pages didn't get faster with it, because their reads go through `StoreSome::assume` (std/src/reactive/store_core.vl, ~line 1046), which `when_remote_live` uses to hand its body a `Store<P>`. Its lend keeps the last payload for a reader running in the turn that ends the variant:

```
lend = |f: |&P| void| {
	mut reached = false;
	lend(|payload: &P| {
		reached = true;
		last = Some(*payload);
		f(&payload);
	});
	...
}
```

`last = Some(*payload)` deep-copies the whole payload on every read below the handle. Kolt wraps an organization's store this way, so reading one task's title copies the entire organization (every task, channel, message and document in the store).

Measured in kolt on next, opening the Tasks list of an organization of 2,089 tasks: 25,000 field reads took 10.3 s, of which copying the fields read was 5 ms; `__clone` ran about 1.7 billion times, roughly 70,000 per read, the size of the organization's maps. Opening Tasks took 16 s, the Board 8 s, the Table 16 s, about the same as on 0.53.1.

Repro (standalone; prints three timings): kolt session scratchpad `assumerepro/assume.vl`, the whole file:

```
import std::hash_map::HashMap;
import std::reactive::store::Store;

[extern("(() => performance.now())")]
external fun clock_ms(): f64;

[derive(PartialEq, Storable)]
struct Record {
	title: str,
	notes: List<str>,
}

[derive(Storable)]
struct State {
	records: HashMap<i32, Record>,
}

/// Reads record 1's title `reads` times through `assume()` (what
/// `when_remote_live` hands its body), the state holding `count` records.
fun read_title(count: i32, reads: i32): f64 {
	mut records: HashMap<i32, Record> = HashMap::new();
	mut index = 0;
	for index < count {
		records.insert(index, Record { title = "a title", notes = ["one note", "another note"] });
		index += 1;
	}
	let store: Store<Option<State>> = Store::new(Some(State { records }));
	let live = store.some().assume();
	let started = clock_ms();
	mut total = 0;
	mut read = 0;
	for read < reads {
		total += live.records().at(1).some().title().get().map_or(|title| title.len(), 0usize).as_i32();
		read += 1;
	}
	total > 0 then clock_ms() - started else 0f
}

fun main() {
	print(i"10 records: {read_title(10, 2000)} ms");
	print(i"1000 records: {read_title(1000, 2000)} ms");
	print(i"10000 records: {read_title(10000, 2000)} ms");
}
```

On 0.53.1: 14.7 ms, 214 ms, 2,850 ms. On next f9fcc6ce: 13.4 ms, 271 ms, 4,264 ms. Time grows with the state, though only one title is read.

Recommendation: keep the fallback without copying on each read. For example, store it only when the variant ends (the turn that makes it not live is the one place it is needed), or keep a reference the lend shares rather than `*payload`. A pin: the repro's three timings within a small factor of each other. Sizing S.
