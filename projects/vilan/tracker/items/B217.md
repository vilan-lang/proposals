# B217 — a generated-code type miss resolved in `build()` (the `prepped_*` route) is not anchored at the `[derive(..)]`: it lands at the declaring `mod` or the type

- status: OPEN — lane cascade-26's find (2026-09-03); B188's anchoring rule has a route it does not cover
- kind: bug
- area: Diagnostics

Two of B201's four pre-fix diagnostics carried no "in code generated
by this attribute" anchor — they landed at `mod shapes` and at `enum
Kind` instead of at the `[derive(..)]`, because they came through the
`prepped_*` type references resolved in `build()`, which the derived-
range redirect does not cover. Moot for B201's program now, real for
any other generated-code type miss. Fix: the redirect covers the
`prepped_*` route (the generated range is known when the references
are prepped); pin with a derive template that names a type that does
not exist (a plant in a test-only generator) and assert the anchor.
