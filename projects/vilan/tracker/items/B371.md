# B371 — INTERNAL ERROR — a generic blanket method that calls the TOTAL `flatten` at an abstract inner source type — `impl type S: Source<type T> { fun switch<U, I: Source<U>>(self, f: sync |T| I): SignalCell<U> { self.map(f).flatten() } }` — fails at emit with `internal: a call resolved to Source's requirement get, which has no body … first reached while emitting flatten (reactive.vl:1538); please report this program`, while the OPTION-shaped twin (`and_then` over `Source<Option<T>>` calling the optional `flatten` at an abstract `I: Source<Option<U>>`) compiles and RUNS. Repro (`scratchpad/andthen/sw6.vl`; the result annotated, so B300(a)'s inference gap is out of the picture):

```vl
import std::reactive::{ Signal, SignalCell, Source, run_with_owner, Owner };
export impl type S: Source<type T> {
	fun switch<U, I: Source<U>>(self, f: sync |T| I): SignalCell<U> {
		self.map(f).flatten()
	}
}
fun main() {
	let n = Signal::new(1);
	run_with_owner(Owner::new(), || {
		let doubled: SignalCell<i32> = n.switch(|m| Signal::new(m * 2));
		print(i"{doubled.get()}");
	});
}
```

→ the `internal:` above, pointed at std's `flatten` (reactive.vl:1538). The free-function spelling `fun switch<T, U, S: Source<T>, I: Source<U>>(source: S, f: sync |T| I)` fails the same way once its result is annotated. The HYPOTHESIS (verify): `flatten`'s subject is `S: Source<type I: Source<type U>>`; at the `switch` call site the receiver is `SignalCell<I_switch>` where `I_switch` is `switch`'s own bound type parameter — `bind_subject_bound_binders` grounds `flatten`'s `I` to `I_switch`, but the emitter then needs `I_switch.get()` resolved to a concrete impl at `switch`'s INSTANTIATION (`SignalCell<i32>` here), and the substitution from the outer generic call is not applied to the inner blanket's bound binders — the requirement `get` is reached with no body. The `Option` twin succeeds, which narrows it: the difference is `self.get().get()` (a chained dispatch on the freshly-bound `I`) versus `match self.get() { Some(let inner) => inner.get() }` (a dispatch on a PATTERN-BOUND local) — so the chained-receiver path is the suspect.

Fix direction: whatever grounds `I` in the inner blanket must carry the OUTER call's substitution (the same lesson as B369: the caller substitutes, the callee's inferred types are handed through verbatim). Pins: `switch` as above runs and prints `2` then `10`; the free-function form; the `Option` twin unchanged; a `b371_*` in the solver's pins beside `b300_*`. Until fixed, A123's std `switch` is written over `on_change` directly (which is the better body anyway — one cell).
