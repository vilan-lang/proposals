# B415 — a HOST for file-level attributes: `[platform("browser")] mod self;` instead of the bare `[platform("browser")];` statement F27 R1 shipped — `self` a reserved module name; and possibly `export *;` → `export self::*`

- status: OPEN — filed 2026-09-25 (the owner's counter-proposal at the Order 41 rulings)
- kind: design
- area: Type system & the type solver

Rec: ADOPT `mod self;` as the host, now — the bare attribute-statement is a grammar oddity, and a declaration gives every future file-level attribute a home (`[internal]`/`[deprecated]` on a module, `[lints]`, `[doc]`); R1 just landed and nothing uses `[platform(..)];` yet, so the respelling costs one order and nothing later. DEFER `export self::*`: `export *;` is fine as is, and `self::` as a path prefix (paths relative to the current module) is a feature of its own — if it is wanted, `export self::*` follows from it and `export *;` can stay as sugar. Order 42, editor lane (with the `mod self;` row in the EBNF, formatter, LSP).

- 2026-09-25 (Order 42 GO): R-d RULED — `export self::*` DEFERRED; `export *;` stays; `self::` paths are Order 43's question. syntax-42 builds `[platform(..)] mod self;` as the host now, removing the bare `[platform(..)];` form.
