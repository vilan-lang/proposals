# A96 — HMR throws WEBSOCKET ERRORS, one per remote source: the socket's HMR teardown (rpc.vl:1054) is a BARE `duplex.socket.read().close()` that never advances the duplex's state, so for the rest of the swap the duplex still reads `Connected` while the browser socket is CLOSING — the tree's disposal (registered AFTER the dial in kolt: `connect_with` at client.vl:47, `mount_root` at :60; teardowns run in registration order) releases every `RemoteSource` lease, each `flush_close` sends its `Unsubscribe` frame through `SocketDuplex::send` (rpc.vl:533, guarded on `Connected` — the guard passes), and every `transmit` on a closing socket is a browser console error ('WebSocket is already in CLOSING or CLOSED state'), one per lease. Then `onclose` fires, `handle_drop` (rpc.vl:952) finds `Connected`, rejects pending with 'connection lost' and REDIALS with backoff — the OLD bundle's duplex reconnects and lives on beside the new bundle's, a zombie connection per swap. Fix: the teardown calls `close_for_good(duplex)` (rpc.vl:925 — state `Closed` first, socket close, `on_terminal` teardowns), so `send` drops the late releases silently and `handle_drop` stops at its guard; no redial, no zombie

**Sequence, as written today.** (1) swap → teardown list in registration order: the duplex's closure runs first in kolt (dial precedes mount), `socket.close()` puts the browser socket in CLOSING; `duplex.state` stays `Connected` because only `onclose`/`onerror` (async, next task) reach `handle_drop`. (2) `mount_root`'s teardown (browser/dev.vl:22) disposes the root: every `RemoteSource` lease releases (rpc.vl:3538), `at_release_settle` defers `flush_close` to the turn's settle + one microtask hop — still before `onclose` — and each sends `Unsubscribe` through `send`, whose `Connected` guard passes: `transmit` on a CLOSING socket, one console error per source. (3) `onclose` → `handle_drop`: state `Connected` → `Reconnecting`, `reject_pending("connection lost")` (errors for any in-flight call), `dial_with_backoff` — the old duplex redials, succeeds against the running server, and re-attaches whatever mirrors survive; the new bundle dials its own. Two connections; the old one is unreachable from the new bundle and never closes.

**Fix.** `hmr_register_teardown(|| close_for_good(duplex))` — `Closed` is written first, so (2)'s sends are dropped by the guard (the server drops the connection anyway; the frames were waste), and (3) stops at `handle_drop`'s state guard: no reject noise, no redial. `on_terminal` runs `dispose_on_close`, which is what a torn-down session should do. Registration ORDER does not need to change (a `Closed`-first close is order-independent), but the shim could run teardowns LIFO for the general case; not required here.

**Pins.** The HMR e2e (hmr.md's real-event path): after a swap, (a) no `transmit` on a socket that is not OPEN (spy on the socket), (b) the old duplex's state is `Closed` and `dial_with_backoff` was not entered again (dial counter), (c) the server holds ONE connection after the swap settles, (d) a `RemoteSource` minted by the new bundle resyncs (the K6 path, already pinned). Kolt is the manual confirmation: no console errors on a swap with the channel list open.
