# B159 — S3's teardown-region widening is dead in every nested scope: a RELEASED miscompile

- status: OPEN — audit run 5's F1, 2026-08-29; FIX-NOW, in-order lane running
- kind: bug
- area: Transformer & codegen
- source: audit run 5 (the lowering differential), reproduced on installed 0.39.0

`widen_over_declarations` (transformer.rs ~7341) looks up
`declared_binding_extents` by `statements[index]` — the DIRECT statement —
while the dataflow keys the map on `chain.first()`, the OUTERMOST enclosing
statement (liveness.rs ~192). Inside an `if`/`match` arm or a loop body
whose construct is itself a statement of an enclosing block, the ids differ,
the lookup misses, the fixpoint never runs, and the emitted `try` traps a
`const` whose read follows it: `ReferenceError` at run time from accepted
vilan. The audit's differential isolates it exactly — the same `if` as the
function's TAIL widens correctly; add one statement after it and it breaks
(one-element vs multi-element chain). Not affected, probe-verified: closure
bodies, the function body itself, the own-parameter split. The existing pin
(`a_teardown_region_never_closes_over_a_name_read_after_it`) covers the
function-body level only. The fix keys the two sides consistently and pins
the SHAPE MATRIX: if arm, match arm, loop body, nested blocks, tail-vs-
statement control, each red-first.
