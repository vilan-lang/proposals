# F127 — A spread of a tuple LITERAL into a spread parameter (`draw(..(3, 4))`) is refused natively — "does not emit a spread element whose tuple type did not resolve yet" — while JS runs it

- status: OPEN — filed 2026-10-09 (lang-a-49's find, Order 49)
- kind: native gap (S)
- area: Native backend

`draw(..p)` over a binding builds natively; spreading the literal itself does not, labelled or not (B569 S4 met it with `draw(..(x = 3, y = 4))`). The spread operand's own tuple type is not recorded for a literal operand (`tuple_element_types` covers elements, not a spread operand), which `spread_tuple` reads. Repro: finds/native_spread_of_a_tuple_literal.vl. Sizing S; vilan-rust (or the analyzer's record for a spread operand).
