# E365 — std gaps met porting kolt's build steps from node to Vilan: no way to start a process, no gzip, no pattern matching on text, a thin `str`

- status: OPEN - filed 2026-11-09 (kolt, `scripts/*.mjs` rewritten as `scripts/src/*.vl`)
- kind: std gaps (several small ones, one item so they are seen together; split as they are taken)
- area: Standard library / process, text

Kolt's three build hooks (fetch a pinned release, check its sha256, gunzip, untar, generate) and its test runner are Vilan programs now. Their outputs were compared with the node scripts' and match. What they had to bind or write themselves:

1. **Starting a process.** `std::process` has `args`, `env`, `exit`, but nothing to run a command. Bound `node:child_process` `spawnSync` plus a `(() => ({ stdio: 'inherit' }))` options helper. Wanted: `process::run(command, args)` giving the exit status, with inherited or captured output.
2. **gzip.** Bound `node:zlib` `gunzipSync`. Wanted: `std::compress::gunzip(Bytes): Bytes` (and tar reading is ~60 lines each script would otherwise repeat; kolt keeps one in `scripts/src/archive.vl`).
3. **Text patterns.** No regex and no character classes: Hunspell's affix conditions (`[^aeiou]y`) and SVG attribute scanning were written as hand scanners over `code_at`. A small matcher (classes, anchors, repetition) would have covered every use.
4. **`str`.** No `index_of(needle, from)`, no way to take one character (`substring(i, i + 1)` everywhere), no `split` on whitespace runs, no radix parse (`parse_i32` is base 10; tar sizes are octal, WordNet counts hex), no `pad_end`.
5. **`fs::exists`.** Written as `fs::stat(path).is_some()`.
6. **A function that never returns.** `process::exit` is typed `void`, so a `fail(message)` helper can't end a value-returning function; callers fall through to code that can't run.

Also noticed: inside a `[library]`, a test file reaches the root module's items as `pkg::lib::{ .. }`; `pkg::{ .. }` says "cannot find 'expand' in the imported path".
