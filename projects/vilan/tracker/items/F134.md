# F134 — Natively a LITERAL leg of a `match` whose subject is a call handing back `Option<&str>` emits Rust rustc refuses — `match shelf.at(0) { Some("first") => .., Some(let name) => *name, None => .. }` fails E0277 (`PartialEq<str>` is not implemented for `Rc<str>`, at `&*__literal0 == "first"`); JS prints `lit` since B577

- status: OPEN — filed 2026-10-12 (fix-51's find, Order 51)
- kind: bug (native; S)
- area: Native targets & rendering

F21 carries the payload view through a `match` subject as a reference, and the literal test compares the reference's `&Rc<str>` against `&str`. The JS side (B577, fix-51) tests a literal leg against the value read out of the kept subject while the capturing leg keeps the view. Natively the literal comparison needs one more deref (`**__literal0 == *"first"`, rustc's own suggestion) when the subject carries a payload view. Expected on both: `lit`, `second`, `none`, `only literal`. Sizing S; vilan-rust's pattern emission. native-51's.
