# B649 — A VIEW of a scalar handed to a BY-VALUE parameter checks clean and answers differently on the two backends - `numbers.contains(&2)`, `numbers.index_of(&2)`, `same(2, &2)` over `fun same(left: i32, right: i32)`, `numbers.contains(&two)` print `false` on JS and `true` natively

- status: OPEN - filed 2026-10-16 (solver-54's find, Order 54)
- kind: miscompile (JS) - a view argument at a by-value parameter
- area: Language

Met writing B637's view pin (`numbers.contains(&make().unwrap_or(2))`). The checker accepts `&expr` where the parameter takes `T` by value (no convention mismatch is reported), and the JS emitter passes the scalar view pair (`[cell, key]`) as the value, so `==`/`eq` compares an array with a number; natively the value is passed. Both doors are open: refuse a `&` argument at a by-value parameter with a steer (drop the `&`), or read the view at the call (auto-deref, as a `*view` would). Rec: refuse (a view the callee cannot keep is noise at a value position; the estate likely has 0 sites - count first). `miscompile`.
- 2026-10-26 (solver-55, Order 55): FIXED on branch solver-55 @0589c782 (`diagnostics`) — refused with "drop the `&`"; estate 0. Premise held, with one correction: a generic parameter whose `T` is a view (`Option<&i32>`'s `unwrap_or(&0)`, B577's fixture) takes a view and is exempt.
