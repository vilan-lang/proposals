# B203 — the watch/HMR leg-skip set is computed before any leg compiles: a leg whose sources include another leg's artifact can skip against a hash about to be invalidated

- status: OPEN — perf-25 lane's find (2026-09-01); pre-existing, shared with the HMR round (E12 half b's structure)
- kind: bug
- area: CLI & build

`build --watch` (M22) and the HMR round decide "fresh" per leg from
recorded source hashes BEFORE any leg of the round compiles. If leg
B's recorded sources include leg A's `dist/` artifact (a server leg
serving the client bundle, say), B can be judged fresh against A's
OLD artifact, then A recompiles and B's inputs are stale for the
rest of the round. Fix: order the legs by artifact dependency
(A's outputs ∩ B's inputs ≠ ∅ ⇒ A first) and decide each leg's
freshness AFTER its predecessors compiled — or re-hash a leg's
artifact inputs at its own turn. Pin: a two-leg workspace where B
reads A's bundle; edit A; B must recompile in the same round.
