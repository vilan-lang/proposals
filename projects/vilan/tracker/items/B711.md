# B711 — Struct keys: `S.x` as a typed `Key<S, F>`, `~` for the expected type, erased `AnyKey<S>`

- status: RULED 2026-11-25 (the owner: "Recommendations accepted for Q1-Q14"; paper rev 2 §8a, R1-R14) - READY TO QUEUE by stage (S1-S5); B753 fixed on `next` 2026-11-25, B758 (a generic view return at a scalar, JS) before S1 or with it; filed 2026-11-05 (kolt)
- kind: language feature
- area: Type system
- paper: `proposal/struct-keys.md`

A value that names a struct field, checked by the compiler, generalizing `TupleKey` from tuples to structs.
- `S.x` (and paths, `S.a.b`) is a `Key<S, F>` that carries the field's type.
- `s[k]` reads in place, and `s[k] = v` writes.
- `~.x` and `~::Variant` take the expected type.
- `AnyKey<S>` is the erased form, for keys known only at run time: `parse`, `all`, `name`, `index`, `typed<F>`, `starts_with`.
- On the wire a key is its index, which needs the contract hash to cover struct layouts (see the paper, §4). Stored data uses names.

Motivation: kolt's reactive-list prototype names changed fields with strings (`slot.edit("status", ..)`), so a typo compiles and leaves a binding silently stale. With keys, those strings become `~.status`. Later stages would let the `PartialEq`, `Json` and `Wire` derives and store projections become library code.

What was built:

- Representation (R11), native only: std's `Key` and the JS output are unchanged (no golden moved). The native struct for `Key<S, F>` gains one hidden Rust field `__access: vilan_rt::KeyAccess<S, F>`: two plain functions for a literal (`&S -> &F`, `&mut S -> &mut F`), one `Rc` of the two halves for `then`. It is no vilan field, so printing, JSON and hashing never see it, and its `PartialEq` answers true, so identity stays the path. The one `Key` std builds (inside `then`) gets the composition of the two keys whose paths it joins, so K5 holds by construction; a `const` key rebuilds its accessors from its path's positions.
- Costs: a subscript through a literal is the plain field chain; through a held key it is `*key_ref(&k.__access, &s)` / `*key_mut(..)`, real Rust places, so `&mut s[k]` is a reference to the field. A literal as a value is one thread-local per distinct literal, copied where written; that copy allocates once (the path's list). The paper's "a literal allocates nothing" holds for the accessors, not the path, because the path keeps its JS shape. `then` allocates the joined list and one `Rc`.
- Refused by name natively: a call handed two loans into one value, one `&mut` and one through a held key (`both(&mut p[j], &mut p[k])`). Left open: two live `let` views through two different held keys reach rustc (B763).
- B760 fixed in passing (a two-view accessor met it).
- A program without keys emits byte-identical native code (154 corpus programs compared); `vilan check` cost unchanged (257.708M vs 257.706M instructions on the tiny program).
