# A38 — the rpc service is one process-wide instance; transport-rpc Q9 says the instance IS the connection's session (per-connection factory + injected globals)

- status: OPEN — the owner's ask while migrating kolt (2026-09-04); triage lane confirmed at 289e2a2b
- kind: design
- area: Reactive core & UI

The owner: the service struct should be instantiated per connected
client so it can hold client data, with globals injected at
construction. Today one instance per PROCESS: `[service]` is the
prelude macro `service(item)` (std/src/rpc.vl ~1773–1983); the
generated `dispatcher(self)` (~1887) captures the one `self` in every
route closure, and `Service::new` (process/rpc_server.vl ~86) hands the
same protocol to every connection (~304 → `accept_socket` → ~377
`protocol.respond(frame)`). A method cannot learn who called:
`RpcRequest { method, deserializer, arity }` (~829) carries no
identity; only the generated `__attach` sees a connection id, because
the client passes it as an argument. Teardown already exists per
connection (`Service.on_connect/on_disconnect` ~73–111, A29); it is
CONSTRUCTION that does not.

The paper already rules it: transport-rpc.md Q9 (✅ settled, ~1163):
"the struct instance is the connection's session (created on connect,
owned by the generated dispatcher)"; ~381 shows `fun on_connect():
Session`. Injected globals are the only new part.

Shape: `Service::factory(|conn| KoltStore::connect(conn, globals),
codec)` replaces `Service::new(protocol)`; `dispatcher()` becomes
`dispatcher_for(instance)` called in `on_connect`; `accept_socket`
threads the connection's dispatcher into `respond`; `Connection { id,
session, remote_addr }`; drop rides `on_disconnect`. `[expose]`d fields
become per-client for free (each instance's own cell, own channel —
what makes A39 tractable). Keep `Service::new` as the stateless
shorthand. Open: the HTTP `{mount}rpc` leg (~222) has no connection —
drop it for factory services or grow one. Contract hash unaffected
(hashes methods/exposures only, ~1806–1832).

kolt today: `store.vl` ~52–60 one `[service]`, built once in
`server.vl` ~14–38; identity is a `token: str` first argument on 7 of 8
rpcs re-resolved by SQL per call (~256); `send_message` takes none.
Migration: `db` into `Globals`, drop the token parameters, resolve the
user once in `connect`. Size M. Related: Q9, §4.2; A29, A30 (closed);
transport-robustness.md ~119 ("server side: nothing").
