# A39 — `[expose]` resyncs the whole value on every change; a message edit costs the channel (keyed deltas + per-key subscription over the wire)

- status: OPEN — the owner's ask while migrating kolt (2026-09-04); triage lane's walkthrough in scratch, to be moved into the item when queued
- kind: design
- area: Reactive core & UI

The owner: sync only what a client subscribed to; a message edit
must not resync every other message in the channel — walk them through
it if the current model can do it. It cannot, fully.

Today: `ReactiveServer::expose` (rpc.vl ~1160) forwards `source.sub(|v|
send(encode_update(.., v.describe(s))))` — whole value, every change;
`RemoteSource` replaces its cache wholesale (~1291). The wire visitor
has no delta vocabulary (wire.vl ~22–60: begin_struct/list/variant +
scalars); `Map` has no `Wire` impl (List ~336, Option ~360; Q8 "launch
without"). A `SignalCell` nested inside an exposed value is a COMPILE
ERROR (derive(Wire) refuses signals, guide/services.md ~146), so
`SignalCell<Map<Id, SignalCell<List<Message>>>>` has no form at all.
Per-channel laziness exists: a starter subs on the first `Subscribe`
(~1187); the counted lease unsubscribes at 1→0 (~1500–1545).

Buildable now, partially (the lane's `ask2-partial-sync-walkthrough.vl`):
`session_of` (~1111) and `expose` are public and mint a channel id at
runtime, so `[rpc] fun subscribe_channel(self, connection, channel):
i32` can hand out per-channel `SignalCell<List<MessageRef>>` (ids)
plus per-message `SignalCell<Message>` (deletes as tombstones): an
edit on 5,000 messages × 40 clients goes 20 MB → ~1 KB; a post 20 MB →
~300 KB (still O(n)). It STOPS AT THE CLIENT: the generated client
surfaces only the `[expose]` mirrors (~1902, ~1934–1957); the
`ReactiveClient` built at ~1948 is dropped into closures (A30 declined
exposing it); `bridge(socket)` twice clobbers `on_frame` (~486). The
app would have to abandon the generated `connect` and hand-wire.

The ideal (L): `Delta<K,T> { Reset | Insert(K,T,i32) | Update(K,T) |
Remove(K) }` + `trait Keyed<K>` in wire.vl; a `Patch(channel, ops)`
arm beside `Update` in `encode_update` (~1071), `RemoteSource` applying
ops; `Subscribe(channel, Option<Key>)` (~1062) so per-key demand is a
protocol property; `impl Map with Wire` (I1); an `[expose(keyed)]`
macro form. Per-client FILTERING needs A38 first (one shared `self.field`
today). kolt today: `[expose] messages: SignalCell<List<str>>`, one
global channel, unbounded append, bare strings; `workspaces`/`tasks`
mirrors consumed nowhere but probe.vl. Related: transport-rpc §8,
Q8; remote-sources.md §2a, §7; reactive-batching.md ~228; A41 (two
bugs on the dynamic path found while writing the recipe).
