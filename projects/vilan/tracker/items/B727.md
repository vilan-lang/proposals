# B727 — A variant that fixes only some of its enum's type parameters drops all of them (`Ok(x)` is `Result` with no arguments); JS prints `Ok(<T>)`

- status: open
- kind: bug (analyzer)
- area: compiler

Found by lane emit-58b (Order 58, 2026-11-09). B720's real cause. `infer_enum_constructor_arguments` drops every type argument when a variant fixes only some. Effects: (1) JS: `let o: Option<i32> = Some(1); let r = o.map_or(|x| Ok(x), Err("e")); print(r);` prints `Ok(<T>)` instead of `Ok(1)`; (2) native: B720's emitter fix fills the arguments from the call's return position, and a call with no position to infer from is refused by name. Attempt: filling the unfixed parameters with unknowns (as B357 did for `None`) fixes the shape but turns `lifetimes::rk_transient_global_ignores_an_ambient_owner_where_transient_is_released_with_it` red with a false "cannot infer" (5,821/5,822); the diff was kept in the session scratchpad as analyzer-b720-attempt.diff.
