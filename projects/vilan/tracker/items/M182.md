# M182 — A `HashMap`'s value can't be changed in place: adding to a list held in a map copies the list every time

- status: OPEN - filed 2026-10-31 (kolt)
- kind: feature (std; S)
- area: Standard library

`HashMap::get` answers "a copy of the value stored under `key`", and the map has no method that changes a stored value where it is (no `get_mut`, no `update`, and `get_or_insert` answers a copy too). So the everyday grouping idiom, rows into each key's list, can only be written as take a copy, push, put it back:

```
mut held = groups.get(key).unwrap_or([]);
held.push(value);
groups.insert(key, held);
```

That copies the whole list on every push: grouping n values under one key is O(n²). Kolt's `sidebar_rows` (each channel's children) and its organization loader (each task's sections, items, links, assignees and field values, each channel's messages) both need it. The loader sorts its rows by key in SQL instead and builds each list as one run, which works only where the rows can be ordered by key.

Repro (standalone; prints three timings): kolt session scratchpad `maprepro/group.vl`, copied below as the whole file. On node 24 it printed 13.6 ms for 1,000 values, 149 ms for 4,000 and 2,784 ms for 16,000: about 16× the time for 4× the values.

```
import std::hash_map::HashMap;

[extern("(() => performance.now())")]
external fun clock_ms(): f64;

/// Appends `count` values under one key, the only way std allows: take a
/// copy, push, put it back.
fun grow(count: i32): f64 {
	let started = clock_ms();
	mut groups: HashMap<i32, List<i32>> = HashMap::new();
	mut index = 0;
	for index < count {
		mut held = groups.get(1).unwrap_or([]);
		held.push(index);
		groups.insert(1, held);
		index += 1;
	}
	clock_ms() - started
}

fun main() {
	print(i"1000: {grow(1000)} ms");
	print(i"4000: {grow(4000)} ms");
	print(i"16000: {grow(16000)} ms");
}
```

Recommendation: an in-place update on `HashMap` in the shape `SignalCell::update(|&mut T|)` already has, e.g. `update(&mut self, key: K, missing: || V, change: |&mut V|)` (Rust's `entry(key).or_insert_with(missing)` then a mutation), so grouping is `groups.update(key, || [], |list| list.push(value))` at O(1) per push. Possibly also a `List::group_by(|T| K): HashMap<K, List<T>>` for the common case. Sizing S.
