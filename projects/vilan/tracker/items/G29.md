# G29 — A `macro fun` in an inline `mod { }` is in scope in that `mod` (G27) and reachable from nowhere else — `import tables::tabled;` reads "cannot find module 'tables' to import", and `[tables::tabled]` is no attribute form — so `export macro fun` inside an inline mod exports nothing

- status: OPEN — filed 2026-10-12 (fix-51's find, Order 51)
- kind: question (macros; S)
- area: Macros & const

G27 (fix-51) registers a mod's macros under the mod-qualified name and resolves them from the innermost enclosing mod out; a sibling mod and the file's top level do not see them (pinned). Macro imports resolve only `std::`/`pkg::`/dependency module paths by leaf (`macros::scope_for`), and an inline mod is not a module path there. Decide: (a) an inline mod's exported macros are importable (`import self::tables::tabled` or whatever reaches an inline mod's member) and `scope_for` learns the path; (b) refuse `export` on a `macro fun` inside an inline mod with a steer; (c) leave it. Rec (b) now, (a) when inline-mod imports are specified. Sizing S.
