# F150 — An `any` position the native backend cannot fill reaches rustc: a bare `None` (`shown(None)` over `fun shown(value: any)`) is E0282 on `vilan_rt::Any::from(None)`, and a struct (`shown(Point { x = 1 })`) is E0277 (no `From<Point>` for `Any`) - both reported as "a BACKEND defect"; JS builds both (`null`, `[ 1 ]`)

- status: OPEN - filed 2026-10-26 (std-55's find, Order 55)
- kind: backend defect - native any coercion
- area: Native targets & rendering

`vilan_rt::Any` holds a number, a `str`, a `bool`, NULL and (through `From<Option<T>>`) an `Option` of those; the checker lets ANY value reach an `any` position (print/hash externs aside, which the native emitter lowers as intrinsics). Two halves: (1) the untyped `None` - emit `Any::Null` for a `None` whose payload type is open; (2) a value `any` cannot hold - refuse it at the checker with the holdable set named ("`Point` cannot be held by `any`: an `any` holds a number, a `str`, a `bool` or an `Option` of one"), which is also what M165's ruling wanted for a bind list (the refusal names the VILAN type, which the JS binder cannot see at run time). (2) is a new refusal: count the estate first (kolt binds only scalars/`Option`s; std's `any` sites are print/hash/db). See the A176 question. `diagnostics` for (2), `fix` for (1).
