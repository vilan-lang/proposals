# M90 — a read-only `let` of a struct FIELD deep-copies it on JS: `let layout = config.layout; layout.table[at]` emits `const layout = __clone(config2[0])` although neither the binding nor `config` is written in scope — in kolt's search matcher that one line cloned a 16K-entry cost table per alignment and turned 0.55 s of queries into minutes; the same shape copies a whole element for `let x = found[a]` inside a `sort_by` comparator

- status: OPEN — filed 2026-09-28 (kolt's search system)
- kind: performance
- area: Performance & footprint

Repro (0.41.1):

```vilan
struct Layout {
	table: List<f64>,
}

struct Config {
	layout: Layout,
}

fun cost(config: Config, at: usize): f64 {
	let layout = config.layout;
	layout.table[at]
}
```

emits

```js
function cost(config2, at) {
	const layout = __clone(config2[0]);
	return __at(layout[0], at);
}
```

The binding is never mutated, never escapes, and `config` is a by-value parameter nothing writes — the case rule 1's copy elision exists for. `config.layout.table[at]` (no binding) emits no clone, so the cost is purely the spelling: naming a sub-value to read it twice is the idiom that gets punished, invisibly (M60's complaint, one level down).

Measured in kolt (`src/lib/search.vl`, `align`): 200 queries over 200 documents took 8,965 ms CPU with the map-backed layout and did not finish in 5 minutes once the layout carried a dense 128×128 table; removing the binding: 551 ms. Second site: `let x = found[a]; let y = found[b];` in a `sort_by` comparator clones two `Match` records (ranges list included) per comparison.

Related: M60 (`get`/`set` deep-copy), F49 (native: a `&self` call on a boxed binding deep-copies), the copy-elision census (`49e0e817` — worth adding this shape to its corpus).
