# B735 — A bare read of a module-level cell returned from a function tail is never copied on JS - the caller's result aliases the cell

- status: open
- kind: MISCOMPILE (JS)
- area: analyzer: cell borrows

`let plain: Shared<List<i32>> = Shared::new([1, 2]); fun from_plain(): List<i32> { plain.read() }` then `mut b = from_plain(); b.push(3); print(plain.read().len())` prints 3 on JS; it must print 2. The same for a `lazy let` cell. The other direction is wrong too: `let held = from_plain(); plain.write().push(3); held.len()` reads 3. A cell passed as a PARAMETER copies correctly (`return __clone(cell.v)`), so the gap is module-level cells only. The same at 98ac8519, at f57ef700 (the held M199 branch) and on next 11404d78. Unchecked guess at the cause: module-level cell reads are missing from `shared_cells.reads`. Repros: `scripts/integration/sweeps/order58/repros/module-cell-return/main.vl` (prints `3 3`, wants `2 2`) and `later-write.vl`.
