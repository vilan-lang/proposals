# L23 — NEW — `release.yml` is exercised by nothing but a real `v*` tag, so a bump to the actions it alone uses (upload-artifact, download-artifact, azure/login, create-github-app-token) is first RUN mid-release: it needs a dry-run lane — build → upload → download → checksum, no publishing step — before upload-artifact v7 / download-artifact v8 land

- status: OPEN — the review of vilan-lang/vilan#3 (2026-09-18; the PR closed unmerged)
- kind: process
- area: Release engineering & beta
- size: S–M

#3's eight green checks were all `ci.yml`. Every `release.yml` bump in it
(setup-node 4 → 7, upload-artifact 4 → 7, download-artifact 4 → 8,
azure/login 2 → 3, create-github-app-token 2 → 3) would have run for the
first time on a tag push, where four of the five channels are one-way.

The pair that matters is upload-artifact v7 / download-artifact v8:

- download-artifact v8 turns a digest mismatch from a WARNING into an ERROR
  (`digest-mismatch`, default `error`).
- v8 no longer unzips everything it downloads: it reads `Content-Type` and
  skips what is not a zip, to support v7's new `archive: false` direct
  uploads. The release uploads with the default (zipped), so this should be
  transparent — "should" is the whole finding.
- `publish` downloads BEFORE it creates the GitHub Release, so a failure
  there is safe. `publish-npm`, `publish-marketplace` and `publish-openvsx`
  download AFTER it: a failure there leaves a release that is live on GitHub
  and absent from npm or a gallery until someone re-runs the job. The re-run
  is idempotent (the EPUBLISHCONFLICT match, `--skip-duplicate`), so the cost
  is a half-published window, not a broken version.

The proposal: a `workflow_dispatch` trigger on `release.yml` (or a sibling
workflow calling the same jobs) that runs `build`, `vsix` and `wasm`, then
the download step with `pattern: release-*` + `merge-multiple: true` and the
`sha256sum` pass, and asserts the asset list is the one a release carries —
and stops. Every publishing job gains a condition on the ref being a tag
(today the tag-only trigger is the sole guard), so a dispatch cannot reach a
channel. A major bump to an artifact action is then
merged only after a green dispatch on its PR branch.

Open question for the design: whether the dry run also covers the `gate` job
(it is `ci.yml`'s two legs again, so probably not) and the token mint of L22.
