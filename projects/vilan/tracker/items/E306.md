# E306 — a binding whose type is an ENUM hovers with a chunk of the enum - its variants under the instantiation's arguments - the way a struct-typed binding hovers with its fields (E237); the owner sees no such chunk on enum-typed bindings in kolt, while E237's pins (`let shape = Shape::Circle(..)` -> `enum Shape { Circle(f64), Rect(f64, f64), Empty }`, `let opt = Some(1)` -> `enum Option<i32> { Some(i32), None }`) are green - so some binding SHAPES miss the table, and the item is to find and close them

- status: OPEN — filed 2026-10-12 (the owner's ask, mid-Order 51; a repro to take on a kolt copy - the pinned shapes already answer)
- kind: editor (hover; XS–S)
- area: Editor

Take the repro on a kolt copy (lucide carried) and say which enum-typed bindings answer with no chunk. Candidates, each a pin: a `let` whose enum type comes from a CALL (`let state = x.states().latest()` - a `TransientState`), from a FIELD read, from a parameter (`fun f(reason: DismissReason)` - the parameter path), a match/`is` CAPTURE (`Some(let root)` - the destructured binder's type is the element-type path, maybe absent from the table's positions), a `mut`, an enum reached through a TYPE ALIAS, an enum from a DEPENDENCY or std (`Ordering`), an enum with STRUCT variants (`Rect { w: f64, h: f64 }` - the member rendering), an enum of more than twelve variants (E237's cap - the chunk should still show, capped), and a binding typed `Option<E>` (the chunk is `Option`'s - fine - but hovering the VARIANT name should be E300's). Likely cause: `type_definitions` builds its table from the positions it is handed, and the binding's `type_id` for these shapes is a different (equal, un-interned) id or one the position set never visited; the fix is to answer by TYPE (intern-equal) rather than by position, or to add the binding type ids to the positions.
