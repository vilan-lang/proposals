# B375 — `[service]` over an `export impl` generates a dispatcher with ZERO routes and the empty contract hash `00001505`, SILENTLY — the attribute walks the impl's members and finds none because the exported form is a different node shape

- status: OPEN — filed 2026-09-21 (Order 39 sweep; papers-39's find; solver-39 declined by ownership)
- kind: bug (macro engine / std::rpc, MEDIUM)
- area: Macros & services

Repro: `export impl AuthService { … }` under `[service]` → the generated dispatcher has no routes; the hash is the empty-set hash; a client call answers 'unknown method' at runtime with nothing said at compile time. Fix: EITHER the walker reads through `export` (rec — `export` is visibility, not shape), OR the attribute REFUSES an `export impl` by name until it does. Either way a `[service]` producing zero routes must be a compile-time refusal ('a service with no methods'), because the empty hash is never what anyone meant. Pins: `service_layer` over an exported impl (routes present, hash non-empty); the zero-route refusal with a planted empty impl.
