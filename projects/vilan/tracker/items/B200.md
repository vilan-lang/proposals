# B200 — unary `-` on a non-numeric operand returns the operand's type: `-true` is `-1` typed `bool`

- status: OPEN — b196 lane's find (2026-09-01); pinned #[ignore]d `b196_a_unary_minus_on_a_non_numeric_operand_is_rejected` (reason retargeted here)
- kind: bug
- area: Type system & the type solver
- source: lane b196; `Expr::Unary(_, operand)` in `infer_type_inner` (~24325) returns the operand's type with no operand rule

The same miscompile B196 closed for binaries, at the unary site:
`-true` is `-1` typed `bool`, `-"12"` is `-12` typed `str`,
`-Level::High` is `-5` typed `Level` matching no variant. Owes a
census (unary minus on non-numeric left operands across the estate —
expected zero, as B196's was) and a refusal in the operand-role
family ("`-` on `bool` has no meaning: …", the admitted set named).
`!` on non-bool is the twin to check in the same stroke. The
numeric-left / non-numeric-right coercion (`12 - "3"` → 9, a real
number really typed as one) is deliberately NOT here — it is
strictness, filed with the `f64 * i32` family when that is ruled.
