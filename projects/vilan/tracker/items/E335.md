# E335 — SIGTERM to `vilan run` does not reach the program it started: node (or the native binary) keeps running, orphaned - a supervisor, an editor task or a harness that stops `vilan run` leaves a server holding its port or a program parked on stdin; and a child killed by a signal is reported as exit 1, not 128+signal

- status: OPEN - filed 2026-10-16 (std-54's find, Order 54)
- kind: tooling (vilan run's child process)
- area: Tooling

`vilan run` waits with `Command::status()` (`exit_code_of`) and handles no signal, so only Ctrl-C in a terminal (SIGINT to the whole foreground group) stops both. Rec: forward SIGTERM/SIGHUP/SIGINT to the child and wait for it (unix; on Windows the job-object equivalent so a killed `vilan run` takes its child), and map a signal death to 128+n as a shell does. Pin: start `vilan run` on a program parked on `read_line`, SIGTERM it, assert the child is gone. Check what `--watch` already does for its rounds before building (it restarts children itself). Met by std-54's stdin harness: a red step's kill of `vilan run` left the native binary running.
