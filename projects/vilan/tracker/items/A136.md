# A136 — a `Memo` maker that builds an owner-tied derivation (`memo.get_or(id, || ….cell())` — kolt model.vl's four handle tables) ties the memoized value to the FIRST CALLER's owner: the memo is program-lifetime and evicts nothing (by design), the `.cell()` dies with the channel page that first asked, and every later `get_or` hands out the DEAD cell — stale on return, never updating again. memo.vl's own doc presents the owner as something the call site's scope 'covers', which is exactly the trap: the maker's CONTEXT reads must be the caller's, its LIFETIME must be the memo's

- status: OPEN — filed 2026-09-28 (the owner's report: after A134's fix, messages in a channel left and returned to stop mirroring; diagnosed by the integrator on 1a33340f)
- kind: bug (std design trap) + docs
- area: Reactive core & UI

Kolt's fix (applied 2026-09-28, checks/builds/fmt clean): the memo holds `get_client().map(|c| c.map(|c| c.get_messages(id))).cell_global()` — a program-lifetime cell of the UNLEASED mirror, the memo's own lifetime — and the lease is the caller's: `.and_then(|mirror| mirror).map(..).cell()` at the call site under the view's owner, released with the view, re-taken (re-minting) on the next visit. Demand still decides the channel's life, as the idiom promised.

The owner's question, answered here for the record: the maker MUST run at the call site (`get_client()` is a context read only the caller's scope covers), and there is no way to run it 'under no owner' from inside a scope — a module-level never-disposed owner would be the same thing spelled long. `.cell_global()` is std's name for it.

Doors: (a) DOCUMENT at memo.vl's head and at `Memo::get_or`: 'what the maker builds outlives the caller — a derivation in a maker is `.cell_global()`; a lease never goes in a maker'; rewrite the 'covered by the scope it was called from' sentence, which today reads as a feature. (b) a CHECK: a `.cell()` (or `effect`, or any owner-taking call) syntactically inside a `get_or` maker closure gets a warning with the `.cell_global()` steer — static, cheap; the memo type is std's so the analyzer can know the seam. (c) `Memo::get_or` runs the maker under `owner_scope.run(<the memo's own never-disposed owner>, ..)` — impossible as a wrapper by the context model's own rule (a closure captures its context at creation; memo.vl says so of the owner). Rec: (a) + (b). Sizing S; std/memo + a check, Order 43.
