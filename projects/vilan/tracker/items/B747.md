# B747 — A mixed list literal at an annotated `let xs: List<any>` is refused ("Expected i32 (this literal's element type), but got str"), though the same literal is accepted as a `List<any>` argument, field, return value or assignment

- status: OPEN - filed 2026-11-12 (kolt; vilan 0.55.1)
- kind: bug (checker; list literals at an expected `any` element)
- area: crates/vilan-core/src/analyzer.rs (list-literal inference: `expected_element` vs `seeded_element`)
- renumbered: filed as B739 on the local branch `kolt-list-any` (kolt-side session); synced to main as B747 on 2026-11-16, because main's B739 is another item (closed). Missed in the first sync of that day (97486c46), which read main's B739 as this one. Still refused at next d20bbfd9 (v0.56.0).

Minimal repro (`vilan check main.vl`, no imports):

```vilan
fun takes(values: List<any>): usize { values.len() }

fun main() {
	print(takes([1, "a"]));
	let xs: List<any> = [1, "a"];
}
```

The call is accepted (and prints `2` on both backends with the `let` removed); the `let` is refused at `"a"`: `Expected i32 (this literal's element type), but got str instead.` With `["a", 1]` it is the mirror (`Expected str ..., but got i32`). A homogeneous `let xs: List<any> = [1, 2]` is accepted.

The same literal `[1, "a"]` at each expected-type position (0.55.1, `vilan check`; the accepted ones also run on JS):

| position | result |
|---|---|
| argument `takes([1, "a"])`, method argument | accepted |
| struct field `Q { params = [1, "a"] }` (`params: List<any>`) | accepted |
| function tail and `ret [1, "a"];` (`: List<any>`) | accepted |
| assignment `mut xs: List<any> = []; xs = [1, "a"];` | accepted |
| `let xs: List<any> = [1, "a"]` (also `mut`, also parenthesized) | REFUSED |
| nested anywhere: `let xs: List<List<any>> = [[1, "a"]]`, `Option<List<any>> = Some([1, "a"])`, an argument `takes([[1, "a"]])` at `List<List<any>>`, `takes(Some([1, "a"]))` at `Option<List<any>>`, a field `rows: List<List<any>>`, a tail at `List<List<any>>` | REFUSED |
| `let xs: List<dyn Show> = [1, "a"]` (`impl i32 with Show`, `impl str with Show`), and as argument, field, tail | accepted |
| nested `dyn`: `let xs: Option<List<dyn Show>> = Some([1, "a"])`, an argument at `List<List<dyn Show>>` | REFUSED |

Cause (read, not patched): the list-literal arm keeps two expectations. `expected_element` comes from the literal's own constraint, and it is what decides `absorbed` (an element the expected element type takes, such as `str` under `any`, is not a mismatch) and M165's `record_any_option_landing`. `seeded_element` also reads `expected_types`, the channel an annotated binding seeds because its readiness probe runs the initializer UNDIRECTED first (A124 R3's comment at that site), and only `seeded_element` is used for the `dyn` seed and B389's numeric seed. At an annotated `let` the probe's constraint is empty, so `expected_element` is `None`, nothing is absorbed, the literal types by its first element and reports, and the result is cached before the directed pass. `dyn` survives the probe because it is seeded through `seeded_element`; `any` does not. The nested rows are the other half: neither expectation reaches a literal inside another literal or inside `Some(..)` (the "not seeded into the element" note at that site), so an inner mixed literal is refused at every position, `dyn` included.

Workarounds in kolt (SQL parameters of mixed types passed as a list): build the list empty and push the values one at a time (`mut xs: List<any> = []; xs.push(1); xs.push("a");`), which works on both backends; or pass the literal straight to the `List<any>` parameter rather than binding it first. Casting one element, `[1 as any, "a"]`, passes the checker and runs on JS but is refused by rustc natively (`vec![(1i32), vilan_rt::Any::from(..)]`, E0308: the `as any` is not kept on the first element), so it is not a workaround.

Rec: decide `absorbed` and the M165 landing on `seeded_element` (the expectation that survives the binding's probe) instead of `expected_element`, so an annotated `let` behaves as the argument does; and carry the element expectation one level down for a literal inside a literal or a `Some(..)` when that expectation is `any` or `dyn` (the two element types that change what an element may be), without seeding concrete types (the site's note on why). Pin on both backends: the table above, each row accepted, and each `let` printing `2`; plus `[1 as any, "a"]` natively. Size S for the `let`, S-M for the nested rows. Related: M165 (any landings at a `List<any>`), B721 (native `List<..>` at a `List<any>` parameter), M175 / `SqlValue` (which retires `List<any>` at the db boundary, where kolt met this).
