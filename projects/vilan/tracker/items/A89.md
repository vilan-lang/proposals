# A89 — `Style::attribute` takes `value: Option<str>`: today it matches an EXACT value only (`[name="value"]`, style.vl:1470), so a PRESENCE condition (`[data-selected]`, `[disabled]`) has no spelling and kolt reaches for the `children`/`divide` chokepoint `child_relation("[data-selected]", ..)` (public only because vilan has no visibility) as a raw-selector escape hatch — and hits its v1 fence the moment a `.hover` nests inside ("takes an unconditioned style"); `None` = presence, `Some(v)` = exact match. The NEGATED form (`:not([disabled])`) is the sibling gap: `pseudo("not([disabled])", hover(..))` is refused as two pseudo-classes in one slot, so 'not disabled AND hovered' is spellable only by carrying the state as an attribute VALUE (`attribute("data-disabled", "false", hover(..))` → `.sX[data-disabled="false"]:hover`, which works today)

- status: OPEN — the owner's ask (2026-09-11)
- 2026-09-11 (the owner, confirming the spelling): negation is a MARKER on the inner style, not a pseudo head — `attribute("disabled", None, not(STYLE))` (or `STYLE.not()` in a chain; `.not { .. }` in a `css` block), negating the immediately ENCLOSING condition. Supersedes the body's (2) as first filed.
- kind: feature
- area: Reactive core & UI

**Today.** `attribute(self, name: str, value: str, inner: Style)` (style.vl:1470) renders `[name="value"]` and validates both tokens at const time; `pseudo` (:1502) allows one pseudo-class per slot; `child_relation` (:1432) refuses any conditioned inner because a pseudo under a child combinator would bind to the child's compound. kolt's `new_button_style` (styles.vl:52) wants `.sX[data-selected]{color}` and `.sX:not([disabled]):hover{background}` and can spell neither.

**The change.** (1) `attribute(name, value: Option<str>, inner)`: `Some(v)` renders `[name="v"]` as today, `None` renders `[name]` (presence). In a `css` block the nested-rule head takes ordinary expressions, so `.attribute("data-selected", None) { .. }` reads as written; the slot key stays one attribute per slot. Every existing call site passes `Some(..)` — a mechanical sweep of std, docs and examples (kolt at the owner's word); OR keep the two-argument form and add `attribute_present(name, inner)` beside it if the `Some` noise at every call is judged worse than a second name — say which, the recommendation is the `Option` (one concept, the owner's ask). (2) Negation — the owner's form: `fun not(self, inner: Style): Style` beside `hover` (:1339), the same combinator shape, so a `css` block's nested `.not { .. }` lowers to it by the name-blind rule and the free spelling `not(S)` is `style().not(S)`. `not` MARKS the inner's rules (a `!` in the condition slot of each rule key, or a flag on the value) and emits nothing itself; the immediately ENCLOSING condition combinator (`attribute`, `within`, `hover`/`focus`/`active`, `pseudo`) that finds the mark emits its own selector NEGATED and clears it: `attribute("disabled", None, not(hover(S)))` → `.sX:not([disabled]):hover`; `hover(not(S))` → `.sX:not(:hover)`; `within("data-theme", Some("dark"), not(S))` → `:not([data-theme="dark"]) .sX`. Reading inside-out, `not` negates exactly the next condition out, so `attribute(a, None, not(hover(S)))` keeps the hover and negates the attribute. Refused at const time: an UNWRAPPED `not` (a marked style that reaches application — 'wrap it in the condition to negate'), `not(not(S))` (say so rather than cancel), and a `not` directly under a MEDIA condition in v1 (`@media not (..)` exists; leave it to a later ruling). Specificity: `:not([x])` counts as its argument, so the composed rule keeps the (0,3,0)-over-(0,2,0) story the other conditions have. (3) Docs: styling.md's condition table gains the presence row and the negation row; the `child_relation` message gains a steer ('for a state on the element itself, `attribute(..)`').

**Pins.** `attribute("data-selected", None, ..)` emits `.sX[data-selected]`; `Some` unchanged (control, the existing pins); `attribute("disabled", None, not(hover(S)))` emits `.sX:not([disabled]):hover`; `hover(not(S))` emits `.sX:not(:hover)`; an unwrapped `not`, a double `not` and a `not` under `md` are refused naming the fix; the `css`-block spelling `.attribute("disabled", None) { .not { .hover { .. } } }` lowers to the same rule; specificity ordering against the plain `hover` rule stated and pinned (`(0,3,0)` over `(0,2,0)`).
