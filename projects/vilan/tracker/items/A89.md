# A89 — `Style::attribute` takes `value: Option<str>`: today it matches an EXACT value only (`[name="value"]`, style.vl:1470), so a PRESENCE condition (`[data-selected]`, `[disabled]`) has no spelling and kolt reaches for the `children`/`divide` chokepoint `child_relation("[data-selected]", ..)` (public only because vilan has no visibility) as a raw-selector escape hatch — and hits its v1 fence the moment a `.hover` nests inside ("takes an unconditioned style"); `None` = presence, `Some(v)` = exact match. The NEGATED form (`:not([disabled])`) is the sibling gap: `pseudo("not([disabled])", hover(..))` is refused as two pseudo-classes in one slot, so 'not disabled AND hovered' is spellable only by carrying the state as an attribute VALUE (`attribute("data-disabled", "false", hover(..))` → `.sX[data-disabled="false"]:hover`, which works today)

- status: OPEN — the owner's ask (2026-09-11)
- kind: feature
- area: Reactive core & UI

**Today.** `attribute(self, name: str, value: str, inner: Style)` (style.vl:1470) renders `[name="value"]` and validates both tokens at const time; `pseudo` (:1502) allows one pseudo-class per slot; `child_relation` (:1432) refuses any conditioned inner because a pseudo under a child combinator would bind to the child's compound. kolt's `new_button_style` (styles.vl:52) wants `.sX[data-selected]{color}` and `.sX:not([disabled]):hover{background}` and can spell neither.

**The change.** (1) `attribute(name, value: Option<str>, inner)`: `Some(v)` renders `[name="v"]` as today, `None` renders `[name]` (presence). In a `css` block the nested-rule head takes ordinary expressions, so `.attribute("data-selected", None) { .. }` reads as written; the slot key stays one attribute per slot. Every existing call site passes `Some(..)` — a mechanical sweep of std, docs and examples (kolt at the owner's word); OR keep the two-argument form and add `attribute_present(name, inner)` beside it if the `Some` noise at every call is judged worse than a second name — say which, the recommendation is the `Option` (one concept, the owner's ask). (2) Negation: `attribute_not(name, inner)` → `:not([name])`, or admit `not(..)` as a pseudo that may WRAP one further pseudo-class (`.sX:not([disabled]):hover`) — the second is the general one and needs the one-per-slot rule relaxed for `not(..)` only. Rec: (2b), fenced to `not(` heads. (3) Docs: styling.md's condition table gains the presence row and the negation row; the `child_relation` message gains a steer ('for a state on the element itself, `attribute(..)`').

**Pins.** `attribute("data-selected", None, ..)` emits `.sX[data-selected]`; `Some` unchanged (control, the existing pins); `not([disabled])` wrapping `hover` emits `.sX:not([disabled]):hover`; a second non-`not` pseudo under `not` still refused; specificity ordering against the plain `hover` rule stated and pinned (`(0,3,0)` over `(0,2,0)`).
