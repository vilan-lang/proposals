# B572 — the "import it first" steer names std's INTERNAL module for a re-exported name — `cannot find type 'Store'; import it first (`import std::reactive::store_core::Store;`)` where the public spelling is `std::reactive::store::Store`

- status: OPEN — filed 2026-10-08 (found migrating kolt's store patch to v0.45.0; Order 48)
- kind: diagnostic (S)
- area: Compiler

Seen on kolt at v0.45.0 with `Store` unimported: the steer (B560's full-path form) walks to the module that DECLARES the name, `std::reactive::store_core`, and spells that; `std::reactive::store` re-exports it and is the path the book, the derive's generated code and `vilan check --fix` all write. A user who pastes the steer reaches an internal module (and A149 S4 now treats std-internal surface as off-limits). Fix: when the declaring module is reached through a re-export in a module the std export index lists as public, spell the re-export; more generally prefer the shortest PUBLIC path the std export index (solver-47's `trait_scope_import` source) knows for the name, and only then the declaring module. Pin beside `b560_the_import_steer_spells_a_nested_std_modules_full_path` with a re-exported name (`Store`, `Storable`).
