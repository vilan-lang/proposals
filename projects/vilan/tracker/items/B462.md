# B462 — an enum VARIANT constructor is not a function value: `[1, 2].map(Some)` is refused ("Expected |i32| Option<i32>, but got Option") where `|x| Some(x)` works; the sketch writes `count.derive(Some)` and `inner.derive(Some)`

- status: OPEN — filed 2026-09-29 (the owner's item, from kolt's `reactive2.vl` sketch; probed on 0.41.1)
- kind: feature (S–M)
- area: Type system & the type solver

**Rule.** A TUPLE variant `E::V(A, B)` named without a call, at a position expecting a closure type, coerces to `|A, B| E<..>`, its generic parameters inferred from the expected type (`Some` against `|i32| Option<i32>` binds `T = i32`). Unit variants (`None`) and named-field variants do not coerce. Tuple structs follow the same rule if/where the language has them.

**Emission.** Eta-expand at the coercion site (a closure literal), or a shared per-variant constructor function — one per instantiation on native, one per variant on JS.

Questions: (1) coerce also where NO closure type is expected (`let f = Some;` — needs a generic function value; rec: no, expected-type positions only, B348's rule shape); (2) the inlay/hover face of a coerced variant.

Related: B348 (a generic `Callable` into a closure-typed position — same expected-type-driven instantiation), the fn-coercion rules.
