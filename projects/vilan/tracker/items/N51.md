# N51 — `watch.vl` is a corpus program that cannot run to completion: nothing in the suite ever EXECUTES it (owner's question)

- status: OPEN — lane hygiene-26's find (2026-09-03); the owner decides the corpus's rule
- kind: hygiene
- area: Testing & CI

`vilan/test/watch.vl` blocks on `flat.next()` for a filesystem change
that never comes (`timeout 20 node watch.mjs` → exit 124). It is
byte-gated by `corpus.rs` (compile only) and, since N49, excluded
from the release differential with that reason — so nothing runs it.
Before N49 it cost the union 600 s to NOT observe it: both builds hit
the 300 s deadline and the gate compared two identical timeout
strings. QUESTION: should the corpus hold a non-terminating program
at all (a corpus program is a program whose OUTPUT is the claim), or
does `Watcher` deserve a runnable fixture — the watcher started, one
bounded change made by the program itself, one event observed, exit?
Recommend the fixture; move the non-terminating form to an example.
