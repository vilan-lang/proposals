# M181 — Percent-encoding has no platform-neutral home: `percent_decode` is browser-only (in `std::web::router`), and there is no encoder at all

- status: OPEN - filed 2026-10-31 (kolt)
- kind: feature (std; S)
- area: Standard library

`std::web::router::percent_decode` is the total decoder (a malformed escape decodes to itself), but `router.vl` declares the `browser` platform, so code that also runs on Node can't call it. Kolt's `code_links.vl` (links to code, parsed in the browser and tested under `vilan test` on Node) gets "`percent_decode` requires the `browser` platform its file declares and cannot run on `node:24`". The server (`files.vl`, an upload's `X-Kolt-Filename` header) is in the same position. And std has no encoder (`encodeURIComponent`), which the same code needs to build links and `Content-Disposition` filenames.

So kolt keeps two externs in `src/lib/std_ext.vl` (`decode_uri_component`, the same total decoder; `encode_uri_component`) that every app writing URLs will repeat.

Recommendation: a platform-neutral `std::url` (or `str` methods) with `percent_encode(text)` (encodeURIComponent's set) and `percent_decode(text)` (total), both on both backends; `std::web::router` re-exports the decoder so existing callers keep working.
