Shape: `Callable` is a MARKER trait in `std::operators` beside `Add`/`Sub`/`Lift` — `trait Callable {}` — and the `call` method the impl declares carries the ARITY and types (no variadic generics needed: the analyzer resolves `x(args)` on a receiver whose type implements `Callable` exactly as it resolves `x.call(args)`, so the signature check is the ordinary method check). A `Callable` value is plain DATA, so `const let space = Scale::new(0.25);` is a const result TODAY under G24's data rule and `space(2f)` in a const context calls through the interpreter — the scale use case needs no closure snapshot

**RULING 2026-09-14 (owner):** Q1 accepted — a `Callable` value coerces wherever a function declaration does: a closure-typed position (`let f: |f64| Length = scale;`, `list.map(scale)`) takes it, lowered as the wrapping closure `|n| scale.call(n)`; fn-coercion.md §1's coercible set gains "a value whose type implements `Callable`". Q2 — the owner: "it should behave the same as a field of a closure. If `b` of `a` is a closure, it's called like `(a.b)()` which seems logical for `b: Callable`" — AGREED, and the language already enforces exactly that rule for closure fields (probed on 9b22ec36: `a.f(1)` on a closure field is refused — "Holder has no method 'f'; `f` is a field holding a closure: parenthesize the field access to call it, `(x.f)()` (a bare `.f()` only looks up methods)" — and `(a.f)(1)` compiles; std writes `(self.body)()`, `(self.wire)()`, `(subscriber.notify)()`, `(self.commit)(value)`). So `a.b(c)` stays METHOD lookup and a `Callable` field is called `(a.b)(c)`; the existing steer's text widens to "a field holding a closure or a `Callable`" — the same ledger row, not a new one. No open questions remain; lane-ready.

**Owner's framing (2026-09-14):** "semantically closures are formally callable structs. So this bridges that semantic gap in the language, which is a nice bonus." Design consequence to carry into the lane: a closure IS an anonymous struct of its captures implementing `Callable` — so `Callable` is the primitive and closures the sugar, not the reverse. Two places this pays: G24's const CLOSURE SNAPSHOT is exactly a `Callable` struct whose fields are the captured const values (the emitted shape is a struct literal + the impl, no IIFE needed), and the closure-field call rule `(a.b)()` is the same rule for the same reason.
