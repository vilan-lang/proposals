# B340 — CALL-OPERATOR OVERLOADING: `impl MyStruct with Callable { fun call(self, n: f64): f64 { .. } }` makes a struct VALUE callable — `let scale = Scale::new(0.25); scale(2f)` lowers to `scale.call(2f)`. Today `my_struct(2f)` is refused ('cannot call this as a function: it is MyStruct', `not_callable_message` analyzer.rs:36289) and `Callable` does not exist ('cannot find trait `Callable`'); kolt's `src/lib/scale_step.vl` carries the use case with a FIXME (`Scale { unit }` + `fun get(self, n: f64): Length { Length::rem(self.unit * n) }` — 'Make into call operator overload when supported'). Shape: `Callable` is a MARKER trait in `std::operators` beside `Add`/`Sub`/`Lift` — `trait Callable {}` — and the `call` method the impl declares carries the ARITY and types (no variadic generics needed: the analyzer resolves `x(args)` on a receiver whose type implements `Callable` exactly as it resolves `x.call(args)`, so the signature check is the ordinary method check). A `Callable` value is plain DATA, so `const let space = Scale::new(0.25);` is a const result TODAY under G24's data rule and `space(2f)` in a const context calls through the interpreter — the scale use case needs no closure snapshot
