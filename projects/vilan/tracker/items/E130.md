# E130 — member completion is blind on a call whose DECLARED return is a type parameter: `SignalCell<T>::get()`'s `.` offers nothing (E107's other half)

- status: OPEN — the owner's find while migrating kolt (2026-09-04); reproduced at 289e2a2b by the triage lane
- kind: editor
- area: Language server & tooling

`let c: SignalCell<List<str>>; c.get().|` → 0 labels, while `c.|`, `let v
= c.get(); v.|`, `style::style().|`, `xs.first().|` (Option), `xs.map(..).|`
and even `c.get().len().|` all answer. User-code reduction with no std:
`impl Box<type T> { fun get(self): T; fun wrap(self): Option<T> }` —
`b.get().|` → 0, `b.wrap().|` → 33. Trigger: the callee's declared return
type is a BARE type parameter (reactive.vl ~517 `fun get(self): T`).

Cause: `call_result_type_id` (vilan-ide/src/completion.rs ~1521) returns
`function.return_type_id` verbatim at ~1532 — `T`'s own TypeId, no
substitution from the receiver; `nominal_type_id` (analysis.rs ~173)
matches only Struct/Enum, a parameter is `Type::Generic` → None; the
`hover_label` fallback (~1450) renders `fun get(self): T` and
`nominal_id_by_name("T")` is None too. The early return also shadows
E107's `inferred_return_types` fallback. The comment at ~1524 states the
assumption that is the bug: "the nominal head is written in the
declaration" — here there is no head.

Fix (S): when `return_type_id` resolves to `Type::Generic`, substitute
through what the analyzer recorded for the call —
`Program::method_call_substitution` (analyzer.rs ~39119,
`SubstitutionContext = HashMap<TypeId, TypeId>`), `own_generic_call_
bindings` / `generic_argument_ids` for free generics. Verify the map is
populated for a MID-EDIT call (the buffer carries `expected a field or
method name after '.'`); if not, E107's own shape: export the resolved
call result type into `Program` and read it first in
`expression_type_id` (~1497), M. A miss falls through to today. Related:
E107 (closed; the declared-vs-inferred sibling), M29 (the table must
answer `get()` — this is its prerequisite).
