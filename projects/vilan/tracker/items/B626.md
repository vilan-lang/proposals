# B626 — A module-level SCALAR binding read ONLY through a view (`&LIMIT`, `&LOOSE` handed to a `&i32`) is never declared on JS — the bundle emits `read([ LIMIT, 0 ])` with no `const LIMIT = [ 40 ]` and throws `ReferenceError: LIMIT is not defined`; natively it prints 41 and 51

- status: OPEN — filed 2026-10-13 (std-52's find, Order 52)
- kind: miscompile (JS; S)
- area: JS backend

Met probing B615's residue. The transformer's `Expr::Variable` arm drops a binding whose `reference_count` is below 1, and a `&NAME` of a scalar module binding (a `let` or a `const let`) leaves it there: a by-value read anywhere in the program (`print(LIMIT)`) restores the declaration (`const LIMIT = [ 40 ]`, boxed for the view), an aggregate binding (`&WORDS` of a `List`) is declared, and a LOCAL (`let x = 5; read(&x)`) is declared. So the `&` of a module scalar is most likely resolved without counting the reference (the emitter's `&` arm emits the right pair; not traced to the resolving site). Silent until run: `vilan check` is clean. Rec: count the reference where the view of a module binding resolves (analyzer core); pin both backends with a `let`, a `const let`, one read inside a closure. Sizing S; the analyzer core.
