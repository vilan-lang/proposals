# B603 — the canonical drain is not a function of the reachable set: a std module first asked for by a PACKAGE module loads after that module, so a redundant `import std::path;` in the entry (std::path already reachable through `pkg::a`) moves `pkg::a`'s function after std's in the emitted module — and on kolt's client std's 55,693 entity ids fall in nine runs cut by package ids

- status: OPEN — filed 2026-10-10 (papers-50's find, Order 50; std-prefix.md §1.4, §4.1)
- kind: determinism (S) — the canonical load order; the std prefix's P0
- area: Type system & the type solver

WO-1b's comment says the drain makes the load order 'a function only of WHICH modules are reachable'. It is a min-heap over the modules KNOWN so far: a std module requested by a package module is discovered when that module loads, so it loads (and its module node, SourceId and walk ids are minted) after it. Repro: `sweeps/order50/papers-50/finds/load_order_by_import_site/run.sh` (a package module imports `std::path::{basename}`; adding the redundant `import std::path;` to the entry reorders `dist/main.mjs`; the program still prints `y.txt`). On kolt's server leg, `import std::db;` in the entry reorders 18 lines of the emitted module; on the client, 5,632 std ids (`rpc::server`, `http`, `fs`, `path`, `ws`, `build`, `db`, ...) are minted after 81k package ids. No behaviour moves (the permutation differential holds the answers); the emitted bytes do, and a std world's ids depend on the package around it, which is what blocks a persisted std prefix. Door (std-prefix.md §4.1): finish discovery, then mint module nodes, SourceIds and the walk in `load_order_key` order over the whole reachable set (std, dependencies, package). Cost: one reorder of emitted declarations for multi-module programs; the corpus and native goldens regenerate once (reorder-only diff). Sequence after M110 S6's C2. Pins: the repro byte-identical with and without the redundant import; the permutation differential. Sizing S.
