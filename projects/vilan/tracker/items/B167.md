The precise class, probe-discriminated (scratchpad kolt-issues/):
- `if stored is Some(let f)` where the payload is a CLOSURE: the binding
  `f` is NEVER EMITTED — a direct call in the arm and a captured call in a
  nested closure both throw `ReferenceError: f is not defined` (issue3c,
  issue3b). No shadowing anywhere; the name chosen is irrelevant (the
  owner's falsifying observation).
- The same pattern with an i32 payload WORKS (issue3d prints 42).
- The same closure payload through MATCH works (issue3e prints "inner").

So the defect sits in the `if`-`is` lowering's capture materialization,
which skips (or mis-declares) closure-typed bindings where match's leg
lowering handles them. The first filing's `drag_handler_2` reading was a
misattribution. Fix at the root — whatever the if-is lowering does
differently from match for a pattern binding's declaration, unified on
the working rule; pins per shape: closure payload direct use, captured
use, nested closure, i32 control, match control, and a struct-payload
control (kolt's servers rely on it in production).
