# B167 — a pattern binding's alpha-rename misses its uses inside nested closures

- status: OPEN — the owner's kolt find (interact.vl), minimized by probe
  2026-08-29 evening; FIX-NOW, queued with B166's lane
- kind: bug
- area: Transformer & codegen
- source: the owner's emitted-JS evidence + the minimal repro, 2026-08-29

When an `is Some(let name)` pattern binding SHADOWS an existing `name`, the
emitter alpha-renames the declaration (`drag_handler_2`) but a use of the
binding INSIDE A CLOSURE created in the arm keeps the old name — the bundle
calls `drag_handler()`, which is not defined: `ReferenceError` at run time
from accepted vilan. Minimal repro (probe `issue3.vl`): an outer
`let drag_handler`, a shadowing `is Some(let drag_handler)`, the binding
called inside a nested closure in the arm. The fix is in the renamer: the
substitution must follow the binding into closure bodies (the same
capture-alias machinery the lifetime work's emission laws touched — "every
minted name comes from one generator"); pins red-first for the closure-use
shape, a two-deep closure, the non-shadowed control (works today, stays),
and the direct-use-in-arm control.
