# E121 — the editor-latency mandate: <10 ms per keystroke for tokens, hints, completion; errors <500 ms, on a large codebase

- status: OPEN — owner-set target 2026-09-01; an ARC (paper first)
- kind: design
- area: LSP & tooling
- source: the owner: "compiler performance at <10ms per keystroke … through whatever combination of caching, debouncing expensive operations, and code rewrites are needed. Semantic highlighting, inlay hints, and auto-complete shouldn't lag even on a large codebase. Errors can lag behind somewhat, but ideally would stay under 500ms for a large codebase/file."

Today (editor-perf, Order 24): a views.vl keystroke costs ~1.8 s to
diagnostics on next (3.7 s on 0.40.0), and every request rides the
SAME whole-program analysis — tokens, hints, completion, and errors
all wait for it. The mandate splits that into two paths:
1. THE KEYSTROKE PATH (<10 ms): parse the edited buffer (the parse
   cache exists), serve semantic tokens and inlay hints from the
   LAST COMPLETED analysis's resolved names re-mapped onto the new
   tree (or from syntax alone where names are unchanged), serve
   completion from a cached symbol index (per module, invalidated by
   the module's own edits) — nothing on this path may type-check.
2. THE DIAGNOSTICS PATH (<500 ms): debounced, cancellable (E117's
   version stamps), and INCREMENTAL — re-analyze the edited module
   and its dependents only, over cached analyses of unchanged modules
   (M19), a base-cache that pkg:: imports do not bypass (M21), and
   whole-program passes (dispatch_refine, const, call-graph — the
   1.2 s "post-passes") either made incremental or memoized on
   content.
The paper (`proposal/editor-latency.md`) measures the per-request
budget with editor-perf's instruments, names the rewrites, and
sequences them; M19/M21/M22 are its first three lanes. Success is
measured on kolt WITH lucide (1,791 functions) as the "large
codebase" exhibit.

## Paper 2026-09-01 — proposal/editor-latency.md: the premise corrected, the mandate sized

NO request waits for the analysis — every handler answers over the
last landed snapshot; the five-provider burst is 15.3 ms while
diagnostics take 1,111 ms. The real defects: every request
RECOMPUTES over the whole program (cost ∝ codebase, not file —
semantic tokens 4.2 → 27.0 ms for 4 → 5,000 reachable functions: the
10 ms budget is spent at ≈490 functions, the 500 ms error budget at
≈600), answers are UNMARKED-STALE (409 ms window, one number for
tokens/hints/diagnostics), superseded analyses are NEVER CANCELLED.
Sequence: N43 → M21 (a syntactic condition at analyzer.rs:40358

second bypass at :40096) → M19's first tranche (a Type-keyed memo on
check_generic_bound_satisfaction, :4315/:4329) → M22 → cancellation
checkpoints; the KEYSTROKE PATH (§2.1: a two-sided byte-identical
anchor, a syntax-only middle window, a declaration-shape stamp, a
per-module symbol index) depends on none of them and is gated on Q1.
The incremental analyzer needs its own paper: Id/TypeId are minted
per OCCURRENCE (:14600). Six owner questions, Q1 gating (stale-but-
unmarked on the keystroke path: tokens yes, hints split). Two finds
filed: E122, E123. Absolute numbers from loadavg 8–11 under a 13-lane
day — a quiet-machine re-record is the next lane's first move.

## RULED 2026-09-01 — the paper's six questions

Q1 stale-but-unmarked on the keystroke path: tokens YES, hints
SPLIT (withheld inside the edit window, otherwise served unchanged).
Q2 debounce: adaptive `clamp(0.3 × last analysis, 150, 500)`, a
bridge that retires itself. Q3 the 500 ms EXCLUDES the debounce (a
CPU-clocked gate). Q4 a withheld hint beats a possibly-wrong one.
Q5 syntactic coloring in the edited region, upgraded on land — the
owner's exhibit: commenting a line must read as a comment at once,
not keep its semantic colors for the staleness window. Q6 the gate's
exhibit is GENERATED, sized like kolt-with-lucide — and the owner's
standing rule: **kolt is never integrated into vilan's codebase**
(no fixture, no golden, no exhibit copied in; kolt is read-only
evidence only).

## The keystroke path BUILT 2026-09-01 (lane keystroke-path, §2.1 as ruled Q1–Q6)

`crates/vilan-lsp/src/keystroke.rs`: an analysis captures its own
token stream, hint list, declaration-shape stamp and symbol index
ONCE on the analysis thread (`LandedSnapshot`, adopted wholesale); a
request re-serves the capture through a two-sided anchor (common
prefix trimmed to a line start, common suffix trimmed forward,
non-overlapping, UTF-8-safe by line boundaries; a straddling span is
dropped, never clamped). Stamp = every lexer token outside a
function body (§2.1.2 cases 1–3; off the lexer so a mid-keystroke
syntax error survives; a lex error hashes as changed). Verdicts:
Exact (re-map + syntax-only window), Stale (whole file syntax-only,
hints still served — Q1's anti-flicker), Unusable (hints withheld).
Q5's exhibit: the lexer emits no token for a comment, so a commented
line reads as a comment on the next keystroke.
THE GATE PASSES — release, generated exhibit (1,791 fns), 50
requests/window, loadavg 42, thread CPU: the replaced walk 1.104 ms;
semanticTokens 0.004; inlayHint 0.001; completion 0.592; BURST
0.828 ms (assertion: path beats the walk, live). kolt views.vl at
loadavg 45 vs the paper's loadavg 11: tokens 12.2 → 0.30 ms, hints
hot 13.8 → 4.25, burst 15.3 → 12.0 (all completion — M25).
Diagnostics 2,971 ms wall / 1,780 CPU: perf-25's path, `diagnostics_
budget` pin `#[ignore]`d at ~925 ms CPU vs 500. 39 tests; the old
"answer the analyzed snapshot" pin went RED and was rewritten to the
ruled contract. Residuals: a `let` added inside a body can shadow a
