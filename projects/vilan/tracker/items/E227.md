# E227 — inlay hints show a type by the TRAIT it is used as, not by its exact implementation, when the type declares one: `Map<Combine<(List<Command>, usize)>, (List<Command>, usize), Option<Command>>` reads as `Source<Option<Command>>`; hover, completion and diagnostics keep the full type

- status: OPEN — filed 2026-09-26 (the owner, after kolt's v0.41.0 migration); INVESTIGATE — a rec, not a ruling
- kind: design (editor)
- area: LSP & tooling

**The observation.** Since A124 S2c a derivation's type is a pipeline node that spells its whole upstream: kolt's `selected_command` hints as `Map<Combine<(List<Command>, usize)>, (List<Command>, usize), Option<Command>>`, and the one fact the reader wants — it is a source of `Option<Command>` — is the LAST argument. An inlay hint is a reading aid, not the type; it may abbreviate where the hover, the completion list and every diagnostic keep the full type (`Document::inlay_hints`, `crates/vilan-lsp/src/document.rs:3848`, reads `program.expr_types` verbatim).

**The correction to the sketch.** The short form is `Source<Option<Command>>`, not `Signal<Option<Command>>`: a `Map` node implements `Source<U>` (`reactive.vl:1835`) and NOT `Signal<U>` (the writable trait, `reactive.vl:1329`). A hint that said `Signal` would promise a `set` the value does not have, which is the one thing an abbreviation must never do. The abbreviated form must also be MARKED so a reader cannot mistake it for the concrete type — Rust-analyzer's `impl Iterator<Item = ..>` does this with the `impl` word; vilan has `dyn Trait` (types.md §5.12) but the value is not an object, so the marker should be a spelling that cannot be written as a type: recommend `: ~Source<Option<Command>>` or `: impl Source<Option<Command>>` (a prefix only the hint uses; `impl` is not a type keyword today, so it is free).

**The problem the owner named — which trait.** A type implements many traits (`PartialEq`, `Hashable`, `Json`, `Source`, …) and a heuristic ('the trait with a type argument', 'the trait the doc names first', 'the only exported trait impl') picks wrong somewhere. **Rec: the author DECLARES it.** A struct or enum carries an attribute — `[hint(Source<U>)]` on `Map<S, T, U>`, `Switch`, `Combine`, `FlattenOption`, `AndThen`, `KeyedCell`'s deltas, `RemoteSource<T>` (→ `Source<T>`), `Memo`… — naming the trait application in the struct's own parameters. The hint renders that application with the instantiation's arguments substituted; a type without the attribute renders as today. No guessing, one line per type in std, and a package author gets the same lever for their own combinators. Rejected: (a) picking by heuristic (wrong somewhere, and silently); (b) collapsing to the supertrait chain's root (`Source` is what you want for `Map`, but `PartialEq` is not what you want for `Theme`); (c) letting the USE SITE decide (the binding's later uses would need a second pass and change the hint as the code below it changes).

**Open questions for the paper.** Q1 the marker's spelling (`~T` / `impl T` / `«T»`); Q2 whether a NESTED node inside a concrete type abbreviates too (`(Map<..>, usize)` → `(~Source<A>, usize)` — rec yes, the substitution is recursive); Q3 whether the attribute may name a trait the type implements only CONDITIONALLY (`Map<S: Source<T>, T, U>` implements `Source<U>` for every instantiation the solver admits, so the answer is 'the impl must be unconditional over the type's own parameters' — check the blanket `impl Map<type S: Source<type T>, T, type U> with Source<U>` qualifies); Q4 an editor setting to turn the abbreviation off (`vilan.inlayHints.abbreviate`, default on); Q5 whether `hover` shows BOTH lines (full type first, the abbreviation beneath) so the reader learns the mapping.

**Sizing.** S–M: the attribute (parser + one analyzer table), the substitution in `inlay_hints` (or a `pretty_print_type` mode), std's ~10 attributes, three LSP pins (a bare node, a nested one, a type without the attribute unchanged), the appendix line. Editor lane, Order 43 candidate; the paper first if the marker question wants the owner.
