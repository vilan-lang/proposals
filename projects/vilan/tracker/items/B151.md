# B151 — the mR2 overwrite double-drops when the RHS throws

- status: OPEN — reproduced on 0.38.0 (lifetimes session probe E3, 2026-08-28); FIX-NOW candidate: a double close today, a double free on any native backend
- kind: bug
- area: Type system & the type solver
- source: the lifetimes session's error-path probes, 2026-08-28

The overwrite lowering pushes the old value's destructor BEFORE walking
the new value's expression (transformer.rs:4314 era). If computing the
RHS panics, the scope-end `finally` then drops the same,
already-destroyed value again — probe output shows the drop line twice.
For a `File` that is a double `close()`; on a native backend it is a
double free. The fix is evaluation ordering, not lifetimes: RHS into a
temporary first, then drop the old value, then assign — proven working
in the probe's hand-fixed emission. Red-first pin: mR2 overwrite whose
RHS throws; assert exactly one drop.
