# F187 — The GPU UI has never run on a real GPU, on Windows or on macOS: a hardware run kit (a report switch in the host, a probe checklist, a runbook) for the owner's machines

- status: open
- kind: verification (native UI; first real-hardware run)
- area: crates/vilan-rt-gfx (host, gpu.rs, window.rs), vilan/examples/{gfx,ui-counter,ui-todo,ui-notes,ui-virtual-list,ui-icons}, F178 (accessibility verification), F167

Everything in the GPU stack has been verified on one target: Linux, X11, Mesa's software Vulkan, under a virtual display. Windows is cross-linted and never run; macOS is not even type-checked. THE KIT (lane hw-58, 2026-11-17): (1) a report switch in the host (an environment variable, no std surface): at start, the adapter's name, vendor, device type, backend and driver, the surface format and present mode, the window's scale factor and size; at exit, frame count and the distribution of per-frame CPU time (layout, paint, encode, submit) and of the interval between presented frames; (2) macOS type-checked from Linux if the target can be added, so compile errors are found here; (3) a runbook: prerequisites per system, the exact commands from a checkout of `next`, the six examples in order, what to try in each (resize by dragging, move between monitors of different scale, typing with an input method, sleep and wake, a screen reader: Narrator, VoiceOver), and what to send back (the report text, a screenshot per example at each scale, anything that looked wrong). WHAT THE RUN DECIDES: whether the three back ends wgpu picks (DX12, Metal, Vulkan) draw what the software renderer draws; real frame times; whether the debug profile is usable or F167's dev-profile ruling is urgent; which of IME, focus scopes and a second window a real app meets first.
