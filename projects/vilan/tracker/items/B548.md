# B548 — a file declaring `[platform("browser")] mod self;` that IMPORTS a platform-twin module (`std::web::ui`) is refused in a node build even when nothing reaches it from the entry: the import binds the PROCESS twin, and the fence walk reports that twin's functions ("`view` requires the `process` layer of `std` and cannot run on `browser` … reachable from `card`, which its declaration fences")

- status: OPEN — filed 2026-10-04 (layout-46's find, Order 46)
- kind: bug (platform colouring; spurious refusal) (M)
- area: Native targets & rendering

Repro: a node entry that imports `pkg::widget::card`, where `widget.vl` is `[platform("browser")] mod self;` + `import std::web::ui::{ View, view };` + `export fun card(): View { view("div") }`. `vilan check` on next: one error inside std's process `ui.vl`. One program has one platform, so a twin import resolves to the build platform's side, and the fence walk then checks a browser-fenced body against the OTHER twin. With a layer the same module (std's `router`, which imports `ui`) was loaded for typing and never fence-walked, so the layer gave zero errors; fenced it gives six on a bare `import std::web::router::location_url;` — the first of the two reasons layout-46 stopped F28. Rec: the fence walk skips a fenced body whose declaration this build's platform does not admit (it is dead in this build by its own declaration, and reachability from the entry already reports a real call into it), or reports only from entry-reachable fenced bodies. Pin: `module_resolution::f28_an_off_platform_call_into_a_single_platform_module_is_one_error_at_the_call` over a fenced tree.
