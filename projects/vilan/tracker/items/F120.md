# F120 — natively, an `async` block whose body is itself an `async` block (`async { async { "s" } }`) is not assimilated: rustc refuses the emitted Rust (E0308) where the analyzer and JS type and run it as one `Task<str>`

- status: OPEN — filed 2026-10-09 (solver-48's find, Order 48)
- kind: bug (native backend defect; S)
- area: Native targets & rendering

`assimilated_task_payload` normalizes a handle the solver FORMS, so `async { async { .. } }` is `Task<str>`; on JS the host's promise adoption makes the runtime agree. The native lowering of the outer block hands back the inner block's handle as its value, one `Task` layer deeper than the type. Pre-existing (the plain `fun deeper(): Task<str> { async { async { "s" } } }` fails the same way at base b5d098ee); B559's written `Task<Task<str>>` now reaches it too. Rec: the native async-block lowering awaits a body whose type is itself a handle (the layers `assimilated_task_payload` strips), as F107 made a written-async call await its declared handle. Sizing S; native.
