# F146 — A native program parked on `read_line`/`prompt` burns CPU while it waits: ~0.12 s of CPU per 5 s of a silent, open stdin (~2.4 %, debug build) against node's 0.00 s - the executor polls its I/O sources every `IO_POLL_INTERVAL` (1 ms) while any source is live

- status: OPEN - filed 2026-10-16 (std-54's find, Order 54)
- kind: performance (native executor; stdin wait)
- area: Native targets & rendering

A173 S1's stdin source is live only while a read waits (so an idle stdin costs nothing), but a human typing a line is exactly that wait, and the executor's turn model sleeps 1 ms between polls when no timer is due (R8: no epoll without libc). terminal.md §5.2 names the refinement: when stdin is the ONLY live source, block on the reader's channel with `recv_timeout` until the next timer deadline (or indefinitely with no timer) instead of sleeping 1 ms; the same shape serves S2's key stream, where the wait is the program's whole life. Measure with the probe's idle.py (native release and debug) before and after; no ordering change (the poll answers the same chunk, only sooner and without the spin).
