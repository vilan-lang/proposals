# B767 — JS: a write through a `&mut` view of a closure-typed place is lost; native is correct

- status: open - filed 2026-11-27 (the integrator, reviewing lane `keys-s3a`; pre-existing on `next` @6744ee9d, no key involved)
- kind: miscompile (JS)
- area: crates/vilan-core/src/transformer.rs (the view protocol: a closure-typed place behind `&mut`)

Repro:

```
struct Holder {
	f: || i32,
}
fun set(place: &mut (|| i32)) {
	place = || 7;
}
fun main() {
	mut f = || 0;
	set(&mut f);
	print(f());
	mut h = Holder { f = || 0 };
	set(&mut h.f);
	let g = h.f;
	print(g());
}
```

`vilan run` prints `0` twice. `vilan run --backend rust` prints `7` twice. The program checks clean. The assignment inside `set` does not reach the caller's place on JS, for a binding and for a struct field alike.

Why it matters now: B711 S3a's `change` lends a place to a closure, so `Holder.f::Some.change(&mut h, |place| { place = || 9; })` answers `true` and leaves the old closure on JS (native writes it). `put` on the same place is correct on both backends. A scalar or struct place is not affected.

Workaround: write the place with a plain assignment (`h.f = ..`) or, through a key, with `put`.
