# A28 — `map`/`combine`/`flatten` derivations can never be detached: a live std leak

- status: OPEN — measured 2026-08-28 (lifetimes session, reactive-graph leg); FIX-NOW candidate, independent of the lifetime work; lifetimes.md S1 owns it
- kind: bug
- area: Reactive core & UI
- source: heap-snapshot SCC analysis of running programs, 2026-08-28

`Signal::map` pushes a `Subscriber` and returns only the derived signal —
no id, no `Subscription`; `combine` computes and DISCARDS its per-input
subscriptions; `flatten` discards its outer one. None can ever be
detached. Measured: the documented router idiom (`current_path().map(parse)`
inside `mount_root`, then dispose) leaks 256 objects PERMANENTLY per
mount/dispose round — 25 rounds left 25 dead subscribers on the
module-level path signal, 26 signals, 50 closures retained forever — and
it is a time leak too: every navigation notifies every dead derivation
ever created. `std::ui`'s chunk signals share the shape. Fix: return the
`Subscription` or register it with the ambient owner the way
`Source::effect` and `RemoteSource::map` already do. Pin: subscriber
count across 25 mount/dispose rounds goes 25 → 0 under the fix.
