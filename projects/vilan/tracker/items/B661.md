# B661 — A closure type taking a closure, written without parentheses (`|str, |bool| void| void`), is a parse error that does not say the inner closure type needs parentheses; in a larger struct the failed parse also drops the struct's other fields and cascades into "no field" errors

- status: OPEN — filed 2026-10-20 (kolt's message editor: `upload: |LocalFile, |Result<str, str>| void| void`)
- kind: diagnostics (parser; S)
- area: Language

```vilan
struct Holder {
	name: str,
	run: |str, |bool| void| void,
}
```

vilan 0.52.0: `found '|' expected ',' or '}'` at the inner closure's closing `|`. The right spelling is `|str, (|bool| void)| void`, as `std` and kolt write elsewhere (`group: |(|| void)| void`), but the message gives no hint of it.

In kolt's 1,900-line `message_editor.vl` the same mistake on one field of `struct Message` was followed by `struct 'Message' has no field 'next_id'` and `... no field 'blocks'` at every use of the struct's other fields: the error recovery threw the whole struct body away, and those cascade errors outnumbered the real one. (The minimal repro above reports only the parse error.)

Asks: (1) at a `|` that would close a parameter list inside a closure type's parameters, suggest "wrap a closure type that is a parameter in parentheses: `(|bool| void)`"; (2) recover at the field, keeping the struct's other fields, so uses of them do not cascade.
