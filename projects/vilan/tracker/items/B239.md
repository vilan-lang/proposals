# B239 — FILE MODE regression from B226: an open non-entry file is analyzed as the entry, so a sibling that imports it (`channel.vl` → `pkg::views`) hits the new "entry cannot be imported" error and everything it carried cascades (kolt's views.vl in the editor: 7 errors, `vilan check .` clean)

- status: OPEN — the owner's report (2026-09-04); reproduced with `vilan check src/views.vl` on kolt (7 errors) while `vilan check .` is clean
- kind: bug
- area: Type system & the type solver

The LSP (and `vilan check <file>` on a non-entry file) analyzes the OPEN FILE as the entry. kolt's new channel.vl imports `pkg::views::{button_style, icon}` and views.vl imports channel — a legitimate module cycle under the real entries. In file mode views.vl IS the entry, so B226's new cycle error (analyzer ~46000: any Pkg module referencing `pkg::<entry_module>`) fires on channel's import, channel fails to load, and `Style has no method 'flex_row'`, `cannot find 'full' in Length`, `cannot find 'icon'/'button_style' in the imported path / in this scope` follow — seven errors the owner never saw before, because before B226 the same situation silently loaded the entry AS A MODULE (siblings' imports worked; the entry's program walk and derive expansion were skipped — the owner's original SidebarTab report). Both behaviors are wrong in file mode. Required: when the analyzed entry is NOT a declared manifest entry (file mode), the file is a module that is also walked as the entry — siblings' `pkg::<file>` imports resolve exactly as module-to-module imports in a cycle do (the crux: a sibling resolves its imports before the entry walks; modules in a cycle work because their scopes/importables are seeded before any walk — give the file-mode entry the same seeding, or load it through the module pipeline AND walk it as the program without double-declaring), derives expand, no `main` required; B226's error and warning fire only for a DECLARED entry. The front end already knows the fact: E119's `platform_reason` ("no entry reaches it (default-entry is …)") is computed exactly when the open file is not a declared entry — thread an explicit `entry_is_declared`/analysis-mode flag through the same project context (CLI `check <file>` via `resolve_project`; the LSP's document analysis), out of the base-cache key like `platform_reason`. Pins: the kolt shape (views ↔ channel cycle, an `impl Style` method reached through the cycle, a `[derive]` in the open file) in file mode → zero diagnostics and the derive holds; the declared-entry cycle (client → views → client) still errors once (B226's pin); the self-import warning still fires for a declared entry only; `vilan check src/<module>.vl` on a module imported by a sibling is clean; B226's four pins unchanged.
