# G15 — a `[[build.hook]]` directory input that is a symlink re-runs the hook every build, forever

- status: OPEN — audit run 5's F3; order-material
- kind: bug
- area: Macros & const
- source: audit run 5

`file_digest` stats with `symlink_metadata`, so a link-to-directory is not
`is_dir()`, falls to `fs::read` (EISDIR), digests as `None`, and the hook is
stale on every build, silently — while the WATCHER's `insert_watched_input`
uses `fs::metadata` and follows the link. The code comment claims the two
match; true for link-to-file only. Reproduced: 3 builds over
`inputs = "linked_static"` ran the hook 3 times; `real_static` once. The
same silent-forever-loop class the generated root closed. No symlink pin
exists in build_hooks.rs — the fix brings the pair (stamp follows the
top-level link exactly as the watcher does) plus the pins.
