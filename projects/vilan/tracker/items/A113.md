# A113 — QUESTION (the owner, 2026-09-21): do Signal EFFECTS clean up their observers? Preliminary answer from source at 0fa109eb (reactive.vl) — YES for the owned forms, BY HAND for the unowned ones, LEAK-AS-TODAY for an ownerless derivation, and there is NO per-run cleanup — to be verified with pins and written into the guide, because today the answer lives only in doc comments

- status: OPEN — filed 2026-09-21 (the owner's ask, mid-Order 38)
- kind: question + documentation
- area: Reactive core & UI

What the source says, to be CONFIRMED by pins (none of this is yet a measured claim of this item):

1. **`effect` / `effect_on_change`** — `get_owner().take(self.on_change(observer))`: they REQUIRE an ambient `owner_scope` statically (no owner, no compile), and the owner disposes the subscription when it is disposed. A mounted view, a `swap` instantiation, a `when` arm, an `each` row each mint an `Owner`, so an effect made inside one dies with it. Since Order 38 (A110 door 1) a disposed subscription also never FIRES again — inline or from a wave the drain already took out — and its queue entry is scrubbed (FIND-2).
2. **`sub` / `on_change` / `observe`** — return a `Subscription`; NOTHING cleans it up. The caller holds it and calls `dispose`, or hands it to an owner (`owner.take(..)`). Dropping the value does not unsubscribe (no destructor on JS; C14 S3 made the subscriber→cell and subscription→list edges WEAK, which helps collection of a dead CELL, not of a live cell's forgotten observer).
3. **Derivations — `map`, `combine`, `flatten`, `selector`** — `register_with_owner`: inside a boundary the derivation's subscription into its source dies with the boundary (A28's measured leak — 25 mount/dispose rounds, 25 dead subscribers — is closed); OUTSIDE every boundary it lives as long as its SOURCE, deliberately ("leak-as-today, not a refusal" — refusing is breaking and was left as the owner's call). `RemoteSource::map` already refuses the ownerless case.
4. **No per-run cleanup.** vilan effects do not auto-track dependencies, so there is no Solid-style dependency list to clear per run; but there is also no `on_cleanup` that runs BEFORE an effect's next run. An effect body that creates subscriptions, timers or DOM on each run cleans up the previous run's only if it routes them through a form (`swap` mints a fresh `Owner` per instantiation and disposes the last) or manages a handle itself. `Owner::defer` runs at DISPOSAL only.
5. **A disposed `Owner` is single-use** (B291): a `take`/`defer` after `dispose` releases on the spot — so a late registration cannot leak, it is torn down immediately.

Owed: (a) one `reactive_lifetimes` pin per row above that does not already have one — count subscribers on the source before/after the boundary's disposal (the A28 instrument), for `effect`, `effect_on_change`, `map` inside and outside a boundary, and a `sub` whose handle is dropped (expected: still subscribed — pinned as the documented contract, not a bug); (b) a guide section 'Who cleans up what' (guide/reactivity.md) with exactly this table; (c) the two RULINGS this question surfaces — should an OWNERLESS derivation be refused (row 3; breaking; the stronger law), and does vilan want a per-run cleanup hook (`on_cleanup` inside an effect, row 4), which A111's suspend/resume and A112's per-element owners would both lean on. Kolt census (read-only): every `sub`/`on_change` whose `Subscription` is discarded.
