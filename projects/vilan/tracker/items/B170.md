# B170 — every binary operator skips its check when the LEFT operand is non-nominal

- status: OPEN — audit run 6's F3; order-material, the b148 class's other half
- kind: bug
- area: Type system & the type solver
- source: audit run 6, 2026-08-29 (guard predates the delta; the spec sentence does not)

`analyzer.rs:32639` `continue`s unless the left operand is a Struct or Enum,
so `void`, tuples, arrays and closures fall through both the native arm and
the no-`Add` refusal: `nothing() + 1` is NaN, `(1,2) + 1` prints `1,21`
(b148's exact miscompile entered from the other side), a closure
concatenates its SOURCE TEXT, and `let v = if false { 1 }; v + 1` prints a
plausible wrong `1`. The right side is already refused (the asymmetry is
exact) and `spec/types.md:501` — added THIS order — says "anything else is
an error". Fix at the guard; per-left-operand-type pins; sweep the sibling
early-continues in the same loop (run 7's charter names this).
