# B690 — JS MISCOMPILE: a module-level `const let` read only from a function reached through an operator (`a > b` -> `PartialOrd::gt` -> `partial_compare`) is never declared in the emitted JS - a ReferenceError at run time; native is fine

- status: OPEN - filed 2026-10-31 (std-a178's find; A178 S1 works around it in std with a private function)
- kind: miscompile (JS emitter; liveness through operator dispatch)
- area: Compiler

The JS emitter's reachability (which module bindings get a declaration) follows call edges; an operator use `a > b` lowers to the trait method through the dispatch table, and the binding read inside the trait method's body is not reached - the emitted module has no `const k` and the call throws `ReferenceError: k is not defined`. Native declares it (the Rust backend emits every module binding). Rec: the emitter's liveness walk must follow operator lowering into the trait impls it selects (the same edge the checker's platform reach already follows - see B686's complaint that it follows TOO many); pin: the probe on both backends in native_differential.
