# B689 — Reading one field through a store's `some()` copies the whole value it's in

- status: OPEN - filed 2026-10-31 (kolt)
- kind: perf bug (std reactive store)
- area: Standard library (reactive store)

A store is meant to be read field by field: `store.records().at(1).some().title().get()` should cost what reading `title` costs. It costs what copying the whole record costs. The read goes through `StoreSome`'s variant reader (`some` → `lent_option` → `get`), and the generated code deep-clones (`__clone`) the held payload on the way, so a record with large fields makes every small read of it slow.

Measured on node 24, 2,000 reads of one record's `title` (repro below):

| The record's `notes` | 2,000 title reads |
| --- | --- |
| 10 strings | 10.7 ms |
| 1,000 strings | 26.7 ms |
| 10,000 strings | 271 ms |

In kolt it's most of the time a big page takes. Opening the Board on an organization of 2,072 tasks took 6.8 s, and a CPU profile put 4.5 s of it in `__clone` under `lent_option`/`get` and a `memo`'s `cell`: each card reads its task's title, status, assignees and so on through `TaskRecord::find(g, id)` (`g.tasks().at(id).some()`), and every one of those reads copies the task (its sections, values, links and body).

Repro (standalone; prints three timings): kolt session scratchpad `somerepro/some.vl`, the whole file:

```
import std::hash_map::HashMap;
import std::reactive::store::Store;

[extern("(() => performance.now())")]
external fun clock_ms(): f64;

[derive(PartialEq, Storable)]
struct Record {
	title: str,
	notes: List<str>,
}

[derive(Storable)]
struct State {
	records: HashMap<i32, Record>,
}

/// Reads one record's title `reads` times through the store, the record
/// holding `size` notes.
fun read_title(size: i32, reads: i32): f64 {
	mut notes: List<str> = [];
	mut index = 0;
	for index < size {
		notes.push("a note of some length, repeated");
		index += 1;
	}
	mut records: HashMap<i32, Record> = HashMap::new();
	records.insert(1, Record { title = "first", notes });
	let store = Store::new(State { records });
	let started = clock_ms();
	mut count = 0;
	mut read = 0;
	for read < reads {
		count += store.records().at(1).some().title().get().map_or(|title| title.len(), 0usize).as_i32();
		read += 1;
	}
	count > 0 then clock_ms() - started else 0f
}

fun main() {
	print(i"10 notes: {read_title(10, 2000)} ms");
	print(i"1000 notes: {read_title(1000, 2000)} ms");
	print(i"10000 notes: {read_title(10000, 2000)} ms");
}
```

Recommendation: a `some()` path should lend the payload in place (as `Shared::read().get(k)` already reads a map entry without a copy) and copy only the leaf a `get()` returns. A pin: the repro's three timings within a small factor of each other. Sizing S–M (the variant reader in `std/src/reactive/store.vl` and the lending codegen).
