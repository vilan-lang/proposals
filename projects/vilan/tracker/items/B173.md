# B173 — a blanket impl never satisfies a bound for a GENERIC value: declared bounds are the only answer

- status: OPEN — b168 lane's find (Order 23); a semantic RULING, not a mechanical fix
- kind: design
- area: Type system & the type solver
- source: lane b168, 2026-08-31; pin `generics::a_blanket_impl_bound_resolves_from_a_generic_body` (#[ignore]d)

`satisfies_trait_bound` answers for a `Type::Generic` value from its
DECLARED bounds alone, never from an impl — so a blanket
`impl type T with Wrap<T>` cannot satisfy `W: Wrap<T>` when `W` is
bound to the caller's own parameter, while a CONCRETE caller passes
the same program. B168's fix improved the neighborhood (the bogus
`': Tag'` refusal is gone; the remaining refusal names the caller's
own parameter), but this mechanism is distinct: the question is
whether an abstract parameter satisfies a blanket impl at all —
adjacent to B161/B162's trait-as-checked-constraint semantics, and
the owner's specificity ruling (B158) presumably governs which impl
would answer. Rule it, then either implement or record the refusal as
deliberate with the pin flipped to a negative.
