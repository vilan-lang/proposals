# F104 — A closure whose body only panics does not build natively: `let run: || void = || panic("x");` (and the block form `|| { panic("x"); }`) emits a closure rustc types as returning `!`, refused against `Rc<dyn Fn() -> ()>` (E0271)

- status: OPEN
- kind: bug (native backend; emitted Rust refused)
- area: Native backend

Repro (vilan 0.44.0 e5e15ca7, `vilan run --backend rust`):

```vilan
import std::io::panic;
fun main() {
	let run: || void = || panic("x");
	run();
}
```

rustc: `error[E0271]: expected {closure@main.rs:9:39} to return (), but it returns !`. The JS leg throws `x` as expected. The block form `|| { panic("x"); }` fails the same way (a block ending in a diverging statement is `!` too); a body whose panic sits under an `if` builds. Cause: the emitted closure's body is the `-> !` runtime call in TAIL position, so rustc infers the closure's return type as `!`, and a `!`-returning closure is not a `dyn Fn() -> ()`. Rec: emit a never-typed tail in a closure whose declared return is `void` as a statement (`{ panic(..); }`), or coerce at the `Rc::new` site. Found by debug-47 writing S0's panic-location probe (`crates/vilan-cli/tests/native/panic_locations.vl` puts the panic under an `if` for that reason).
