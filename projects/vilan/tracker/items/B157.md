# B157 — static-or-dynamic component values: bless the trait-bound pattern; the `union` alternative recorded

- status: OPEN — owner-proposed 2026-08-29 (the `union` sketch); the
  probe-verified finding reframes it — discussion needed on the residual
- kind: design
- area: Type system & the type solver
- source: the owner's union proposal, 2026-08-29; probe the same day

The owner's ask: components should accept static AND dynamic values with no
call-site ceremony — `foo("x")` and `foo(Signal::new("x"))` against one
parameter — sketched as an anonymous `union Value { str, Signal<str> }` with
implicit injection, "comparable to `<div name(...)>`".

**The probe's finding: the element position's acceptance is not compiler
magic, and the pattern is user-reachable TODAY.** `attr<V: AttrValue>` is a
bounded generic; `impl str with AttrValue` sets once and
`impl Signal<str> with AttrValue` tracks — "the value's TYPE decides its
life" (element-syntax.md §5). The user-side spelling compiles and runs on
the shipped compiler: a `trait TextValue` + two impls + `fun badge<V:
TextValue>(label: V)` accepts both call forms with zero call-site ceremony,
static dispatch, no runtime discrimination — the owner's "compile-time
feature, no runtime logic" intuition, delivered by shipped machinery. The
declaration ceremony moves to ONE trait+impls block instead of every call
site, which is also where a `union` declaration would sit.

**What the trait route cannot do, honestly — the union's residual niche:**
(1) STORABLE values: a struct field or list element typed "str or
Signal<str>" needs a real type, not a bound (generic structs or an enum);
(2) match-based consumption — though the trait route mostly dissolves this
(behavior lives in the impls, tell-don't-ask).

**Why the general `union` is partial by necessity:** discrimination inside
the consumer needs the HOST to tell members apart, and vilan structs erase
to untagged JS objects — `union V { Point, Vector }` over two `{x, y}`
structs cannot be matched at runtime. A sound feature needs a
DISTINGUISHABILITY FENCE (every member pair host-separable: primitive kinds
vs objects, at most one untagged struct, ...), which admits exactly the
str-vs-Signal case and refuses much else; the moment general members want
tags, the feature has reinvented `enum`. (TypeScript avoids this by never
discriminating for the user; Zig by tagging.)

**The owner's two problems, probed 2026-08-29 (dev toolchain, post-2ad39dd0):**
(1) REACTION — solved by making the trait method EFFECT-shaped rather than
getter-shaped, which is `AttrValue`'s own answer: `fun bind(self, react: |T|
void)` — the static impl fires the handler once, the `Signal` impl
subscribes, and the probe shows the component reacting to a later `set`
(the std version rides `effect`/owner registration so the subscription dies
with its boundary, per A28's machinery). (2) GENERICITY — two-thirds
shipped: `trait MaybeSignal<T>` and `impl Signal<type T> with
MaybeSignal<T>` both compile and dispatch today (the owner's guessed
spelling IS the grammar, `hash.vl`'s `impl Option<type T: Hashable>` the
precedent). The missing third is the BLANKET static impl `impl type T with
MaybeSignal<T>` — accepted at declaration, internal error at first dispatch
(filed as B158). Coherence is sound to add: blanket (`V = T`) and signal
(`V = Signal<T>`) impls can never overlap at finite `T`. Until it exists,
the static side is per-type impls — a bounded set std could ship for the
common value types.

Recommended course: (a) BLESS the trait-bound pattern as the documented
component idiom (guide section from the badge exhibit); (b) consider ONE
std trait for the static-or-reactive pair specifically (a generalized
`AttrValue` — name open: `Source<T>`-trait shaped) so component authors
share a vocabulary instead of minting per-component traits — this could
also let the attr/bind_attr, styled/bind_styled PAIRS collapse one day;
(c) the `union` former stays recorded here as the alternative, warranted
only if the STORABLE case grows real exhibits — and then likely as sugar
over an enum with implicit injection (nominal, tagged, total) rather than
an anonymous structural union (partial by the fence). `std::into`'s
`Into<T>` trait (shipped, near-unused) is the injection seam if (c) ever
builds.
