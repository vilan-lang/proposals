# M31 — the analyzer's 35 `IndexMap`/`IndexSet` tables still hash with SipHash: 7.4M SipHash calls, 6.7% of a kolt client check

- status: OPEN — kolt-benchmark's find (2026-09-04; callgrind at 289e2a2b); E48's residual
- kind: performance
- area: Type system & the type solver

E48 moved the analyzer's `HashMap`/`HashSet` onto `crate::fx`
(`FxHashMap`/`FxHashSet`), and that half shows in the profile as
cheap `hash_one` frames. The other half did not move: the 35
`IndexMap<_, _>` / `IndexSet<_>` fields (`functions`,
`external_functions`, `traits`, …) take indexmap's default
`RandomState`, i.e. SipHash-1-3 — **7,388,275 SipHash calls,
`sip.rs` 6.7% of a full client check's 7.19e9 Ir**, keyed on the
same `u32` newtypes E48 diagnosed. The largest single driver is
`functions.get` inside `method_signature`, reached 856,908× from
`analyze_over_world` (M30's path); `classify_resource`,
`infer_type_path`, `async_infer::members_named` and
`call_bumps_positions` follow at 170k–370k each. `FxBuildHasher` is
already `pub` and implements `BuildHasher + Default`, so this is an
alias — `pub type FxIndexMap<K, V> = IndexMap<K, V, FxBuildHasher>`
beside the two existing ones — and a mechanical swap; the SipHash
uses in `content_hash`/`load_package_module` (content keys) stay.
Note E48's honest-provenance rule: the alias reuses the in-house
hasher, no new dependency. Pin: `sip.rs` ≤ 1% of a cold `vilan
check` of kolt's client (the E47/E48 harness shape); iteration
order is insertion order for `IndexMap` regardless of hasher, so no
golden moves — assert that on the corpus.
