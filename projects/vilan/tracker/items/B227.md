# B227 — an `any` parameter FILLS an unfilled closure parameter instead of coercing: one `print(x)` types `x` as `any` and silences every later check on it (`on:keydown(|event| ..)`'s `event: any` is this)

- status: OPEN — the owner's finds while migrating kolt (2026-09-04); reproduced at 289e2a2b by the triage lane
- kind: bug
- area: Type system & the type solver

The owner: "printing a value that infers its type causes its inferred
type to become `any`" and "`event` in `on:keydown(\|event\| ..)` is `any`
instead of `Event`". Both reproduce and are one defect: `fun apply(f:
sync |i32| void) { f(1) } fun main() { apply(|v| { print(v); v.no_such()
}) }` → "cannot call method 'no_such' on any"; drop the print → "i32 has
no method 'no_such'". A user `fun sink(m: any)` does the same, so it is
the `any` PARAMETER, not print. `<div on:keydown(|event| { print(event);
event.bogus() })>` → "on any"; without the print → "Event has no method
'bogus'" — the `on:` desugar (elements.rs ~120–145 → `.on_event`, ui.vl
~189 `(|Event| void) context turn_scope`) is sound; kolt's `|event:
Event|` annotations (views.vl ~550, ~717) are the workaround. (`Event::
key` is a method — `event.key()`.)

Cause: B13's "adopt a concrete declared parameter" rule (analyzer.rs
~30056–30065): `if is_unknown_closure_parameter(argument_id) { let
declared = substitute_type(..); if generics.is_empty() && !matches!(
declared, Type::Unknown | Type::Unresolved) { fill_unknown_closure_
parameter(argument_id, &declared) } }` — `Type::Any` passes the guard,
so the `any` call WRITES `any` into the pending slot (~25576 via
`write_type_slot`) before the enclosing call types it; first writer
wins, permanently.

Fix (S, low risk): add `| Type::Any` to the guard — an `any` parameter
is a one-way coercion sink and must never type an inference hole. Skip
WITHOUT deferring (fall through, slot unfilled), not `Resolution::
Deferred`, or a closure whose only use is an `any` call deadlocks; the
existing "type of variable could not be resolved" covers the never-
filled case. Pins: the lane's `i5/g_ctx` / `h_ctx_nop`, the `on:keydown`
pair, a control where the `any` call is the sole use. Related: B13,
B185 (closed; the same `unfilled_closure_parameter` machinery).
