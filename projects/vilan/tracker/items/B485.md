# B485 — which words should be KEYWORDS and which ATTRIBUTES: the language marks declarations two ways — keywords (`export`, `external`, `async`, `sync`, `lazy`, `own`, `mut`, `const`, `macro`, `dyn`, `borrows`, `context`) and bracket attributes (`[resource]`, `[platform(..)]`, `[deprecated]`, `[internal]`, `[must_use]`, `[rpc]`, `[expose]`, `[service]`, `[derive(..)]`, `[hint(..)]`, `[lints]`) — with no stated rule for which a new marker becomes; B413 already moved `resource` from a keyword to an attribute

- status: OPEN — filed 2026-10-01 (the owner's item); DISCUSSION — a short paper, then a ruling
- kind: design discussion
- area: Type system & the type solver

The paper: (1) a census of every marker, where it may appear, and whether it changes TYPING/semantics (`async`, `own`, `mut`, `dyn`, `lazy`), ownership class (`[resource]`), visibility/linkage (`export`, `external`, `[internal]`), tooling only (`[deprecated]`, `[must_use]`, `[hint]`), or code generation (`[derive]`, `[service]`, `[rpc]`, `[expose]`); (2) a candidate RULE — e.g. a keyword when the word changes how the item is typed or called and a reader must see it to read the signature; an attribute when it is metadata, a check, or generation a reader can ignore on first pass; (3) the misfits under that rule in each direction (is `export`/`external` an attribute? is `[resource]` a keyword again now that it changes move semantics and marks traits? `macro`, `const`, `lazy`?), with the migration cost of each move; (4) one ORDER for stacked markers (attributes then keywords, or free — B445). Doors per misfit, recs, then the owner rules. No build until ruled. Sizing: paper S–M; papers lane, Order 45.
