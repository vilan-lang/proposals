# E338 — A call inside an element hole (`{f(a, b, c)}`) is measured without the hole's closing `}`: the 101-column hole line stays inline and the 102-column one splits

- status: OPEN - filed 2026-10-16 (fmt-54's find, Order 54)
- kind: fmt edge
- area: Formatter

Found pinning E329's 'inside an element hole unchanged' case. The hole is not a statement, so no statement hook arms the split at the line's true width; the Call arm's own measure ends at the `)`, one column short of the line (the `}`). The result is a 101-column hole line left as written, the same one-column edge E329 closed for a terminated call statement. Left unchanged by E329 on purpose (the brief pins the hole as it was). Fix, if wanted: the hole print passes the same one-column extra the statement hook's `terminator_end` gives a `;` (the hole's expression ends where the hole's `}` begins). Sizing XS; owner's taste whether the hole's `}` counts.
