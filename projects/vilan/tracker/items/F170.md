# F170 — `std::ui` keeps each element's scene in window coordinates, so an insert or a removal rebuilds the scene of every element below it (30,000 scenes for a 10,000-row list)

- status: open
- kind: perf (native UI; paint)
- area: crates/vilan-rt-gfx/src/ui (per-element cached scenes)

Every row below an insert or removal gets a new box, and because a cached scene holds window coordinates it is rebuilt. Keep each element's scene in its own coordinates and place it under a translate: a moved element then keeps its scene and the paint cost of a list operation is close to constant. Layout's share (taffy re-placing 10,000 cached siblings, 30,000 moved boxes) is separate and goes with P4's virtual list. Check clips and scroll offsets, which already translate, and the hit test, which reads boxes not scenes.
