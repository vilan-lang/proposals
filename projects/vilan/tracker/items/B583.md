# B583 — a user's exported blanket impl in a MODULE makes std's OWN method calls ambiguous: `export impl type T with Describe { fun describe(self): str }` in `describe.vl` turns std's `items.describe(serializer)` (`std/src/wire.vl:601`, `:608`) into "'describe' is ambiguous on 'List<T>': both 'Wire' and 'Describe' provide it" — the same blanket written in the ENTRY is invisible to std

- status: OPEN — filed 2026-10-08 (incr-48's find, Order 48; met building M121's reach record)
- kind: semantics (S–M) — analyzer, method resolution vs std
- area: Language & type system

Repro (vilan 0.45.0 @e75bc57c, `vilan run main.vl` in a package; files under `sweeps/order48/incr-48/finds/user-blanket-std-ambiguity/`): `describe.vl`: `export trait Describe { fun describe(self): str; }` / `export impl type T with Describe { fun describe(self): str { "mine" } }`; `main.vl`: `import std::io::print; import pkg::describe::Describe; fun main() { print(Describe::describe(4)); }` -> two errors located in std's `wire.vl` (601, 608), 'describe' is ambiguous on `List<T>` and on `usize`. Written in the entry (`inference::traits::b511_a_qualified_call_reaches_a_blanket_through_a_bound_and_a_tuple_subject` does exactly that) it compiles, because std resolves before the entry walks. Cause: std's own member lookups consult every impl the world holds, and B515's trait-scope rule (a trait's methods resolve only where the trait is imported) is not applied to std's files (std is exempt from importing what it calls) — so a package trait std has never heard of competes with std's `Wire::describe` at std's call sites. Expected: std's calls resolve among the traits STD's files reach; a package blanket cannot make std's code ambiguous. M121's reach record does not count std's own questions against an ENTRY impl for exactly this reason (otherwise B553's deferred order would surface this error for that b511 pin). Sizing S–M (solver).
