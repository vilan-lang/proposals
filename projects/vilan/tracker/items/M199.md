# M199 — A `match` over a `Shared` read copies the payload even when the arm only views it; `is Some(let _)` copies too

- status: OPEN - filed 2026-11-04 (kolt)
- kind: perf (codegen)
- area: Compiler / copies

`match cell.read().value { Some(let item) => f(&item), .. }` deep-copies the payload (`const item = __clone(...)`) before `f` gets a view of it. The arm only views `item`, so no copy is needed. The same read through `cell.downgrade().get()` copies nothing, which is how std's `peek` methods read in place (M86). So the copy comes from how the binding is lowered, not from what the program asks for.

`x is Some(let _)` copies the payload too (`const _ = __clone(...)`), though `_` binds nothing.

Kolt met both in a reactive list prototype (`planning/proposal/live/`). A field read of one row (`|t| t.title`) copied the whole row on every read, on mount and on every write, until it went through `downgrade().get()`.

Repro (0.54.0): kolt session scratchpad `probe3/main.vl`, the whole file:

```
import std::shared::Shared;
struct Task { title: str, tags: List<str> }
struct Holder<T> { value: Option<T> }

// Copies the whole Task before handing out a view of it.
fun project<T, F>(cell: Shared<Holder<T>>, read: sync |&T| F): Option<F> {
	match cell.read().value {
		Some(let item) => Some(read(&item)),
		None => None,
	}
}

// The same read through `downgrade().get()`: no copy.
fun project_view<T, F>(cell: Shared<Holder<T>>, read: sync |&T| F): Option<F> {
	let weak = cell.downgrade();
	match weak.get() {
		Some(let holder) => match holder.value {
			Some(let item) => Some(read(&item)),
			None => None,
		},
		None => None,
	}
}

// `let _` binds nothing, but the payload is still copied.
fun has<T>(cell: Shared<Holder<T>>): bool {
	cell.read().value is Some(let _)
}

fun main() {
	let cell = Shared::new(Holder { value = Some(Task { title = "a", tags = ["x"] }) });
	print(i"{project(cell, |t| t.title).debug()} {project_view(cell, |t| t.title).debug()} {has(cell)}");
}
```

`vilan build main.vl` and look at `main.mjs`: `project` has `const item = __clone($a[1]);`, `project_view` has none, and `has` has `const _ = __clone($j[1]);`.

**Expected:** a binding that is only viewed (passed as `&`, read for a field, compared) reads in place, as `downgrade().get()` does. A `_` binder copies nothing.

Possibly the same cause as B689 (a store's `some()` read copies the whole record): that path goes through `lent_option`'s binding.

- 2026-11-05 (the integrator, at the sync to main): Synced from kolt-053. Overlaps M193 (lane solver-56's find): since B691 (0.54.0) every enum with a payload is copied at the value seams, and both items ask for the same elision - a binding that is only VIEWED (passed as `&`, read for a field, compared, or `_`) needs no copy. One copy-elision lane for both; it helps std's Store reads and kolt's prototype alike (its `viewing` helper exists to work around this).
