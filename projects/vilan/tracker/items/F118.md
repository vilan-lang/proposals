# F118 — natively, std's tuple-family blankets (B443: `compare`'s position-by-position `eq`, `hash`'s canonical hash, `debug`'s rendering) are refused at the `TupleKeys` intrinsic ("does not emit the intrinsic `TupleKeys` yet"), so tuple `==`, a tuple map key and `(..).debug()` build on JS only

- status: OPEN — filed 2026-10-08 (solver-48's find, Order 48)
- kind: bug (native refusal; S–M)
- area: Native targets & rendering

The blankets walk the tuple with `self.keys()` and `self.get(key)` (A122's `Tuple` surface). Before B443 the analyzer refused tuple `==` on both backends, so nothing regressed; the native refusal is honest (a `does not emit` refusal, not a rustc failure). Rec: emit `TupleKeys`/`TupleGet` natively (the arity is known per instance, so the walk unrolls), or give the three traits native tuple impls (Rust's tuples already derive `PartialEq`/`Hash`). Sizing S–M; native.
