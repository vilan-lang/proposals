# B212 — no duplicate top-level type declaration is refused, and a struct written as a bound gets no "'S' is a struct, not a trait"

- status: OPEN — paper lane b184-paper-2's bycatch (2026-09-03); Order 26 lane b211-b212
- kind: bug
- area: Type system & the type solver

Probed: two structs, two traits, or a struct and an enum with ONE
name in one module are all accepted with no diagnostic, and `x: N`
resolves by DECLARATION ORDER. And `fun f<T: S>(…)` where `S` is a
struct gets no refusal naming the sort. Fix: (1) a duplicate
top-level declaration of any sort in one module is refused at the
second site, naming the first (spans both), with the curated voice;
(2) a struct/enum written in bound position is refused: "`S` is a
struct, not a trait — a bound names a trait" with the steer to the
trait the author probably meant when one exists with a similar name.
Pins: struct+struct, trait+trait, struct+enum, struct+trait (the
B184 ambiguity), a cross-module same-name control (allowed — modules
are namespaces), the bound refusal for struct and enum, and a
control that a trait bound still works. Ledger rows as NEW.
