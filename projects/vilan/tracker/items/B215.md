# B215 — a bare `let b = x is Some(let n);` binds `n` afterwards and emits a dangling reference: `ReferenceError: n is not defined` at run (MISCOMPILE)

- status: OPEN — lane bindings-26's find (2026-09-03); Order 26 lane b214-b215 the same day
- kind: bug
- area: Type system & the type solver

Outside any condition there is no polarity frame (B195/B199), so the
analyzer falls back to B171's plain answer — `n` visible to the end
of the scope — and accepts `print(n)` after the `let`; codegen never
materializes the capture, so the reference dangles. Decide and pin
the rule: an `is` with a capture in EXPRESSION position outside a
condition either (a) binds nothing afterwards (the capture is
refused with a steer to `if x is Some(let n)`), or (b) binds `n` as
`Option`-narrowed only where `b` is known true — which the language
has no flow-typing for — so (a). Refusal in the curated voice; pins:
the bare `let`, the capture used inside the same expression (allowed:
`x is Some(let n) && n > 1` is a condition spine), a `match` arm
control.
