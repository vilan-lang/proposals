# E112 — `line_indices` caches a closed workspace file forever

- status: OPEN — editor-health lane's find (Order 23)
- kind: bug
- area: LSP & tooling
- source: lane editor-health, 2026-08-31

`line_index_for` (crates/vilan-lsp/src/main.rs) caches by path for
files NOT buffered, documented "written for std, whose files do not
change" — but CLOSING a document makes a workspace file cacheable,
and the index is then never invalidated when the file changes on
disk. A stale index means wrong positions on the next reference into
that file. Correctness, not perf. The lane exempted it from the
leak-baseline pin and COUNTS it in the trace summary, so a real
session can also refute the "bounded by project size" claim. Fix is
an invalidation hook on did-close/did-change-watched, or restricting
the cache to std paths as documented.
