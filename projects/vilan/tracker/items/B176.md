# B176 — a BOUNDED generic right operand of `str + x` never calls its `Display` impl

- status: OPEN — operators lane's find (Order 23); LIVE MISCOMPILE, FIX-NOW lane launched
- kind: bug
- area: Type system & the type solver
- source: lane operators, 2026-08-31

`fun show<T: Display>(value: T): str { "v=" + value }` compiles —
correctly, the bound is the promise `str + renderable` wants — but the
emitted JS is a raw `+`: `show(Point{x=1,y=2})` prints `v=1,2`, the
Display impl NEVER CALLED. Silent wrong output on a legal program,
outside B169's stated unbounded scope (that fix refuses; this one
admits and then miscompiles the admission). The fix is codegen-side:
the admitted str+renderable path must route a generic operand through
the same render call a concrete renderable gets. Check the i-string
desugar too — it rides the same admitted set, so `"v={value}"` under
a bound likely has the identical hole.
