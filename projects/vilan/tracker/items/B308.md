# B308 — DEAD CSS from every intermediate `Style` in a condition nest: `Style::rule` (style.vl:935, the one chokepoint) calls `emit("css", ..)` at CONSTRUCTION, so `attribute(.., hover(inner))` puts the inner `hover(..)` style's own `.sY:hover{..}` on the sheet beside the composed `.sX[..]:hover{..}` although `sY` never reaches an element — one dead rule set per nesting level per leaf declaration (`md(within(attribute(hover(x))))` emits four rule sets for one applied class); measured on a two-level probe: two of five emitted rules were for classes the bundle never applies

- status: OPEN — the owner's ask (2026-09-11)
- 2026-09-11 (integrator, from lane styles-33): NOT IMPLEMENTABLE as ruled — `emit` is const-only and every application path (`styled`/`bind_styled`, the element class path) is runtime code through `class_list`; the plateau is Rust-side (`const_eval.rs`'s `results.insert`) and knows no std type. MEASURED (dead = a sheet class absent from the bundle): kolt 11 dead/562 B of 9,144 B (10.7% of class-rule bytes); corpus style.css 27.6%; a 4-level nest emits 5 rule sets, 4 dead. THREE DESIGNS priced: (1) a Rust plateau flush that learns `Style` by type — L, a semantics decision; (2) RETRACTION at consumption (`__retract_asset`: each combinator re-renders the inner's exact line and retracts the LAST matching entry — correct by evaluation order per const site; ~20-line interpreter arm + a const-only extern + `retract_inner` at five call sites) — M; (3) prune in the CLI collector (drop css lines whose classes appear in no emitted JS) — M with a real correctness surface (three assemble sites; HMR assembles css before the JS is known). - kind: bug
- area: Reactive core & UI

**Mechanism.** `Style::rule` is the only place a rule is minted and it emits on the spot; a combinator (`hover` :1339, `attribute` :1470, `within` :1380, `pseudo` :1502, `child_relation` :1432) then re-mints the inner's rules under a composed condition into a NEW class and drops the inner — but the inner's emission already happened. The sheet is therefore the union of every `Style` ever constructed at const time, not of the styles applied.

**Fix.** Emit at APPLICATION, not construction: `rule` records `(class, rendered_rule)` on the `Style` (beside `rules`), and the sheet receives a style's rendered rules when the style is APPLIED — `styled(..)`/the element-syntax class path — or, keeping the const-time model, when a `Style` value is BOUND at module level or returned from a `const` (the plateau the emission already relies on). A combinator then simply does not carry the inner's rendered rules forward. Alternative if application-time emission is too large: the combinators un-emit — impossible with a write-only `emit` channel, so no. Measure on kolt's sheet before/after (bytes; count of rules whose class is absent from the bundle — the probe's method); pin: a two-level nest emits exactly the composed rule; the standalone `hover` style still emits when it is itself applied (control); `ssr_differential` and `hmr_css_matrix` green.
