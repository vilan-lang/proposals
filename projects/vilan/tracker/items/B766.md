# B766 — Native: `a.get() + b.get()` where `get` returns an impl's type parameter instantiated at `str` emits `Rc<str> + Rc<str>` and rustc refuses it (E0369); JS is correct

- status: open - filed 2026-11-26 (lane `keys-s2`'s find; pre-existing on `next` @75fb9cdc, no key and no field syntax involved)
- kind: backend defect (native: a checked program does not build)
- area: crates/vilan-rust/src/lib.rs (the `+` on two `str` operands whose static type comes through a generic method's return)

Repro:

```
struct Cell<T> {
	value: T,
}

impl Cell<type T> {
	fun get(self): T {
		self.value
	}
}

fun main() {
	let a = Cell { value = "l" };
	let b = Cell { value = "r" };
	print(a.get() + b.get());
}
```

JS prints `lr`. `vilan run --backend rust` stops at rustc: "cannot add `Rc<str>` to `Rc<str>`". The emitter lowers a `str` concatenation to `vilan_rt::str_concat` when it knows the operands are `str`, and here it emits a bare `+`: the operand's type is read as the method's declared `T`, not the instantiation.

A mixed chain shows the same on its right operand: `"x" + " " + a.get()` builds, `a.get() + " " + b.get()` does not.

Workaround: bind each read first (`let l: str = a.get();`), then concatenate.

Why it matters now: handles read through `[field_syntax]` (B711 S2a) make `user.first.get() + user.last.get()` an ordinary line.
