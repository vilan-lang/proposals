# E361 — A `vilan` launch configuration drops `preLaunchTask`, `postDebugTask` and VS Code's other generic launch attributes

- status: OPEN - filed 2026-11-09 (kolt, as E358 on branch kolt-053; renumbered E361 on sync 2026-11-09 because main's E358 is an archived Order 56 find). RULED 2026-11-09 by the owner: fix it as a PATCH after v0.55.0 (v0.55.1), not in the cut
- kind: bug (VS Code extension)
- area: Editor tooling / debugging

`resolveAdapterLaunch` and `resolveLaunch` (`editors/vscode/src/debug.ts`) build the resolved configuration from scratch, from a fixed list of the fields they know. VS Code reads its own generic attributes from that RESOLVED configuration (`resolveDebugConfiguration`'s result), so they're silently dropped:
- `preLaunchTask`, `postDebugTask`, `preRestartTask`, `postRestartTask`;
- `presentation`, `internalConsoleOptions`, `serverReadyAction`, `suppressMultipleSessionWarning`, and so on.

There's no warning. The task just never runs.

Kolt met it with a launch that starts the desktop app through `preLaunchTask` and stops it through `postDebugTask`. The server session started, the task never ran, and the desktop app never appeared. Two rounds of debugging went to the task's own definition before this showed up. Kolt now works around it with a compound around the session (a compound's `preLaunchTask` is VS Code's own), plus a supervisor that follows the session's process to stop and restart along with it.

Repro: a `launch.json` with
```json
{ "type": "vilan", "request": "launch", "name": "x", "program": "${workspaceFolder}/main.vl", "preLaunchTask": "any task" }
```
Start it: the task doesn't run. The same task as a `node` configuration's `preLaunchTask` runs.

**Expected:** spread the user's configuration into the resolved one (`{ ...configuration, type, request, ... }`), so every attribute the extension doesn't own reaches VS Code. Or copy VS Code's generic attributes explicitly. A test in `src/test/debug.test.ts` should pin that `preLaunchTask` and `postDebugTask` survive both resolutions.

**Kolt's workaround** (kolt `7e02ce9`, confirmed working by the owner 2026-11-09): `.vscode/launch.json` wraps the session in a compound, and `desktop/dev.mjs --follow` tracks the session's process. Once this is fixed, it can go back to a plain `vilan` configuration with `preLaunchTask: "desktop: dev"` and `postDebugTask: "desktop: stop"`.
