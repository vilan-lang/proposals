# E321 — `vilan fmt` never breaks a call's ARGUMENTS outside a markup hole - `for command in state_group(next_command_id, "text-selection", const search_dict::expand(..), ..)` (kolt command_palette.vl:98) and `Overlay::custom(Anchor::Container, AxisSpec { .. }, AxisSpec { .. }, default_panel_style)` (app_overlay.vl:16) stay one 200-column line; E314 took the argument-per-line layout inside holes only

- status: OPEN - filed 2026-10-13 (fmt-52's find, Order 52)
- kind: formatter (call layout; owner decision; M)
- area: Editor

E314's item says a call outside markup 'already breaks' its arguments one per line; it does not (print_call_arguments: R5, last-argument layout is the only layout, `a_single_link_and_a_plain_long_call_stay_inline` pins it). E314 therefore built the argument list layout (one argument per line with a trailing comma, `)` at the call's indent, the argument that ran the line out also broken, a lone argument that is still too wide left alone) and GATED it to calls inside an element-body hole (`hole_depth > 0`), so the estate moves in six holes only. Ungated, the same code moves ~1,813 diff lines in 60 files of the estate (kolt 488, std 949, native tests 149, the website 147, benchmarks 36, examples 23, test 21), i.e. every long call in the tree: a reformat of other lanes' files, so it was not taken inside a 'formatter.rs + fmt goldens only' lane. The two refusals that keep the old layouts under the ungated code are already in place and tested by the estate run: a call met inside another call's INLINE attempt never breaks (the outer call owns the first refusal, so `fold_service_requests(self.services, |request| respond_from_build(..))` breaks the OUTER arguments, not the inner), and the operands of a binary chain of three or more never break their own arguments (the chain breaks at its operators first - std base64.vl). Rec: generalise as one slice in a quiet order (drop the `hole_depth` gates in the Call arm, the call-subject door and the split-chain subject; the integrator reformats the estate in the same commit), after the owner reads a sample of the 1,813 lines.
