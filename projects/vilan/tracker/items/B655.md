# B655 — A `struct` declared INSIDE an `impl` block is accepted without a word and then does not exist: no error at the declaration, and a use reports "unknown struct: Hidden" (an unused one is silent altogether)

- status: OPEN — filed 2026-10-19 (kolt's rich text editor: a scripted edit landed a `struct` between two methods of an `impl`, the file built, and the failure surfaced only in the module that named the type)
- kind: diagnostics (parser/checker; S) — a missing error
- area: Language

```vilan
struct Counter { value: i32 }

impl Counter {
	fun bump(&mut self) { self.value += 1; }

struct Hidden {
	label: str,
}

	fun get(self): i32 { self.value }
}

fun main() {
	let hidden = Hidden { label = "x" }; // "unknown struct: Hidden"
}
```

vilan 0.52.0: the `impl` keeps both methods, the `struct` is dropped without a diagnostic, and the only error is at a use site — in another module, "cannot find 'Hidden' in the imported path", which reads as an export or spelling problem. With no use, nothing is reported at all and the declaration is dead code that looks live. Rec: refuse any item other than a member (`fun`, an associated `let`/`const` if the grammar has one) inside an `impl` body, spanned on the item's keyword: "a `struct` cannot be declared inside an `impl` — move it to the module's top level". The same gap likely covers `enum`, `trait`, `impl` and `mod` inside an `impl` — pin each.
