# A45 — no element mount hook: `View::on_mount(|el| ..)` and `View::autofocus()`; kolt focuses three modal inputs with three UUIDs, three timers and a private `focus` extern

- status: OPEN — the owner's ask while migrating kolt (2026-09-04); triage lane's survey at 289e2a2b
- kind: feature
- area: Reactive core & UI

The owner: an on-create callback or a general autofocus; HTML's
`autofocus` does not work with custom modals. No hook exists (zero hits
for on_mount/ref/autofocus/rAF in std/kolt/website); `View { element }`
(ui.vl ~64) is reachable; `std::dom::Element` (browser/dom.vl ~45–131)
has NO `focus` binding. Attachment happens at six unhooked sites: `mount`
(~767), `Slot::place` (~674/681/696), `children` (~208), `bind_each`'s
order pass (~361), `when` (~394), `swap` (~457).

kolt's workaround, character-identical three times (views.vl ~341, ~529,
~694): `let input_id = random_uuid(); set_timeout(|| get_element_by_id
(input_id).focus(), 1)` with the comment "queue_microtask runs too
early", plus its own `[extern(method, "focus")]` (~474).

Shape: (1) dom.vl `impl Element { [extern(method, "focus")] external fun
focus(self) }` — one line, kolt deletes its copy; (2) `View::on_mount(
self, action: sync |Element| void): View`, browser body `let element =
self.element; queue_microtask(|| action(element))` — `queue_microtask`
is already an extern (reactive.vl ~57). kolt's "too early" is true of
THEIR shape only: they schedule during the build and `mount_root`
drains its turn (~201) BEFORE `mount` (~779); a microtask scheduled in
the same synchronous build still runs after `mount()` returns. Pin: the
element is in the document inside the callback; if a `bind_each` row
appended in a later drain wave fails it, fall back to at_settle-then-
microtask. (3) `View::autofocus(self) = self.on_mount(|el| el.focus())`.
(4) process/ui.vl twins as no-ops returning self ("KEEP IN STEP"). Size
S; additive. Related: A7 (SSR parity).
