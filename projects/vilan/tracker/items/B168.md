# B168 — a bound's BARE generic argument loses its constraints inside a generic body

- status: OPEN — found by lane a33 (Order 22) widening `swap`; minimized,
  pinned `#[ignore]`d in generics.rs beside its passing twin
- kind: bug
- area: Type system & the type solver
- source: lane a33's report, 2026-08-29

A `Source<T>` bound whose argument is a BARE generic parameter resolves the
callee's `T` to the impl's own unbound parameter inside a generic body, so
the callee's `T: PartialEq` is checked against something carrying no bound
and refused — `swap_split` calling `self.swap(gated, render)` from exactly
such a body is the minimized exhibit. The constructed-argument twin
(`Source<List<T>>`, `bind_each`'s bound) resolves fine and shipped, which
localizes the defect to the bound CHECK on bare-parameter arguments (an
explicit turbofish does not help; dropping the callee's bound compiles and
runs). When fixed: un-ignore the pin and widen `swap`/`swap_split`/
`chunk_preload` together IN GENERIC-PARAMETER ORDER (the split gate's
`rebind_by_position` rebinds positionally — a33's report records the
constraint).
