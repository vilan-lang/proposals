# F123 — native (perf): a std METHOD over a field of a `Shared` view still copies the field out of the cell — `cell.read().seen.contains("x")` clones the whole set per membership test (F114 covered the intrinsics only)

- status: OPEN — filed 2026-10-09 (native-49's find, Order 49)
- kind: perf (native) (S–M)
- area: Native targets & rendering

F114 reads the reading INTRINSICS (`len`, `get`, the `str` readers) over a `Shared` view's spine through a view of the cell. `HashSet::contains`, `HashMap::get` and `contains_key` are std functions, not intrinsics, and they run the key's `Hash`/`Eq` — user code that could reach the same cell through another handle (F39's runtime half), so a view held across them needs F102's reach analysis (no argument, closure or key type can touch the cell) before it is sound. Repro: finds/shared_view_std_method_copies.vl (prints `true`, `[ 0, 4 ]` on both; the emitted `main` holds `read_with(|view| view.seen.clone())`). Sizing S–M; native.
