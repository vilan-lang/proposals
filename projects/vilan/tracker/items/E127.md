# E127 — the server has no `did_change_watched_files` handler: the client sends them, tower-lsp drops them, and the disk-read paths (`modules_in_root` for the B4 import steer and `check_library_contract`) go stale until the next analysis

- status: OPEN — lane m25-e125's find (2026-09-03)
- kind: editor
- area: Language server & tooling

The VS Code client registers `synchronize.fileEvents`
(`extension.ts:293`) and sends `workspace/didChangeWatchedFiles`;
the server registers no handler, so `tower-lsp`'s default discards
them. Consequences: a package file created/deleted/renamed outside
the editor (a generator, a checkout) is invisible to the module
listing until something re-analyzes; `modules_in_root` is read from
disk inside the analyzer (the B4 import steer at ~41867, the library
contract at ~40791) — a staleness class INSIDE the compiler if ever
cached process-globally (which is why M25 captured the listing per
analysis instead). Build: handle the notification; on a `.vl` or
`vilan.toml` event outside open buffers, invalidate the parse cache
entry for that path and schedule a re-analysis of the affected
entries (E113's reachability); pin with the LSP harness (a file
appears on disk → the next completion offers it without an edit to
the open buffer).
