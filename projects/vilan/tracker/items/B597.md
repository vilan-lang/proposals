# B597 — A tuple-typed `[rpc]` parameter or `[derive(Wire)]` field is refused quoting its type as `_` — "parameter `message` of `[rpc]` method `echo` is `_`, which is not Wire"

- status: OPEN — filed 2026-10-09 (lang-a-49's find, Order 49)
- kind: diagnostics (XS)
- area: Diagnostics

`render_type` (analyzer.rs) renders a name, a generic application and a `::` path as written and falls back to `_` for every other form; a tuple (labelled or not), an array and a closure type are the common cases. The refusal is right (tuples have no Wire impl; a user `impl (i32, i32) with Wire` is not consulted by these syntactic checks either), the quote is not. `render_type` also feeds the derive generators' emitted source, so the fix is a separate quoting path for the messages, not a wider `render_type` (lang-a-49 tried the wider one: the Wire derive then emitted `(x: i32, y: i32)` where its generated code needs an expression path, and failed later and worse). Repro: finds/tuple_quoted_as_underscore.vl. Sizing XS.
