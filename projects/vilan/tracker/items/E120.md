# E120 — every std import steer is silently dead in the playground (no filesystem behind the wasm)

- status: OPEN — playground-prelude lane's find (2026-09-01)
- kind: bug
- area: LSP & tooling
- source: `node_mode_takes_the_base_set_and_names_no_manifest` pins the silence

`std_module_files` is built by `std::fs::read_dir` at the analyzer's
construction; the wasm has no filesystem, so the inventory is empty
and NO steer fires in the playground — not the B4 import steer, not
`web_prelude_steer`, not the removed-alias steer's module-path arm.
Today the silence is honest by accident (the web-set steer's repair
is a `vilan.toml` line a pasted buffer cannot write), but the plain
"cannot find `Signal`; import it: `import std::reactive::Signal;`"
steer is exactly what a playground visitor needs. Fix: the embedded
std (vilan-embedded-std) carries the module inventory — build
`std_module_files` from the embedded manifest when no filesystem
backs std; and give the web-set steer a playground-aware arm ("flip
the prelude toggle" instead of "set vilan.toml"). Pin: the steer
fires under the wasm compile path; the manifest-key arm never does.

## BUILT 2026-09-01 (lane playground-steers) — with a filing correction

The inventory is derived at build time from the embedding
(`modules_in_root` over `vilan_embedded_std::FILES`, K9's listing),
never hand-written; the web-set steer gained a `PreludeRepair::Toggle`
arm for front ends with no manifest. CORRECTION to the filing: the
removed-alias steer's module-path arm was NEVER dead in the
playground — `removed_std_alias` is a curated table, not an inventory
read. The silence pin rewritten (it had recorded a defect as a
guarantee). Closes at Order 25's close.
