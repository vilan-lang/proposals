# A63 — a `Debounce` in `std::time`: kolt built one over `Timer` (trailing edge, deadline pushed out per call, callback replaced) and std has only the primitives — plus the answer to its own TODO, that the `Shared` cell IS required, because the `async` block outlives `run`'s `self` loan (rule 1) and writes the cell from inside it (rule 3)

- status: OPEN — the owner's kolt TODO/FIXME sweep (2026-09-07)
- kind: feature
- area: Reactive core & UI

kolt/src/debounce.vl is 37 lines of app code that is not app-specific:

    struct Debounce {
        delay: Duration,
        // TODO: Investigate whether the `Shared` cell is needed.
        runner: Shared<Option<(Instant, || void)>>,
    }

    impl Debounce {
        fun run(self, fn: || void) {
            if self.runner.read() is Some(mut runner) {
                runner.0 = now().add(self.delay);
                runner.1 = fn;
            } else {
                self.runner.write() = Some((now().add(self.delay), fn));
                async {
                    for self.runner.read() is Some(let (moment, _)) {
                        let timer = Timer::after_for(moment.since(now()));
                        if !timer.wait() { jump break; }
                        let (moment, fn) = self.runner.read().unwrap();
                        if now() < moment { jump continue; }
                        fn();
                        self.runner.write() = None;
                    }
                };
            }
        }
    }

WHAT STD HAS TODAY: `std::time` ships the primitives and nothing built from them — `Timer::after` /
`after_for` / `wait` / `cancel` (time.vl:238-271), `sleep` / `sleep_for` (:191, :197), `Instant` and
`Duration` with the arithmetic this needs (:33-109). No debounce, no throttle. A tracker grep finds
`debounce` only in E121 (the LSP's own diagnostics debounce — a NUMBER, "clamp(0.3 x last analysis, 150,
500)", not a mechanism) and in A14, where the draft-reconnect ruling says "no default debounce" — which is
about std declining to debounce ON THE APP'S BEHALF, a different question from std offering the tool.

The semantics kolt landed on are the ones worth standardising, and they are subtler than a `sleep`: one
in-flight timer ever; each `run` pushes the deadline out AND replaces the callback; the loop re-reads the
deadline after every wait, so a call that arrived during a wait cannot fire early. It runs the LAST
callback, not the first — trailing edge.

THE OWNER'S OWN TODO, ANSWERED: YES, the `Shared` cell is required, and rule 1 is why. `run` takes `self` by
loan; the `async` block OUTLIVES that loan — it reads `self.runner` on every timer tick, long after `run`
returned — so a plain field would be a read through a dead loan. `Shared` is the cell that makes the escape
legal, and rule 3's interior mutability is what lets the block WRITE it (`self.runner.write() = None`)
through what is only a loan. Both directions are load-bearing; it cannot be a plain field. (The same
read-then-write-the-same-cell shape is what B267's cell-aware last-use elision reasons about, so this is a
customer for that work too.)

PROPOSED: `std::time::Debounce` with `new(delay)`, `run(fn)`, `cancel()` and `flush()` (fire the pending
callback now), the trailing-edge semantics above stated in the doc rather than left to be discovered, and
kolt's implementation taken as the starting point with its `Shared` cell kept. Rule a `Throttle` sibling in
or out in the same pass — leading-edge is the other half of the question and it will be asked next.
