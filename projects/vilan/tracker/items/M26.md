# M26 — a superseded analysis is dropped at `land`, never cancelled; `did_open` registers no `pending` generation

- status: OPEN — e122 lane's find (2026-09-01); E121's "cancellation" step, the diagnostics half of the mandate
- kind: performance
- area: Language server & tooling

The paper (editor-latency.md §4.2) sequenced cancellation after
M21/M19/M22; the seam is now concrete: `analyze_and_publish` stamps
each analysis with the world revision it read (E117) and `land` drops
a superseded result — but the superseded analysis RUNS TO
COMPLETION on its 128 MiB thread, and a keystroke burst queues one
full analysis per debounce window. `did_open` (E123) schedules
through the same path but registers no `pending` generation, so an
edit right after an open leaves two analyses in flight. Build: a
cancellation token checked at the analyzer's phase boundaries (and
inside the checks loop per function), set when a newer revision
arrives; `did_open` registers its generation; the keystroke path's
`dependency_moved` seam (passed `false` today) is what a
cancellation-aware scheduler fills. Pin: a burst of N edits performs
ONE complete analysis plus at most one partial; CPU per keystroke on
the generated exhibit under the 500 ms budget with the cancel.
