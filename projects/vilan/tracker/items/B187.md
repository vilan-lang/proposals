# B187 — a negated `is` whose then-branch diverges binds the continuation (the guard clause)

- status: OPEN — owner question 2026-09-01, off B171's scope ruling
- kind: design
- area: Type system & the type solver
- source: the owner: "`if !(x is Some(let y)) { return }` — would the binding be accessible after?"

Not today: B171's ruled scope is the then-branch and the `&&`-right
operand only. The guard-clause shape — negate, diverge, continue with
the binding — is Rust's `let Some(y) = x else { return };` and is
worth having: flow-sensitive, sound because the continuation is only
reached when the pattern matched. Semantics to rule: the then-branch
must be provably diverging (return/panic/never-typed tail — the
existing divergence analysis decides); the binding's scope is the
rest of the enclosing block; `||`-composed conditions do not qualify.
Spelling alternatives for the discussion: `let Some(y) = x else
{ … }` (a new form) vs recognizing the negated-`is` shape as written.
