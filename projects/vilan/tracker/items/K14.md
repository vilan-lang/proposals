# K14 — the playground's buffers carry no prelude, so its examples teach the pre-prelude spelling

- status: OPEN — the v0.40.0 deploy's find (2026-09-01); OWNER QUESTION
- kind: design
- area: Web presence
- source: the deploy's smoke gate, when the alias sweep hit the seeded examples

A manifest-less buffer gets no prelude (B156's weakest-scope rule has
no [package] to hang the key on), so the playground's hello/server
examples now open with `import std::io::print;` — correct, but the
FIRST vilan a visitor reads teaches the spelling the prelude exists
to delete, while `vilan init`'s scaffolds demonstrate the ambient
idiom. The question: should the playground (and scratch-file
analysis generally — E113's lane noted infer_platform still serves
manifest-less buffers) SEED the base prelude, so a pasted
single-file program means the same thing it would inside a fresh
package? Doors: (1) the playground passes a synthetic package with
`prelude = "std::prelude"` (web set for browser mode?) — smallest,
playground-local; (2) scratch files everywhere default to the base
prelude — language-level, needs a spec sentence; (3) keep explicit
and let the examples teach real paths. The examples flip back to the
ambient spelling whichever prelude door opens.

## RULED 2026-09-01 — door 1, with a toggle

The owner: "Add the prelude. Maybe add a toggle to disable it." The
playground seeds the base prelude (web set in browser mode is the
lane's call — recommend the web set, since the playground's browser
mode IS a web app) through a synthetic package on the wasm compile
path; a UI toggle ("prelude: on/off") turns it off for teaching the
explicit spellings; the seeded examples flip back to the ambient
idiom.

## BUILT 2026-09-01 — with a correction to the filing

The filing's premise was wrong in one half: `Workspace::default()`'s
`entry_prelude` is `PreludeSpec::default()`, so the BASE set already
reached manifest-less buffers at v0.40.0 (the website's re-added
`import std::io::print;` was redundant — my local smoke had run an
older cached wasm). What was missing: the WEB set in browser mode and
the toggle. Shipped: `PlaygroundPrelude { Default, Off, Module }`,
`compile_with(source, platform, prelude)`; browser → std::web, node →
std::prelude, `"off"` = none; synthetic package context via
`Workspace::entry_prelude` (§9.2 holds); 6 pins. Website branch `k14`
(@764442d, NOT pushed) carries the toggle, `&prelude=off` share
fragment, examples flipped to the ambient idiom, examples.js
regenerated — MERGES ONLY AFTER THE CUT that ships `compile_with`
(the deploy installs the latest release's wasm). Closes when that
merge lands. Side-find: E120.
