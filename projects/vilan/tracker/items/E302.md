# E302 — an OPT-IN chain inlay-hint strategy, `vilan.inlayHints.chains = "changes"`, hints a stage of a multi-line chain only where its type DIFFERS from the previous stage's — `Some(5)` / `.map(|x| x * 2) as Option<i32>` / `.and_then(|x| Some(x + 1))` (hidden: still `Option<i32>`) / `.is_some() as bool` — against today's one hint per stage (E278)

- status: OPEN — filed 2026-10-12 (the owner's ask, mid-Order 51)
- kind: editor (inlay hints; opt-in setting; S)
- area: Editor

A new setting `vilan.inlayHints.chains`: `"every"` (today's behaviour, the default) \| `"changes"` (opt-in): in a chain split one stage per line, a stage's ` as T` hint is shown when its type differs from the PREVIOUS stage's and hidden when it is the same - the first hinted stage always shows (there is no previous), the last stage shows when it differs from its predecessor (`.is_some() as bool`), and a hidden stage still counts as the predecessor for the next comparison. "Same" is judged on the type as the hint would PRINT it after abbreviation (so `~Source<Option<str>>` twice is the same), not on the slot id; a chain whose every stage is the same type shows the first only. The "Ascribe every stage" action (E278) is unchanged - it ascribes every stage, hidden ones included (the hints are a view; the ascription is the code); its title says so. Applies live (the setting is read per request like `abbreviate`). Pins: the owner's four-line example (2 of 3 stage hints shown), every-stage-same (1 shown), a chain on one line (no hints, unchanged), the default unchanged (E278's pins stand), the action ascribing all.
