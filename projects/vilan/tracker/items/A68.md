# A68 — a `css { … }` block is `const` BY CONSTRUCTION: today `let b = css { padding: 1rem; };` is refused ("`raw` … is compile-time-only; evaluate this call inside a `const` expression") and every block needs `const` written in front; a block is a compile-time asset by definition, so it is one, and const-eval refuses a hole that reads a runtime value

- status: OPEN — the owner's ask (2026-09-07); css-30
- kind: feature
- area: Reactive core & UI

The css desugaring wraps its chain in `const`; a hole reading a runtime binding gets const-eval's existing refusal at the hole. Pins: `let b = css {…}` compiles; `.styled(css {…})` on an element compiles; a runtime hole is refused at the hole; the written `const css {…}` still compiles (idempotent).
