# B175 — `T::default()` under a multi-bound infers as the BOUND, not the parameter

- status: OPEN — operators lane's find (Order 23)
- kind: bug
- area: Type system & the type solver
- source: lane operators, 2026-08-31

In std's `List::sum` (`list.vl:135`): `impl List<type T: Add +
Default> { fun sum(self): T { mut total = T::default(); … total +=
item } }` — `T::default()` infers as `Type::Trait(Default)` instead of
`T`, so `total` arrives trait-typed at `+=`. B170 was forced to put
`Type::Trait` on the operator check's SKIP list solely because of
this (7 inference tests red otherwise) — fixing the inference here
lets that hole in the operator check close. B162's trait-associated
functions land in this same territory (Trait::func resolution), so
rule the interaction: `T::default()` with `T: Default` should type as
`T`.
