# F109 — A fixed-array literal under a `[T; n]` annotation is emitted natively as `vec![..]` while the binding's type renders `[i32; 3]`: `let fixed: [i32; 3] = [1, 2, 3]; first(fixed)` is refused by rustc (E0308, expected `[i32; 3]`, found `Vec<i32>`)

- status: OPEN
- kind: bug (native backend; emitted Rust refused)
- area: Native backend

Repro: `sweeps/order48/debug-48/finds/native_fixed_array_literal.vl` (vilan 0.45.0 + debug-48, `vilan run --backend rust`):

```vilan
fun first(values: [i32; 3]): i32 {
	values[0]
}

fun main() {
	let fixed: [i32; 3] = [1, 2, 3];
	print(first(fixed));
}
```

JS prints `1`. Natively the `let` emits `vec![(1i32), (2i32), (3i32)]` and `rust_type` renders the parameter `[i32; 3]` (`vilan-rust` `rust_type_inner`'s `Type::Array` arm), so rustc refuses the call; `dbg(fixed)` fails the same way at the printer's `&[i32; 3]`. F100 covers the REPEAT literal `[value; n]` only; this is the plain list literal at an array type (and `fixed.len()` is refused by name). Rec: lower a list literal whose expected type is `[T; n]` to a Rust array literal, or render `[T; n]` as `Vec<T>` throughout. Found by debug-48 probing `dbg` over every printable shape. Owner: native.
