# F131 — Natively the INNER literals of a nested array literal handed to a callee whose parameter is generic over its own binders emit as `Vec`s — `grid == [[1, 2], [3, 4]]` (std's `impl [type T: PartialEq; const N]`, whose `b: [T; N]` is the argument's expected type, unsubstituted) is refused by rustc "expected `[i32; 2]`, found `Vec<i32>`"; JS prints `true`

- status: OPEN — filed 2026-10-10 (lang-50's find, Order 50)
- kind: bug (native; S)
- area: Native targets & rendering

The analyzer types the operand by the left side (a wrong inner count is refused "this array literal has 3 elements, but its type is `[_; 2]`"), but records no type for the nested literals, so the native list-literal arm falls back to the expected type, the callee's `[T; N]`: the outer literal now takes its own count (array-lengths S5), and the inner one meets `T`, which resolves to nothing under the caller's substitution, and renders `vec![..]`. Fix: the argument's expected type under the CALL's substitution (T = [i32; 2], N = 2), or the analyzer recording a directed literal's settled type. A flat literal (`fixed == [1, 2, 3]`) builds. Sizing S; vilan-rust's call-argument expectation.

The two items are one fix family (the emitter's expected-type propagation into literals).
