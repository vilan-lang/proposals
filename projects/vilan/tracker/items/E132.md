# E132 — linkedEditingRange answers in ANALYZED coordinates; the client mirrors keystrokes into unrelated live text (E125's twin; CORRUPTS working code)

- status: OPEN — the owner's find while migrating kolt (2026-09-04); reproduced at 289e2a2b by the triage lane with a fix verified green on the full vilan-lsp suite
- kind: bug
- area: Language server & tooling

The owner: editing under element syntax sometimes deletes or changes
unrelated text; repro = add lines, then type where an element tag WAS
before the lines were added, before the server catches up. Reproduced
exactly: buffer with one line typed above `<div>"hello there"</div>`,
analysis not landed, caret on the new line 3 char 4 → the server
answers open=3:2–3:5 close=3:21–3:24; the live text under them is
`et ` and `1;`. The open range CONTAINS the caret, so VS Code accepts
the pair and mirrors every keystroke into `1;` — a line with no tag.
With the caret on the tag where it now is, the answer is None: while
typing, the feature is dead where it should work and armed where it
must not be. Control passes once the analysis lands. Window =
DEBOUNCE_MS 150 + 80–190 ms analysis.

Cause: `linked_editing_range` (vilan-lsp/src/main.rs ~2662–2684)
converts the request position through `analyzed_offset` and returns
`analyzed_range(..)`, and `linked_tag_ranges` (document.rs ~2240)
re-parses `self.analyzed_text()`. Nothing here is program data — it is
a RAW PARSE (an S2 citizen handed the S1 text). It is also the only
edit-PRODUCING handler with no S3 staleness refusal (`rename` ~2822,
`prepare_rename` ~2878, `code_action` ~2981 all check `is_stale()`).
Ruled out: line_index.rs (UTF-16, clamping, correct) and `did_change`
(~2353, synchronous in-order splice) — the server's live text IS the
client's buffer.

Fix (S, verified): parse `&self.text` in `linked_tag_ranges` and use
`document.line_index` in the handler — four lines; full suite 564/564
with it applied, and the feature then works DURING typing. Do not use
the S3 refusal alone: it would kill tag rename exactly when it is used.
Pins: the lane's two tests (the mirrored range lands on unrelated live
code; the control after landing) in scratch `triage27/lsp-sync/repro.rs`.
Interim for the owner: `"editor.linkedEditing": false` (VS Code; off by
default, the extension declares nothing). Related: E125 (closed; the
same class on semanticTokens/range), E121, M29 (no new cost class —
this handler already parses per request), E131 (completion's twin).
