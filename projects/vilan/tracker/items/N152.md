# N152 — `scripts/cut-release.sh`'s CHANGELOG rewrite depends on the awk flavour — under mawk 1.3.4-20200120 (Ubuntu 22.04) it emits DOUBLED `---` separators between entries; mawk 20250131 (Debian) and gawk 5.1 give the committed answer

- status: OPEN — filed 2026-10-06 (found by the first self-hosted CI run; Order 48)
- kind: portability (S)
- area: Hygiene

Found on the first run of the Linux self-hosted runner (ghcr.io/actions/actions-runner, Ubuntu 22.04): `release_scripts::the_cut_retitles_the_section_and_orders_it_by_family`, `the_cut_refuses_an_entry_it_cannot_classify_instead_of_guessing` and `allow_red_ci_overrides_loudly_and_lifts_only_the_ci_red` fail because the `CHANGELOG_AWK` rewrite mode writes `---` twice (and once a third time) between entries. The owner's box (mawk 1.3.4 20250131) and GitHub's ubuntu-latest pass. The runner image now installs gawk to pass; the script should either run the same under every awk the release tooling may meet (find the construct: a `length(array)`, `delete array`, regex interval or `printf` difference between the two mawk builds is the usual suspect) or `require gawk` explicitly at its top with a steer, so a stale awk refuses loudly instead of writing a wrong changelog. The same scan for `perf_gate.py`'s Python floor: it already refuses on < 3.11 with a clear message (seen on the same run); the cut script should match that behaviour.
