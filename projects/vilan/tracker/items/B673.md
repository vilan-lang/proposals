# B673 — a closure type taking a closure (`|A, |B| void| void`) is a parse error with no hint to parenthesize, and the struct it's in is then reported as having no fields

- status: OPEN — filed 2026-10-24 (kolt spelling: a provider struct of callbacks)
- kind: diagnostic (parser; S)
- area: Language & checker

```vilan
struct Provider {
	check: |List<str>, |List<str>| void| void,
}

fun main() {
	let p = Provider { check = |_, done| done([]) };
	(p.check)(["a"], |found| print(i"{found.len()}"));
}
```

→ (v0.52.0, `vilan check`)

- `Provider expects 0 fields, but got 1 instead: check is not a field of Provider` (listed first)
- `found '|' expected ',' or '}'` at the inner closure type's closing `|`

The written form is ambiguous (the inner `|` closes which list?), and `|List<str>, (|List<str>| void)| void` is the accepted spelling, so the parse error is fair. Two things make it slow to see. It doesn't say what to write. And it's followed, or in a larger file preceded, by errors at every use of the struct, each saying the struct has no fields. In kolt that was four "expects 0 fields" errors, at four constructors in another part of the file.

Recommendation: when a closure type's parameter list meets a `|` that starts another closure type, say so: "a closure type as a parameter needs parentheses: `(|List<str>| void)`". And a struct whose body failed to parse should be left out of later field checks rather than taken as empty.
