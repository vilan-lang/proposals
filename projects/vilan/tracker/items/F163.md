# F163 — std::http `Request` has no peer address - kolt's sign-in throttle reads it through a JS binding native refuses

- status: open
- kind: std gap (blocks M1)
- area: std::http

The last behaviour-dropping workaround in kolt's native server build (W1 in sweeps/order58/native-m1-report.md). Kolt reads `request.socket.remoteAddress` through an app binding; natively `peer_address` returns an empty string, so every client shares one sign-in throttle unless KOLT_TRUST_PROXY=1. Fix: `Request::peer_address(self): Option<str>` (or `remote_address`) in std on both backends - node's `socket.remoteAddress`, the native accept's peer. This is ruling S2's first door (general binding moves into std); the two-arm `[extern(js = .., rust = ..)]` is not needed for it. Size S. Closes M1's build half with zero workarounds.
