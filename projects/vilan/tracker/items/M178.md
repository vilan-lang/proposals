# M178 — `ResponseStream::send_bytes(chunk: Bytes)` (and a `fs::Reader`-fed body) - file serving streams from storage instead of holding a whole `Bytes`

- status: OPEN - filed 2026-10-26 (http-55's follow-up, Order 55; R-g)
- kind: feature (std::http; S-M) - the response mirror of M176
- area: Standard library

`ResponseStream::send` takes `str` chunks only, so a large file is served from a whole `Bytes` buffer (`body_bytes`): kolt's `GET /files/{id}` reads the stored upload whole (`(storage.get)(sha)`) and hands it to `etag_response`, so a 25 MB file costs 25 MB per concurrent download (the upload measurements in M176 bound it: the read is the same size as the body). Ask: `send_bytes(self, chunk: Bytes)` (node `response.write(Uint8Array)`, natively `Response::write` over bytes - the native `write` takes `&str` today), and a `ResponseBuilder::body_reader(reader)` that pipes an `fs::Reader` with backpressure (`drain`). Pins: a 64 MiB file served at a few MiB of RSS on both backends; `Content-Length` declared when the size is known.
