# N181 — `vilan check .` on kolt (two legs) is not instruction-deterministic: identical runs of one binary read 13.04 / 13.41 / 13.54 / 13.62 G instructions with the world cache off and a fixed check cache (and 10.0-13.7 G with the persisted prefix on its default `~/.vilan/cache/worlds`), where a single-entry program (reactive-ui) repeats to 0.001 %

- status: OPEN — filed 2026-10-16 (incr-54a's find, Order 54)
- kind: tooling (measurement)
- area: Performance & footprint

The two legs run concurrently and share the in-process base cache and the macro-world machinery, so which leg builds what varies run to run; the persisted std prefix adds its own load/write split. A lane comparing kolt's cold check in instructions needs either per-leg runs (`vilan check src/client.vl`) or medians over many runs; the RSS probe's 3 % gate is unaffected in practice but rides the same variance. Rec: document it in `perf_count.py`'s header and have `perf_gate.py`'s kolt row measure the legs one at a time (or with the legs serialized by a flag).
