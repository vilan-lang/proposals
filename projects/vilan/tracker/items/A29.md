# A29 — `DuplexEnd.me` is never cleared: a session's server and wire retained per disconnect

- status: OPEN — measured 2026-08-28 (lifetimes session, reactive-graph leg); lifetimes.md S1 owns it
- kind: bug
- area: Reactive core & UI
- source: heap-snapshot SCC analysis of the live todo server, 2026-08-28

`ReactiveClient::new`/`ReactiveServer::new` register `on_frame` closures
capturing their own client/server (`self[1].v = [0, handler]`), and no
path ever clears `DuplexEnd.me` — `dispose`/`drop_session` empty
`sources`/`live` but leave the transport holding the closure. Under the
JS GC this pins a 70-node component per closed connection until the
transport itself dies; under any counted backend it is a leak per
disconnect. Fix: a `clear_on_frame`, called from `dispose` and
`drop_session` — one line each.
