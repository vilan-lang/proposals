`function_signature_label` renders each parameter as `name: <declaration_type_label_for(type)>` and THEN appends `context_clause_label(parameter_contexts[parameter])` (analyzer.rs ~19137, E9's original channel — 'hover shows clauses'). B309 later made the clause a property of the TYPE: `Type::Closure(parameters, return, contexts)` prints as `(|T| void) context owner_scope` in `pretty_print_type_at` (~49852), which is what the type label already returns. So since B309 every injected-closure parameter prints its clause once as part of its type and once more from the entity-keyed index. The parenthesized first copy is the type's; the bare second copy is the stale append.

Fix (S): delete the append at ~19137 — the type's printed form is the one spelling (B309's own comment says so: 'the clause is a property of the TYPE and shows up wherever a type does'); then check whether `parameter_contexts` has any reader left besides the context pass (it is also exported on `Program` at ~50684 — if hover was its only label reader, the comment at its declaration is updated, not the field removed: the context pass still asks 'does this parameter hold an injected closure'). Verify the OTHER label sites for the same overlap: `let` bindings holding an injected closure (the hover on the binding), struct FIELDS of closure type, the trait/impl pair renderer (`function_signature_label` FOR one side, ~19104), completion `detail`, signature help, and the diagnostics that quote a signature.
