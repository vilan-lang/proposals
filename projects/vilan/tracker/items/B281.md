# B281 — the server's receive loop SERIALIZES frames TCP coalesced into one read: `for event in parser.feed(chunk) { … turn(FlushPolicy::AtEnd, || protocol.respond(…)) … }` (rpc_server.vl ~1117–1176) awaits each event's `respond` before parsing the next, so a handler that awaits something only the NEXT frame's handler supplies never completes — on a fast local link coalescing is the common case; a present-tree hazard and the prerequisite of every awaited server→client call
