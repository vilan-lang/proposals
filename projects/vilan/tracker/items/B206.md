# B206 — `function_signature_label` renders a `B = Self` defaulted parameter as the TRAIT's name: `declare fun eq(self, b: PartialEq): bool`

- status: OPEN — operators-25 lane's find (2026-09-01); pre-existing, whole trait-conformance family
- kind: bug
- area: Diagnostics

`impl P with PartialEq { }` advises ``declare `fun eq(self, b:
PartialEq): bool` `` — a signature nobody can write; the defaulted
type parameter `B = Self` should render as the implementing type
(`b: P`). B197's own arm routes around it by rendering the signature
itself; the ordinary missing-member arm still prints the trait name.
Fix in `function_signature_label`: substitute `Self` (and defaults
that resolve to it) with the impl's subject; pin on `PartialEq`,
`Add` and a user trait with a `Self`-defaulted parameter.
