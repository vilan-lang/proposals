# B698 — A closure-typed selector subject (`(impl List<|T| i32>)`) never selects its block, even with a bare name - unification of the closure type against the block's subject fails

- status: OPEN - filed 2026-11-03 (lane lang-56b's find)
- kind: bug (import selectors; A181 residue, pre-existing)
- area: Checker / resolver

The selector matcher compares a written subject against each block's subject by unification; a closure type (`|T| i32`, `(|| View) context owner_scope`) is apparently not unified structurally (parameters, result, the context clause), so no block with such a subject is ever admitted - a `import m::(impl \|T\| i32);` admits nothing and row 496's 'admits nothing' message fires, which at least is honest. Rec: unify function types structurally in the selector matcher (arity, each parameter, the result, `sync`/`async`/context markers as the block's spelling has them), pin bare and absolute forms.
