# B716 — A struct LITERAL's generic fields are checked against the struct's DECLARED bounds instead of the enclosing impl's: inside `impl Outer<type K: PartialEq + Hashable>`, `Outer { inner = Inner::new() }` (where `Inner::new` lives in `impl Inner<type K: PartialEq + Hashable>` and `struct Outer<K: Hashable>`) is refused with `generic parameter 'K' is missing the bound ': PartialEq' required by this call`, while `let inner: Inner<K> = Inner::new(); Outer { inner }` is accepted

- status: OPEN - filed 2026-11-09 (lane lens-s5's find, A185 S5)
- kind: bug (checker; struct literals and impl bounds)
- area: Checker / solver

Repro: the eight lines in the lane's report (two generic structs, the inner constructor bounded on the impl). Rec: when a struct literal's field expression is checked, the generic parameters in scope are the ENCLOSING impl's (with its bounds), not the struct declaration's; pin the literal form, the typed-let form and the bound-on-struct form.
