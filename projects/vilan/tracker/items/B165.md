# B165 — `type` binders do not resolve inside an impl head's bounds

- status: OPEN — found by the a32-paper lane (Order 22); Order 23 material
  beside B157's generic blanket
- kind: bug
- area: Type system & the type solver
- source: reactive-traits.md §9.1/Q9

`impl type S: Source<type T> with MaybeSignal<T>` — the blanket-over-a-bound
B157's generic form needs — fails with `cannot find type 'T'`: a `type`
binder introduced inside a BOUND's argument list is not in scope for the
rest of the head. B158 ships blanket impls this order; this is the
follow-on that lets a blanket constrain its subject by a parameterized
trait and reuse the parameter. Wants the binder-scope rule written into the
same spec section B158's lane is chartered to write.
