# E316 — a function's signature label drops an IMPLICIT parameter's trait arguments - `fun login_block(username: Signal<str>, password: Signal<str>)` hovers as `fun login_block(username: Signal, password: Signal)`

- status: OPEN — filed 2026-10-13 (editor-52's find, Order 52)
- kind: editor (hover; XS)
- area: Editor

An implicit generic (`x: Signal<str>`) renders by its constraint NAME (B261's bare rendering), which is the trait's name without its arguments; the declaration label prints that. The parameter's own hover (E237's block) and E310's trait hover carry the arguments. Fix in the signature label writer: an implicit generic's position prints its bound (`Signal<str>`), not the binder name. Pins: a one-argument trait parameter, two parameters of one trait at different arguments, a bound written `<S: Signal<str>>` (unchanged: `S`).
