# B618 — The type of `async e` depends on whether `std::task` is in the program — without it `async work()` is `Promise<i32>` (an annotation `let again: Promise<i32> = task` checks clean), with it `Task<i32>`

- status: OPEN — filed 2026-10-12 (native-51's find, Order 51)
- kind: bug (checker; S)
- area: Type inference

`promise_struct_id` and `task_struct_id` are both registered and the async value takes `Task` only when `std::task` loaded. Hover, annotations and the native backend's host-handle rules see two types for one expression (F130 now refuses `print` of either by its vilan type). Either `async e` is always `Task<T>` (std::task in the prelude's closure) or `Promise<T>` is retired as its type. Sizing S; the solver.
