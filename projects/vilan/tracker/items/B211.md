# B211 — `reconcile_type`'s `(_, Type::Generic(constraint_id))` arm binds a generic the body has no right to bind: `swap(A, B)` prints A's impl reading a B's field (MISCOMPILE, pre-existing)

- status: OPEN — paper lane b184-paper-2's bycatch (2026-09-03); Order 26 lane b211-b212 fixes it the same day
- kind: bug
- area: Type system & the type solver
- source: `analyzer.rs:19393`, the arm `trait-objects.md` §1.4 flagged as "the leak", now shown leaking in a second direction

Two garbage runs on 0.40.0 (635e3728), both reproduced with WRITTEN
generics (a bounded `<T: X>` AND an unbounded `<T>`), so neither is
B186's parameter sugar's doing:
1. `fun swap(a: X, b: X) { mut c = a; c = b; c.who() }` called as
   `swap(A { tag = "aa" }, B { n = 7, label = "bb" })` prints `A/7` —
   A's `who` reading field 0 of a `B`: an `i32` through a declared
   `: str`.
2. `fun f(x: X) { need_a(x) }` where `need_a(a: A)`, called as
   `f(B { n = 9 })`, prints `9` — the same escape.
Root: inside a body, reconciling a value against a generic
parameter's type BINDS the parameter to the value's type (the arm
meant for call-site inference), so `c = b` re-binds `T` from A to B
and `need_a(x)` binds `T := A` with no check that the argument IS an
A. Fix: a generic parameter is rigid inside its own body — the arm
must not bind a `Type::Generic` that belongs to the enclosing
function's own binder (only a callee's parameters are inferable at a
call). Pin both runs (refused: `Expected A, but got T`-shaped, in the
curated voice), a control that call-site inference still binds a
callee's `T`, and the same two shapes through B186's sugar.
