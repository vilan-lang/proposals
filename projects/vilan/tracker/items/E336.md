# E336 — vilan-dap names a std frame by V8's own inference, not by its vilan function: a closure std passes to `with_finally` shows as `running_wake.v`, others as `(anonymous)`, beside correctly named user frames

- status: OPEN — filed 2026-10-16 (debug-54's find, Order 54)
- kind: tooling (vilan-dap; cosmetic; XS-S)
- area: LSP & tooling

The sidecar describes the USER's functions only (std is ignore-listed, its frames subtle), so a std frame falls back to the inspector's `functionName`, which V8 infers from the nearest assignment — in the traced wake's stack `run_traced`'s body closure reads `running_wake.v` (the property its sibling closure assigns). The frames are subtle and collapsed by default, but a user who expands them reads a name the program never wrote. Rec: name a frame with no sidecar record by the map's `names` at its function head (S5 marks function heads with names, std's included), falling back to V8's only where the map has none; a closure as `a closure in <name>`, as the sidecar spells a user's. Sizing XS-S, adapter only.
