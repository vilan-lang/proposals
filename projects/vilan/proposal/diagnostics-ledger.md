# The diagnostics ledger (diagnostics-standard.md §5)

Every `diagnostics.push` site, its message head, and its audit verdict.
Verdicts: **QUALIFIES** (rules met, pin cited) · **RE-ANCHOR** (fails
A-rules) · **REWORD** (fails B-rules) · **DEMOTE** (cascade) ·
**NOTE-NEEDED** (wants C3) · *(blank = unreviewed)*. Line numbers are the
snapshot at generation; the message head is the stable key. Updated per
audit batch, in the batch's commit.

Rendering convention (E76, 2026-08-20): a rendered `file:line:col` header
and the label beneath it name the SAME position — every span reaches
ariadne in one index space (char offsets, converted exactly once per span
by `char_range` at the CLI's render boundary, reused for the report
location and its label). `IndexType::Byte` broke this for every
cross-source note: ariadne 0.6 derives a secondary group's sub-header
from the label's already-converted char offset as if it were still bytes,
so multibyte text earlier in the noted file dragged the sub-header lines
above its label (`reactive.vl:363:26` over a line-365 label). Pinned end
to end in `vilan-cli/tests/diagnostics.rs` (the three `e76_*` pins: both
live note flavors agree, a same-file note is byte-identical).

**The gate.** `crates/vilan-cli/tests/diagnostics_ledger.rs`, over a committed
index `crates/vilan-cli/tests/diagnostics-ledger.tsv` — one line per row here,
`row → flagship? → key`. The index lives in the vilan repository because the
proposals repository is not present in a CI checkout; the two are ONE record,
and a row lands in both in the change that ships the message. Six properties,
red on every suite run:

- *Every row still lives.* Each key is split on its `{…}` slots and `…`
  elisions and its longest literal fragment is searched, fixed-string, over the
  compiler sources and `vilan/std/**/*.vl` — with Rust's string-literal line
  continuations normalized away first, which is the artifact that made batch
  8's and L13's scans hand-triaged work. A reworded or deleted message reds the
  row that keys on it. This is L13's mechanical re-key, run by the suite
  instead of by a lane.
- *Every diagnostic is rowed.* Two anchors are enumerated in full: every
  `Error { … msg: <literal> }` site in the compiler crates, and every
  `errors.push(<literal>)` in `manifest.rs` (the manifest refusal family). A
  message no row's key matches AS A PREFIX reds, named by file, line and text.
  Prefix, not "appears anywhere": the loose form silently accepted B158's
  reworded impl-ambiguity sentence under row 214's key, which is F20 mechanized
  badly.
- *The index is well formed*: rows ascend, none repeats, and every keyless or
  fragment-less row is recorded by number and reason rather than skipped (154,
  a forwarding push; 229, the nine `ParseErrorReason::Rule` statements; 291,
  const evaluation's composed failure envelope).
- Three more hold the appendix — see N37 below.

What the gate does NOT do, stated so nobody reads more into a green: it
verifies no verdict, pin, span or anchor; it does not enumerate helper-built
messages (a `msg:` that names a variable), std's runtime refusals, or CLI
output text — those rows are held by the FIRST property only, so a reword of
one still reds but a brand-new message in one of those families escapes the
second; and it proves nothing about reachability. `Note { … msg: … }` sites are
enumerated and deliberately not rowed: a C3 note is recorded inside its
primary's row, the convention every batch has used. Regeneration is
deliberately not automated — a new message is meant to cost its author a row
and a verdict, and a `--fix` flag is how this record went three orders stale.
