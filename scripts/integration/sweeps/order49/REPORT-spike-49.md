### The design as built (`crates/vilan-core/src/analyzer/id_windows.rs`, ~500 lines; `analyzer.rs` hooks; `tests/id_windows_spike.rs`)
- **Windows**: one per TOP-LEVEL item of every module-level walk — the six module-level `walk_expr_nodes` calls (modules, std's and the dependencies' `lib.vl`, generated expansions, the hot set, the entry) now go through `walk_module_items`, which opens a window at the three counters (entity, type, scope), walks the item, closes it. Laid out contiguously in load order by construction, disjoint in every lane; inline `mod` blocks are ONE window (not split — noted limitation). The stored world clones its windows; the hot set appends after the prefix.
- **Density**: `type_id_sources` (the one dense Vec) stays dense-with-PADDING — a window's room is padded with its source at close (4 bytes per slack slot; a run-length form is the production shape, not built); `source_ranges`/`frozen_ranges`/`world_ranges` are contiguous per source and unchanged; the two id-range loops (`analyzer.rs:18051` the loop/break scan over `source_ranges`, `derived_type_origin`'s range contains) tolerate gaps (a gap maps to no entity). `debug_assert_eq!(type_id_sources.len(), id)` kept for global mints.
- **Anchors**: `resolve_constraints` sets `id_windows.set_anchor(constraint.anchor())` per constraint (memoized by anchor id, binary search over windows) and clears it after the loop; every later mint is classified by anchor and phase (Walk / Resolve / Build / Checks).
- **Modes** (`VILAN_ID_WINDOWS`): `census` (windows recorded exactly, no id moves — today's ids, numbers only), `walk` (room = `max(walk mints × VILAN_ID_WINDOW_SLACK% [default 100], 8)`, counters jump past it, later mints in the tail stamped with their anchor), `types` (+ anchored TYPE mints relocated into the anchor's window while it has room, else spilled to the tail and counted), `all` (every lane relocated). Plants `VILAN_ID_WINDOWS_PLANT=anchor-off|cross`. `Program.id_windows: Option<IdWindowsReport>` + a `[vilan windows]` stderr line per analysis + `VILAN_ID_WINDOWS_DUMP=<path>` per-window rows (walk/relocated/spilled per lane; needs `build-release-2`).
- **Overflow policy as built**: a relocated mint that finds no room spills to the global tail (the id is still anchored and counted; `overflowed` per window). For S6/S7 the policy should be: a window sized from the item's PREVIOUS analysis (the per-item record carries its demand), ×1.5; an item that overflows on a re-walk is re-laid out at the end of the id space (its ids were going to move anyway — it changed) — see the numbers for why a fixed ratio of the walk cannot work.
