### Per item: verdict and real cause
- **E276, done.** `dbg(-0.0)` printed `0.0` because the printer used the same number rule as `print`.
  - Now `__dbg_float` (JS) and `vilan_rt::show::float` print `-0.0`.
  - std's `f32`/`f64` `.debug()` also answers `"-0.0"`, so a derived `Debug` and `dbg` still agree. `print` keeps `0`.
- **E277, done.** The layout broke every value past 80 columns one entry per line.
  - A layout group now carries a `fill` flag. It is set for a `List`, `[T; n]` or `HashSet` whose element is a scalar: a number, string, bool, void, a backed enum, or an enum whose variants carry no data.
  - A filled list packs entries up to 80 columns, each followed by a comma; the `… N more` marker packs like an entry. Aggregates keep one entry per line, and the 100-entry cap stands.
  - Both layout runtimes produce identical bytes.
- **E275, done.**
  - **Hypothesis was partly wrong:** the item title says "written OR derived impl decides", but the ruling body says a *written* impl overrides and the derive agrees. I built the body's version:
    - A written impl overrides at every position: top level, field, list element, option payload, generic `T`.
    - std's impls and the derive's impl keep printing structurally, so `dbg` still breaks a long derived value over lines. A derived `.debug()` is the same text on one line.
  - The rule lives in `printer::written_debug`: the impl that impl selection picks for the concrete type counts as written unless it is in std or was generated by `derive(Debug)`. A written generic impl whose bound the type misses doesn't apply.
  - The derive now qualifies variants (`Shape::Circle(1.5)`). `str`'s `Debug` now escapes exactly as the printer does, replacing `JSON.stringify`.
  - `.debug()` stays opt-in (pinned).
  - Only std's `Option`/`Result` print bare; a program's own enum named `Option` prints qualified.
  - **Ripple:** std's own derived enums now print qualified too (`RpcError`, `Status`, `ConnectionState`, `DraftState`, `WriteState`, `DialFailure`). That turned 22 tests red in the first full run, all string expectations:
    - harnesses `examples`, `hmr_swap`, `transport_robustness`, `service_layer`, `reactive_channels`, `rpc_http`, and `native_differential`'s kolt-shape server;
    - the rpc example's expected output and its README.
  - I updated those expectations, including negative `contains` checks that would otherwise have passed vacuously.
  - kolt only logs these values: its log text changes and nothing breaks.
  - The only analyzer change is that `Program::derived_origin` is now `pub(crate)`.
- **N149, done.** N136's wrap came from a static recording that cannot see `T`.
  - The JS emitter now also reads the argument's type under the instance's substitution (`prints_a_number`), so number instances get the wrapped body and a string instance doesn't.
  - Using the emitter's types alone was not enough: they don't cover every argument (I measured about 60 goldens dropping their wrap). So it is the union of the two.
  - This also fixed closure parameters whose type is inferred later, e.g. `for_each(|n| print(n))`.
- **S1b `dyn`, done.** A `dyn` prints as `dyn Area(Square { side = 2 })`, or `dyn Label<str>(..)` with trait arguments.
  - In a program that calls `dbg` (and doesn't strip it), every trait-object table carries a printer entry:
    - **JS:** a `$show` key in the table. No vilan name can start with `$`.
    - **Native:** a `dbg_show` method on the object trait, renamed if a trait member already uses that name. Pinned with members named `show` and `dbg_show`.
  - A program with no `dbg` gets no slot, so no corpus golden moves.
- **Closure spelling fix (my find).** The printer wrote `<closure |i32| -> i32>`, which the parser refuses. It now writes `<closure |i32| i32>`, and pipe labels follow.
- **E260 tuple case: waiting.** B557 is not on `origin/next`. The ignored pin `s4_debug_covers_a_tuple` stays as it is.
